## 二、信息论创作指令（完整版）

### 2.1 核心指令格式

```
【信息论创作指令】
- 本章熵预算：需解决关于"XXX"的伏笔，并暗示XXX的存在。
- 自信息要求：请在主角与反派对峙时，设计一个读者意想不到的第三方介入。
- 互信息要求：主角的一切决定必须与其"XXX"的核心动机强相关，互信息不得为0。
- 关联设定：[[角色A]]、[[角色B]]、地点[[地点X]]、伏笔"伏笔Y"。
请基于以上，续写下面的大纲为3000字正文：
（在此粘贴大纲摘要）
```

### 2.2 熵预算设计指南

| 熵级别 | 含义 | 适用场景 |
|--------|------|---------|
| 高熵 | 大量新信息引入 | 开篇、高潮、反转 |
| 中熵 | 中等信息量 | 过渡、铺垫、日常 |
| 低熵 | 信息回收为主 | 收尾、伏笔回收 |

### 2.3 互信息检查清单

- [ ] 主角行为是否与其核心动机一致？
- [ ] 情节发展是否与前文设定强相关？
- [ ] 角色对话是否符合其性格设定？
- [ ] 伏笔回收是否有足够的铺垫？

## 七、模型配置指南

### 7.1 推荐模型配置

| 任务类型 | 推荐模型 | 推荐参数 |
|---------|---------|---------|
| 快速生成 | deepseek-v4-flash | temp=0.7, maxTokens=8192 |
| 高质量生成 | doubao-seed-2-0-pro | temp=0.8, maxTokens=16384 |
| 分析评估 | glm-4-plus | temp=0.3, maxTokens=4096 |
| 长文本生成 | qwen3-max | temp=0.7, maxTokens=32768 |

### 7.2 模型切换策略

```
- 优先使用 proModel（高质量）
- 快速任务使用 flashModel
- 长文本任务使用支持长上下文的模型
- 分析评估任务使用推理能力强的模型
- 断联时自动降级到本地模型（Ollama）
```

### 7.3 上下文管理策略

```
- 紧凑模式：仅包含当前章节上下文
- 标准模式：包含前3章上下文
- 扩展模式：包含前10章上下文
- 全局模式：包含全书上下文
- 根据任务类型和字数自动选择
```

## 八、工作流操作指南

### 新建项目

1. 使用「创建项目」命令或模态框创建项目
2. 填写项目名称、类型（原创/同人）、题材分类
3. 进入「完整写作工作台」开始创作

### 规划一卷

1. 在「完整写作工作台」中使用「大纲规划」步骤
2. 填写分卷大纲，包含每章核心冲突和信息功能
3. 使用「场景级细纲编辑」展开到场景级

### 写一章的完整流程

1. 使用「批量建章」或「新建章节」创建章节文件
2. 在「协同写作视图」中打开章节文件
3. 使用「信息规划」步骤设计本章内容
4. 使用 AI 生成正文（支持续写/改写/扩写）
5. 使用「质检分析」检查质量
6. 使用「润色打磨」优化文本
7. 使用「章节结算」更新状态

### 写完一章后的更新步骤

1. **更新人物状态**：在人物页面修改 `当前状态`
2. **更新伏笔状态**：将回收的伏笔移到已回收表
3. **更新时间线**：添加本章事件到时间线看板
4. **更新信息债**：检查并记录信息债变化

## 九、写作规则（文件驱动）

> ⚠️ 写作规则已改为文件驱动，不再硬编码。
> 规则文件位置：`00-系统模板/写作规则.md`

### 规则读取流程

```
写作规则.md → 正则提取 ## 一、强制写作规则 章节
  ↓
清洗: 去掉 ### 数字标题 / 检查方法 / 统一列表符号
  ↓
注入 System Prompt 的 【强制写作规则】
  ↓
修正 API 也收到规则（作为【写作规则参考】）
  ↓
checkWritingRules() 从文件动态读取，不再硬编码
```

### 规则版本管理

- 规则文件包含版本号
- 规则版本不匹配时会发出警告
- 修改规则文件后自动刷新缓存
- 设置页可查看规则版本状态
