## Gate 2: 质量门校验（实现后）

### 类型安全

- [ ] `tsc --noEmit` 退出码 = 0
- [ ] `tsc --noEmit` 输出无任何 ERROR 行
- [ ] 无新增 `// @ts-ignore` 或 `// @ts-expect-error` 注释
- [ ] `:any` 类型标注减少 > 50% (从 ~250 降到 ~125 以下)

### 测试覆盖

- [ ] `npm test` 全部通过（118+/119 文件，token-bucket 可有1个预存flaky）
- [ ] 删除的3个死文件测试不再被执行
- [ ] 新增的并行化代码有单元测试覆盖
- [ ] 新增的缓存逻辑有单元测试覆盖
- [ ] 新增的 LSH 索引有单元测试覆盖

### 边界覆盖

- [ ] 空文本解构：无 LLM/向量服务时正常降级，不崩溃
- [ ] 单章节文本：分段逻辑正确处理 1个分段的情况
- [ ] 超长文本（> 100万字）：不OOM，进度正常
- [ ] 并发冲突：同时触发两次解构，第二次正常排队或取消
- [ ] 缓存损坏：损坏的缓存文件被跳过，回退到全量重算
- [ ] 网络异常：LLM API 超时时正常降级，不影响其他维度

### 降级策略

- [ ] 向量服务不可用：维度降级到 `standard` 模式，不整体失败
- [ ] LLM 服务不可用：维度降级到 `fast` 模式，不整体失败
- [ ] 文件写入失败：错误被捕获，用户收到通知，不静默失败
- [ ] 分段缓存写入失败：跳过缓存，回退到全量重算

### 性能基准

- [ ] 维度并行化：8维度全量解构耗时 < 原串行耗时的 50%
- [ ] 增量缓存：未修改文档的重复解构跳过率 > 80%
- [ ] LSH 索引：`semanticMatch` 在 n>500 时耗时 < 原来的 10%
- [ ] 批量实体补救：3+ 失败实体时，API 调用从 F 次减少到 1 次
- [ ] Prompt 缓存：连续写作场景下 prompt 构建耗时 < 原来的 50%

### 渲染正确性

- [ ] 节奏标签页 `coolPoints` 散点图：数据点正确显示（非 NaN）
- [ ] 节奏标签页 `plotStages` 时间线：显示正确名称和百分比
- [ ] 节奏标签页 `structureMatches` 柱状图：显示正确匹配分数
- [ ] 节奏标签页 `chapterRhythm`：章节节奏图正确渲染
- [ ] 节奏标签页质量评分卡：显示 6项评分指标
- [ ] detail-modal 无假数据：所有回退改为空状态提示
- [ ] "基于全书 N 字"：10个标签页中至少8个展示字数（标签页/概览可例外）
- [ ] 各维度质量评分卡：completeness/consistency/confidence/overall 值在 0-1 合理范围

### 可维护性

- [ ] 无新增 TODO/FIXME/HACK 标记（除非有对应 Issue 跟踪）
- [ ] 新增代码遵循现有命名约定

## 手动验证清单

### 解构流程

- [ ] 打开一个有分析数据的书籍，进入知识库管理
- [ ] 点击"重新分析" → 观察进度条正常推进
- [ ] 切换到节奏标签页 → 所有图表正确渲染
- [ ] 点击任意数据点 → detail-modal 显示正确数据（无假数据）
- [ ] 切换到其他标签页（风格/结构/人设/伏笔/商业/可读性/技巧）→ 数据显示正常
- [ ] 质量评分卡在每个标签页正常显示
- [ ] "基于全书 N 字"在每个标签页一致性展示

### 实体生成

- [ ] 从知识库触发实体批量生成
- [ ] 观察生成进度 → 失败的实体被批量补救（非逐一）
- [ ] 生成结果去重正确（无重名实体）
- [ ] 重试耗尽的实体被丢弃并通知用户

### 并发行为

- [ ] 在解构进行中修改文档 → 解构继续或正确取消
- [ ] 快速连续点击"重新分析" → 第二次排队或取消第一次
