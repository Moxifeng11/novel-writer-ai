## 2. 现状（事实，不写愿望）

- **语言解析**：`resolveLocale(setting)` —— `auto` 时读 `window.localStorage.getItem('language')`
  （Obsidian 自己就是这么记的），`zh*` → `zh-CN`、`en*` → `en-US`、读不到或抛错 → `zh-CN`。
- **翻译语义**：`translate(locale, key, params)` 查找顺序「目标语言 → zh-CN → 键名本身」；
  命中不到时 `console.warn('[i18n] 缺少文案键：' + key)` **每个键只警告一次**，界面不炸。
  插值走 `/{placeholders}/g`（源码为 `\{(\w+)\}`，未提供参数的占位符原样保留）。

## 4. 关键决策

- **不依赖 Obsidian 的 locale API**：桌面/移动/测试环境可用性不一致。只读
  `localStorage.language`，读不到就当 `zh-CN`——宁可「跟随不到就中文」，也不要启动即空白。
- **缺失键不抛错**：返回键名并在控制台警告一次。理由：一期只有 42 条，任何一处漏配键都不该
  把整页炸成白屏；键名本身在界面上可见，也自带定位信息。
- **`label` 做成 getter 而不是函数或常量**：`SETTINGS_TAB_DEFINITIONS` 被 6 处消费
  （`settings-tab.ts` / `mini-settings-modal.ts` / `settings-menu.ts` / `settings-search.ts` /
  `main.ts` / 单测），全都要 `tab.label: string`。getter 保持类型不变，同时每次读都取当前语言；
  若算成字符串，切语言后必须重建整个常量表（消费方拿到的仍是旧串）。
- **生效点放在 `SettingsService.loadSettings()` 之后**（`engine/engine-registry.ts` Phase 5）：
  那是设置加载的唯一收敛点，启动路径不走 `plugin.loadSettings()`，放别处会读到默认值。
- **切换语言 = 整页重开**（`reopen()`）：`t()` 在渲染时求值，局部 `refresh()` 只会重绘当前分区，
  分组栏/页签/标题仍是旧语言。代价是一次重绘，收益是不会出现「半中半英」的中间态。
- **命令面板文案必须在注册命令之前定语言**：Obsidian 的 addCommand({ name }) 把字符串
  一次性存进命令表，之后再 setLocale() 只影响后续渲染的 t()，面板里的名字不会变。
  因此 main.ts 在 commandRegistry.registerObsidianCommands(...) 前一行显式
  applyLocaleSetting(this.settings.language)（此时 SettingsService.loadSettings() 已在
  engine initialize 阶段跑完）；engine/engine-registry.ts Phase 5 的调用保留，覆盖其它晚加载路径。
- **切换语言后命令面板要重启才更新**：理论上可以 removeCommand + 重新 addCommand，
  但热键按命令 id 存、重注册有丢配置风险，也不是 Obsidian 插件的常规做法。选择在语言设置的
  desc 里如实写明「重启 Obsidian 后生效」，不做假热更新。
- **棘轮而非一刀切禁止**：存量 11892 条中文不可能一次清零。基线按**文件粒度**记录，
  规则是「per-file 只许降不许升」+ 新文件默认允许 0 条；改文案导致条目下降要
  `--update-baseline` 收紧，否则棘轮会松。无基线文件时按当前状态放行并提示（首次接入友好）。
- **门禁用 `ts.transpileModule` 求值资源**：`i18n/messages/*.ts` 是 TS ESM，node 直接 `import`
  需要实验开关；降级成 CommonJS 再 `new Function` 求值，跨 node 版本稳定。
- **`check-i18n` 只扫 `ui/**`**：引擎/服务层的中文多是日志、提示词、数据字段，不是界面文案，
  一刀切会逼人给日志加 `t()`（那才是错）。界面文案的真正边界就是 `ui/`。
- **主题名与描述不迁**：`shared/theme-gallery.ts` 的「宣纸墨 / 青瓷 / 靛蓝 …」会被
  `galleryThemeToPreset` 写成配色方案名存进 `settings.themePresets`。一旦按语言渲染，
  用户切一次语言，同一套方案就换个名字出现在列表里（甚至重复）。宁可名字保持中文，
  也不要制造随语言漂移的持久化数据；真要英文化，应改成「存 id、渲染时查表」。
- **notice 用插值而非拼接**：`applyGalleryTheme` 的提示是
  `t('settings.appearance.themeApplied', { theme: theme.name, mode: modeLabel(mode) })`——
  拼接会把语序写死在代码里，英文语序与中文不同，插值让译者能决定句子结构。
- **`Setting.addButton` 的文案不在容器子树里**：单测里 `container.allText()` 取不到按钮文字
  （按钮挂在 `stubDocument` 上），对外观页「恢复默认配色」这类按钮只能断言 `textContent` 或跳过。
  `tests/unit/ui/appearance-settings-i18n.test.ts` 因此删掉了那一条断言并留了注释。
- **`shared/` 里的界面文案也可以迁**：`shared/secret-display.ts` 是「密钥怎么显示」的单源
  （设置页、供应商管理弹窗、知识库分区共用），把它迁到 `t('secret.*')` 比在三处各写一遍更稳；
  `check-i18n` 的静态键校验本来就把 `shared/` 纳入扫描范围。反例是 `shared/theme-gallery.ts`
  的主题名与 `THINKING_LEVELS`/`BUDGET_TIERS`——它们是数据或跨模块常量，迁了会污染持久化数据
  或造成半边界面英文、半边中文，故保留中文并记 backlog。
- **展示常量改成函数，不要留模块级字符串**：`SECRET_LOCKED_PLACEHOLDER` 原来是
  `export const`，import 时就把当时语言的文案定格；改成 `secretLockedPlaceholder()` 后
  每次渲染取当前语言。语义相同的还有 `SECRET_INPUT_ATTRS`（纯属性，不涉及语言，保持常量）。
- **拼接片段自带前导空格**：`describeKeyEncryptionStatus()` 的 legacy/mismatch 提示是
  句尾追加，中文不需要空格、英文需要，所以键值里就带一个空格（`' ' + t(...)` 再加一层保险），
  避免英文出现 `... to read them.3 more legacy ...`。
- **通用设置六个分区不拆文件**：`general-sections.ts` 1258 行、六个 Section 类共享
  `addStatCard` / `renderInfoItem` 等工具方法。本次只替换文案（`t('settings.general.*')`），
  不动类结构——拆文件是独立的重构议题，mix 进 i18n 会让 review 同时面对两种风险。
- **关键词样例按语言本地化**：`settings.general.kw*Hint` 原是中文例句
  （`气若游丝, 命悬一线` 等），但 `i18n-parity.test.ts` 硬性禁止 en 资源出现 CJK，
  且 en 界面里塞中文例句会显得像漏翻。最终 zh 保留中文真词、en 用等义英文例
  （`dying, gasping` 等），并刻意压短到输入框两行内、不出现横向滚动条。
  规则正文里的 vault 路径（`元文件/00-系统模板/写作规则.md`）属于**用户数据**，
  en 文案改成描述性说法（`the writing-rules file inside the vault's metadata /
  system-template folder`），不翻译真实路径，也不在资源里写中文。
- **错误信息用 `{message}` 插值**：`rulesCheckFailed` / `aboutCheckFailed*` 把 `(e as Error).message`
  作为参数传入，避免在代码里拼「检查失败：」+message（英文语序不同，且异常文本本身不可译）。
- **顺手修了规则状态提示的对比度**：`nw-st-notice--success` 原来
  `background: var(--background-modifier-success); color: var(--text-success)`，默认主题里
  两者接近同色，实机截图只剩 emoji 可见（中英一致，属既有视觉问题，被本片截图发现）。
  改成中性底 `--background-secondary` + 左侧 3px 语义色描边 + `--text-normal` 正文，
  warning 同步处理。不改文案、不动 DOM。

- **大文件迁移用「精确串替换」脚本，不手改每个字面量**：`writing-sections.ts` 851 行、175 行含中文，
  逐条手改必然漏改或改坏缩进。做法是仓外脚本（`D:\nw-tmp\migrate-writing-1/2/3.cjs`）持
  `[[old,new],...]` 对，逐条 `if(!s.includes(a)){console.error('MISSING: '+a)} s=s.split(a).join(b)`——
  某条没命中就显式报 MISSING 并让脚本非零退出，比静默跳过安全。三个硬坑：
  （1）该文件是 **CRLF**（850 个 \r\n、0 个裸 \n），**多行 old 串必须带 \r\n**，否则整条 MISSING；
  （2）替换值必须是字符串字面量，写成 `W('key')` 之类的代码会被 node 当成脚本执行（`ReferenceError`）；
  （3）**长串先替换**，`'本地模型'` 若先于 `'选择协同写作使用的 Ollama 本地模型'` 命中会拆坏长串。
- **动态行数据从文案字段改成键字段**：布局页的面板尺寸行原来是
  `{ key, label: '写作工作台 · 左栏', desc: '写作工作台左栏…', min, max, fallback }`，
  文案在数据里就无法静态校验。改成 `labelKey`/`descKey` 后渲染时 `t(row.labelKey)`，
  描述再套一层插值模板 `t('settings.writing.sizeRowDesc', { desc: t(row.descKey), min, max, fallback })`
  （zh：`{desc}（{min}–{max}px，默认 {fallback}px）`）——语序交给译者，代码只传值。
  代价是 `check-i18n` 的键引用扫描会多记 2 处「动态键」（全仓 4 处），已在门禁输出里可见。
- **多行占位符要写真实换行，不要写 `\n` 转义**：`antiAiPlaceholder` 的 zh 值是
  `'例如：\n话说\n说白了\n不妨\n'`（单反斜杠 n = TS 源码里的真实换行）。
  生成资源脚本若把它当普通字符串用 JSON 转义写入，文件里会变成双反斜杠（界面显示字面 `\n`），
  需要用 `\\n` → `\n` 修回；en 对应 `'e.g.\nTo be fair,\nIn fact,\nPerhaps,\n'`（不得含 CJK）。
- **同一 UI 在两个宿主里各写一份的文案，以资源键为准**：异步刷新条在 `ui/settings-tab.ts` 与
  `ui/mini-settings-modal.ts` 各有一份字面量（设置页与设置弹窗两套外壳），迁 i18n 时两处都改成
  `settings.shell.asyncStale`/`asyncRefresh`，避免下次只改一处、实机再出现中英混排。

- **`services/` 也可以 `import { t }`**：提示词分类标签被三处 UI 消费（设置页分类按钮、
  模板详情行、创建弹窗的分类下拉），放在 `services/prompt-manager.ts` 里做单源比在三处各写一遍稳；
  这也让 `PROMPT_CATEGORY_LABELS`（模块级中文常量，切语言会定格）变成渲染时求值的
  `promptCategoryLabel()`。代价是 `check-i18n` 的动态键警告从 4 处增到 6 处（服务层两处），
  已列入 §7 统一收敛。
- **未登记分类回落原始 key，不回落空白**：老 vault 里可能存在历史 category 值
  （`category` 是自由字符串），`prompt.category.<id>` 查不到时显示原值比显示空白好排查；
  `hasMessage()` 判断而不是 try/catch，是因为缺失键会走 `translate` 的 console.warn。
- **`t` 会被局部变量静默遮蔽**：`templates.filter(t => ...)`、`const t = getTemplateById(v)`
  这类写法不会报「未使用 import」，只会在调用 `t('…')` 时报 TS2349 / TS2721（`PromptTemplate`
  不可调用 / 可能是 null）。迁移大文件时把形参与局部变量统一改名（`tpl`）是唯一稳妥做法。

- **搜索索引存键、不存「已经算好的文案」**：主题词的 `name` 改成 `nameKey`，结果行统一用
  `entryLabel(entry)` 求值。索引在设置页初始化时就建好并长期驻留，若那时就把 `t()` 的结果塞进条目，
  切语言后搜索结果仍是旧语言（且 `check-i18n` 静态扫描看不见键）。tab 级条目不需要额外处理——
  `tab.label` 本来就是 getter（见 §4 第一条决策）。
- **同义词表写中英并集，不按当前语言二选一**：`topicKeywords()` 同时读 zh-CN 与 en-US 资源的
  `settings.search.topic.<id>.keywords` 并合并。按语言过滤会让用户「切到英文后反而搜不到中文词」，
  而并集最多多出一两条结果；mcp 主题词在 en 列表里带 `mcp search`，这就是英文界面搜 `mcp`
  会命中「Web research (canon)」的原因（预期行为，别当 bug 报）。

- **常量还有非界面消费者时，「保留常量 + 并出函数」而不是改常量**：`DIMENSION_LABELS`（拆解八维度名）
  被 `engine/deconstruction-scheduler.ts` 用在任务日志与进度串（:197 / :1113 / :1177 / :1294），
  直接换成 `t()` 会把日志变成随语言漂移的文本（且引擎层不该依赖界面语言）。做法是新增
  `DIMENSION_LABEL_KEYS` + `dimensionLabel(dim)`（`hasMessage()` 判空后回落原中文），
  UI 只调函数、引擎继续读常量。与 `PROMPT_CATEGORY_LABELS` 的差别只在于后者没有非界面消费者，所以删了。
- **维度描述表从「文案字段」改「键字段」**（同布局页的 `labelKey`）：`DIMENSION_DESC` 改成
  `DIMENSION_DESC_KEYS`，渲染时 `t(key)`。同理三个 slider 的实时 desc 是
  `t('settings.deconstruction.vectorCacheDesc', { count })`——数值走插值，不拼字符串。
- **分区文件不要从 `'@/main'` 取依赖**：`@` alias 指向仓根，`import … from '@/main'` 在 vitest 里会
  先命中**构建产物** `main.js`（默认扩展序 .mjs/.js/.mts/.ts），于是报
  `Error: Cannot find module 'obsidian'` + `Require stack: …\novel-writer-ai\main.js`。
  `main.ts:739` 对 `shared/deconstruction-settings` 只是再导出，直接
  `import { … } from '@/shared/deconstruction-settings'` 即可，tsc / 单测都过。

- **计量单位用「同一键 + 按语言换基数」，不新增成对键**：字数徽标中文按「万」（`12.3万字`）、
  英文按「k」（`123.4k words`）。若拆成 `wordCountWanCjk`/`wordCountWanEn` 两个键，
  两边占位符集合虽一致但语义错位（一个键只剩一种语言用），`check-i18n` 的键一致性检查也失去意义。
  做法是键只写单位模板（zh `'{n}万字'`、en `'{n}k words'`），基数在 `formatWordCount()` 里按
  `getLocale()` 折算——语序与单位仍归译者，数字归代码。
- **列表行渲染器也算分区文案**：分区类只画卡片骨架，行内容由 `ui/fingerprint-utils.ts`
  这类 util 渲染（空态、徽标、按钮 title、字数）。只迁分区文件时 zh 页面看起来「迁完了」，
  en 页面才会露出中文（第十片来由）。迁设置分区前先顺着渲染函数找 util。
- **数据源在 services/ 时一并迁，日志留在代码里**（第十一片，util 教训的 services 版）：
  `setup-section.ts` 渲染的清单项 label/detail/fix 由 `SetupReadinessService.check()` 逐次构造，
  不迁它 en 页照样满屏中文。做法是服务方法体内直接 `t()`（每次 `check()` 新建服务实例，
  构造时求值 = 当时语言，符合「渲染时求值」语义）；`log.info`/`log.warn` 是日志不是界面，保留中文。
  反例是不改 `ReadinessItem` 接口让服务吐键、分区再求值——那要把插值参数也搬进接口，纯增复杂度。
- **vault 路径与目录名进文案：zh 直写、en 换说法，两边零占位符**：`conventionsDesc` 的
  `写作知识库/插件使用约定.md` 与 `workspaceMissingFix` 的 `写作知识库` 是 vault 固定路径——
  写进 en 资源就是 CJK 被 parity 拦。做法是 zh 值保留原路径、en 值改用「usage guide note /
  knowledge-base folder」等说法（两边占位符集合同为空，parity 不挑）；而 `templatesLabel` 的
  `「{root}」模板树`、`workspaceOkDetail` 的 `已生成说明文件：{path}` 这类「路径在运行时拼接」的键，
  才走插值参数（值是数据，不进资源）。
