# 全系统业务板块优化专项（PROGRAM）

> 版本：v5-plan-1 · 建立：2026-11-01
> 定位：**本文件是全系统优化的任务组级唯一入口**（做什么、怎么分组、谁负责、怎么验收、什么时候交）。
> 结构边界看 [`docs/PLAN.md`](PLAN.md)；问题取证看 `docs/audits/`；进度报告看 [`docs/progress/PROGRAM-STATUS.md`](progress/PROGRAM-STATUS.md)。

## 一、专项原则（先定规则，再排任务）

1. **按"数据一致性边界"分组，不按目录分组**。共享同一份磁盘事实（正文/步骤结果/结算产物/缓存/台账）的板块必须同组改，否则拆开改必然出现"一边新、一边旧"。
2. **不可逆操作单独成闸**：删除、迁移、覆盖写、重编号，必须 dry-run / 备份 / 回滚演练齐全才允许合入。
3. **每条修复必须有可复现证据**：文件:行号 + 触发路径 + 失败现象；修复必须带单测或 E2E 锁定。
4. **先量化再优化**：性能项没有前后数字不进主线；体验项没有"用户可感知的差异"不立项。
5. **门禁只降不升**：分层/循环/实例白名单/CSS 预算按棘轮收紧；确因新功能需要放宽时，必须在基线文件写明原因。
6. **专项进度可追溯**：任务状态只改 JSON；报告由脚本生成；CI 校验一致性。

## 三、交叉依赖归类 → 7 个优化任务组

分组依据：**同写一份数据 / 同一条主链上下游 / 同一类失效模式**。每组可独立排期，但组内**不得再拆给不同人并行改**。

| 组 | 覆盖板块 | 为什么必须同组 | 目标版本 |
|---|---|---|---|
| **G1 创作主链闭环** | B1 B4 B5 B6 B13 B15 | 正文写入、步骤结果、结算产物、上下文缓存、统计台账共享同一份磁盘事实；写锁/幂等/缓存失效必须一次对齐 | v4.23.0 |
| **G2 语料与注入链** | B7 B8 B9 B6 | 知识库拆解产物 → 检索 → 总线 → 指纹/实体注入，是同一条读取链；跨项目读错会静默污染正文 | v4.24.0 |
| **G3 项目生命周期与三模式** | B10 B11 B15 | 删除/迁移/重命名/导出都依赖项目定位与模式隔离；错一处即不可逆 | v4.24.0 |
| **G4 配置与凭据治理** | B12 B14 | 设置默认值、迁移、密钥加密、供应商、主题、命令入口共享同一份 settings 与命令表 | v4.23.0 |
| **G5 交互一致性与可访问性** | B1 B2 B3 B4 B10 B12 B13 | IME/键盘/空态/进度/Notice 是横向原语，分散改必然一处漏改 | v4.25.0 |
| **G6 性能与存储** | B15 B1 B7 B13 | 全库遍历、写放大、缓存上限、启动路径必须一起量化，否则单点优化会被别处抵消 | v4.25.0 |
| **G7 质量基建与可观测** | B16 + 全板块 | 它是其余六组的"刹车"：覆盖率、门禁、台账、联动回归清单 | v4.25.0 |

> 组间顺序：**G7 先立规 → G1/G4 并行（都在 v4.23）→ G2/G3 → G5/G6**。G2/G3 依赖 G1 的写入原语稳定；G5/G6 依赖前三组把"改哪里"定死，避免重复返工。

## 四、任务组详解

> 任务状态与验收证据以 `docs/progress/program-status.json` 为准；本节只写**目标、范围、验收口径、风险与坏人场景**。

### G1 创作主链闭环（v4.23.0）

- **目标**：一条章节数据从生成到结算到统计，全程字段不丢、不覆盖他方结果、失败可恢复。
- **验收口径**
  - 并发写同一伏笔库/时间线：条目数不减、状态不回退（单测）；
  - 同章重复结算：关系值/时间线/出场记录不重复累加（单测）；
  - 插入章节后：内存编号与磁盘文件名一致，无同章双份正文（E2E 或集成测试）；
  - 保存一章：今日统计立即反映净增长，改写不扣历史（单测 + E2E）。
- **风险**：结算与统计都写盘 → 若不同组改，会出现"结算回写了旧 word_count，统计少算"。**禁止把 B13 拆出去单独改。**
- **已完成**：写锁收口、幂等、重编号两阶段、大纲树单遍重建、统计台账接入（见 JSON G1-1…G1-6）。

### G2 语料与注入链（v4.24.0）

- **目标**：知识库→拆解→向量→检索→总线→注入 全链可解释：每个被注入的片段能回答"从哪本书哪一段来、为什么被选中"。
- **验收口径**
  - 步骤结果 frontmatter 有 `rag_sources`（片段 id + 书名 + 相似度）；
  - 跨项目同名实体/指纹不串（单测：两项目同名角色）；
  - 样文缺失/检索为空时降级有提示，不静默注入空串；
  - 预算：本地 4200 / 云端 24000 字上限生效，超限截断顺序稳定可复现。
- **风险**：知识库与指纹都按"项目路径"定位，若同组不同步改定位原语，切项目即串数据。
- **已完成**：指纹跨项目写入、样文小节解析（G2-1、G2-2）。

### G3 项目生命周期与三模式（v4.24.0）

- **目标**：创建/迁移/重命名/删除/导出五类操作在三模式下行为一致且可回滚。
- **验收口径**
  - `deleteProject` 路径防线（空/`.`/`..` 拒绝）——已有单测；
  - 迁移：dry-run 计划 → 执行 → 失败回滚，前后文件数一致；
  - 三模式快捷工具被过滤时显示空态说明，而不是整组消失；
  - 导出：短篇/剧本给出未完成单元提示（已完成）；三种格式可打开。
- **风险**：删除/迁移不可逆，验收必须包含"故意传空路径"的负向用例。
- **已完成**：删除防线、短篇/剧本导出前检查（G3-1、G3-2）。

### G4 配置与凭据治理（v4.23.0）

- **目标**：任何设置变更都不会静默丢值；任何密钥都不会以明文落盘或被错字段覆盖。
- **验收口径**
  - 三个向量 Key 字段隔离（单测）——已完成；
  - 加密锁定态保存不覆盖密钥（单测）——已完成；
  - 改当前供应商端点，`apiEndpoint/availableModels` 同步（单测）——已完成；
  - 内置主题切换后 CSS 变量与 settings 同步（E2E）——已完成；
  - `settingsBackup` 不含密钥字段（待办 G4-5）。
- **风险**：迁移路径与加密路径耦合，改动必须同时跑"旧配置升级"用例。

### G5 交互一致性与可访问性（v4.25.0）

- **目标**：中文输入、键盘、空态、进度、错误提示全插件一致；长任务可取消、失败必可见。
- **验收口径**
  - IME：组字中 Enter/Tab/Escape 不触发业务动作（`shared/keyboard.ts`，已有 15 处覆盖）；
  - 全局按键只在焦点位于本面板时接管；
  - 保存/导出/删除类入口 0 处"只 console 不提示"；
  - 批量任务只有一条常驻进度提示 + 结束汇总；
  - 移动端无白屏（宠物/状态栏已做守卫）。
- **风险**：交互原语改动面大，必须按"原语 → 全量替换 → E2E 抽查"顺序，不允许逐点手写。

### G6 性能与存储（v4.25.0）

- **目标**：长篇 200+ 章下打开/落盘/结算不卡；写放大与内存有上限；启动不阻塞。
- **验收口径（全部要前后数字）**
  - 落盘/结算/统计路径 0 次全库 `getFiles()`；
  - 200 章落盘 < 200ms；上下文缓存写入 20 章后 size ≤ 16（已完成）；
  - `index.json` 体积不随缓存值增长（已完成）；
  - 启动：embedding 探测、更新检查均移出 onload 关键路径。
- **风险**：缓存与统计都依赖"文件变化感知"，优化必须同时保证增量正确性（漏算比慢更糟）。

### G7 质量基建与可观测（v4.25.0）

- **目标**：覆盖缺口可度量、门禁不可绕过、问题可定位、进度可追溯。
- **验收口径**
  - CI 跑 styles/deps/engines/program 四道门；
  - 0 个占位测试（`expect(true)`）与无效断言；
  - 盘点出的 0 测试核心文件全部补最小行为测试；
  - 每组改动都要过"三链联动回归"（见第五节）；
  - 台账 JSON → MD 一致（`npm run check:program`）。
- **已完成**：CI 门禁、占位测试清理、专项台账（G7-1…G7-3）。

## 五、稳定性门禁（三道闸，缺一不合入）

| 闸 | 时机 | 内容 | 失败处理 |
|---|---|---|---|
| 闸 1 · 编辑期 | 每次提交前 | `typecheck` + 目标模块单测 + 新增用例覆盖改动分支 | 不回滚代码，补测试或修实现 |
| 闸 2 · 提交前 | 每次 commit | `npm run preflight`（含 lint/test/模板/样式/CSS/内联/分层/引擎/台账）+ `build` + `check:release` | 任一红则禁止提交 |
| 闸 3 · 发布前 | 版本节点 | 真实 Electron E2E 全量 + 三链联动回归 + 迁移/删除负向用例 | 打回对应任务组 |

### 三链联动回归（每次涉及 G1–G3 的改动必跑）

1. **生成链**：创建项目 → 写第 1 章 → 质控 → 定向修订 → 结算 → 统计变化；
2. **语料链**：知识库导入/拆解 → 检索命中 → 注入正文（`rag_sources` 可查）；
3. **项目链**：三模式各建一个项目 → 迁移 dry-run → 删除（含空路径负向）。

## 八、进度报告机制

1. 任务状态只改 `docs/progress/program-status.json`；
2. `npm run program:render` 生成 `docs/progress/PROGRAM-STATUS.md`（禁止手改）；
3. `npm run check:program` 校验两者一致，已接入 `preflight` 与 CI；
4. 每个版本节点在 JSON `changelog` 追加一条（日期｜组｜摘要｜证据）；
5. 同步对象：`docs/PLAN.md`（结构）、`.trae/CURRENT-PROGRESS.md`（跨工具基线）、vault `.trae/DOCUMENTATION-INDEX.md`（索引）、`CHANGELOG.md`（发版流水）。

### 10.3 性能 / 体验 / 架构（Top 项）

**性能（P0/P1）**
1. `saveSettings` 每个密钥一次 PBKDF2-210k，且 salt 随机导致密钥派生缓存永不命中；设置页逐键 onChange → 单次保存 150–400ms + 全量重写。
2. vault `modify` 事件**无防抖**直接刷新信息债：全库 `detectProjects` + 每项目 2 次 `getFiles` + 串行读全部人物卡。
3. `write-chapter-modal` 写第 N 章前循环 `n=1..N`，每轮 4 次 `getFiles()` → 第 200 章约 800 次全库扫描 + 800 次串行读。
4. 拆解监控 500ms 整块重建（丢展开态/滚动/焦点）；工作台每一步 `empty()` 重建。
5. `onload` 里 `await knowledgeVectorStore.init()` 串行读每本书向量（100 本 = 数百次读盘），直接计入启动阻塞。

**体验（P0/P1）**
1. `continue-chapters` 常驻 Notice 只在成功路径 hide + 循环无 try/catch → 失败时永久「正在创建 k/N」且无错误提示（已修）。
2. 引擎层约 10 处「注入/记忆/样章失败 → log.warn 跳过」，用户看不到质量下降。
3. 整卷审查、结算、批处理**无取消/无进度百分比**。
4. 常规流程每章需多次手动点击；1200+ 次点击写过 200 章。
5. 20 处 `new Notice(msg, 0)` 当进度条，无百分比、无取消按钮、并发堆叠。

**架构（P1）**
- 34 个文件 >1500 行（最大 5198）。
- 真实重复：`escapeHtml`×4、`countWords`×4、`cosineSimilarity`×2、`escapeRegExp` 双拼写——**字数口径不统一会直接影响达标判定**。
- `shared/entity-reader.ts` 规定唯一读取入口，实测 67 处直接拼前缀 + 130 处 `getFiles()`。
- 循环依赖 6 组（177 节点大团）。
- `knowledge-vector-store.ts` 缓存键含裸 NUL 字节，使该文件对 grep/工具"不可见"（已修）。
