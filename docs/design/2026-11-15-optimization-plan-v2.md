# 优化方案 v2（2026-11-15）

> 依据：全仓审计 `docs/audit/2026-11-15-plugin-data-model-audit.md` + 用户决策
> ① 时间线/伏笔：每事件/每伏笔一文件 + 看板派生
> ② 关系：**R1 每关系一文件**（不用单表 md）
> ③ 迁移对旧项目生效，原文件**转成派生视图**
> ④ 优先级：先 B（统一索引）后 A（卡片化）
> ⑤ **文件名必须用数据库式唯一编码，查询要精准，禁止模糊匹配进入上下文注入**（防过度注入 → AI 幻觉）

## 零、核心原则：ID 优先，名称只做展示

| 层 | 用途 | 匹配方式 |
|---|---|---|
| **ID**（唯一编码） | 一切程序引用、关系连接、上下文装配 | **精确相等** |
| **名称/别名** | 展示、用户输入解析（一次性解析成 ID） | 精确相等；同名多义时**必须让用户选** |
| 标签 | 切片检索（未回收伏笔、某势力成员） | 精确 tag 匹配 |
| 正文全文 | 用户主动搜索 | 允许模糊，但**不自动注入**上下文 |

**铁律**：上下文注入只接受「ID 精确命中」与「标签精确命中」；模糊/子串匹配只出现在用户可见的搜索 UI 里，且必须由用户点选后才进入上下文。

## 一、唯一编码（ID）方案

### 1.1 编码格式

`<类型前缀>-<4 位序号>`，序号项目内唯一、**永不复用**：

| 类型 | 前缀 | 示例 |
|---|---|---|
| 人物 | `CHR` | `CHR-0001` |
| 地点 | `LOC` | `LOC-0001` |
| 势力 | `FAC` | `FAC-0001` |
| 物品/功法 | `ITM` | `ITM-0001` |
| 世界观条目 | `WLD` | `WLD-0001` |
| 设定条目 | `SET` | `SET-0001` |
| 时间线事件 | `EVT` | `EVT-0001` |
| 伏笔 | `FSH` | `FSH-0001` |
| 关系 | `REL` | `REL-0001` |
| 章节 | `CHP` | `CHP-0001` |
| 规划节点 | `PLN` | `PLN-0001` |

### 1.2 ID 登记表（单一真源）

`<项目>/04-项目总控/ID登记表.json`：

```json
{
  "version": 1,
  "counters": { "CHR": 12, "EVT": 40 },
  "entries": [
    { "id": "CHR-0001", "type": "character", "path": "01-世界架构/人物/CHR-0001_林玄.md", "createdAt": 0, "retired": false }
  ]
}
```

- **分配**：只增计数器，`ID = 前缀-补零(计数+1)`
- **改名**：更新 `path`，ID 不变
- **删除**：`retired: true`，ID 不复用（避免旧引用指错）
- **校验**：启动/迁移时检查「entries 的 path 是否存在」「文件里的 id 是否与登记表一致」

### 1.3 文件命名（含 ID，人可读）

```
01-世界架构/人物/CHR-0001_林玄.md
01-世界架构/地点/LOC-0001_青云宗.md
01-世界架构/势力/FAC-0001_青云宗.md
01-世界架构/物品功法/ITM-0001_青锋剑.md
01-世界架构/世界观/WLD-0001_灵气体系.md
01-世界架构/设定/SET-0001_货币.md
01-世界架构/关系/REL-0001_CHR-0001_CHR-0002.md   ← 关系用两端 ID 命名
02-时间线与伏笔/时间线事件/EVT-0001_0012-03-05_入门大典.md
02-时间线与伏笔/伏笔/FSH-0001_断剑来历.md
03-大纲与章节/正文/第1卷/CHP-0001_第1章_初入山门.md
```

- 名称部分仅供人读；**程序只用 ID**
- 重名不影响（ID 唯一）；名称改动不改文件名（可选同步，非必须）
- 关系文件额外规则：`REL-<id>_<A-ID>_<B-ID>.md`，A/B 按 ID 字典序，保证同一对关系只可能有一个文件

### 1.4 frontmatter 必填

```yaml
id: CHR-0001
type: character
aliases: [林玄, 小玄]      # 原生 aliases，Obsidian 双链可解析
tags: [nw/人物, nw/人物/主角]
```

## 二、精准查询契约（防幻觉的关键）

### 2.1 查询 API（索引层）

```ts
interface EntityQuery {
  id?: string;              // 精确
  ids?: string[];           // 批量精确
  type?: EntityType;        // 精确
  tag?: string;             // 精确 tag
  alias?: string;           // 精确别名（去空白后全等）
  title?: string;           // 精确标题
  folder?: string;          // 前缀
  text?: string;            // 全文（仅 UI 搜索，不用于注入）
  limit?: number;
}
```

### 2.2 名称 → ID 解析（`resolveEntity`）

```
输入名称 X：
1. 精确匹配 id（X 形如 CHR-0001）→ 命中唯一
2. 精确匹配 aliases/title（trim + 全角半角归一）→ 命中唯一
3. 命中多个 → 返回候选列表，**不自动选**（UI 让用户点选 / Agent 追问）
4. 未命中 → 返回空，不猜
```

**禁止**：子串/模糊/拼音近似自动解析（只在 UI 搜索里做，且必须用户确认）。

### 2.3 上下文注入规则

写正文时的上下文包只由以下来源构成：

| 来源 | 精度要求 |
|---|---|
| 大纲中显式写的 `@CHR-0001` 或 `[[CHR-0001_林玄]]` | ID 精确 |
| 上一章 frontmatter `涉及人物` 里的 ID 数组 | ID 精确 |
| 伏笔文件 `当前状态=planted/progressing` 且 `埋设章节 ≤ 本章` | 状态+ID 精确 |
| 时间线事件 `章节 ≤ 本章` 且 `涉及人物` 含本章 ID | ID 精确 |
| 世界观/设定：被本章 ID 引用（frontmatter `关联`）或标签精确命中 | ID/tag 精确 |

**每一份注入都要记录来源 ID 与路径**（可审计、可复现）；超过 token 预算时按「ID 直接相关 > 标签 > 时间线」截断，不做模糊扩展。

## 五、迁移策略（旧项目生效）

1. **备份**：迁移前把要改的文件复制到 `_versions/migration/<时间戳>/`
2. **补 ID**：扫全项目 → 分配 ID → 写 ID 登记表 → 在文件 frontmatter 写 `id`（文件名可暂不改，登记表记 path）
3. **改名**（可选第二步）：按 `ID_名称.md` 重命名，登记表同步
4. **拆分**：时间线/伏笔/世界观/设定/关系 → 生成条目文件
5. **派生视图**：原文件内容替换为「自动生成视图 + 说明」（顶部注明「本文件由插件生成，请勿手改」），数据从条目文件渲染
6. **幂等**：已迁移的跳过；dry-run 输出变更清单
7. **回滚**：`_versions/migration/` 保留原文件
