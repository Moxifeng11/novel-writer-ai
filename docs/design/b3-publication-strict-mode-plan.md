# B3 严格出版模式：产品口径修改方案

> 日期：2026-11-06 · 状态：**已按用户拍板实施（方案 A）** · 关联：v5 B3（`shared/publication-profile.ts` + 导出弹窗）
> 结论先行：用户已拍板 **方案 A —— 三档交付级别 + 显式导出范围**（默认成品；投稿全格式必填作者；空单元豁免仅成品档）。已随 v4.59.0 实施。
> 落地区间：本文 §三 是设计口径，§五 是拍板结论；实现与设计的差异见 §〇，判据以 `shared/publication-profile.ts` 与 `ui/export-manuscript-modal.ts` 代码为准。

## 〇、落地差异（v4.62.0 代码实测）

| 设计（§三） | 实际实现 | 影响 |
|---|---|---|
| §3.5 错误卡提供「排除空单元继续 / 去补写」两个动作 | 只抛出 blocker 汇总；成品档附文案「可将导出范围改为仅已写单元后重试」，无跳转按钮 | 用户需手动改下拉；不新增 UI 组件 |
| §3.5 导出摘要实时显示级别/范围/字数 | 摘要未实时刷新；只在导出时以 Notice 汇总出版建议 | 不影响阻断语义 |
| §3.2 `submission` 默认锁定 `full` | 切到 `submission` 时强制 `scope='full'` 并禁用范围下拉 | 与设计一致，且回切后自动解禁 |
| §3.4 `level` 缺省沿用旧矩阵 | `level === undefined` 走 legacy 矩阵；新弹窗显式传 `finished` | 旧调用方零行为变化 |

测试覆盖见 `tests/unit/shared/publication-profile.test.ts`（含导出弹窗三档/范围接线契约）。

## 一、现状（代码实测）

### 1.1 判定矩阵（当前）

| 条件 | 级别 | 说明 |
|---|---|---|
| 书名为空 | **blocker** | 所有格式 |
| 作者为空 | **blocker** | **仅 EPUB/DOCX**；TXT/MD/HTML 不阻断 |
| 没有任何正文 | **blocker** | `writtenCount <= 0` |
| 存在任一空正文单元 | **blocker** | **始终阻断**（含批量建章留下的 pending 骨架） |
| 总字数 < 下限一半 | **blocker** | 长篇 <5 万 / 短篇·剧本 <2.5 万 |
| 总字数 < 下限 | warning | |
| 单元数 < 下限 | warning | 长篇 <10 章 / 短篇 <8 节 / 剧本 <40 集 |
| EPUB 未含标题 | warning | 目录不完整 |
| 重复标题 | warning | |

### 1.2 交互现状

- 导出弹窗只有一个布尔开关「严格出版检查（阻断导出）」，默认关闭。
- **导出恒为整包**（`collectChapters` 收集项目全部单元，无范围选择），所以文案写「整包交付口径」；但用户**没有**「只导样章/已写单元」的入口——文案的建议目前无法执行。
- 阻断时整个导出 job 失败，只给一条汇总错误。

### 1.3 已确认的问题

1. **空骨架即死锁**：批量建章后存在 pending 骨架，严格模式必然阻断；用户要么逐章补空，要么关掉严格检查——没有「排除空单元导出」的中间路径。
2. **字数一刀切**：低于下限一半直接 blocker，对「先导 3 万字样章给编辑」的合理场景过度阻断。
3. **作者要求只在 EPUB/DOCX**：番茄/红果投稿同样需要作者/笔名；而导出 TXT/MD 时反而不提示。
4. **一个开关承担三种意图**：自存草稿、交编辑审阅、平台投稿的风险容忍度完全不同，却共用同一套阻断集合。
5. **阻断反馈不可操作**：只报「存在 N 个空单元」，没有「排除这些单元并继续」或「去补写」的按钮。

## 二、方案对比

| 方案 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| **A · 三档交付级别 + 范围（推荐）** | 下拉：草稿 / 成品 / 平台投稿；成品与平台档可选「排除空单元」 | 覆盖三种真实意图；空骨架死锁有解；作者按级别要求 | 需要改 UI 与 facts 契约，测试矩阵变大 |
| B · 保留布尔，软化阻断 | 空单元、字数不足降为 warning，只保留书名/无正文 blocker | 改动最小 | 平台投稿仍无强校验；用户仍无法区分意图 |
| C · 只加导出范围 | 增加「全部 / 仅已写单元」，判定不变 | 解决空骨架死锁 | 字数/作者问题仍在；范围与级别耦合不清晰 |

**推荐 A**。它把「检查强度」与「导出范围」解耦：级别决定风险容忍，范围决定检查对象。

## 三、方案 A 详细设计

### 3.1 交付级别（`PublicationLevel`）

| 级别 | UI 文案 | blocker（阻断） | warning（建议） |
|---|---|---|---|
| `draft` | 草稿导出（仅提示） | 书名为空、完全没有正文 | 其余全部 |
| `finished` | 成品导出（推荐） | 书名为空、完全没有正文、**存在空单元且未选择排除** | 字数不足、作者缺失（TXT/MD/HTML）、单元数不足、重复标题、EPUB 无标题 |
| `submission` | 平台投稿（严格） | 书名为空、**作者为空（所有格式）**、完全没有正文、存在空单元且未排除、字数 < 下限一半 | 字数 < 下限、单元数不足、重复标题、EPUB 无标题 |

- 默认级别：`finished`（原默认是不检查；考虑到误导出成本，建议默认成品但仍可一键改草稿）。
- `submission` 额外要求：导出前必须填写作者；若平台目标为番茄/红果，作者与简介进入导出头（复用 `platform-export.ts`）。

### 3.2 导出范围（`PublicationScope`）

| 范围 | 行为 |
|---|---|
| `full` | 导出全部单元；空单元参与判定 |
| `written-only` | **实际过滤掉空正文单元**（不写入导出文件）；判定用过滤后的事实 |

- UI：在「导出范围」下拉提供「全部单元 / 仅已写单元」；`draft`/`finished` 可用，`submission` 默认锁定 `full`（平台投稿需整包），切到 `written-only` 时提示「平台投稿建议补齐全部单元」。
- 过滤发生在收集之后、编译之前，空单元不会出现在 TXT/MD/EPUB/DOCX 中；导出摘要显示「已跳过 N 个空单元」。

### 3.3 作者口径

| 格式 / 级别 | draft | finished | submission |
|---|---|---|---|
| EPUB / DOCX | 建议 | **阻断** | **阻断** |
| TXT / MD / HTML | 不提示 | 建议 | **阻断** |
| 平台包（番茄/红果） | 建议 | 建议 | **阻断** |

### 3.4 API 变更（向后兼容）

`PublicationFacts` 新增可选字段：

```ts
/** 交付级别；缺省按 'finished'，保持旧调用方行为可预期 */
level?: 'draft' | 'finished' | 'submission';
/** 导出范围；缺省 'full'。written-only 时调用方应已过滤空单元（本模块只按事实判定） */
scope?: 'full' | 'written-only';
/** 是否已排除空单元（用于空单元阻断的豁免） */
excludeEmptyUnits?: boolean;
```

- `checkPublicationReadiness` 保持纯函数，只按 `level/scope/excludeEmptyUnits` 分级；**不做过滤**（过滤在导出链路做，避免纯函数产生副作用）。
- 缺省值组合等价于旧行为（`level='finished'` 时若 `excludeEmptyUnits` 未传，空单元仍阻断；旧调用方需显式传 `excludeEmptyUnits: true` 才豁免）。为真正向后兼容，可让 `level` 缺省时沿用旧矩阵，新 UI 显式传级别。
- 新增 `requiresAuthor(level, format)` 与 `levelLabel` 供 UI 复用，避免文案第二套。

### 3.5 交互与错误反馈

- 严格检查失败时，错误卡列出 blocker，并提供两个动作：
  - **排除空单元继续**（仅 `finished`，等价于 `written-only`）；
  - **去补写**（跳转首个空单元）。
- 导出摘要实时显示：级别、范围、总字数 / 下限、空单元数。
- 平台投稿级失败时额外提示「平台投稿需整包 + 作者」。

### 3.6 测试矩阵（新增）

1. `draft`：空单元/字数不足/缺作者均不阻断；
2. `finished`：空单元阻断；`excludeEmptyUnits=true` 时豁免；缺作者 TXT 不阻断；缺作者 EPUB 阻断；
3. `submission`：缺作者 MD 阻断；字数 <50% 阻断；空单元未排除阻断；
4. `written-only` + 已过滤事实：不因空单元阻断，导出文件不含空单元；
5. 旧调用（不传 level/scope）：矩阵与 v4.58.0 完全一致（回归）。

## 四、影响与迁移

- 数据/配置：无迁移；不变更任何落盘格式。
- 行为：默认级别建议定为 `finished`（较旧默认「不检查」更严），需在发布说明标注；如担心打扰，可让默认保持 `draft` 并在设置页提供「默认交付级别」。
- 回滚：`level` 可选，回滚只需 UI 回退；纯函数缺省路径保留旧矩阵。
- 文档：`docs/guides/USER-GUIDE.md`、`COMMERCIAL-GUIDE.md` 更新判定矩阵；`shared/platform-export.ts` 的简介/标签/作者口径对齐。

## 五、拍板结论（已落地，v4.59.0）

1. **级别默认值**：`finished`（成品导出）。可在弹窗内一键改草稿。
2. **平台投稿强制作者（所有格式）**：是。
3. **空单元豁免**：仅 `finished` 档允许（`submission` 必须整包，范围下拉锁定）。
4. **本轮实现**：是（v4.59.0）；后续差异见 §〇。

> 方案 A 落地后，v4.58.0 的「整包口径」文案被级别文案替代；严格模式不再是单一布尔开关。本文件 §一～§三 保留为决策前设计记录，不作为现状描述。
