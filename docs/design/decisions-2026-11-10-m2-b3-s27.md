# 决策记录：本地模型自动切换 / Worker 分发 / 重定向安全（2026-11-10）

> 用户拍板：① 自动切换模型；② 分发取舍不能丢失质量；③ 重定向方案兼顾兼容与质量保全。
> 落地：第45轮（M-2 + B-3）与第43轮（S2-7 IPv6 段）+ 本轮文档约束。

## 一、M-2 本地模式未选模型 → 自动切换云端

- 生效模式由 `resolveEffectiveCoWriteMode(settings)` 统一判定：只有**显式选中本地模型**才留在 local；否则视为 cloud。
- `resolveCoWriteModel` 与 `buildCoWriteOptions` 都走同一判定，模型名、端点、API Key 不再分叉。
- `CoWriteCallOptions.autoSwitchedToCloud` 标记自动切换，协同视图打开时提示“已自动切换到云端模型”。
- 显式云端模式行为不变；显式本地模型仍强制本地、不回退云端。
- 回归：`tests/unit/engine/co-write-options-mode.test.ts`（3 条）。

## 二、B-3 Worker 分发取舍：不丢质量

- 决策：**保留双 worker（zip/BRAT 离线程） + 社区三文件安装走主线程**，不为减小 zip 体积合并/删除 worker，也不把 683KB 内联进 main。
- 质量保证：
  1. worker 入口与主线程复用同一批拆解器模块（`deconstruction-worker.ts` 直接 import 8 个 Deconstructor），不存在第二套算法；
  2. 无 worker 时 manager 明确降级主线程，结果与直接调用拆解器逐字段一致；
  3. `tests/unit/engine/worker-quality-parity.test.ts` 锁定以上两点；后续如需合并 worker，必须先让该测试与真实拆解 E2E 同时通过。
- 性能取舍：主渠道用户承担主线程计算（已有 `yieldToUI`）；zip 用户继续享受离线程。

## 三、S2-7 重定向：兼容/质量优先，地址段拦截 + 残余记录

- `requestUrl` 无 redirect 策略、无最终 URL；改用 `fetch({redirect:'manual'})` 会在桌面触发 CORS、移动端不可用，**降低兼容与抓取成功率**，与“质量保全”冲突。
- 决策：保持 `requestUrl` 作为抓取通道；在**请求前**拦截私网/回环（含 IPv4-mapped、`fc00::/7`、`fe80::/10`、尾点 localhost）；3xx 跟随后的目标无法逐跳校验，作为**已知残余**记录，不伪装成已解决。
- 后续若需要闭环：只能在桌面用独立网络栈（Electron net）实现手动重定向并逐跳校验，移动端仍需保留 `requestUrl` 残余；需单独立项评估，不在当前批次偷偷切换。
- 回归：`tests/unit/services/canon-research-ssrf.test.ts`（5 条表驱动）。
