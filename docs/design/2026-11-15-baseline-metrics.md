# 写作效果基线（阶段 0 采集结果）

> 对应 `2026-11-15-architecture-remediation-plan.md` §3.3。用于 C/B/A 各阶段改动的对照基线。
> 采集工具：`plugin.runBaselineProbe(project, chapterName)`（`services/baseline-probe-service.ts`）。

## 采集条件

| 项 | 值 |
|---|---|
| 项目 | `长篇小说/基线项目`（测试用固定夹具，保留以便复测） |
| 章节 | 第1章 初入山门 |
| 模型 | `deepseek-flash`（真实 API 调用，usage 由响应回传） |
| 数据 | 世界观 1 篇 / 设定库 1 篇 / 人物 2 张 / 时间线 1 行 / 伏笔 1 条 / 分卷大纲 1 章 / Scene 展开 2 场 |
| 采集时间 | 2026-11-15 |

## 结果

| 策略 | 输入字符 | prompt token | total token |
|---|---|---|---|
| 旧：整份注入 | 3207 | **2690** | 3062 |
| 新：场景精确注入 | 1146 | **902** | 1382 |
| 差值 | −2061 (−64%) | **−1788 (−66.5%)** | −1680 |

结论：**同一项目、同一模型下，场景精确注入的 prompt token 下降 66.5%**。

## 口径说明（避免误读）

1. 这是**注入侧**成本，不是写作质量。质量需人工评分（§3.2），C/B/A 每阶段结束补测。
2. 两策略的 system 提示相同（极简替代），只对比 user 侧注入体量；真实正文步 system 更长，但差额同量级。
3. maxTokens=32，输出截断不影响 prompt token 统计。
4. 当前只有 1 个项目 1 章，属于**单点基线**；每阶段复测时用同一夹具保证可比。

## 复测方法

在 Obsidian 控制台执行：

```js
const p = app.plugins.plugins['novel-writer-ai'];
await p.runBaselineProbe('长篇小说/基线项目', '第1章');
```

结果同时进入 `usage-ledger`，可在用量面板追溯。
