# 三个独立入口与项目内容架构设计方案

## 一、现状与目标

### 1.1 现状

当前工作台是单一平铺项目网格：

- 所有项目混在同一列表，仅靠卡片上的模式徽章区分。
- 新建项目只有一个通用入口，短篇/剧本模式藏在弹窗内部。
- 右侧快捷工具是全局一套，长篇/短篇/剧本共用。
- “批量建章”“全部章节”等入口仍使用长篇术语。
- 批量建章不跟随当前选中项目，从短篇/剧本项目进入会先显示长篇状态。
- 短篇/剧本内容仍存放在长篇式 `03-大纲与章节/正文/第N卷/第N章_正文.md` 中。

### 1.2 目标

建立“创作中心 → 三个独立入口 → 各自项目列表 → 各自内容树”的分层体系：

```text
创作中心
├─ 长篇小说入口
│  └─ 项目 → 卷 → 章 → 11 步结果
├─ 短篇小说入口
│  └─ 项目 → 五维分类 → 故事核 → 分节大纲 → 节 → 质检
└─ 剧本入口
   └─ 项目 → 人物/场景圣经 → 分集大纲 → 集 → 场 → 镜 → 质检
```

三个入口共享底层能力，但**不共享项目列表、快捷工具、内容树、批量逻辑和导出逻辑**。

---

## 二、分层内容管理模型

### 2.1 四层结构

| 层级 | 长篇小说 | 短篇小说 | 剧本 |
|---|---|---|---|
| L1 创作域 | 长篇入口 | 短篇入口 | 剧本入口 |
| L2 项目 | 项目列表 | 项目列表 | 项目列表 |
| L3 内容域 | 卷/章 | 故事核/分节大纲/正文/质检 | 人物/场景/分集/场/分镜 |
| L4 单元 | 章 | 节 | 集 → 场 → 镜 |

### 2.2 入口隔离原则

1. 进入短篇入口后，只看到 `mode=short` 的项目。
2. 进入剧本入口后，只看到 `mode=script` 的项目。
3. 进入长篇入口后，只看到 `mode=long` 的项目；旧项目缺少模式字段时按长篇显示。
4. 每个入口的“新建”按钮预填本模式，不要求用户再选模式。
5. 每个入口的快捷工具只包含本模式动作；不出现其他模式术语。
6. 跨模式只能“返回创作中心”或“复制为新项目”，不允许原地切换模式。

- 不显示“节”“章”“卷”。

### 3.4 长篇入口

保留现有长篇工作台能力，但作为独立入口：

- 项目列表仅 `mode=long`。
- 保留卷/章、11 步、批量建章、全书规划、章节结算、全稿导出。
- 现有 `FULL_WRITER` 命令变成“打开长篇入口”的别名，避免旧用户路径断裂。
- 长篇入口不显示短篇/剧本动作。

## 四、路由与命令

### 4.1 路由

```ts
type CreationDomain = 'long' | 'short' | 'script';

interface HubRoute {
  view: 'hub' | 'domain';
  domain?: CreationDomain;
  project?: string;
}
```

- `hub`：创作中心。
- `domain`：某个创作域的项目列表。
- `project`：某个项目的内容工作区。

### 4.2 命令

| 命令 ID | 名称 | 行为 |
|---|---|---|
| `novel-writer-hub` | 🏠 创作中心 | 打开三入口首页 |
| `novel-writer-open-long` | 📖 打开长篇创作 | 直接进入长篇入口 |
| `novel-writer-open-short` | 📄 打开短篇创作 | 直接进入短篇入口 |
| `novel-writer-open-script` | 🎬 打开剧本创作 | 直接进入剧本入口 |
| `novel-writer-create-long` | 新建长篇项目 | 预填 `long` |
| `novel-writer-create-short` | 新建短篇项目 | 预填 `short` |
| `novel-writer-create-script` | 新建剧本项目 | 预填 `script` |

保留旧命令：

- `novel-writer-create-project`：打开未预填的新建弹窗，兼容旧习惯。
- `novel-writer-full-writer`：等价于 `novel-writer-open-long`。

### 4.3 Ribbon

推荐：

- 一个「🏠 创作中心」Ribbon 图标。
- 三个直达命令放入命令面板。
- 可选设置项“在 Ribbon 显示三个直达图标”，默认关闭，避免左侧栏拥挤。

如果产品坚持三个独立 Ribbon 图标，则分别使用 `book-open`、`file-text`、`clapperboard`，但必须与创作中心卡片一致。

## 五、项目列表与卡片

### 5.1 项目索引

```ts
interface ProjectIndexEntry {
  name: string;
  path: string;
  mode: CreationDomain;
  taxonomyVersion?: number;
  status: 'active' | 'completed' | 'archived';
  targetWords: number;
  currentWords: number;
  targetUnits: number;
  completedUnits: number;
  updatedAt: number;
  cover?: string;
}
```

索引由扫描 `.project` 构建，缓存到 `data/project-index.json`；文件变更时增量更新。

### 5.2 卡片字段

| 模式 | 卡片字段 |
|---|---|
| 长篇 | 书名、题材、卷/章进度、已完稿章、下一章、更新时间 |
| 短篇 | 书名、主分类、节进度、已完稿节、下一节、质检分 |
| 剧本 | 剧名、类型、集进度、场数、分镜数、下一集、卡点集 |

### 5.3 空状态

- 每个入口的空状态只显示本模式引导：
  - 长篇：“创建第一部长篇”
  - 短篇：“创建第一篇番茄短篇”
  - 剧本：“创建第一部红果短剧”
- 不显示其他模式入口，避免误入。

## 六、物理存储方案

### 6.1 推荐方案：模式库

```text
{ vault }/
  长篇作品/
    {项目名}/
      00-系统模板/
      01-世界架构/
      02-时间线与伏笔/
      03-大纲与章节/
      04-项目总控/
  短篇作品/
    {项目名}/
      00-短篇配置/
      01-故事核/
      02-人物/
      03-情绪与反转/
      04-分节大纲/
      05-正文/
      06-质检/
      07-导出/
  剧本作品/
    {项目名}/
      00-剧本配置/
      01-卖点/
      02-人物与场景/
      03-分集大纲/
      04-剧本/
      05-分镜/
      06-质检/
      07-导出/
```

优点：物理隔离彻底，入口扫描简单，误写风险低。  
缺点：旧项目需要迁移或兼容。

### 6.2 兼容策略

- **新项目**一律写入模式库。
- **旧长篇项目**保留根目录，通过索引映射到长篇入口；不强制移动。
- **旧短篇/剧本项目**保留原路径，通过 `.project` 的 `mode` 映射到对应入口；内容树仍按旧结构显示，标记“旧版结构”。
- 提供“迁移到模式库”动作：先复制、校验、再删除旧目录；默认不自动执行。
- 迁移失败回滚：保留旧目录与原路径，不覆盖。

### 6.3 备选方案：根目录 + 模式索引

不移动文件，只按 `.project` 的 `mode` 过滤。优点是零迁移；缺点是无法实现真正的物理分层，且未来路径冲突风险高。仅作为回退方案。

## 七、内容工作区

### 7.1 长篇

```text
项目
├─ 世界观/人物/势力/地点/物品
├─ 全书规划 → 分卷大纲
├─ 卷 → 章
│  └─ 11 步结果 + 正文
└─ 导出全稿
```

### 7.2 短篇

```text
项目
├─ 五维分类
├─ 故事核
├─ 人物与关系
├─ 情绪曲线/反转表
├─ 分节大纲
├─ 节 → 正文
├─ 节级质检/全篇质检
└─ 导出短篇
```

### 7.3 剧本

```text
项目
├─ 类型/集数/时长
├─ 人物小传/关系图/场景圣经
├─ 分集大纲
├─ 集 → 场 → 剧本
├─ 分镜表
├─ 集级质检/全剧质检
└─ 导出剧本 + 分镜 CSV
```

### 7.4 内容树隔离

- 短篇工作区不得出现“卷”“章节结算”“信息债”等长篇节点。
- 剧本工作区不得出现“节”“章”“全书规划”等节点。
- 长篇工作区不得出现“分镜”“场次”“付费卡点”等剧本节点。
- 每个工作区只加载本模式的模板、提示词、校验器。

## 九、模式切换与转换

### 9.1 禁止原地切换

已有项目的 `mode` 是不可变字段。原因：

- 内容树不同，原地切换会导致大量文件无法解释。
- 工作流状态不同，切换后无法恢复。
- 分类、模板、导出格式不同，容易产生混合数据。

### 9.2 复制为新项目

提供“复制为新项目”：

1. 选择目标模式。
2. 复制可迁移的素材（书名、简介、人物、世界观摘要）。
3. 不复制流程状态、章节结构、步骤结果。
4. 新项目写入目标模式库，旧项目保留。
5. 明确提示“这是复制，不是转换”。

## 十、迁移方案

### 10.1 扫描与建索引

1. 扫描 vault 中所有含 `.project` 或 `01-世界架构/` 的目录。
2. 读取 `.project` 的 `## 创作模式`；缺失按 `long`。
3. 生成 `ProjectIndexEntry`，写入 `data/project-index.json`。
4. 入口只读索引，不重复扫描。

### 10.2 旧短篇/剧本

- 保留原目录；索引 `mode` 指向 short/script。
- 缺少五维标签的，按主分类默认值补齐，标记 `needsTaxonomyReview=true`。
- 内容树显示“旧版结构”，提供“升级为短篇/剧本结构”动作；升级前备份。

### 10.3 旧长篇

- 零改动；索引 `mode=long`。
- 仍使用现有 `03-大纲与章节` 与 11 步。

### 10.4 回退

- 设置项 `unifiedProjectGrid=true` 时，恢复旧版单列表。
- 索引与模式库不影响旧版读取；回退不删除任何文件。

## 十一、功能开关与权限

| 开关 | 默认 | 行为 |
|---|---|---|
| `enabledModes.long` | true | 关闭后隐藏长篇入口与直达命令 |
| `enabledModes.short` | true | 关闭后隐藏短篇入口与直达命令 |
| `enabledModes.script` | true | 关闭后隐藏剧本入口与直达命令 |
| `unifiedProjectGrid` | false | true 时回退旧版单列表 |
| `showThreeRibbonIcons` | false | 控制是否显示三个 Ribbon 直达图标 |

权限规则：

- 关闭模式只隐藏入口，不删除数据。
- 已有项目仍可通过直接路径打开，避免数据锁死。
- 团队/企业如需限制，可在设置层扩展角色权限；当前插件无用户体系。

---

## 十二、性能与加载

- 创作中心只加载项目索引，不加载项目内容。
- 进入某个入口才加载该模式的项目列表与统计。
- 进入项目才加载该模式的工作流、模板、状态。
- 短篇/剧本入口不得初始化长篇 `ContextManager`、`StepRunner`、章节缓存。
- 索引增量更新；文件变更事件只更新对应项目。
- 封面懒加载；大项目列表虚拟滚动或分页。

---

## 十三、验收标准

1. 创作中心显示三个独立入口，每个入口显示本模式项目数与进行中数量。
2. 短篇入口只显示 `mode=short` 项目；剧本入口只显示 `mode=script`；长篇入口只显示 `mode=long`/旧项目。
3. 每个入口的“新建”按钮预填本模式，弹窗内模式不可误选为其他模式（可改，但明确提示会切换创建类型）。
4. 短篇工作区无“卷/章/批量建章”；剧本工作区无“节/章”；长篇工作区无“分镜/场次”。
5. 每个入口的快捷工具只包含本模式动作。
6. 批量生成必须默认当前项目，且只在本模式内执行。
7. 导出使用本模式编译器；短篇按节、剧本按集，长篇按章。
8. 旧项目通过索引正确归入对应入口，不丢失、不移动。
9. 回退开关可恢复旧版单列表，数据不受影响。
10. 静态测试保证短篇/剧本入口不导入长篇 Runner/模板。

## 十四、实施阶段

| 阶段 | 工作 | 风险控制 |
|---|---|---|
| P0 | 项目索引 + 模式字段 + 三入口骨架 | 先只读，不改旧工作台 |
| P1 | 短篇入口 + 短篇流程 | 独立目录、独立 runner，先小范围 |
| P1 | 剧本入口 + 剧本流程 | 独立目录、分镜模型 |
| P2 | 长篇入口迁移为独立域 | 旧命令别名，保留回退 |
| P2 | 批量/导出模式化 | 默认当前项目，补测试 |
| P3 | 旧项目升级/迁移工具 | 复制优先，删除需确认 |
| P3 | 回退开关与灰度 | 可一键回旧版 |
