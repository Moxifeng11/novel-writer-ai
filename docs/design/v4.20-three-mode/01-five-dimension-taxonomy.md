# 五维分类体系（番茄短篇标准主分类 + 四级创作标签）

## 一、口径说明

### 1.1 “五级”的业务含义

本方案的“五级”指**五个一级核心分类**：

1. 主分类
2. 情节
3. 角色
4. 情绪
5. 背景

每个一级分类下再设二级分类与三级标签。它不是五层树深，也不建议强行做成五层树：番茄平台对外只要求一个主分类，其余四维是内部创作、检索和提示词约束，不应该伪装成平台上传字段。

### 1.2 平台口径与内部口径

| 层级 | 是否平台官方 | 数量 | 是否必选 | 用途 |
|---|---|---|---|---|
| 主分类 | 是，严格采用番茄 24 类 | 1 | 是 | 平台投稿分类、频道、读者预期 |
| 情节 | 否，行业通用创作标签 | 1 主 + 0–3 辅 | 是 | 故事引擎、冲突设计、检索 |
| 角色 | 否，行业通用创作标签 | 1 主 + 0–3 辅 | 是 | 人物关系、对手设计、选角感 |
| 情绪 | 否，行业通用创作标签 | 1 主 + 0–2 辅 | 是 | 情绪承诺、曲线、兑现点 |
| 背景 | 否，行业通用创作标签 | 1 主 + 0–2 辅 | 是 | 时代、空间、世界规则、美术感 |

**硬规则**：只有“主分类”进入平台投稿元数据；其余四维只进入项目内部配置、提示词和质检，不冒充平台分类。

### 1.3 版本与治理

- `taxonomyVersion` 从 `1` 开始，任何主分类增删或释义变更必须升版本。
- 24 个主分类以用户提供的番茄分类表为唯一基准；平台调整时先更新数据表，再迁移项目。
- 二级/三级标签是内部资产，可增补；已使用的标签不删除，只标记 `deprecated`，避免旧项目失配。
- 每个项目保存 `taxonomyVersion`，读取时做兼容映射。

## 二、一级维度总览

| 维度 | 核心问题 | 选择规则 | 影响 |
|---|---|---|---|
| 主分类 | “这本书在平台归哪一类？” | 唯一、必选、与性别频道一致 | 平台分类、读者预期、开篇承诺 |
| 情节 | “故事靠什么事件推进？” | 1 个主情节 + 最多 3 个辅助 | 冲突链、反转、节拍 |
| 角色 | “谁在推动/阻挡故事？” | 1 个主角原型 + 1 个对手/阻力 + 关系结构 | 人物动机、对白、关系张力 |
| 情绪 | “读者主要为什么继续看？” | 1 个主情绪 + 1 条曲线 + 强度 | 情绪承诺、爽点/虐点/钩子 |
| 背景 | “故事发生在什么时代与规则里？” | 1 个时代 + 1 个空间 + 世界规则 | 场景、服化道、语言、可行性 |

### 3.1 主分类选择规则

1. 先判断平台频道：女频、男频、通用。
2. 再判断故事主线：感情线为主，还是成长/事业/复仇/悬疑为主。
3. 最后判断背景：现代、古代、年代、民国、非现实。
4. 一个项目只能有一个主分类；主分类决定平台上传分类，不允许用“情节”替代。
5. 与平台释义冲突时，以平台释义为准；例如“女性成长”明确排除复仇、打脸、虐渣作为主线。

### 4.1 情节组合规则

- 必须有一个“主推进力”：关系变化、身份揭示、复仇计划、规则解谜、时代机会、权力博弈，六选一。
- 辅助情节最多 3 个，且不能互相抢主线。例如“悬疑探案 + 甜宠 + 家庭伦理”三者并重会失焦，必须指定主次。
- 每个情节标签必须能回答：它带来什么冲突、什么选择、什么代价。
- 不允许只写“家庭”“职场”这种场景词而没有冲突对象；标签必须落到可执行冲突。

### 6.3 强度与兑现

- 强度：轻、中、强。短篇默认“强”，但每 1000–1500 字必须有一次推进，不能一直高压无兑现。
- 兑现频率：每 1000–1500 字一次小推进；每 3000–5000 字一次可感知反转；每节结尾一个钩子。
- 情绪禁区：憋屈无兑现、虐而无意义、甜而无冲突、恐而无逻辑、爽而无代价。

| `B07` | 乡村 | 村镇、返乡、扶贫、乡村创业 |
| `B08` | 1950s–1970s | 建国初期、知青、厂矿 |
| `B09` | 1980s–1990s | 改革开放、下岗、个体户 |
| `B10` | 民国 | 1912–1949，民国画风 |
| `B11` | 古代 | 宫廷、后宅、江湖、朝堂 |
| `B12` | 架空 | 非真实历史，规则自洽 |

### 7.2 空间

家庭住宅、医院、学校、公司、法院、警局、宫廷、后宅、江湖、战场、村镇、封闭空间（电梯/别墅/孤岛/列车）。

### 7.3 世界规则

现实、轻幻想、玄幻、仙侠、西幻、末世、无限流、穿书、系统。非现实规则必须写明：能力边界、代价、限制、信息差。

### 7.4 地域文化

北方/南方、少数民族、海外、民国上海、港风。只作为氛围与语言选择，不替代时代。

## 八、组合规则与冲突校验

### 8.1 必选与数量

- 主分类：1 个，必选。
- 情节：1 个主组 + 0–3 个标签。
- 角色：1 个主角原型 + 1 个对手/阻力 + 1 个关系结构；功能角色 ≤ 4。
- 情绪：1 个主情绪 + 1 条曲线 + 1 个强度。
- 背景：1 个时代 + 1 个空间 + 1 个世界规则。
- 总标签数 ≤ 10；超过时提示“标签过载，主线会失焦”。

### 8.2 兼容矩阵（必须拦截）

| 主分类 | 必须 | 禁止/警告 |
|---|---|---|
| 现言甜宠 | 现代背景、甜/暖情绪、感情线为主 | 古代背景；主情绪为虐/怕 |
| 青春虐恋 | 现代校园/婚恋、虐情绪 | 纯甜无冲突；古代背景 |
| 虐心婚恋 | 现代婚姻阶段、虐/追悔 | 无婚姻关系；纯爽文 |
| 女性成长 | 女主主观成长、燃/暖/治愈 | 以复仇/打脸/虐渣为唯一主线 |
| 宫斗宅斗 | 古代宫廷/后宅、权谋 | 现代背景；无权力结构 |
| 年代 | 1950s–1990s、年代画风 | 现代都市；民国 |
| 民国旧影 | 1912–1949、民国画风 | 现代/古代 |
| 玄幻仙侠 | 非现实世界规则 | 现实背景且无幻想元素 |
| 悬疑惊悚 | 悬/怕、线索闭环 | 无谜题；甜宠为主 |
| 女频脑洞/男频脑洞 | 脑洞规则、代价、边界 | 规则无限制；主角性别与频道冲突 |
| 纯爱 | 双男主/双女主感情主线 | 异性恋主线；无感情线 |
| 其他 | 自由 | 仍需填写其余四维 |

### 8.3 性别一致性

- 女频主分类：主角原型应为女性或双女主；男性可为对手/搭档。
- 男频主分类：主角原型应为男性或双男主；女性可为对手/搭档。
- 通用主分类：不限，但必须在角色维度写清主视角。
- 纯爱：双男主或双女主，感情线为主线。

## 十、UI 交互规范

### 10.1 分类选择器

- 左侧五个一级 Tab：主分类、情节、角色、情绪、背景。
- 右侧显示当前维度的二级分组与三级标签 chips。
- 主分类必须最先选；未选主分类时，其余维度可浏览但保存时拦截。
- 顶部固定“已选摘要”，显示 5 个维度的当前选择。
- 底部显示标签数量与冲突警告。
- 支持搜索标签；支持“清空当前维度”。
- AI 推荐只能作为建议，必须用户点击确认后写入。

### 10.2 保存与回显

- 保存时写 `.project` 镜像 + `创作配置.md` YAML。
- 重新打开时优先读 YAML，失败再读 `.project` 镜像。
- 标签失效（被废弃/重命名）时显示黄色警告，保留原值，提供“映射到新标签”。
- 分类变更后，标记下游产物 `stale`：故事核、分节大纲、正文、质检；不自动删除。

### 10.3 导出

- 平台上传只使用主分类。
- 导出文档页脚可附带完整五维标签，供作者自查，不作为平台标签提交。
- 剧本导出使用主分类 + 剧本类型，不混用短篇五维字段。

## 十一、验收标准

1. 24 个主分类名称、释义、性别与用户提供的表逐字一致。
2. 五个一级维度均可选择、保存、回显；缺失必选项时阻止进入创作流程。
3. 情节/角色/情绪/背景的二级、三级标签可检索，标签数量上限生效。
4. 兼容矩阵能拦截至少 12 组明显冲突（如“现言甜宠 + 古代”“女性成长 + 复仇主线”）。
5. 分类数据进入短篇提示词与质检；长篇提示词不受影响。
6. 旧短篇项目缺少四维标签时，自动用主分类默认值补齐并标记 `needsTaxonomyReview`。
7. 新增/变更标签有版本号，旧项目不因标签调整而丢失原值。
