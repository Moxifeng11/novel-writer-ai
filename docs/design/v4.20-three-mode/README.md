## 一、设计目标

把当前“一个工作台 + 平铺项目列表 + 长篇 11 步复用”改造成三个边界清晰的创作域：

| 创作域 | 内容单元 | 核心流程 | 入口 |
|---|---|---|---|
| 长篇小说 | 卷 → 章 | 既有 11 步流水线 | 长篇入口 |
| 短篇小说 | 故事核 → 分节 → 节 | 短篇 10 步独立流程 | 短篇入口 |
| 短剧剧本 | 分集 → 集 → 场 → 镜 | 剧本 9 步独立流程 + 分镜 | 剧本入口 |

三个入口共享底层基础设施（AI 客户端、文件 IO、日志、模型路由、导出文件写入），但不共享创作流程、步骤状态、提示词模板、校验器和内容树。

## 二、必须同时满足的三条硬约束

1. **分类可执行**：五维分类不是说明文字，而是写入项目元数据、参与提示词、参与校验的结构化数据。
2. **流程不复用**：短篇和剧本不得调用长篇 `StepRunner`、`ALL_FULL_STEPS`、`BatchPipelineRunner`，不得复用长篇步骤键与卷/章状态机。
3. **入口真隔离**：三个入口各自只显示本模式项目、各自只提供本模式动作；批量、导出、章节管理不得把用户带到其他模式。

## 三、实施顺序建议

| 阶段 | 内容 | 交付物 |
|---|---|---|
| P0 | 分类数据层 + 项目元数据扩展 | `short-story-taxonomy`、`.project` 五维字段、设置校验 |
| P1 | 短篇独立流程 | 短篇 10 步定义、runner、状态文件、短篇入口 |
| P1 | 剧本独立流程 | 剧本 9 步定义、分镜模型、剧本入口 |
| P2 | 三入口重构 | 创作中心、模式项目列表、独立内容树、直达命令 |
| P2 | 隔离门禁 | 静态导入检查、步骤键检查、跨模式写入检查 |
| P3 | 迁移与回收 | 旧短篇/剧本项目补标签、旧入口开关、回归测试 |

## 四、关键决策摘要

- 主分类采用用户提供的番茄 24 类，逐字保留名称、释义、性别频道。
- 情节、角色、情绪、背景是**内部创作标签**，不冒充平台上传分类；用于检索、提示词和一致性校验。
- “五级”在本方案中指**五个一级核心分类**；每个一级下再设二级分类与三级标签，不强行制造五层树深。
- 短篇/剧本使用独立目录与独立状态文件，宁可复制少量基础设施，也不复用长篇步骤逻辑。
- 旧项目不原地改模式；需要跨模式时使用“复制为新项目”，避免不可逆的数据污染。
- 三入口上线时保留“统一视图”回退开关，出现问题时不影响现有长篇工作流。
