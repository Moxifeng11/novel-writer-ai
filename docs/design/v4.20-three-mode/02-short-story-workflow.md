# 短篇小说独立创作流程

## 一、设计原则

短篇小说不是“缩短版长篇”。它的商业逻辑是：**一个强情绪承诺、一条单主线、三到五个反转、每一节都有钩子、结尾必须兑现**。因此短篇流程不复用长篇 11 步，也不复用长篇的卷/章状态机、Scene 展开器、信息规划模板和章节结算逻辑。

### 1.1 与长篇的硬隔离

短篇流程禁止：

- 导入 `engine/step-runner.ts`
- 导入 `engine/step-definitions.ts` 中的 `ALL_FULL_STEPS`
- 导入 `ui/full-writer/batch-pipeline-runner.ts`
- 使用长篇步骤键：`infoPlan`、`plotDistill`、`characterSoul`、`outline`、`emotionPlan`、`sceneExpand`、`bodyGeneration`、`qualityControl`、`analysisReport`、`settlement`
- 使用“卷 → 章”内容树、分卷大纲解析、章节结算
- 直接把长篇提示词加一段“短篇覆盖块”当作独立流程

短篇允许共享的只有底层能力：AI 客户端、模型路由、日志、文件 IO、导出文件写入、提示词预算、五维分类数据。流程、步骤、模板、校验器、状态文件全部独立。

### 1.2 流程总览

```text
S0 初始化与五维分类
  ↓
S1 故事核（一句话 + 情绪承诺 + 终局兑现）
  ↓
S2 人物与关系卡
  ↓
S3 情绪曲线与反转表
  ↓
S4 分节大纲（8–40 节）
  ↓
S5 开篇三屏（前 3 段 / 前 300 字）
  ↓
S6 逐节正文生成（1500–4500 字/节）
  ↓
S7 节级质检（钩子/推进/情绪/连贯）
  ↓
S8 全篇收束与情绪兑现
  ↓
S9 平台适配与导出
```

S6/S7 是循环：每一节生成后立即质检，未通过则修复或重生成，再进入下一节。不是全部写完再统一检查。

## 三、十个步骤

### S0 初始化与五维分类

**目的**：把平台分类和创作约束固定下来，避免写到一半才发现方向不对。

**输入**

- 项目名、目标字数（5–10 万）
- 五维分类：主分类、情节、角色、情绪、背景
- 平台：番茄短篇
- 目标读者与一句话卖点（可选）

**输出**

- `00-短篇配置/创作配置.md`
- `00-短篇配置/流程状态.json`
- `.project` 五维镜像字段

**规则**

- 主分类必选且唯一；其余四维各有一个主选择。
- 目标字数 50,000–100,000；建议 80,000。
- 目标节数 8–40；建议 20。
- 兼容矩阵校验；冲突时必须先修正分类。
- 配置变更后，下游产物标记 `stale`，不自动删除。

**质量门**

- 五维齐全；主分类与性别频道一致；标签总数 ≤ 10。

**模型策略**：不需要 AI，纯表单与校验。

---

### S1 故事核

**目的**：用一句话锁定“谁、要什么、被什么阻止、反转是什么、读者最后得到什么情绪”。

**输入**：五维分类、目标字数、卖点。

**输出**：`01-故事核/一句话故事.md`、`故事核展开.md`

**必须包含**

1. 主角：身份 + 当前处境 + 伤口/欲望
2. 目标：具体、可验证，不是“变强/幸福”这种空话
3. 阻力：具体对手或规则
4. 反转：至少一个“读者以为 A，实际是 B”
5. 情绪承诺：读者主要为什么继续看（爽/甜/虐/暖/悬/燃）
6. 终局兑现：最后一节给读者什么具体画面或结果

**提示词要求**

- 只允许基于五维分类和用户输入，不允许自行发明平台分类。
- 输出 3 个候选故事核，每个 ≤ 120 字；用户选定一个后再展开。
- 禁止先写世界观；先写人的处境和冲突。

**质量门**

- 一句话故事必须包含“主角 + 目标 + 阻力 + 反转 + 情绪承诺”。
- 不能是“一个女孩经历了很多事最后成长了”这种无冲突摘要。

**模型策略**：flash；输出上限 1,200 tokens。

---

### S2 人物与关系卡

**目的**：用最少的人物支撑单主线，避免短篇人物膨胀。

**输入**：故事核、五维分类中的角色维度。

**输出**：`02-人物/人物关系卡.md`、`角色状态.json`

**人物数量**

- 核心 2–4 人：主角、对手/阻力、关键关系人、功能角色（萌宝/闺蜜/导师/证人）。
- 总人物 ≤ 6；超过时合并或删除。

**每人必须写**

- 身份与当前处境
- 想要什么（外部目标）
- 真正需要什么（内部缺口）
- 害怕/隐瞒什么
- 与主角的关系张力
- 在故事中推动哪一次转折
- 说话方式与动作习惯（用于对白和动作表达）

**关系卡**

- 主角 ↔ 对手：权力差、信息差、情感牵制
- 主角 ↔ 关键关系人：支持、误解、牺牲、背叛
- 对手 ↔ 关键关系人：是否存在双重关系

**质量门**

- 每个核心人物至少推动一次转折；没有功能的人物删除。
- 对手必须有可理解的动机，不能只是“天生坏”。

**模型策略**：flash；输出上限 1,500 tokens。

---

### S3 情绪曲线与反转表

**目的**：把“好看”拆成可执行的节拍，而不是让模型自由发挥。

**输入**：故事核、人物关系卡、五维分类中的情绪维度。

**输出**：`03-情绪与反转/情绪曲线.md`、`反转表.md`

**反转表字段**

| 序号 | 发生节 | 反转前读者以为什么 | 实际是什么 | 主角付出什么代价 | 情绪变化 | 下一钩子 |
|---|---|---|---|---|---|---|

**规则**

- 3–5 个关键反转；少于 3 个会平，多于 5 个会乱。
- 每个反转必须改变至少一项：关系、权力、信息、目标、身份。
- 反转不能靠“突然出现新人物/新能力”硬拐；必须有前文伏笔。
- 情绪曲线必须与主分类一致：甜宠不能长期压抑无甜；虐恋不能没有伤害；悬疑不能提前揭底。
- 每 3,000–5,000 字至少一个可感知反转；每节结尾一个钩子。

**质量门**

- 反转表覆盖开篇、前中段、后段、终局。
- 每个反转都能在分节大纲中找到落点。

**模型策略**：flash；输出上限 2,000 tokens。

---

### S4 分节大纲

**目的**：把情绪曲线落成 8–40 节的可写单元。

**输入**：故事核、人物、反转表、目标字数/节数。

**输出**：`04-分节大纲/分节大纲.md`

**每节必须写**

- 节号与暂定标题
- 本节目标（主角要做什么）
- 核心冲突（谁阻止、为什么）
- 信息增量（读者新知道什么）
- 情绪变化（从什么情绪到什么情绪）
- 反转/升级（本节至少一个变化）
- 结尾钩子（具体画面/一句话/悬念）
- 预计字数（1,500–4,500）

**结构建议**

- 第 1 节：主角 + 异常处境 + 第一个悬念；前 3 段必须抓人。
- 第 2–3 节：第一次升级，明确对手和代价。
- 第 4–8 节：第一次大反转，关系/身份/目标重排。
- 中段：每 2–3 节一次小兑现，防止持续压抑。
- 后段：第二次大反转，主角主动选择。
- 最后 2 节：情绪兑现 + 收束；不开放式敷衍。

**质量门**

- 节数 8–40；总字数在 5–10 万。
- 每节都有冲突、变化、钩子；没有“过渡节”纯铺垫。
- 单主线：辅助情节不超过 1 条，且必须服务主线。

**模型策略**：flash；输出上限 6,000 tokens；按 8–12 节分批生成，避免截断。

---

### S5 开篇三屏

**目的**：短篇的生死线。前 3 段决定读者是否继续。

**输入**：第 1 节大纲、故事核、人物。

**输出**：`05-正文/第01节-开篇.md`（合并入第 1 节正文）

**硬规则**

- 前 3 段必须出现：主角、异常处境、第一个悬念/冲突。
- 前 300 字必须让读者知道“谁在受苦/谁在施压/马上要发生什么”。
- 禁止先写世界观、家族谱系、天气抒情、主角起床照镜子。
- 第一段不超过 80 字；对话或动作优先。
- 开篇承诺必须与主分类一致：甜宠先给关系张力，虐恋先给伤害，悬疑先给异常，复仇先给不公。

**质量门**

- 3 段内出现主角 + 冲突 + 悬念。
- 没有大段设定说明。
- 读完后能说出“主角现在最怕/最想要什么”。

**模型策略**：pro；输出 3 个版本，用户选一个；每版 ≤ 800 字。

---

### S6 逐节正文生成

**目的**：按分节大纲逐节写正文，每节独立完成、独立质检、独立保存。

**输入**

- 当前节大纲
- 前 1–2 节摘要（不是全文）
- 人物状态（关系、秘密、权力位置）
- 五维分类约束
- 项目文风与禁用词（可选）

**输出**：`05-正文/第NN节.md`

**每节结构（建议）**

1. 开场 1–2 段：承接上一节钩子，立刻进入当前冲突。
2. 中段 2–4 个 beat：目标 → 阻力 → 选择 → 代价。
3. 转折：信息/关系/权力至少变一项。
4. 结尾钩子：具体画面、未完成动作、或一句带信息量的话。

**写作规则**

- 单节 1,500–4,500 字；目标中位数 3,000–4,000。
- 每 1,000–1,500 字至少一次信息推进、冲突升级或情绪转折。
- 短段落，对话独立成段；避免长篇式环境铺陈和支线。
- 心理描写必须外化为动作、表情、身体反应或可感细节。
- 不写“总结式旁白”和“作者解释”。
- 每节结尾必须是钩子，不是总结。

**上下文包（只给短篇字段）**

```text
【五维约束】...
【故事核】...
【人物状态】...
【前情摘要】上一节 200–300 字
【本节大纲】目标/冲突/信息增量/情绪变化/反转/钩子
【文风】...
【硬规则】...
```

**禁止**：读取长篇卷纲、章节步骤结果、Scene 展开、章节结算。

**质量门（生成后立即执行）**

- 字数在 1,500–4,500。
- 本节目标是否完成？冲突是否升级？
- 是否有信息增量？读者新知道了什么？
- 情绪是否发生变化？是否兑现了一个小爽点/虐点/暖点？
- 结尾是否有具体钩子？
- 是否出现长篇式铺陈、支线、重复解释？

不通过：优先局部修复；修复失败则重生成当前节，不回滚已完成节。

**模型策略**：pro；按节生成，单次输出上限按 4,500 字配置；超长时拆成 2 次（前半/后半）并做衔接校验。

---

### S7 节级质检

**目的**：把质量问题挡在下一节之前，避免错误累积。

**输入**：当前节正文、当前节大纲、人物状态、五维约束。

**输出**：`06-质检/第NN节-质检.md`

**评分维度（每项 0–20，总分 100）**

| 维度 | 检查点 |
|---|---|
| 钩子 | 开篇是否承接上一节；结尾是否有具体钩子 |
| 推进 | 本节是否完成目标；是否有信息增量 |
| 冲突 | 阻力是否具体；主角是否做出选择并付出代价 |
| 情绪 | 是否兑现情绪承诺；曲线是否变化 |
| 连贯 | 人物动机、关系、时间线、道具是否连续 |
| 文风 | 是否短篇节奏；是否有长篇式铺陈/解释 |

**通过线**：≥ 80 分，且“钩子/推进/冲突”三项均 ≥ 12 分。低于通过线时：

1. 输出可执行的修复清单（逐条对应段落）。
2. 用户选择“局部修复/重写本节/接受并标记”。
3. 修复后重新质检；连续 2 次不通过则暂停，要求人工确认。

**模型策略**：flash（规则质检可 0 次 AI；语义质检用 flash）。

---

### S8 全篇收束与情绪兑现

**目的**：短篇不能烂尾。最后一节必须兑现主情绪，关闭主冲突，给读者一个明确的情绪落点。

**输入**：全篇各节摘要、反转表、人物状态、主分类与情绪承诺。

**输出**

- 最后 1–2 节正文
- `06-质检/全篇质检.md`

**必须完成**

1. 主冲突解决：对手/阻力被击败、被理解、被离开，或主角主动放弃并承担代价。
2. 主情绪兑现：爽文给具体打脸/反杀；甜宠给关系确定；虐恋给真相/追悔/释然；悬疑给真相闭环；成长给可见的新生活。
3. 反转闭合：前面埋的伏笔至少回收 80%；未回收的必须是有意留白，不是遗忘。
4. 人物弧光：主角的选择与开篇不同，且这个不同有代价。
5. 结尾钩子：短篇可以留余味，但不能用“开放式结局”逃避兑现。

**质量门**

- 主冲突是否解决？主情绪是否兑现？伏笔是否回收？
- 最后一节是否仍在推进，而不是总结全文？
- 是否出现“突然天降解决方案”？

**模型策略**：pro；输出上限 6,000 tokens。

---

### S9 平台适配与导出

**目的**：把作品整理成番茄短篇可提交的形态。

**输入**：全篇正文、五维分类、质检报告。

**输出**

- `07-导出/书名候选.md`（3–5 个）
- `07-导出/简介.md`（100–200 字，含钩子，不剧透核心反转）
- `07-导出/导出稿.md`（按“第N节”）
- 平台元数据：主分类、目标字数、标签建议

**规则**

- 书名必须与主分类和主情绪一致；不标题党到与内容不符。
- 简介前 2 句必须出现主角处境 + 冲突 + 悬念。
- 平台只提交主分类；其余四维作为作者自查，不作为平台标签。
- 导出标题使用「第N节」；不输出卷标题。
- 导出前跑一次全篇检查：字数、节数、错别字、重复段落、未闭合伏笔。

**质量门**

- 总字数 5–10 万；节数 8–40；每节 1,500–4,500 字。
- 主分类与内容一致；简介不泄露终局反转。
- 导出文件可被番茄编辑器正常粘贴，标题层级正确。

**模型策略**：flash（书名/简介）；导出不需要 AI。

## 四、独立 Runner 设计

### 4.1 类型

```ts
export type ShortStepKey =
  | 'short.init'
  | 'short.premise'
  | 'short.characters'
  | 'short.curve'
  | 'short.outline'
  | 'short.opening'
  | 'short.sectionGen'
  | 'short.sectionReview'
  | 'short.finale'
  | 'short.export';

export interface ShortWorkflowStep {
  key: ShortStepKey;
  label: string;
  required: boolean;
  repeatable: boolean;
  modelStrategy: 'flash' | 'pro' | 'none';
  inputArtifacts: string[];
  outputArtifacts: string[];
  validate(ctx: ShortWorkflowContext): ShortValidationResult;
}
```

### 4.2 Runner 约束

```ts
export class ShortStoryWorkflowRunner {
  // 只依赖共享底层能力
  constructor(
    private ai: ShortAiPort,
    private vault: ShortVaultPort,
    private taxonomy: ShortTaxonomyPort,
    private logger: Logger,
  ) {}

  async runStep(step: ShortStepKey): Promise<ShortStepResult> { ... }
  async runSection(index: number): Promise<ShortSectionResult> { ... }
  async resume(): Promise<void> { ... }
}
```

- 不注入 `ContextManager`、`StepRunner`、`ChapterStateManager`。
- 不读取 `03-大纲与章节`。
- 不写 `stepResults`、`stepCompleted` 等长篇字段。
- 所有步骤键以 `short.` 开头；所有产物路径在 `00-短篇配置` / `01-故事核` / ... / `07-导出` 下。

### 4.3 断点与恢复

- 每完成一步写 `流程状态.json`；每完成一节写 `sectionIndex` 与质检结果。
- 重启后从 `currentStep + sectionIndex` 恢复，不重跑已完成节。
- 配置变更时，将受影响的步骤标记为 `stale`，由用户选择重跑范围。
- 任何写入前先备份旧文件；生成失败不覆盖上一版。

## 五、与长篇要素的适配

| 长篇要素 | 短篇适配 | 禁止做法 |
|---|---|---|
| 清晰表达 | 每段有信息增量；短句；场景目标明确 | 直接套用长篇“信息论章节生成”模板 |
| 设定规范 | 极简故事圣经：3–6 人、1 主场景、1 核心规则 | 长篇世界观/势力/时间线全套 |
| 分镜演绎 | 节内 beat sheet：目标→阻力→选择→代价→钩子 | 长篇 Scene 展开器 |
| 动作表达 | 身体动作、表情、可感细节替代心理独白 | 长篇式大段心理描写 |
| 环境描写 | 1–2 个感官细节服务情绪 | 长篇式环境铺陈 |
| 章节结算 | 节级质检 + 全篇质检 | 长篇章节结算/信息债看板 |

## 六、UI 入口与流程页面

短篇入口只显示短篇项目。项目详情页的步骤条为：

```text
分类 → 故事核 → 人物 → 情绪/反转 → 分节大纲 → 开篇 → 逐节写作 → 节级质检 → 收束 → 导出
```

- 不出现“卷”“章”“全书规划”“批量建章”“章节结算”。
- 右侧显示五维分类摘要、当前节目标、质检分数、未解决问题。
- “继续写作”直接进入 `sectionIndex` 对应的下一节。
- “批量生成”只能在短篇流程内按节循环，不能调用长篇批量建章。

## 七、验收标准

1. 短篇流程不导入任何长篇步骤/Runner/模板；静态导入测试通过。
2. 可完整生成 5–10 万字、8–40 节的短篇，每节 1,500–4,500 字。
3. 开篇前 3 段满足“主角 + 异常处境 + 悬念”。
4. 至少 3 个关键反转，且每个反转在分节大纲中有落点。
5. 每节质检有分数、问题清单、修复记录；低于通过线不能静默进入下一节。
6. 最后一节完成主冲突与主情绪兑现，伏笔回收 ≥ 80%。
7. 导出为「第N节」，无卷标题；平台元数据只使用主分类。
8. 中断后可恢复到具体节，不重跑已完成节，不覆盖旧稿。
