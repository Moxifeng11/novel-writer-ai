# 方案 v3 补丁：稳健性评估与缺口补齐（2026-11-15）

> 回答「当前计划够不够稳妥」：**不够**。v2 只解决了「数据怎么组织 + 注入怎么变小」，
> 没有回答「改完之后，一致性 / OOC / 节奏 / RAG / 回写 是否还成立」，也没有覆盖短篇与剧本。
> 本文基于三份新增审计补齐：`docs/audits/2026-11-15-atomization-audit.md`、
> 短篇/剧本链路审计、RAG/一致性/OOC/节奏/回写审计（均 2026-11-15）。

## 一、结论：四个必须补的缺口

| # | 缺口 | 现状事实 | 后果 |
|---|---|---|---|
| 1 | **一致性只消费章级数据** | 断言来源：frontmatter/digest/fact-store/ledger-event/正文（**只取前 4000 字**，`fact-maintenance.ts:47,92`）；不读场景卡 | 原子化后「哪一场、哪一句」无法定位；矛盾检测退回章级粗判 |
| 2 | **一致性结果不回注** | 矛盾写 `矛盾.json`，**无写作侧读取** | 审核是事后报告，不是前馈约束 → 同类矛盾反复出现 |
| 3 | **OOC 保障覆盖不全** | 灵魂层 9 字段 + 词表检查 + 质量门禁；**无角色级口吻样本注入**；LLM OOC 检查只在协同写作（`co-writer-engine.ts:1889`），一键流水线不走 | 配角靠词表近似；主角口吻无样本锚定 |
| 4 | **RAG 与项目事实是两套体系** | RAG 只索引知识库书籍（+同人虚拟书），**项目正文/人物卡不进 RAG**；查询计划基于场景目标/正文/情绪/章纲/人物名 | 场景级注入变精确后，RAG 仍拿不到「本作事实」；`rag_sources` 归因仍是步级 |

另有两条结构性问题：

- **回写靠正则、无校验、按名字匹配**：`report-parser.ts` 逐行正则，无 JSON schema/值校验；实体按「路径=名字」匹配，改名/别名即 miss；指令无去重/冲突解决
- **短篇/剧本是旁路实现**（详见第三节），不接 BodyWriter/模板/上下文/场景结构

## 二、阶段调整：在 B → A → C 之后加 D（短篇剧本）与 E（质量保障）

### 2.1 RAG 升级（并入 C）

| 项 | 现状 | 改造 |
|---|---|---|
| 查询计划 | 场景目标/上场景结尾/正文/情绪/章纲/人物名（`shared/rag/query-plan.ts:63-84`） | 增加 **场景 ID 锚**：当前场景卡的在场实体 ID、地点 ID、伏笔 ID、时间点 |
| 语料 | 只有参考书 | 新增「本作事实检索」通道：**不走向量**，走 B 阶段索引的 ID/tag 精确命中（避免噪声与幻觉） |
| 归因 | `rag_sources` 步级 | 下探到**场景级**：记录本场注入的知识块 + 事实 ID |
| 评测 | hit@k/MRR 只在测试 | 接入生产：每章抽样记录命中率，进质量面板 |

### 2.2 一致性与 OOC 升级（新增 E 阶段）

| 机制 | 现状 | 改造 |
|---|---|---|
| 断言锚点 | 章号 + 正文 offset | 加 **场景 ID + 实体 ID + 关系 ID**；场景级快照（每场结束记录在场实体状态） |
| 一致性前馈 | 无 | 把「本章已存在的矛盾/高风险断言」以**约束清单**注入正文 prompt（不是全文报告，只取相关 ID 的若干条） |
| OOC 检查 | 词表 + 灵魂层；主角才走 LLM | ① 主角+主要配角都走 LLM OOC 检查（可配置成本）② 新增**角色口吻样本**字段（`voice_samples`，2–3 句台词）随场景注入 ③ 场景级归属（按在场 ID，不按整章切句） |
| 节奏 | 情绪曲线 + 场景节奏注入 + 钩子 + 信息债（章级） | ① 场景级信息债：本场应释放/应埋设的伏笔 ID 清单 ② 节奏偏离：从「需人工标注」改为**情绪曲线推导基准**（相邻场景强度差、钩子间隔） |

### 2.3 回写安全（新增 E 阶段）

1. **结构化指令**：`UPDATE_/NEW_/RELATION:` 改为 JSON 对象 + schema 校验（字段白名单、数值范围、ID 存在性）
2. **ID 匹配**：目标实体按 ID（B 阶段索引）匹配，名称仅用于解析到 ID；解析多义 → 进入「待确认」队列而非猜测
3. **场景锚点**：每条回写记录来源场景 ID + 章 + 时间点，便于回溯与冲突定位
4. **冲突解决**：同实体同字段多指令 → 按「场景顺序 + 显式优先级」合并，冲突写待确认
5. **事务**：沿用 journal 回滚，补 V2 关系/承诺账本/角色弧线回滚后的重写（现状受限，`settlement-engine.ts:648-663`）

## 三、短篇 / 剧本：审计结论与必须补的坑

### 3.1 现状（事实）

- **不是 11 步流水线**：逐单元单次 AI 调用（载入上下文 → 拼 prompt → 流式生成 → 保存 → 质检 → 轻结算）
- **旁路实现 8 处**：绕过 BodyWriter（无版本备份/无格式契约/无写锁）、提示词全硬编码（不走模板系统）、上下文自拼（不走 context-manager/story-context-graph）、状态机只有 pending/written/settled、结算只写 `entity_status`（不更新关系/伏笔/时间线）、单元重生成不备份、frontmatter 手写、质检/结算报告只写不读
- **注入/产出比失衡**：剧本每集注入 ≈12–15k token，目标正文仅 ≈1000 字（≈10:1）；分镜表**整表**注入每一集，不按集切片
- **剧本「场」无结构**：只在集正文里以 `###` 标题存在，唯一接触点是质检正则计数；场景圣经是单文件、无解析器
- **短篇**：故事核/分节大纲/节骨架都是单文件；节骨架已具备「本节目标：冲突/信息/情绪/钩子」——**天然的节级场景卡雏形**

### 3.2 D 阶段：短篇/剧本统一化

| 项 | 改造 |
|---|---|
| 落盘 | 单元正文改走 BodyWriter（版本备份 + 格式契约 + 不变量 + 写锁 + 广播） |
| 提示词 | 改走模板变量体系（用户可改 prompt） |
| 上下文 | 接入统一索引 + `SceneContextPack`（短篇锚＝节卡；剧本锚＝集卡 + 当前场卡 + 在场实体 ID） |
| 剧本场结构 | 集正文解析出 `场`（集号-场号），存场卡（`### N-M` + 人物 + 动作 + 对白 + 时长）；场景圣经按 `## 场景N` 拆条目 |
| 分镜 | 分镜表按集/场切片注入；镜号（`E01-S01-SH01`）作为原子 ID |
| 结算 | `settleLight` 升级：写关系/伏笔/时间线/成长（与长篇共用回写管道） |
| 原子化 | 短篇：故事核 5 字段、分节大纲每节 7 字段、节骨架；剧本：场景圣经条目、分集大纲 6 字段、集内场、分镜每镜 |

### 3.3 D 阶段验收

- 单测：集/场/镜解析、节卡/场卡构建、分镜按集切片
- 实机：造短篇与剧本项目 → 生成一节/一集 → 注入体量下降、落盘有版本备份、结算能更新实体/伏笔
- 对比指标：注入 token / 产出字数比（剧本目标从 10:1 降到 ≤4:1）

## 四、验收指标体系（贯穿 B/A/C/D/E）

| 指标 | 来源 | 目标 |
|---|---|---|
| 单步注入 token | `injection-ledger`（已存在） | 正文步下降 ≥50% |
| 真实调用 token | `usage-ledger`（已存在） | 单章总 token 下降 ≥40% |
| 截断/重试次数 | `step-runner-retry` / `warnIfTruncated` | 截断事件 → 0；重试率下降 |
| 一致性矛盾数 | `矛盾.json` + CED 指标 | 每章矛盾数下降、无新增高危 |
| OOC 命中率 | 人物一致性报告 + LLM OOC | 高危 OOC 下降；口吻一致性抽检通过 |
| 节奏偏离 | 情绪曲线 + 钩子间隔 | 无「连续 3 场无钩子/无冲突升级」 |
| 回写正确率 | 待确认队列 / rejectedFields | 误写（改名/别名 miss）→ 0 |
| RAG 命中 | hit@k/MRR 接生产 | 场景级命中率可观测 |

**每个里程碑必须给出指标前后对比**，否则不算完成。

## 六、仍不确定、需要你定的点

1. **成本 vs 质量**：主角+主要配角都走 LLM OOC 检查会增加调用成本（每章 +1~3 次）。接受吗？
2. **剧本场结构**：是否允许插件改写集正文（把 `###` 场标题规范化、加场 ID）？还是只做只读解析？
3. **短篇/剧本是否也要「每节/每集一文件 + 派生视图」**（现在已经是每单元一文件），还是只做「场/镜」原子化？
4. **一致性前馈**的注入量：只取「涉及在场 ID 的 3–5 条高风险断言」，可以接受吗？
