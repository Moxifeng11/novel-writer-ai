推荐模式验收口径

不是“跑完就算”，每一步都要有文件与结构校验。

规划完整性5 步缺 1 步即停在规划，不跳正文
截断finishReason=length → partial，不标记完成
正文保护截断不覆盖已有完整稿，写 _截断草稿.md
结算幂等status: settled 时需显式“重新结算”
分析去重已有步骤 9 报告 → 0 次 AI 结构化提取
失败停留停在失败步骤，可从该步续跑
已知边界：批量候选在本地模型输出非法 JSON 时会回退为 3 次串行；此时耗时回到旧水平，但候选数量不受影响。守卫与验证未合并，仍可能各发 1 次。

为什么不做这些

不减少 / 隐藏 11 步。步骤是用户可检查、可编辑、可单独重生成的契约；一键编排只是驱动它们。

不把质量控制和分折报告合成一次调用。两个 prompt 都很大，硬合并会挤掉正文与问题清单，属于用质量换次数。

不改候选内容标准。只改调用组织方式：方向数、长度、禁止分析文本、插入即用，全部保留。

不自动加定向修订。修订是显式按钮；本轮只让分析报告消费质量问题，避免重复检测。

下一步若还要降调用，优先级应是“守卫与验证按正文 hash 去重”和“相同上下文 in-flight 合并”，而不是继续合并步骤。
