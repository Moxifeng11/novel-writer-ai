| 回溯标记 | 无（靠引文启发式猜） | **模型显式给 isCurrentState** |

## 关键发现：根治引入了回归，已定位并部分修复

### 回归现象

新 prompt 首次评测：**427 条误报，全部是 `duration`（时长不相容）**。

### 根因（两层）

**① 规范谓词把时间类事实压成同一个值「时间」**
旧 prompt 下每条时间事实的谓词是自由文本（「事件时长」「时间点」等），天然区分；
新 prompt 全部归一为「时间」，R5 按 (主体, 谓词) 分组时把**无关时间事实**两两比较。

**② 拆解侧对时间点类事实一律给 `numeric: 0`**
「今天清晨冒雨冲入渭城」这类事实没有时长，但模型填了 0；
R5 只判 `typeof numericValue === 'number'`，于是 0 被当成有效时长参与比较。

### 已修

R5 增加守卫：`numericValue > 0` 且（无单位 或 单位为时长单位）。
→ 误报 **427 → 21**。

### 仍剩 21 条（未解决，如实记录）

剩余误报形态：

```
[duration] 事件「宁缺」在 第8章 记为「在草原上呆了将近一年」，
           在 第47章 记为「再过二十来天参加书院入院试」——两处时长不相容
```

**根因**：R5 按「主体」分组，而「宁缺」有多个**不同事件**（入楼十七日 / 苦求十余年 / 请五天病假）。
规范化谓词无法区分事件，因为「事件身份」这一维度**在拆解产物里不存在**。

### 正确的下一步（不是继续打补丁）

在拆解产物中新增 **`event` 字段**（事件名/事件锚），R5 改为按 (event) 分组。
这需要在 prompt 与校验里加一个字段——和这次「规范谓词」同性质的结构化改造，
而不是又在规则层猜。

## 结论

| 判断 | 结论 |
|---|---|
| 规范谓词是否有效 | ✅ 有效（谓词全部枚举，回溯有显式标记） |
| 是否引入回归 | ⚠️ 是（427 条），已定位并修到 21 |
| 21 条能否靠补丁解决 | ❌ 不能——缺「事件身份」维度，需结构化改造 |
| 旧 prompt 是否更优 | 当前数字上旧 prompt 误报 0 更优，但那是**谓词自由文本偶然带来的区分度**，不可依赖 |

**建议**：下一步加 `event` 字段（结构化），再重跑对照；在此之前不建议用新 prompt 替换线上。
