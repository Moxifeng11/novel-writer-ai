# C 臂实验 · 阶段二结果（真实原著 30 章）

> 结论先说：**拆解层质量优秀，但"值比较"策略在真实文本上误报率极高**。
> 这推翻了"有了结构化条目就能直接判矛盾"的假设，也验证了 v4.88.0
> 「7 个子类只进疑似、不做值比对」的保守取舍是对的。

## 一、拆解层（LLM 质量）

《将夜》前 30 章，逐章真实调用 DeepSeek：

| 指标 | 值 |
|---|---|
| 成功率 | **30/30 = 100%** |
| 条目总数 | **456 条**（平均 **15.2 条/章**） |
| 被校验拒绝 | 5 条（1.1%，多为编造引文/类型越界） |
| 类型分布 | world-rule 89 · knowledge 74 · relationship 73 · ability 57 · location 40 · possession 38 · timeline 37 · memory 36 · age 12 |
| token | in 59,625 / out 33,115 |
| 耗时 | 136s（4.5s/章） |
| 成本 | **¥0.295 / 30 章** → 折算 200 章 ≈ **¥1.96** |

**拆解层可用**：9 类都有产出、成功率 100%、引文校验拦住了 5 条垃圾、成本极低。

## 二、冲突判定层（问题所在）

把 456 条按「同主体 + 同谓词」分组，用 `validFrom/validTo` 有效区间判定冲突：

```
条目 456 条 · 分组 392 个 · 候选冲突 165 处（跨章 92）
类型分布: memory 62 · possession 42 · relationship 38 · ability 11
          age 5 · knowledge 5 · location 2
```

**抽检前 12 条，全部是误报**：

| 候选 | 实际 |
|---|---|
| 宁缺\|年龄：第1章「约摸十五六岁」 vs 第15章「十五六岁」 | 同一事实的措辞差异 |
| 桑桑\|年龄：第1章「十一二岁」 vs 第5章「将将十一二岁」 | 同一事实 |
| 桑桑\|身份：第1章「宁缺的侍女」 vs 第24章「宁缺的小侍女」 | 同一关系 |
| 桑桑\|身份：第5章「户籍上是婢女」 vs 第16章「路边拣的丫头」 | **不同侧面**，不是互斥 |

**误报率目测 >90%**（165 候选里真矛盾应为 0——原著本身没有明显 bug）。

### 根因（三条，都是结构性的）

1. **`value` 是自由文本**：`「约摸十五六岁」≠「十五六岁」` 但语义相同。
   字符串比较在这里几乎必然失灵。
2. **谓词粒度太粗**：`身份` 一个谓词下混了「户籍身份」「出身」「主仆关系」三个侧面。
3. **「同主体同谓词即互斥」这个前提本身是错的**：真实叙事里同一主体同一谓词
   可以有多个**同时成立**的值（"既是侍女又是拣来的丫头"）。

## 三、这意味着什么

- **不要**用「值不等即矛盾」——即使在结构化条目上也不行。实测 165 误报。
- **拆解层是对的**（LLM 把正文变成结构化事实，100% 成功率、低成本）。
- **判定层要改**：候选冲突必须再过一道**语义判定**，而不是直接输出。

## 四、下一步（三个可选方案，按性价比）

| 方案 | 做法 | 成本 | 预期 |
|---|---|---|---|
| **A. 加判定层**（推荐） | 候选冲突（165 处/30 章）交 LLM 判「是否真矛盾」，严格 JSON + 双侧引文 | ¥0.1/30 章 | 误报可降到可接受，召回靠判定 |
| B. 值归一化 | 数字归一化（十五六岁→15-16）+ 关系同义词表 + 谓词细分 | 零 token | 能消掉约一半误报，但治标 |
| C. 提高置信门槛 | 只报 confidence ≥0.95 且**值差异显著**的 | 零 token | 漏报大增 |

**推荐 A + B 组合**：先用 B 做廉价归一化压掉明显同义（侍女/小侍女、十五六岁/约摸十五六岁），
再把剩下的候选交 LLM 判定。这样判定层调用量从 165 降到几十，成本可控。

## 五、产出文件

- `docs/analysis/knowledge-batch.json`：456 条拆解条目（含章节、类型、值、引文、有效区间）
- `scripts/dev-decompose-batch.mjs`：批量拆解（可复用，改 N 即可）
- `scripts/dev-decompose-conflicts.mjs`：冲突分析（当前策略，供对照）

## 六、一句话

**LLM 拆解解决了"没有结构化数据"的问题（0 → 456 条，¥0.3），
但没解决"如何判矛盾"的问题——165 个候选里几乎全是同义表述差异。**

判定必须再过一道语义关，这是 C 臂第三阶段的核心工作。
