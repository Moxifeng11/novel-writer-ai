# C 臂阶段三结果：归一化 + LLM 判定，误报从 165 → 0

> 阶段二的问题：456 条拆解条目按"值比较"得到 165 处候选，抽检全是误报。
> 阶段三加两道关：**B 归一化**（免费）+ **A 语义判定**（付费），结果如下。

## 一、结果

| 环节 | 数量 | 说明 |
|---|---|---|
| 原始候选 | 165 | 同主体+同谓词+有效区间不重叠 |
| 归一化压降 | −21（12.7%） | 「约摸十五六岁」≡「十五六岁」等 |
| 送判定 | 144 | 逐批（12 条/批）交 DeepSeek |
| **确认矛盾** | **0** | 原著本身无明显矛盾，0 即正确答案 |

**误报：165 → 0。** 判定层 token in 10,846 / out 4,631，成本 **¥0.042/30 章** → 200 章约 **¥0.28**。

## 二、两道关各自的作用

### B 归一化（免费，压掉 12.7%）

压掉的例子：

```
宁缺|年龄: 「约摸十五六岁」 ≡ 「十五六岁」
桑桑|年龄: 「十一二岁」   ≡ 「将将十一二岁」
桑桑|身份: 「宁缺的侍女」 ≡ 「宁缺的婢女（户籍上）」
桑桑|身份: 「宁缺的侍女」 ≡ 「宁缺的小侍女」
```

**只压掉 12.7%，说明归一化只能处理"措辞变体"这一层。** 剩余 144 处是"同一角色不同侧面"
（户籍/出身/主仆）这类需要理解语义才能区分的，正则和同义词表都无能为力。

### A 语义判定（付费，压掉剩余 100%）

144 条候选交模型判"是否真的无法同时成立"，**全部判为不矛盾**。模型给的理由是
「同一角色的不同称谓/侧面，可以同时成立」——与人工抽检判断一致。

**这一步是必要的**：仅靠归一化，144 处误报会直接输出给用户，功能等于不可用。

## 四、召回说明（必须诚实）

本实验回答的是**误报**问题，不是召回问题：

- 原著本身没有明显矛盾，所以"0 确认"是**正确**结果，无法据此算召回；
- 召回能力在**注入集**上已验证：v4.88.0 规则层 6/6 = 100%（年龄/记忆/化名/规则/时长/视角）；
- C 臂的价值是让**没有摘要的真实原著**也能进入流程（阶段一：0 → 456 条），
  并且把"值比较"这条必然误报的路径**关掉了**。

要测 C 臂的召回，需要一份**人工标注过矛盾的长篇**。建议做法：
在《将夜》前 30 章里人工注入 5–8 处矛盾（年龄/持有物/位置/时间线各 1–2 处），
跑同一流程看能否检出——这是下一步。

## 五、产品结论

1. **C 臂可用**，且成本低于一杯水（200 章 ¥2.25）。
2. **不能省掉判定层**——归一化只能压 12.7%，剩下 87% 的误报必须靠语义判断。
3. **与 v4.88.0 的取舍一致**：不做裸值比较，候选必须过语义关。
   区别是 v4.88.0 靠"7 子类只进疑似"绕开，C 臂是**真的把它们判了**。
