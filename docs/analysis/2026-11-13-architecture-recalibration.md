# 架构校准：故事创作流程与知识库的正确位置（2026-11-13）

> 起因：用户指出「架构理解有点偏差」。复盘确认**确有偏差**——
> 我在 `engine/consistency/knowledge-base.ts` 造了一个**平行知识库**，
> 而系统里已经存在**故事上下文总线**（`engine/context/`）+ **统一 RAG 检索管线**（`engine/rag/`）
> + **知识库系统**（`services/knowledge-base-manager.ts`）。
>
> 本文是把流程与架构重新对齐后的结论。

## 一、真实创作流程（按代码事实）

### 1. 写作前：上下文装配

```
大纲/章纲 + 上一章结尾 + 人物状态 + 世界设定 + 伏笔 + 情绪弧
        ↓  template-vars-builder（31 个注入段）
   StoryContextGraph（engine/context/）——标准化成"图"
        ↓  自动关联：场景卡→人物/地点/POV/伏笔/情绪；伏笔→人物/主线；时间线→实体
   检索（engine/rag/ 统一管线）
        查询计划 → 并行检索 → 合并去重 → 邻块扩展 → MMR 去重 → 预算打包 → citation
        ↓  两套预算：本地 4200 tokens / 云端 24000 tokens，必含项永不丢
   PromptBuilder → 模型生成
```

**关键事实**：上下文装配**已经**是"图 + 检索 + 预算"的正规管线，
不是各入口自己拼字符串。RAG 已经有查询计划、邻块扩展、MMR 多样性、预算打包、citation、遥测。

## 二、我的偏差与正确位置

### 偏差

| 我做的 | 问题 |
|---|---|
| 新建 `engine/consistency/knowledge-base.ts`（自有 facts 数组 + 自写检索） | 与 `engine/context/`（图）+ `engine/rag/`（检索管线）职责重叠，形成第二套事实源 |
| 计划"新建知识库落盘 + 检索" | 系统已有向量库（`knowledge-base-manager`）与图检索 |
| 把 C 臂当作独立能力设计 | 它应该是**图节点的产出方式**，而不是另一条数据线 |

### 正确位置

```
正文/摘要
   ↓ 拆解（LLM）——C 臂的产物
StoryContextGraph 节点（engine/context/）
   ├─ character / item / location / faction 的**状态**
   ├─ timeline 事件（含有效区间）
   ├─ foreshadow 伏笔（已兑现/未兑现）
   └─ setting / world-rule（世界规则）
   ↓
① 写作前：既有 RAG 管线检索 → 注入提示词（替代"让模型自己回忆"）
② 写作后：一致性审核读同一张图 → 跨章比对
③ 既有正则功能：作为"候选生成器"查图取权威状态
```

**一句话：拆解结果应该喂进已有的图，而不是另建一个库。**

### 保留的部分（仍有价值）

- `knowledge-decompose.ts`（拆解 + 严格校验 + 有效区间）——**产物格式正确**，只是去处要改
- `candidate-judge.ts`（归一化 + 语义判定）——**判断层独立于存储**，可复用
- `knowledge-base.ts`——降级为"图节点的**中间表示**与查询视图"，
  不作为独立事实源；落盘仍走既有知识库/图序列化

## 三、修正后的接入路线

| 阶段 | 内容 | 与既有组件的接口 |
|---|---|---|
| **P0** | 拆解产物 → StoryContextGraph 节点 | `story-context-graph.ts` 的节点构造；不新增存储层 |

## 四、必须先确认的三个问题（避免再偏）

1. **StoryContextGraph 的节点是否足以承载「带有效区间的事实」？**
   若不足，是扩展节点类型，还是新增一类 `fact` 节点？（倾向后者，但要走图的标准关联）
2. **`services/knowledge-base-manager.ts`（向量库）与图是什么关系？**
   一个管"向量检索的文本块"，一个管"结构化节点"——拆解事实应进图，原文块进向量库，两者通过实体 id 关联。
3. **一致性审核的权威源**：digest（LLM 摘要）已经是派生数据，
   现在再加拆解事实，两者冲突时以谁为准？（按红线：**正文 > 图 > 摘要**）
