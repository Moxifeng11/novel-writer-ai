# 产品定义（PRODUCT）

> 版本：v4.56.0 · 2026-11-04
> 本文回答“为谁做、解决什么、不做什么、如何衡量”。实现细节见 [ARCHITECTURE.md](ARCHITECTURE.md)，排期见 [roadmap/ROADMAP.md](roadmap/ROADMAP.md)。

## 1. 一句话定位

**在 Obsidian 里完成一篇长篇 / 短篇 / 短剧从设定、大纲、写作、质控到导出的全过程，并且每个环节的上下文都来自同一套项目事实。**

不是“AI 续写器”，也不是“写作素材库”：核心价值是**把长篇创作中容易断链的事实（人物状态、伏笔、关系、时间线、规则版本）持续维护住**，让作者不必靠记忆和手工表格对齐。

## 2. 目标用户

| 画像 | 特征 | 最痛的点 |
|---|---|---|
| 长篇连载作者 | 日更 4k–1w，10 万字以上，多卷多章 | 写到后期人物/伏笔/设定对不上；改一章牵动全书 |
| 短篇投稿作者 | 5–10 万字，番茄/七猫等平台 | 开篇钩子、节奏密度、平台格式反复试错 |
| 短剧编剧/工作室 | 40–120 集，分集分场 | 分集钩子、场景可拍性、人物关系一致性 |
| 已有 Obsidian 用户 | 笔记/设定已在 vault 里 | 不想再开一个封闭 SaaS，数据要留在本地 |

共同约束：**数据必须在用户自己的 vault 里**；不强制登录、不强制云同步；API Key 由用户自带。

## 3. 核心问题与产品回答

| 问题 | 产品回答 | 落点 |
|---|---|---|
| 上下文不够、越写越散 | 项目事实总线：规则 + 设定 + 实体 + 前文摘要 + 指纹按预算注入 | `engine/context-*`、`engine/rag/`、`KnowledgeInjector` |
| 规则/提示词版本漂移 | 写作规则唯一来源 + 版本化 + 内容哈希 | `services/rules-service`、`engine/prompt-resolver` |
| 改一章影响全书 | 结算 → 实体状态/伏笔/关系更新 → 连续性账本 | `engine/settlement-*`、`engine/revision-*` |
| 多模式割裂 | 长篇/短篇/剧本共用项目/章节基础设施，能力按模式配置 | `shared/creation-mode`、`ModeRuntime`（M3） |
| 不知道 AI 在干什么/花了多少 | 执行时间线 + 调用账本 + 任务中心（M2/M4） | `ExecutionLogPanel`、`JobService` |

## 4. 产品原则

1. **单一事实源**：同一事实只允许一个权威实现；UI 只做展示与调用。
2. **本地优先**：正文、设定、规则、会话都在 vault；插件目录只放配置与缓存。
3. **可解释**：每次 AI 产出能追溯到步骤、模板版本、规则版本、上下文来源。
4. **引导而非禁令**：写作规则用“单一镜头”等创作锚点，不堆数值禁令。
5. **渐进增强**：新能力用 feature flag/strangler；旧项目与旧配置必须可读。
6. **失败可见**：用户操作型入口不允许静默失败；错误给原因和下一步。

## 5. 非目标

- 不做实时多人协作、账号体系、订阅计费（至少 12 个月内）。
- 不做通用笔记/知识管理替代品；只服务创作链路。
- 不做云端托管模型；用户自带 Key 或本地模型。
- 不追求“一键全自动写完一本书”；人始终在关键节点确认。

## 6. 北极星指标

**周活跃项目中完成“写作 → 质检 → 结算”闭环的章节数。**

辅助指标：

- 首启到写出第一章的完成率与耗时（目标：3 分钟内）。
- 单章 AI 调用失败率 / 重试率。
- 结算后实体状态冲突数（目标：持续下降）。
- 短篇/剧本从创建到导出的完成率。
- 任务取消/重试成功率。

## 7. 当前能力边界（v4.29.0 事实）

- 长篇：11 步流水线、结算、实体图谱、伏笔、质量闸门、版本/回滚、导出 EPUB/DOCX/TXT 已可用。
- 短篇/剧本：创建、独立目录、AI 故事核/大纲/场景圣经/分镜、单元写作、六维/可拍质检、轻量结算、番茄/红果平台包导出已闭环；**知识库/RAG/指纹完整注入与完整图谱结算仍在 M4**。
- Agent 工作台：工具循环、写入审批、dsh 后端可用；写入默认需确认。
- 多端：Windows 实测；macOS/Linux/移动端需发布前人工冒烟。

## 8. 成功标准（下一阶段）

- 新用户 3 分钟内完成“配置 → 示例项目 → 第一章”。
- 短篇/剧本创建→导出无手填断点。
- 任务中心可取消、重试、查看失败原因。
- 关键门禁（lint/typecheck/test/write-entry/docs）在 CI 与本地一致，且能真的拦住回归。
