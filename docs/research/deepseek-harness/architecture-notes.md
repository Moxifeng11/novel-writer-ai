# dsh 架构要点与本地映射

> 每条给出：dsh 的做法（归纳）→ 为什么值得借鉴 → 本仓库映射 → 落地批次。
> 证据与置信度见 `sources.json`；本仓库文件行号以 2026-11-01 为准。

## 1. 事件日志是唯一事实源，模型历史由它派生

**dsh**：append-only `SessionEvent` 日志；`deriveMessages()` 把日志投影成模型可见历史。原则是「模型可见的，必须可从日志重建」。日志按版本命名（`session.vN.jsonl[.zstd]`），相邻版本做迁移，不改名。

**为什么**：长篇小说需要跨章连续性、可回放、可审计。压缩/裁剪一旦脱离日志，就会出现「模型看到的与落盘的不一致」。

**本地映射**：`engine/agent/harness/session-log.ts` 已有 `derive()` 与 `tool_result` 裁剪；但事件无时间戳/序号，`tool_result.data` 被丢弃，压缩摘要在日志里伪装成 `user_message` 前缀。

**批次**：C1。

## 2. Step 级工具集快照

**dsh**：每次模型 step 解析出一个不可变的工具集（`ResolvedToolSet`），prompt 装配与执行都用它；重试不重新装配，同名替换不影响已放行的调用。

**为什么**：避免「提示词里说有某个工具，执行时却不存在/换了实现」的不确定性。

**本地映射**：`engine/agent/harness/tool-registry.ts:35-60` 每次全量渲染目录；没有快照语义。

**批次**：C2。

## 3. 工具执行管线

**dsh**：`tool/call` 落日志 → `pre-execute` 拦截 → 单调守卫 → 审批（缺省即拒绝，fail-closed）→ 执行包装（超时/重试/指标）→ 写意图门 → `post-execute`（可替换结果/追加上下文）→ 结果落日志 → 附加上下文作为 user 消息注入。

**为什么**：把权限、超时、审计、失败恢复放在统一位置，而不是散落在每个工具里。

**本地映射**：`tool-registry.ts:63-131` 已有守卫与可选超时；审批只在 `host-tools.ts` 的 `run_command` 内，`create_*_project` 等写工具无确认；`sideEffect: 'dangerous'` 未参与审批。

**批次**：C2。

## 4. 压缩公式与保留带

**dsh**：触发阈值近似 `floor(min(W×0.8, W−O−B))`（`B` 为固定 headroom，文档示例 65,536）；保留最近约 16% 的 `(W−O)` 原文；最旧的一段「平衡跨度」替换为一条带标记的摘要消息；先跑工具结果裁剪（不调模型），再考虑图片卸载；溢出时进入恢复路径。

**为什么**：只按「保留最近 N 条」会用完窗口或过度丢弃；按窗口比例 + headroom 更稳。

**本地映射**：`engine/agent/harness/harness-engine.ts:31-42` 用「≥30 轮或 ≥32k 字符」触发、保留 12 轮；`session-log.ts:153-206` 的切点已避开工具配对，这一点与 dsh 的「平衡切点」一致。

**批次**：C3。小说场景额外约束：切点不得落在章节/场景中间（本地领域规则）。

## 5. Spill：大结果移出上下文，返回定位符

**dsh**：超阈值文本写到上下文之外，模型只拿到预览 + 定位符 + 重新读取的指引；存储失败时保留原文。

**为什么**：一次全文检索/整章读取就能吃掉窗口；Obsidian 本身就是文件库，天然适合落盘。

**本地映射**：`spill-store.ts` + `agent-loop.ts:366-382` 已实现（`.sessions/spill/agent/<project>`，6000 字符阈值，600/200 头尾）。

**批次**：已具备；C2 补「定位符可读性」与失败提示，不重做。

## 6. 子代理：能力声明 + 深度限制

**dsh**：统一的子代理激活 API，带 `outputSchema`、`depthLimit`（默认 1，0 禁止委派）、`delivery: parent|caller`；结构化结果优于解析散文。

**为什么**：小说流水线的「拆书/大纲/写作/润色」本质是多阶段委派；结构化输出可减少协议解析失败。

**本地映射**：当前没有子代理；11 步流水线是固定阶段，`SingleCallRunner` 已有结构化契约（`engine/harness/structured-output.ts`）。

**批次**：本轮不引入子代理（延后），但 C2 的结构化工具结果与 C1 的事件类型为将来留位。

## 7. 权限：沙箱模式 + 审批结果封闭 + 如实报告执行强度

**dsh**：`read-only | workspace-write | danger-full-access`；审批结果是封闭集合（允许一次/拒绝/取消/不可用），缺省拒绝；执行强度如实报告 `full|partial`（例如某平台只能部分沙箱）。

**为什么**：安全默认值比“能力”更重要；“假装沙箱生效”比没有沙箱更危险。

**本地映射**：`HarnessTool.sideEffect` 已有语义但只在重复守卫里使用；`runCommand` 白名单 + 危险正则确认是唯一审批点。dsh 可选后端（Batch D）采用全 vault 只读 + 写入逐次批准，并在 UI 明确“Obsidian 无法真正沙箱”的事实。

**批次**：C2（native）、D2（dsh）。

## 8. 前缀缓存友好布局

**dsh**：会话级冻结的前缀放在所有派生历史之前；中途内容 append-only；压缩摘要调用重放同一段热前缀；工具目录更新用「只增/或写入历史 + 延迟加载」避免缓存失效。

**为什么**：云端模型按前缀命中缓存，稳定前缀能显著降成本/延迟；本地模型无缓存时可跳过。

**本地映射**：`prompt-sections.ts` 每次按序拼接系统提示，plan/memory 变化会改写前缀。

**批次**：C2/C3 做「回合内冻结系统前缀 + 变化写入 context_message」的最小版本；不实现 provider 级缓存协议。

## 附：明确不借鉴

- `run_code`/PTC 任意代码执行：插件运行在用户 vault 内，攻击面不可接受。
- Cordis 内核与 profile/bundle/patch 组合：我们的组合点是现有 `ENGINE_NAMES` 注册表与构造函数注入。
- `dsh_session_log` 上传：隐私边界，可选后端也必须关闭。
- 桌面/终端/LSP/SSH/MCP 市场：与写作插件无关。
