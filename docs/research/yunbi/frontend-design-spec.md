## 一、信息架构：33 个抽屉面板

云笔的一切编辑都在**右侧抽屉**完成，不跳页。这是它最核心的交互决策。

### 1.1 六档宽度语义

| 宽度 | 语义 | 面板举例 |
| ---: | --- | --- |
| **560px** | 管理类（列表 + 表单 + 操作按钮） | 功法体系 / 特殊设定 / 已历事件 / 资产管理 / 伏笔管理 |
| **520px** | 主数据类（列表为主） | 势力阵营 / 故事核心 / 货币体系 / 物品列表 / 力量体系 / 大纲设定 / 角色管理 / 人物关系 / 大纲编辑 / 时间线 / AI完善 |
| **480px** | 辅助类（内容为主） | 世界观 / 地理地图 / 伏笔AI / 情节脉络 / 情节AI / 情节完善 / 支线故事 / AI生成 |
| **450px** | 只读详情 | 大纲详情 |
| **420px** | 单条编辑 | 功法编辑 / 力量编辑 / 特殊设定编辑 / 伏笔编辑 / 情节编辑 |
| **380px** | 轻详情 | 势力详情 / AI角色生成 |
| **320px** | 常驻助手 | AI助手 |

**拖拽 clamp 范围**：不同面板不同上限
- `280~600`（窄面板）
- `360~800` / `400~900`（中）
- `450~950`（宽）

**命名规律**：`{数据对象}{侧边栏|抽屉|面板}`
- `侧边栏` = 列表视图（多条目）

- `抽屉` = 复合编辑器（如大纲编辑含树 + 表单）

## 二、三栏工作台布局

```
┌──────────────┬────────────────────────────┬──────────────┐
│   左侧栏      │       中间画布/编辑器        │  右侧属性面板  │
│   树/列表      │       （可视化编辑）        │  （详情/编辑） │
│   可拖拽       │                            │  可折叠       │
└──────────────┴────────────────────────────┴──────────────┘
        ↑ 拖拽手柄                            ↑ 悬浮按钮组
```

### 2.1 左侧栏：树形导航

- 缩进算法：`paddingLeft = 层级 * 16 + 8 px`
- 每项：展开箭头（▼/▶）+ 颜色点 + 名称 + 类型图标 + 子节点数 + 删除按钮
- 空状态：大图标 + 文字（如「🗺️ 暂无地图数据」）

### 2.2 中间画布

- 两种布局模式可切换：
  - **层级模式**：父在中央、子向外辐射，结构清晰
  - **网络模式**：自由力导向，节点自然聚簇
- 交互：拖拽节点移动 · 滚轮缩放 · 锚点连线 · 右键设父子

### 2.3 右侧属性面板

- 可 `面板折叠`
- 悬浮按钮组（垂直排列，5 个）：
  1. 生成历史（带次数 badge）
  2. AI 生成（生成中显示 spinner）
  3. 最大化/恢复面板尺寸
  4. 展开属性面板
  5. 关闭

**设计要点**：操作提示直接写在 UI 上 ——「拖拽节点移动 · 滚轮缩放 · 锚点连线 · 右键设父子」

## 三、设计 token

### 3.1 CSS 变量（30 个）

```css
/* 背景层级（6 层，从深到浅） */
--bg-darker → --bg-dark → --bg → --bg-lighter → --bg-card → --bg-hover
/* 模态/卡片专用 */
--bg-main, --bg-primary

/* 主色 */
--primary / --primary-hover / --primary-dark / --primary-color

/* 语义色（各有 -rgb 变体用于透明度叠加） */
--success / --warning / --error / --info
--success-rgb / --error-rgb / --primary-rgb …

/* 文字层级（4 层） */
--text / --text-primary / --text-secondary / --text-tertiary / --text-muted

/* 边框 */
--border / --border-color
```

**关键设计**：每个语义色都有 `-rgb` 变体，用于 `rgba(var(--primary-rgb), 0.1)` 做半透明叠加。这是深色主题的标准做法，本仓已有同类实现。

### 3.2 图标体系

- **Remix Icon**，共 **565 个不重复图标**
- 高频族：`ri-arrow-*`(20) / `ri-file-*`(19) / `ri-user-*`(16) / `ri-chat-*`(14) / `ri-map-*`(8) / `ri-shield-*`(8) / `ri-checkbox-*`(8) / `ri-folder-*`(8) / `ri-book-*`(7)

### 3.3 动画（13 种，语义命名）

```
fade / fade-slide / panel-fade / preview-fade
slide / slide-down / slide-up / slide-right / slide-in / slide-panel / slide-detail
scale / expand
```

**按语义命名而非 `transition-1`**，说明有明确动效语言：
- `slide-panel` = 抽屉进出
- `slide-detail` = 详情展开
- `panel-fade` = 面板淡入

### 3.4 Toast 通知

| 类型 | 时长 | 设计考量 |
| --- | --- | --- |
| success | 3000ms | 标准 |
| info | 3000ms | 标准 |
| warning | 4000ms | 多给时间 |
| **error** | **4000ms** | **比成功长 33%**，让用户读完 |

**细节**：错误提示时间比成功长，这个不对称是对的。

## 四、生成结果四态（★ 最重要的交互模式）

| 状态 | UI 表现 |
| --- | --- |
| **生成中** | 「正在生成」+ 流式内容实时显示 |
| **完成待确认** | 「生成完成，请确认是否采用」+ 采用/弃用按钮 |
| **失败** | 「解析生成结果失败，请重试」+ 重试按钮 |
| **已取消** | 「已取消生成」 |

### 「待确认」态是核心

生成结果**不直接落库**，要用户点了才写。

本仓已实现引擎侧（`BodyWriteRequest.requireConfirm` + `pendingPath` + `adoptPending`/`discardPending`，commit `d8210792`），**缺 UI 入口**。

## 五、进度文案策略（★ 意外的好设计）

云笔**把内部步骤名直接展示给用户**：

```
正在加载上下文...
正在构建生成提示词...
章节大纲完善完成，继续生成正文...
正在分析正文内容...
检测新角色并生成人生经历...
正在加载事件线数据...
正在加载主角事件线...
正在加载支线事件流...
正在加载章节事件流数据...
正在生成物品列表...
正在生成伏笔...
正在生成功法...
```

**为什么这是好设计**：
1. AI 生成要几十秒，不显示进度用户会以为卡死
2. 「正在加载主角事件线」比「加载中...」更能建立信任
3. 也暴露了内部流程——**这也是能逆向出来的原因之一**

**本仓对照**：已做得不错（有 `Phase 2: 正在生成第{current}/{total}卷大纲` 这类细粒度文案），不需要改。

## 六、11 步探讨模式的三件套

每步都带三样东西（这是前端设计的精华）：

| 要素 | 作用 | 例子（世界观步骤） |
| --- | --- | --- |
| **引导说明** | 告诉用户这一步要决定什么 | 「世界观应当贴合你已采纳的开篇题材。告诉我世界基调（光明/黑暗/末世/盛世）、核心规则（灵气复苏/魔法衰退/科技崩坏…）」 |
| **输入占位** | 给一个具体例子 | 「例：一个修真与凡尘交织的东方玄幻世界，天道失衡灵气枯竭，九州分裂为五大宗门」 |
| **快速想法** | 4 个可一键点的方向 | 「经典东方玄幻九州大陆」「末世+灵气复苏双设定」「高魔中世纪魔法王国」「近未来都市异能觉醒」 |

**为什么有效**：用户不需要懂「世界观该填哪些字段」，只需回答「你想写什么」。

数据契约见 `contracts.md` §2.2。
