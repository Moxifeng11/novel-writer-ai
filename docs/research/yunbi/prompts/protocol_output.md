# 协议行输出（protocol_output）

- 分类：写作规则
- 预估 tokens：1500（正文汉字 3611，约 1641 tokens）
- 普通模式：开启
- 专注模式：关闭
- 匹配得分：5.0

---
现在请按以下协议，对你刚才写的正文进行结构化提取，**只输出协议行，不要任何解释**：

- 关键动作（≤20字/条）
- 角色名:「保留对话原话」（每场景 ≤ ${o} 句，每句 ≤ ${i} 字）
- 关键道具/伤势/状态变化

- ⚠ PE/PI/CR/CF 仅记录【本章】发生的变化或新增内容，不要重复历史累积；若本章无该类信息，对应整段省略
- ⚠⚠ PI 角色字段必须是【有姓名/称号的人物】：地点（如「塘东工薪园/云屿公馆区」）、物品（如「合同文件/咖啡杯」）、势力严禁填入 PI 的角色字段
- ⚠⚠ PI 物品名不要带引号、书名号、括号等标点，直接使用物品名称
- 【消耗品规则】若物品为消耗品（如泡面/快餐/药剂/箭矢/灵石等）且本章已被使用完毕（如「A送给B一桶泡面，B当场吃掉」），不要输出PI（避免脏数据）；仅当消耗品仍剩余、已损坏、被赠与或被长期携带时才输出
- 【财务/数额规则】现金、银行卡余额、工资、灵石数量等「持续累计型」物品，按本章实际增减输出：收入/进账→获得，支出/出账→消耗；数量字段填写本章变动数额（不是总额）。例：PI|陆子期|现金|获得|3000|工资进账
- 【金额结算规则】⚠⚠⚠ 当正文出现【多步骤计算/倍率加成/分步结算】时，数量字段【只取最终落袋数额】，不要把中间过程值与终值相加。识别要点：含「最终/合计/总计/共/共计」的数额是终值；「基础/初始/本金/×N倍/加成后」是过程值，必须忽略。
  - 正例：「赞助30元，返利10倍=300元已发放，加成3倍最终返利900元」→ 只输出 PI|角色|现金|获得|900|赞助返利（最终落袋900，不是1200也不是1230）
  - 正例：「卖了10块灵石，每块50金，本来该500金，老板抹零给了480金」→ 只输出 PI|角色|金币|获得|480|卖灵石所得（取实际到手480）
  - 反例（禁止）：把过程值300+终值900加成1200；把基础30+终值900加成930
- 【同物品归并规则】同一角色对同一物品在本章发生【多次独立变动】（如上午赚300+下午赚500、几次不同场景的购买），同变动类型合并为一行输出，数量取累加值，原因列举主要项；【不同变动类型】才分行（例：本章既有充值又有消费 → 1 行获得 + 1 行消耗）
  - ⚠ 归并 vs 结算边界：「多笔独立流水」才合并累加，「同一笔交易的多步骤计算」应遵「金额结算规则」取终值
  - 正例合并：本章上午工资收入 3000 + 下午兼职收入 1500 → PI|A|现金|获得|4500|工资+兼职收入
  - 正例取终值：赞助30元×10倍=300×3倍加成=900元 → PI|A|现金|获得|900|赞助返利（不要加成1200）
  - 判别关键：能否在结算后只看到一笔「到账」？是 → 取终值；存在多笔独立到账？是 → 合并累加
- 【首次披露规则·动作型】当本章正文【首次清点/翻出/掏出/亮出/穿戴/佩戴】角色之前未在历史中登记的随身长期携带品（如钱包/钥匙/手机/打火机/烟/护身符/常备武器等），即使无「获得」动词也应输出 PI|角色|物品|获得|数量|首次披露持有，让物品进入角色物品表
  - 正例：「江沅翻口袋掉出钱包、半盒烟、打火机、家里钥匙」→ 输出 4 行 PI（变动类型=获得，原因=首次披露持有）
  - 触发条件：① 仅在该物品【首次出现】时触发，同物品后续章节再次出现不要重复输出；② 一次性消耗品（如本章吃掉的泡面/喝完的药）不适用，仍按消耗品规则
  - 边界：单纯背景描写「他穿着夹克」中的服装/已穿在身上的常规衣物不必登记，仅当作为情节焦点被特意展示/清点时才记录
- 【首次披露规则·展示型】⚠⚠ 当本章正文【首次明确给出某角色"原本就持有"的资产/物品当前数额】（如「银行卡里有327.6元」「钱包剩200块」「灵石还有50枚」「兜里只剩三个铜板」「账户余额×××」「家底×××」），即使没有清点/翻出动作，也必须输出 PI|角色|物品|获得|当前数额|首次披露持有底数。该规则与"动作型"互补，覆盖账户余额、库存、押金、存款、随身现金等"叙述型披露"
  - 正例：「江沅瞟了眼银行APP，余额327.6元」→ 输出 PI|江沅|现金|获得|328|首次披露持有底数（小数四舍五入）
  - 正例：「林宇打开储物袋，里面剩下5枚下品灵石」→ 输出 PI|林宇|下品灵石|获得|5|首次披露持有底数
  - 触发条件：仅当该角色在历史中【未登记该物品 或 登记数量为0】时触发；若已有登记，不再重复输出
- 【底数与本章变动分行规则】⚠⚠⚠ 若本章同时存在"首次披露原有底数"+"本章变动"（如开局有327.6元 + 本章新到账20000元），必须输出 2 行独立 PI，绝不合并相加：
  - 正例：① PI|江沅|现金|获得|328|首次披露持有底数 ② PI|江沅|现金|获得|20000|赞助返利
  - 反例（禁止）：PI|江沅|现金|获得|20328|首次披露+本章返利合并（违反入库累加机制，会导致后续章节再次"首次披露"时数据重复）
  - 反例（禁止）：PI|江沅|现金|获得|20000|赞助返利（漏掉底数，导致最终余额=20000而非20328，丢失原有资产）
- 【数量格式】数量字段必须是阿拉伯数字（如1/3/3000），不要写「三千/万元/一批」等中文数字或模糊描述；若为模糊额度，取下限整数；纯数量类物品（钥匙/烟盒）填写明确件数，无法判定填1
- 【变动类型】只允许输出以下 6 个：获得/消耗/失去/损坏/赠与/转移。「奖赏/拾到/抓到/披露/清点出」→获得，「购买/交换」拆为双行 PI（失去货币 + 获得物品），「偷窃/失窃」→失去，「损坏/破损」→损坏，「送人/给予」→赠与
- 【转移对偶规则】物品转移必须输出两行 PI：失去方一行(变动类型=转移，原因注明去向角色) + 获得方一行(变动类型=获得，原因注明来源角色)。例：「A把现金1000给B」应输出 PI|A|现金|转移|1000|转移给B 与 PI|B|现金|获得|1000|来自A
