## 二、6 个「无静态提示词」模块的实现方式

这几个不是长文本，而是运行时把数据拼成 prompt 片段：

| 模块 | 实现方式 |
| --- | --- |
| **注意力锚点** | 代码生成核对清单（JS 拼接），同一份清单在 prompt 头尾各放一次（Sandwich） |
| **前章实际文本** | 从上一章文件读正文尾部，套进正文 system 里的 `${prevChapterEnding}` 槽位 |
| **章节事件流** | 从事件流数据表查询后拼成 bullet 列表 |
| **角色物品** | 从角色持有物品表拼列表 |
| **支线事件流** | 从支线故事表拼列表 |
| **记忆注入** | 从蒸馏出的章节记忆拼回顾段落 |

**这意味着**：这几个模块的价值不在文案，而在**数据结构设计**（该存什么字段、怎么拼）。
详见第二层数据契约。

## 五、和数据基线交叉验证过的部分

有三个模块的内容本仓已实测验证过对错：

| 模块 | 云笔原文 | 实测结论 |
| --- | --- | --- |
| 叙事铁律 · 铁律 9 | 「长句 ≥36 字占 **10–20%**」 | ❌ **错**。139 段真人实测 ≥35 字占 **39.13%**（P25 26.98）。抄的时候必须改。 |
| 协议行输出 | CR/CI/NE/BT 四类结构化行 | ✅ 有价值，可省一次 distill LLM 调用 |
| 文笔技法 · 调色层 | 烘托（侧面笔触）：「写剑快不写剑，写敌人的头发被剑风扬起」 | ✅ 有效，可直接用 |

**抄这些提示词时必须逐条对照 `docs/audits/2026-11-25-zhuque-criteria-correction.md` 的实测数据**，
不能整段照搬——云笔的数值型约束有几处是错的。
