# ADR-009 · Agent 覆盖已有文件默认需要确认

- 状态：Accepted
- 日期：2026-11-04
- 决策人：项目维护者
- 关联：`engine/agent/harness/agent-loop.ts`、`ui/services/agent-port.ts`、`ui/settings/agent-section.ts`

## 背景

Harness 的写工具带 `sideEffect: 'write' | 'dangerous'`，但审批条件只有 `writeApproval === 'ask'` 或 `dangerous`。全仓没有任何地方设置 `writeApproval`，默认值是 `allow`。`ui/services/agent-port.ts` 的 `write_file` 可以覆盖任意非隐藏文本文件，包括正文和设定。

风险有两类：

1. 模型误解指令，整篇覆盖用户正文；
2. 提示注入（例如从网页/资料里读到的内容）诱导 Agent 写文件。

## 选项

| 选项 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A | 全部写入都确认 | 最安全 | 新建文件也弹窗，Agent 自动化体验差 |
| B | 仅“覆盖已存在文件”确认，新建放行 | 安全与效率平衡 | 需要判断目标是否存在；设置开关要清晰 |
| C | 保持默认放行 | 无感 | 数据风险不可接受 |

## 决策

选择 **B**：

1. 设置新增 `agentWriteApproval: 'ask' | 'allow'`，默认 `ask`。
2. Agent 工作台把设置映射为 Harness 的 `writeApproval`；Harness 默认值保持不变（库级兼容），由宿主显式传入。
3. `dangerous` 操作（删除、删项目等）始终确认，不受该开关影响。
4. 新建文件不需要确认；覆盖已有文件需要确认；审批 10 分钟无响应默认拒绝。

**不做**：不把“删除”纳入可放行开关；不允许 Agent 写入 `.obsidian` 配置目录；不隐藏审批弹窗。

## 后果

- 正面：模型错误/提示注入无法静默覆盖已有内容；用户可在设置里显式放行。
- 负面/代价：覆盖场景多一步确认；长批量操作需要用户在场。
- 迁移与兼容：旧配置没有该字段时回落默认 `ask`；已有测试显式传 `allow` 保持原断言。
- 如何验证：Harness 工具管线测试（覆盖已存在文件需确认 / 新建放行 / `allow` 放行 / `dangerous` 始终确认）。

## 替代与后续

- M2 任务中心可为批量写入提供“本次会话允许覆盖”的临时授权，但仍需可见、可撤销。
- 若未来支持多步计划审批，可把逐次确认升级为“计划级确认 + 写入清单”。
