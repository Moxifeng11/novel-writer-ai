# ADR-010 · ModeRuntime：三模式共用上下文与结算，不复制长篇流水线

- 状态：Accepted（M3 实施）
- 日期：2026-11-04
- 决策人：项目维护者
- 关联：[PRODUCT.md](../PRODUCT.md)、[ROADMAP.md](../roadmap/ROADMAP.md)、`shared/creation-mode.ts`、`shared/mode-content.ts`

## 背景

长篇已有完整 11 步流水线、结算、实体图谱、质量闸门；短篇/剧本设计了自己的 10/9 步，但实际只实现 4/5 个阶段：故事核/大纲/分镜是纯 textarea，没有单元质检、结算、知识库/指纹注入。用户看到“六维质检”文案，实际只显示句长等 6 个本地指标。

直接把长篇 11 步套到短篇/剧本会带来两个问题：步骤语义不匹配（章 vs 节/集、卷 vs 分集），以及上下文来源不同（短篇需要故事核/分节大纲，剧本需要场景圣经/分镜表）。

## 选项

| 选项 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A | 复制长篇流水线，改文案 | 快 | 两套事实源，后续维护爆炸 |
| B | 抽 `ModeRuntime`，按模式注入上下文/质量/结算策略 | 单一基础设施，模式差异显式 | 需要重构接口，短期工作量大 |
| C | 维持现状，只补文档 | 成本最低 | 半成品长期存在 |

## 决策

选择 **B**，并明确边界：

- `ModeRuntime` 只提供**共用能力**：项目上下文、章节/单元解析、实体读取、故事核/场景圣经、RAG、指纹、结算适配。
- 模式差异通过配置表达：`CreationModeSpec`（根目录、单位、字数/单元目标）、`QualityProfile`（维度与阈值）、结算适配器（章/节/集）。
- 长篇现有 11 步与结算**不重写**；短篇/剧本按自己的阶段顺序调用同一批引擎。
- 先做最小闭环（M3），用 feature flag 控制；不追求一次补齐所有长篇能力。

**不做**：不为短篇/剧本复制一套 `settlement-engine`；不让模式判断散落在 UI 条件分支里。

## 后果

- 正面：短/剧获得与长篇一致的上下文/质检/结算基础设施；后续加模式只需加配置。
- 负面/代价：需要把现有长篇上下文聚合逻辑抽出接口；短期存在适配层。
- 迁移与兼容：长篇路径保持原行为；短/剧旧项目按现有目录读取。
- 如何验证：短篇/剧本 mock AI 最小旅程 E2E 各 1 条；长篇主旅程无回归；单元质检/结算落盘断言。

## 替代与后续

- 若某模式需要完全不同的创作理论（如互动剧），可在 `QualityProfile` 之外增加独立策略，但仍复用项目/实体/结算基础设施。
