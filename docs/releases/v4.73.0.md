# v4.73.0 — Agent 可执行命令扩容与一致性护栏

发布日期：2026-11-08

## 为什么发这一版

用户拍板：把「Agent 可见不可执行」的调色板命令真正注册进 registry。第 102 轮的一致性测试又发现**统一入口七命令**存在同样的历史缺口。本版一次性补齐，并加上防止复发的护栏测试。**无数据迁移。**

## 主要变化

### 1. Agent 可执行命令扩容（用户拍板）

- 第 90 轮发现：`list_commands` 按 id 前缀枚举、`run_command` 按 `plugin.registry.has(id)` 校验，两侧不一致——`rename-project` / `prune-sessions` / `populate-setting-lib` 可见但执行必失败，`switch-provider` 可执行但漏列。
- 第 90 轮已统一过滤口径（`registry.has`）；本版把三个命令**注册进 InternalRegistry**：
  - `rename-project`：委托 `renameProject()`（打开重命名 Modal，自带确认环）；
  - `prune-sessions`：委托 UI 执行器的会话清理（manual=true）；
  - `populate-setting-lib`：委托 `populateSettingLib()`（世界观 → 设定库，仅长篇）。
- **安全边界**：危险关键词正则补 `prune|populate`——Agent 执行清理会话 / 生成设定库前必须获用户确认；`rename-project` 打开 Modal 自带确认环，不走 dangerous。
- **模式守卫**：`populate-setting-lib` 保持 LONG_ONLY（世界观→设定库仅长篇），Agent 在短篇/剧本项目下会被模式守卫拒绝并给出替代路径。

### 2. 统一入口七命令补注册

- `open-home` / `job-center` / `project-health` / `asset-registry` / `usage-ledger` / `backup-center` / `onboarding` 七命令补进 InternalRegistry（面板可点但 registry 无执行体的历史缺口，`command-ui-executor` 已有分支）。
- 一致性测试的 `KNOWN_PALETTE_REGISTRY_GAPS` 豁免**已删除**，恢复 `toEqual([])` 严格断言——新增面板命令不再可能悄悄漏注册。

### 3. command id 三语义一致性测试（+3 例）

- 调色板 addCommand id ⊆ InternalRegistry 注册集；
- InternalRegistry id ⊆ `CommandIds` 清单（防拼写漂移）；
- `command-mode-rules` key ⊆ `CommandIds`（防规则引用不存在命令）。

### 4. 自动化：advisor 分工红线过滤与采集面鲁棒性

- backlog 判定按路径前缀过滤：`engine/**` 与 `ui/views/**` 的脏路径属 ZCode 分工红线，不计入 Trae 的在途收口（+2 例；缺省回退旧语义）。
- `resolveMetricWithFallback`：`bundleBytes` 读 `main.js` 实文件（statSync）、`anyRemaining` 读 `.any-baseline.json` 的 `total`（不再解析 gateMargins 正则）。
- `isFreshDispatch` 判据改 `>=` + `lastDispatchId` 去重（跨方轮次编号漂移不再漏判同号派工）。
- `GenrePreferenceMemory` 默认数据浅拷贝修复（多实例/reset 不再与 DEFAULT 共享引用互相污染）。

### 5. 版本治理补漏

- v4.72.0 版本节点的 `package.json` bump 遗漏已补（`f54b899`），9 处文档版本戳补全（`9afba2b`）。
