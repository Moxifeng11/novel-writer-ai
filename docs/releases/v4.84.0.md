# v4.84.0 — agent 自愈六动作 + 修复遥测 + 孤儿向量对账

发布日期：2026-11-12 · tag：`4.84.0`（无 `v` 前缀，Obsidian 社区目录规则）· 上一版本 v4.83.1

## 为什么发这一版

v4.83.1 让 agent **能诊断**「我的设定为什么没进正文」；本版让它**能修复**。

核心变化是 `repair_flow` 从 2 个动作扩到 **6 个**，并且修复结果进入**会话遥测**——agent 事后能自证「我修过什么、修成了没有」。同时把 v4.83.1 遗留的两个「假绿」补掉：知识库显示「已加载 1 本」但索引是空的（孤儿向量），以及降级提示只显示最旧的三条。

版本性质：无破坏性变更；`repair_flow` 是写操作，**全部走审批且 fail-closed**。

## 主要变化

### 🔧 agent 自愈：2 动作 → 6 动作

| 动作 | 修什么 |
|---|---|
| `revectorize_book` | 单本知识库重算向量（不重拆解、不调生成模型） |
| `reload_fingerprints` | 按磁盘重载三层指纹（模板/全局/项目） |
| `cleanup_orphan_vectors` | 清理不在知识库索引里的孤儿向量 |
| `fix_zero_intensity` | 修复强度为 0（等于禁用）的指纹 |
| `cleanup_disk_vectors` | 清理磁盘上未加载的孤儿向量文件 |
| `rerun_canon_research` | 重跑官方考据 |

**安全设计**：`sideEffect: 'write'` + 审批 fail-closed 双层——
无 `requestApproval` 一律拒绝（哪怕回合层 `approvalGranted=true` 也不放行）；
有回调但抛错/返回非 true 也拒绝。修复失败一律 `ok:false` 带原因，不静默成功。

### 📊 修复结果进会话遥测

新增 `engine/agent/harness/repair-telemetry.ts`：引擎在回合结束时累积 `telemetry.repairs`，
记录每个修复动作的参数、结果与时间。agent 因此能回答「我修过什么」而不是「我好像修过」。

### 🧹 孤儿向量对账（修「假绿」）

v4.83.1 的运行层验证发现：知识库索引 **0 本**，但向量库 `index.json` 有 **1 本**，
界面「检索」却显示「已加载 1 本」——用户以为有数据。

- 新增 `engine/knowledge-vector-reconcile.ts`：`reconcileVectorBooks` 纯函数，
  分出「孤儿 / 缺失 / 正常」三类，另有 `summarizeVectorReconcile` 摘要
- `store.reconcileWithIndex`：惰性加载后对账，不一致打 warn
- **清理不静默**：`removeOrphanVectors` fail-closed（`confirmed!==true` 一个不删），
  整轮清理放在**单次写锁**内（避免 TOCTOU），`saveIndex` 从 N 次合并为 1 次
- 磁盘孤儿单独可见：`VectorReconcileReport.diskUnloaded`
- UI：知识库链路状态注入「向量库 M 本不在知识库索引」，工具栏新增「🔗 向量对账」按钮，
  默认只报告、确认后才清理

### 🔗 repair_flow UI 接线

新增 `ui/services/flow-repair-host.ts`，把修复动作桥到 `DeconstructionScheduler.revectorizeBook`
与 `StyleFingerprintLibrary`；工作台构造引擎时注入 `flowRepair`，工具可达且有接线测试。

### 🎯 链路状态语义修正

- **降级只取最近 3 条**：原实现 `slice(0, 3)` 取的是**最旧**的三条，与「最近」语义相反，
  还会把新出现的孤儿/降级提示挤掉；改为 `slice(-3)`
- **孤儿在环节级可见**：`KnowledgeFlowInput.orphanCount > 0` 时「检索」环节降为 warn，
  detail 附注「其中 M 本不在知识库索引」

### 🌱 示例项目种子（让三条链路可被真实验证）

新增 `scripts/seed-demo-vault.mjs`：在临时目录造一个最小但真实的 vault
（1 个项目 + 1 本知识库书 + 2 个指纹 + 1 份同人设定），
然后 `verify-three-flows.mjs --vault <dir>` 输出**三条链路全部已验证通过（exit 0）**。

这是「核心命题可验证」第一次在真实数据上跑通——此前只能判「无法验证」。

### 📈 覆盖率

- `ui` 15.22% → **20.43%**
- `ui/views` 12.95% → **28.26%**
- 新增纯逻辑模块 10 个、假 DOM 渲染测试覆盖 `kb-config-panel` / `link-status` 等此前 0% 的构建器

## 升级提示

- 无破坏性变更，可直接升级。
- `repair_flow` 需要宿主提供审批回调才会执行；未提供时一律拒绝（这是刻意的）。
- 若界面出现「向量库 M 本不在知识库索引」，点「🔗 向量对账」查看明细，确认后再清理。
