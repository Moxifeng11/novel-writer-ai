# v4.61.0 — 取消挂起修复与 B3 出版边界补测

发布日期：2026-11-07

## 为什么发这一版

v4.60.0 之后连续四批（第 44–48 轮）聚焦「取消语义」与测试债务：修掉一个会让调用方永久挂起的真实缺陷，并用回归锁定修复在真实调用方生效；同时继续 any 收窄与 B3 边界补测。**无新增功能，无配置/数据迁移。**

## 主要变化

### 1. 取消后任务 Promise 永久挂起（真实缺陷）

- **根因**：`cancelTask` 先把 `task.cancelled` 置 `true`，再调 `rejectTask`；而 `rejectTask` 旧实现带 `if (!task.cancelled)` 守卫，导致取消时的 reject 被吞掉——任务 Promise 永不结算，`engine/deconstruction-scheduler.ts` 的 `await taskPromise` 会永久挂起。
- **修复**：`rejectTask` 改为无条件 `task.reject(error)` 后再 `activeTasks.delete`。`resolveTask` 的 `!cancelled` 守卫保留（取消后不再 resolve 成功值）；取消路径三个分支（队列移除 / `abortController` / worker `postMessage`）都只结算一次。
- **回归**：新增 `tests/unit/services/worker-manager.test.ts` 6 用例（降级成功与进度透传、处理器抛错原样拒绝、未注册处理器按类型拒绝、`cancelAll` 拒绝且不再执行 handler、`destroy` 幂等、Worker 初始化超时）。

### 2. 调用方 abort 路径回归（+2 用例）

- `tests/unit/engine/deconstruction-scheduler-abort.test.ts`：真实 `WorkerManager` + 挂起 handler → `abort()` → 100ms race 断言 `Task cancelled`（若修复被回退会超时失败）；维度完成后 abort 不回调 cancel、不改变已结算结果。

### 3. 类型收窄

- `ui/svg-charts.ts` any 5→0：新增文件内 `TimelineLayoutItem`，删除 4 处回填写回与 1 处首元素读取的 `as any`。纯类型擦除。

### 4. B3 出版边界补测（17→20 用例）

- CRLF 换行 frontmatter 也能剥离；重复标题按 `trim` 归并。
- `draft`：EPUB 缺作者仍只是建议，但空稿（无正文）任何档位都阻断。
- 仅传 `scope: 'written-only'` 也豁免成品档空单元；`submission` 仍必须整包。
