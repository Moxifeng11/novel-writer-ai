# v4.24.0 — 完整开发系统：文档、门禁与注释基线

发布日期：2026-11-02

## 为什么发这一版

仓库不缺代码，也不缺文档，缺的是「单一事实源 + 可执行约束」：同一事实在 4 个文档里有 4 个版本、门禁清单有 6 处手抄、分层模型有 4 种写法；`check:dsh-isolation` 漏掉了真实的 `require('child_process')`；基线文件缺失会自动放行。本版把这些收口成一套可校验的开发系统。

## 主要变化

### 1. 文档体系

- `docs/README.md`：唯一入口 + 真相源责任表 + 新鲜度规则。
- `docs/handbook/`：上手、环境、架构、模块标准、接口契约、测试、门禁与发布、排障、评审、注释规范、文档政策。
- `docs/adr/`：决策索引与模板（链接既有 ADR-001~007）。
- `docs/generated/`：代码索引与门禁表改为生成物，CI 用 `--check` 比对。
- `docs/glossary.md`、`docs/releases/TEMPLATE.md`。

### 2. 门禁与流程

- 新增 `check:docs`、`check:jsdoc`、`gen:docs`。
- `preflight` 现在包含文档/注释门禁、`build` 与 `check:release`；发布前用 `preflight:release`（含覆盖率）。
- 架构基线缺失时失败（`--require-baseline`），CI 默认启用。
- 修复 dsh 隔离漏检，并把桌面系统命令收口到 `shared/desktop-shell.ts`。
- `check:release` 增加 `main.js` 语法检查与发布说明存在性校验。
- CI/Release 工作流使用同一组门禁，并检查生成物漂移。

### 3. 注释基线

- 注释规范落地：文件头四段式、导出声明必须带 JSDoc、事故注释四要素。
- `check:jsdoc` 棘轮：已注释数不得下降、新导出必须注释、不完整 JSDoc 不得增加。
- 当前导出覆盖 46%（基线已入库），后续按 shared → core/domains → services → engine 分批推进。

## 验证

- `preflight`：524 文件 / 5866 用例通过。

## 影响与迁移

- 无用户可见行为变更；`保护元文件` 的内部实现改为窄接口，失败提示不变。
- 新增 `.nvmrc`（20）与 `engines.npm >= 10`。
- 文档不再是「写完就不管」：新增文档必须登记索引，版本戳与编码由门禁校验。
