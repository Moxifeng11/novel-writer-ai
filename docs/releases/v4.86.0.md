# v4.86.0 — 静默失败门禁 + 生产环境测试闭环

发布日期：2026-11-13 · tag：`4.86.0`（无 `v` 前缀，Obsidian 社区目录规则）· 上一版本 v4.85.0

## 为什么发这一版

v4.85.0 修掉了 27 处静默失效，但那是**人工审查逐个抓**的——同类问题还会再长出来。
这一版补的是**机制**：

1. 把「读失败当没有 / 写失败当成功」做成**门禁**，从今往后新增一处就 CI 拒绝
2. 把「真实 Obsidian + 真实 AI」做成**一键冒烟**，拦住「单元测试全绿但生产不可用」
3. 生产环境实测又抓到 **1 个 high 级缺陷**：用户配了密钥，AI 却全线返回「未配置」

版本性质：无破坏性变更；新增两条可执行检查（`check:silent-failures` / `check:prod`）。

## 主要修复

### 🔴 AI 调用全线失败：密钥在 providerKeys 里、apiKey 为空（1 处，high）

生产环境测试当场发现：用户已配置 DeepSeek 官网密钥，界面显示可用，
但**任何 AI 调用都返回「API密钥未配置」**。

根因链条：

```
settings.apiKey 只在 ProviderManager.switchProvider() 时从 providerKeys 同步
  → 插件重载 / 重启 / 只填过供应商管理没点过「切换」时 apiKey 为空
  → UI 守卫 hasUsableAiCredentials 看 providerKeys，通过
  → 但 AI 调用只读 apiKey，判定「未配置」→ 全部失败
```

即 **界面说能用，实际一个请求都发不出去**。

影响三处并全部修复：`callAIInternal`（非流式）、`callAIStream`（**写章/共写主路径**）、
`callAIAsyncIterator`。新增 `shared/ai-credentials.ts#resolveProviderApiKey`，
统一按「显式传入 → apiKey → 当前端点所属供应商的 providerKeys」取值。

> 8130 条单元测试全绿也没抓到，因为 mock 里 `apiKey` 总是有值。
> 这正是「测试替身不忠实」的典型——所以这一版同时补了生产冒烟。

### 🛡️ 新增门禁：静默失败（`check:silent-failures`）

扫 `engine/ services/ shared/ ui/`（821 文件 / 1651 个 catch），识别两类模式：

- **A 读失败当没有**：catch 返回 `null` / `[]` / `{}`
- **B 写失败当成功**：catch 只 log（或空 catch）

且必须处于**写上下文**（邻近行有真实写调用）才算违规——读路径的降级是合法的。

基线：191 处 / 95 文件（只降不升）。量具自检：扫 0 文件 → exit 2；基线文件消失 → exit 2。

### 🔧 项目创建：关键写入失败不再谎报成功（12 处）

`ui/services/project-create-service.ts`：

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| 写 `.project` 失败 | 只记日志，仍提示「✅ 创建完成」 | **中止创建**（没有 `.project` 就不是项目） |
| 覆盖时删除旧目录失败 | 旧内容残留，「新」项目混着旧数据 | **中止创建** |
| 同人设定复制失败 | `.project` 已声称绑定该路径，实际没有 | **中止创建** |
| 模板文件复制失败 | 用户不知道少了几份文件 | 提示里写明「N 个文件复制失败」 |

### 🧪 新增一键生产冒烟（`npm run check:prod`）

用 Obsidian 官方 CLI 在真实实例上验证 6 步：

```bash
npm run check:prod              # 完整：真实调一次非流式 + 一次流式（约几十 token）
npm run check:prod -- --no-ai   # 零 token：只查版本一致性与 dev:errors
```

| 步骤 | 拦什么 |
|---|---|
| 版本一致性 | 运行中插件 ≠ 磁盘版本（发版后忘 reload，测的是旧代码） |
| `dev:errors` | 加载期/运行期崩溃 |
| **真实 AI 非流式** | 密钥配置、端点、请求体、解析全链路 |
| **真实 AI 流式** | 写章/共写是另一套代码 |

**skip 不算通过**（退出码 2），避免「环境没准备好」冒充绿。

### 🐛 其他修复

- **章节摘要**：写盘前独立探测三个台账文件可读性，读失败跳过写盘（不再用空账本覆盖正确摘要）
- **知识归因**：`getFileCache` 为 null 时回退 `readFrontmatterFallback`（刚写入的文件不再被丢弃）
- **批量导入重试**：返回 `{retried, missing}`，全过期时提示「任务记录已过期」
- **流式 usage**：新增 `usageUnavailable` 标记，0 不再冒充正常用量
- **向量库对账**：`reconcileWithIndex()` 参数加默认值（无参调用不再抛压缩错误）
- **门禁精度**：静默失败检测先剥注释/字符串再匹配，消除 121 处假阳性
  （`[CoWriterEngine]` / `BodyWriter` 这类标识符曾被误判为写操作）
