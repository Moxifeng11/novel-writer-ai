# v4.77.0 — 跨窗口监听修复 + 门禁存量清零

发布日期：2026-11-08

## 为什么发这一版

v4.76.0 新增的 `check:obsidian-api` 门禁登记了两类存量：`console-direct` 24 处、`global-document-listener` 9 处，另留了 `engine/**` any 第二批。本轮把三笔一起清掉，并且**在清理过程中发现一处真实泄漏**——不是风格债，是关不掉的监听器。

## 主要变化

### 1. engine any 第二批：analysis-session 系 10→0

| 位置 | 原类型 | 收窄后 |
|---|---|---|
| `AnalysisSession.characterResult` / `SessionCreateOptions.characterResult` | `any` | `CharacterResultSnapshot \| null`（三个候选数组只约束 `name`，兼容历史 JSON 额外字段） |
| `plotResult` | `any` | `unknown`（无生产者/消费者，不凭空造接口） |
| `otherResults` / `SessionAction.details` | `Record<string, any>` | `Record<string, unknown>` |
| `AnalysisSessionManager.private vault` / 构造参数 | `any` | 文件内 `AnalysisSessionVaultPort`（adapter 七方法，按真实用法收窄） |
| `extractCharacterNames(characterResult)` | `any` | `CharacterResultSnapshot \| null \| undefined` |

any 基线 **106/48 → 96/46**；补 2 例覆盖此前空缺的分支（`llmVerified`/`ruleCandidates` 回退、`plotResult`/`otherResults` 导出导入往返）。

### 2. console-direct 24→0

19 处 `console.warn/error` 改 `shared/logger`（11 个文件）。去掉了手写 `[Module]` 前缀——`createLogger` 自带 scope，保留会输出双前缀。`agent-loop` / `harness-engine` 的 `log` 名已被 `AgentSessionLog` 占用，用模块级别名 `logger`。

5 处进白名单，理由写进规则注释：
- `shared/logger.ts` ×4：console 的唯一合法出口（sink 本身）；
- `shared/store/middleware/logger.ts` ×1：`%c` 样式化 setState 调试，5 条单测断言精确参数；换 logger 会丢样式，且默认 `warn` 级别下静默。

### 3. document 级监听 9→0（含 popout 修复与一处真实泄漏）

新增 `shared/dom-window.ts`：

```ts
const dispose = onNodeDoc(this.containerEl, 'pointermove', (ev) => this.drag(ev));
// onClose / destroy：dispose() —— 用同一个 document 解绑
```

`resolveNodeDoc` 优先取 Obsidian 注入的 `Node.doc`（窗口迁移后会跟随），回退标准 `ownerDocument`。逐点：

| 宿主 | 问题 | 修复 |
|---|---|---|
| `create-project-modal` / `story-linkage-modal` | Modal 在活动窗口打开，全局 `document` 收不到 popout 内的外部点击 | `onNodeDoc(this.modalEl, …)`，disposer 在 onClose 释放 |
| `model-picker-popover` | 弹层 root 固定挂主窗口 `document.body`，popout 中会开到另一个窗口 | root / 查询 / 尺寸整套跟随 `anchor.doc`（`doc.defaultView` 取代全局 window） |
| `draggable-panel`（ItemView，用户可拖入 popout） | 拖拽完全失效；视口尺寸按主窗口算 | `onNodeDoc(containerEl, …)` + **`onWindowMigrated` 重绑**（窗口迁移后 onOpen 不重跑）；尺寸改 `containerEl.win` |
| `categorization-review-panel` | **真实泄漏**：外部点击监听只在「点到外部」时自删；`destroy()` 只清 DOM；`CharacterRecognitionModal.onClose()` 从不调用 destroy | 监听存 disposer，destroy 释放；模态 onClose 显式销毁面板；`document.createElement` → `container.doc` |
| `writing-pet` | 主窗口浮窗（设计如此），但全局 document 与宿主同文档 | 一并归位到 `onNodeDoc(this.root, …)`，行为等价 |

`global-document-listener` 基线 **9→0**——今后任何新增的 `document.addEventListener` 都会直接让门禁失败。

## 影响与迁移

- 行为变更：把任意视图拖进新窗口后，浮窗拖拽、下拉外部点击、模型弹层现在都在**该窗口内**正常工作；关闭角色识别模态不再残留监听器。
- 配置/数据迁移：无。
- 回滚建议：revert 监听批次会恢复 popout 失效与泄漏（不建议）。
