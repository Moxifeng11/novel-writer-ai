# v4.83.0 — 治理版本：包体积回血 + UI 可测性 + 安全 r3 收尾

发布日期：2026-11-11

## 为什么发这一版

这是一次**治理优先**的版本，不含新功能。v4.82.0 的审计给出了三条主线，本版把它们全部落地：

1. `main.js` 距 5 MB 自设上限只剩 **0.7% 余量**（35,469 B），下一次功能批次就会顶破；
2. UI 层占源码 37% 但覆盖率仅 **9.7%**，绝大部分视图改动只能靠人工点击发现回归；
3. 安全 r3 还剩 5 项 P3（S3-17~S3-21）悬在 Agent 权限边界上。

审计同时明确了几件**不做**的事：不追 UI 整体覆盖率数字、不按行数继续切片 `co-writing-view.ts`（切片对 bundle 是净增）、不在 0.7% 余量下加功能。本版严格遵守这些边界。

## 主要变化

### 1. 包体积治理

| 动作 | 效果 |
|---|---|
| 内置更新日志 94 个版本 → 最近 12 个 | **−56,196 B** |
| 收款码 39 KB JPEG → 12 KB 自适应调色板 PNG | **−26,780 B** |

`main.js` **4,964,531 → 4,876,932 B（−87,599 B）**，距 5 MB 上限余量 **35,469 → 123,068 B（0.7% → 2.46%）**。

三个细节：

- **更新日志不是简单删**：完整历史仍在仓库 `CHANGELOG.md` 与 GitHub Releases，弹窗 footer 新增「查看完整更新日志 →」外链（纯 `href` + `target="_blank"`，交给宿主处理，不接管点击、不新增网络请求）。并补了 **2 条防回归守卫**（条数 ≤12、总字节 ≤12,000）——发版时必须同步裁掉最旧一条，否则测试失败。
- **收款码做了体积-质量实测**：该图本质只有白/黑/支付宝蓝三色，JPEG 却存了 5,251 色全是噪声。实测 2 色会破坏黑白对比**导致不可扫**，4 色视觉近乎无损，8 色等同原图 → 取 4 色。
- **确认过在加功能前先回血**：这 124 KB 余量是后续开发的空间，不是为了过门禁。

### 2. UI 可测性（把判定逻辑从 DOM 里抽出来）

新增 6 个纯逻辑模块，全部无 DOM、无 `this`、不 import obsidian，因此可以单测：

| 模块 | 职责 | 新增用例 | 自身覆盖率 |
|---|---|---:|---|
| `book-detail-metrics.ts` | 书籍详情页数据准备（归一化/图表组装/筛选排序/查表） | 31 | 98.55% |
| `kb-panels-logic.ts` | 知识库面板状态映射与统计聚合 | 22 | 100% |
| `kb-card-logic.ts` | 卡片判定（配色档位/警示显隐/标签取样/溢出计数） | 24 | — |
| `kb-format.ts` | 七个格式化（字数/日期/时长/两套状态映射/频道） | 27 | 95.65% |
| `kb-book-filter.ts` | 书籍筛选排序与计数 | 24 | 100% |
| `kb-task-panel.ts` | 任务面板筛选/统计/批量操作集合/行内按钮 | 33 | 100% |

其中 `book-detail-metrics.ts` 的来源文件原为 **2,247 行 / 覆盖率 0.1% / 零测试**。

三个值得说明的判断：

- **筛选规则做了差分验证**。`getFilteredBooks` 有 7 维叠加 + 4 种排序，手写用例无法穷举。抽取时把旧实现逐行复刻为 reference，用 **300 组随机数据 × 7 维随机组合**对比新旧输出，逐条相同后才删脚本。手写用例因此只覆盖语义，不穷举组合。
- **锁住了两类"容易改坏"的规则**：批量**取消**只针对进行中/待执行、批量**删除**只针对已终结任务——两个集合不同，测试专门断言无交集（混用会取消已完成任务或试图删除运行中任务）。以及"任务 6 档状态"与"书籍拆解 5 档状态"是两套映射、不可复用。
- **抽取时保留了看似不统一的写法**：`data-action` 只写在两个按钮上、强制取消用内联样式 + `onclick` 而其余用 `addEventListener`——这些逐处保持原样，只搬"决定什么"，不动"怎么渲染"，避免"顺手统一"引入显示回归。

另附 `knowledge-base-view` 结构勘察报告（`docs/audits/knowledge-base-view-structure-survey.md`），记录 5 处抽样风险点（子题材嵌套条件、`formatWordCount` 的 `0` 与 `undefined` 同显未知等），供后续接手者参考。

### 3. 安全 r3 收尾（S3-17 ~ S3-21）

五项同属"提示注入可借合法工具越界"类问题。

| 编号 | 问题 | 修复 |
|---|---|---|
| S3-17 | Agent「移动文件」可跨项目搬运 | 源与目标必须同项目，跨项目拒绝并报出双方归属 |
| S3-18 | 会话大结果溢出目录与端口作用域**分叉** + slug 碰撞 | 统一 resolver；目录名附加 scope 稳定短哈希 |
| S3-19 | 会话恢复接受任意记忆键、事件无上限 | 白名单槽位键 + 2000 条事件上限 |
| S3-20 | 考据抓取把重定向/错误页当正文 | 拒绝非 2xx（**部分修复**，重定向复核需上游支持） |
| S3-21 | 章节文件名 helper 不净化标题 | helper 内净化，纯非法字符给兜底 |

其中两处需要单独说明：

- **S3-18 是真实缺陷而非理论风险**：spill **写入**用工作台的 `resolveActiveProject()`，而**端口白名单**用 `plugin.getActiveProject()`。用户在工作台内切换项目后两者分叉 —— 模型写进 A 的溢出目录、却只被允许读 B 的，**读不回自己落盘的原文**。日常切换项目就会踩，不需要被攻击。
- **S3-19 顺带挖出一个既有 bug**：`context.projects` 用 `String(item)` 转换，`null` 会变成 `"null"` 字符串（truthy）混进项目列表，于是**已删除项目会以 `"null"` 的身份继续"存在"**。
- **S3-20 只做了能做的**：Obsidian 的 `requestUrl` 由 Electron net 实现，**强制跟随重定向且不暴露最终 URL**，renderer 也没有 dns API。所以"逐跳校验私网"与"DNS 解析校验"在插件层做不到。已如实写进代码注释与审计文档，**没有假装修好**。

安全 r3 现状：**21 项中 20 项已修**，仅 S3-5（dsh 凭据机制）与 S3-20（重定向控制）保留上游依赖残余。

### 4. 新增门禁：视图测试下限

第 26 道 preflight 门禁 `check:view-tests`。规则：`ui/` 下超过 **200 行**的文件必须被至少一个测试 `import`。

三个设计决定：

- **口径刻意偏宽松**（只 import 类型也算）。门禁的职责是拦"**完全没人碰过**"的文件，断言级精度交给覆盖率。一道松门禁能长期存在，一道严门禁会被绕过。
- **棘轮只允许清单变短**：首期基线登记 94 个存量未达标文件；新增未达标文件直接失败。
- **实测过棘轮真的能拦住**：临时造一个 260 行空文件会如期报错，删掉后恢复通过。

豁免口径：`.d.ts` / `*-types.ts` / `*.generated.ts`（编译期擦除或生成物）。

### 5. 顺手修掉一处自己埋的问题

前几批我在 `book-detail-metrics.ts` 里加过一个 `resolveChannelLabel`，映射写成 `other → 综合`——而视图里真实用的是 `neutral → 中性`，且该函数**零生产调用方**。本版删除它，把正确映射收进 `kb-format.ts`，并加了一条断言 `formatChannelLabel('other') === 'other'` 防止有人把它"修"回 `综合`。
