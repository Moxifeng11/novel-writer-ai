# v4.64.0 — 短篇/剧本导出误报修复与采集性能

发布日期：2026-11-07

## 为什么发这一版

第 58 轮的性能审计发现两件事：阶段面板采集会重复全库扫描，且短篇/剧本的导出产物检测一直是失效的。本版同时修复这两项——一个用户可感知的缺陷，一个每次打开工作台都会发生的性能浪费。**无配置/数据迁移。**

## 主要变化

### 1. 修复：短篇/剧本导出产物误报「未导出」

- **根因**：`hasExportArtifact` 只查项目根 `05-导出`/`06-导出`，而短篇/剧本的产物实际落在 `短篇创作/05-导出`、`剧本创作/06-导出` 下，磁盘检测恒不命中。
- **影响**：`localStorage` 导出标记丢失（换设备、清缓存、换浏览器）后，已有导出文件的短篇/剧本仍显示「未导出」，阶段进度也随之失真。
- **修复**：`hasExportArtifact(app, project, mode)` 按模式映射目录（目录名复用 `mode-content` 的 `SHORT_DIRS`/`SCRIPT_DIRS`，不复制字面量），并兼容旧版项目根目录；长篇行为不变。
- **回归**：+4 用例（短篇新目录命中、剧本新目录命中、剧本旧根兼容、短篇双目录皆空=未导出）。

### 2. 性能：阶段采集全库遍历 3→2 / 3→1

- `hasExportArtifact` 改用 `listFolderFiles` 局部遍历导出目录（`extensions: []`、`recursive: true`），不再 `vault.getFiles()` 全库扫描。
- `listModeUnits` 的 own/legacy 共用一次 `getFiles()` 快照（own 命中即返回，排序与回退语义不变），旧结构 2→1。
- 单次采集：长篇 3→2、短篇/剧本 1–3→1；`main.js` 净 +112B（行为修复与类型导入开销）。
- `ui/full-writer/creation-flow-state.ts` 纳入 `check:hotpath-scans` 的 `HOT_FILES`（10→11），防止回退。
- **已知边界**：该门禁只查文件内直接调用，不追 `getChaptersForProject` 的间接扫描；彻底收敛需改 helper（已记入 PERFORMANCE §2/§5.2，待立项）。

### 3. 测试

- 新增 `tests/unit/ui/creation-flow-state-scan.test.ts` 11 用例：扫描次数（长篇 2、短篇新结构 1、旧结构 1）+ 导出判定四语义 + 模式目录映射。
