# v4.79.0 — 结算回滚安全加固 + 密钥门禁 + 支持作者收钱码

发布日期：2026-11-09

## 为什么发这一版

v4.78.0 之后连续做了三轮**双视角交叉审计**（生命周期 / 数据一致性 / 安全），本版把其中可安全落地的 P1 全部修掉，并补了两件用户直接要求的事：推送前密钥门禁、支持作者入口。**无数据迁移；除「全角数字章节标题」外无行为变更。**

## 主要变化

### 1. 数据一致性：结算回滚不再误删用户文件（P1）

| 问题 | 修复 |
|---|---|
| `recordWholeFileBefore` 把「存在但读失败」当新建 → 回滚时删除已有文件 | 三态判定：不存在才登记新建；读失败标记 `snapshotIncomplete`（回滚转 `settlementPartial` 可见）；调用方传 `knownBefore` 避免二次读 |
| `DELETE_ENTITY` 不进 journal → 部分失败回滚后文件永久消失 | 删除前锁内记录整文件前值，回滚可重建 |
| 回滚后 `created*` 未清零 → 结算表误报「新建 N 项」 | 回滚分支一并清零 |
| `NEW_*` 创建锁外检查 + 无锁写 → 并发双写、回滚互删 | 存在性判断移入 `withWriteLock` 内重查，只有真正新建才登记 |

测试 +4；审计报告 `docs/audits/auto-cross-audit-2026-11-09-data-consistency.md`。

### 2. 安全：2 项 P1 + 审批摘要 + 密钥门禁

- **知识库源文本路径穿越**：文件名段此前用原始书名（`../../x` 可逃出书目录覆盖任意 `.txt`）→ `kbBookSourceFile()` 单源，目录与文件名都走 `sanitizeName`。
- **Agent 覆盖确认绕过**：`write_file` 用原始路径判断是否新文件，带引号路径会 `exists=false` 自动放行 → `shouldAutoApproveNewFile()` 先净化再判存在。
- **审批摘要**：`run_command` 带 `reason` 时仍显示命令 ID；写/删/移显示真实路径（80 字符截断）。
- **`check:secrets`**（新增，preflight + CI）：只扫 git 跟踪文件；检测 `sk-…` / `oc_sk_…` / 真实 v1/v2 密文载荷 / 长 Bearer，以及禁止入库路径（`data.json` / `data/` / `.sessions/` / `.trae/mailbox/` / `*.bak`）；命中只打印脱敏片段。
- 审计报告 `docs/audits/auto-cross-audit-2026-11-09-security.md`（含 1 项误报纠偏：S-3「密文当凭据」经复核不成立）。

### 3. 密钥明文风险明确标注（S-4，用户拍板 B）

未设置会话口令时，设置页「密钥加密」行明确提示：**密钥以明文保存在 `data.json`，会随 vault 同步/备份扩散；共享/公开库请勿填写真实 Key**。保存行为不变；文案由 `describeKeyEncryptionStatus()` 单源生成。

### 4. 新增：支持作者（支付宝收钱码）

设置 →「ℹ️ 关于」页新增独立支持卡片与放大按钮；点开直接展示支付宝收钱码。图片以 data URI 内嵌（社区市场只分发 `main.js`/`manifest.json`/`styles.css`，独立图片不会随插件安装），原图保留 `assets/support/alipay-qr.jpg`，改图后 `npm run gen:support-qr` 重新生成。原转账账号方式作废；插件不发起支付、不读取支付信息。

### 5. 全角数字章节标题

`第１２章` / `第 １２ 章` / `１２、` / `卷１２` / `Chapter １２` 均可识别；删除 4 条被 `/i` 与字符类覆盖的冗余模式（bundle 功能净减 −3B）。
