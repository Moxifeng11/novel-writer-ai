# v4.23.2 — dsh 边界决策确认

发布日期：2026-11-02

## 为什么发这一版

v4.23.1 把 dsh 在 Windows 上跑通了，但还有两项产品边界没有正式拍板。本版把决策写死到代码与文档，避免后续实现再回到「逐次审批」的假设上。

## 决策

1. **整会话 `workspace-write` 是唯一的写入方式**
   - 默认 `read-only`，dsh 读写工具都会被执行沙箱拒绝。
   - 用户打开「允许 dsh 写入 vault」后，本次会话整段可写；启动前还会弹一次确认，明确「SDK 协议没有逐次审批通道」。
   - 取消确认 = 本次仍按只读运行，不会降级成直接写。

2. **接受 dsh 完整依赖树（含 `bash` / `pwsh`）**
   - dsh 由用户自行安装，插件不自动安装、不自动升级。
   - 安装即接受这些工具随包存在；设置页已写明。

## 变更

- 设置页「🤖 Agent 对话后端」补充依赖树与写入语义说明。
- `integration-dsh.md`：待决策项改为已决策；架构图的「逐次审批 Bridge」改为「启动前一次性确认」；安全条款同步。
- 研究档案 README 与架构笔记删除「写入逐次批准」的过时表述。

无。本版只固化决策与文案；dsh 后端的运行行为与 v4.23.1 一致。
