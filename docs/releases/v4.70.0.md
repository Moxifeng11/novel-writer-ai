# v4.70.0 — 优化方向判断模块与测试加固

发布日期：2026-11-07

## 为什么发这一版

v4.69.0 之后连续十二轮（第 72–87 轮）的双工具协作沉淀了一批基础能力：把协作循环的决策逻辑固化为可执行模块、三处零覆盖模块补上契约测试、六个文件完成 any 清零、handbook 与源码重新对齐。**无运行时行为变更**：`main.js` 4,869,777 逐字节不变。

## 主要变化

### 1. 新增：优化方向判断模块 `automation:advise`

- 把双方协作循环的「候选池 → EV 评分 → 决策阶梯」固化为可执行模块，双方每轮可复用：
  - `shared/optimization-advisor.ts`：纯函数核心（探测/评分/决策），零依赖零 any，不进 bundle；
  - `scripts/optimization-advisor.mjs`：采集 git/台账/门禁/体积/测试/文档/信箱七类事实，渲染决策（tier：dispatch/backlog/gate/score/idle）；
  - 命令：`npm run automation:advise`（默认摘要 / `--json` / `--write` 落盘建议台账 / `--check` 自检）。
- `check:automation` 补建议台账校验：schemaVersion / 带时区 / tier 合法 / 推荐 1–2 条 / round 落后 ≤1。
- 关键约束：派工只认「轮次号 > 当前台账 round」或 6 小时内消息；体积候选只在 >20KB 或 ≥1% 时触发（当前 +0.29% 不误报）。
- **在途收口口径**：backlog 层级只统计「未在台账登记的脏路径」——已登记待收单的路径仅告警，不锁定层级，避免 Trae 不提交时每轮恒为 backlog、评分被旁路。
