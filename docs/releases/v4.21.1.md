# v4.21.1 — 执行登记表、RAG 评估基准与真实 AI 链路实测

发布日期：2026-10-31

## 为什么发这一版

v4.21.0 发出去之后，还剩三件事没闭环：Agent 触发的长流程（成文/结算/导出）跑完读不到结果；RAG 的阈值与预算没有可回归的基准；前面几轮建的机制（注入溯源、伏笔闭环、实体字段、结算回写）**一次真实模型都没跑过**。

这是一版补丁：先把「跑完能读到结果」和「检索可评估」补上，再拿真实项目真跑一章，把实测暴露的 6 个缺陷一并修掉。

## 主要变化

### 1. 执行登记表（Agent 长流程闭环）

`services/execution-ledger.ts`：插件级内存表（上限 20 条），记录命令 / 项目 / 状态 / 耗时 / 失败原因 / 结算回写量。

| 埋点 | 记录内容 |
|---|---|
| 一键成文（写章弹窗结算后） | 章节 + 结算摘要 |
| 章节结算（完整 / 轻量） | 结算摘要；异常记 failed + 原因 |
| 步骤式结算（StepRunner） | 成功摘要 / 无结果 / 抛错；已 settled 的幂等跳过也留痕 |
| 导出成稿、生成看板 | 章数/字数、看板数量 |
| 后台整章失败 | 异常信息（此前被吞） |

Agent 侧新增工具 `get_execution_status`（可按项目过滤、limit 夹到 1–20、逐项渲染结算与伏笔闭环）；`run_command` 改走 `executeCommandAsync()`，派发即抛错不再被吞；引导策略补一条「长流程完成后主动查结果再汇报」。

### 2. RAG 评估基准

`npm run eval:rag -- --input <fixture>`（hit@k / MRR / **近重复占比**），评分逻辑下沉 `shared/rag/eval-score.ts` 并进单测。近重复用**重叠系数**而非 Jaccard——重叠分块的重复是「一段包住另一段」，Jaccard 会因长度差把 0.95 压到 0.7。

### 3. 真实链路实测（第2章一键成文）

用真实项目 `九霄逆脉行` 第2章跑通，产物逐项读盘核对：

| 项 | 结果 |
|---|---|
| 正文 | `第2章_锁痕_正文.md`，2904 字（`word_count: 2894`），标题由模型自拟并回写文件名 |
| 规划 | 信息规划 / 大纲摘要 / 情绪规划（7300 字）/ Scene 展开（16574 字）全部真实内容 |
| 结算 | 更新 13 项、新建 16 项、出场记录 6 条、归属链接化 4 条；伏笔闭环 **通过**（回收 2、埋设 5） |
| 落盘 | `出场记录.md`、`结算表.md`、`叙事总览.md`、`章节状态快照`、伏笔库（+923 字） |
| 实体字段 | `当前位置` 写入 3 个人物、`修为等级` 写入沈砚（此前 8 个人物 0 个有这些字段） |

### 4. 实测修复的 6 个缺陷

1. **正文对话校验误判（每章必中）**：写作规范输出中文弯引号“”，校验器只认 ASCII `"` 与「」，含 18 对对话的 2682 字正文被判「缺少 对话描写」→ 一键成文中断。统一 `DIALOGUE_PATTERN`。
2. **质量控制校验误判**：真实输出是 `## 一、写作技法检查`、`## 【修改建议汇总】`，只认 `## 关键词`；三项必填齐全但缺一个加分项时永远到不了 85 分，且 `missing` 为空（用户看不到原因）。规范化中文序号/包裹符 + 三项齐全即判完成。
3. **模型空返回导致整章中断**：思考型模型偶尔把预算全花在 reasoning、正文为空且 `finish_reason=stop`，旧实现直接判「AI返回为空」。现同模型**关闭思考重试一次**（流式与非流式）。
4. **后台整章异常被吞**：命令层 fire-and-forget，异常不上报，实测「跑满 15 分钟毫无反应」。现 try/catch → 登记表记 failed + 界面提示。
5. **同一章重复结算**：一键成文与后台整章先后跑到同一章，各自无条件 `settle` → 实体重复更新、`status` 来回翻。后台整章加「磁盘已 settled 则跳过」守卫。
6. **按标题重命名后章节反解失败**：正文重命名为 `第2章_锁痕_正文.md` 后，`openChapterByPath` / `parseChapterFromPath` 的正则要求「第N章_正文.md」紧贴 → 「请先打开一个章节」。改为按 `第N章` 前缀反解。

### 5. 真实链路专用用例

新增 `tests/e2e/real-ai.spec.ts`（playwright project `real-ai`）：默认 skip，`E2E_REAL_AI=1` 才打开真实 vault；跑一键成文 → 轮询终态 → 读盘核对 → 输出 `test-results/real-ai-observations.json`；卡在规划步会降级到后台整章，正文已达标则不重复生成。

## 升级说明

无数据迁移。升级后：
- Agent 用 `run_command` 触发的长流程完成后，会自动用 `get_execution_status` 汇报回写量与伏笔闭环，不再让你去界面看。
- 已写过的章节重复触发后台整章时，不会再次结算（幂等）。
- 正文文件被标题重命名后，工作台/协同写作仍能正确识别章节。

## 已知边界

- **RAG 未在真实链路触发**：`九霄逆脉行` 的写作知识库没有拆解参考书（`写作知识库/` 只有索引与标签体系），`embeddingCalls=0`。要验证 RAG 需要先导入并拆解 ≥1 本参考书。
- **自动化入口竞态**：工作台从 `workspace.json` 恢复时，`openChapterByPath` 复用旧 tab 可能尚未回填视图状态，`real-ai.spec.ts` 遇到该情况显式 skip 并留日志（真实用户手点章节不受影响）。
- **信息债看板 ENOENT 噪声**：结算时读取尚不存在的 `04-项目总控/信息债看板.md` 会打一条 console error，不影响结算（文件随后由结算写出）。
- 一键成文的「正文结构校验不通过」仍会中断整章（设计如此），只是不再误判；真实缺项时仍建议重试该步。
