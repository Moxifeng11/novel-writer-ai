# v4.37.0 — 质检解析与伏笔「未揭示」误判修复

发布日期：2026-11-05

## 为什么发这一版

v4.36.0 的 ui 覆盖率爬坡用行为测试锁定了三个疑似 bug，用户确认后本版集中修复。其中伏笔状态误判的影响面比最初报告更大：`status.includes('揭示')` 在 5 个文件里重复出现，导致「未揭示 / 待揭示」的伏笔被当成已揭示跳过——直接影响章节上下文注入、信息债统计、结算统计与批量建章。

## 主要变化

### 1. 质检报告解析

- **⚠️ 变体选择符残留**：`⚠️` 是 `⚠(U+26A0) + U+FE0F` 双码点，旧字符类只剥离前者，问题文本与定位文本开头残留不可见码点。修正为 `[❌⚠✅]\uFE0F?`。
- **第N段/第N字 定位丢失**：定位正则的捕获组 1/2 从未被读取，`第3段` 会回落成问题文本前 20 字。修正后返回 `'3'`，与函数 JSDoc 示例一致。

### 2. 伏笔「未揭示」误判（影响面 5 个文件）

- 新增 `shared/foreshadow-status.ts`：
  - 空状态 → 未揭示（保持旧统计口径）；
  - 先匹配否定词（未揭示/待揭示/未回收/未兑现/埋设/铺垫中）；
  - 再匹配肯定词（已揭示/已回收/已兑现/揭示/回收）；
  - 其余（已废弃/自定义备注）→ `unknown`，由调用方计入 abandoned 或忽略。
- 修复的消费方：
  1. `engine/chapter-context-builder.ts` — 未揭示/待揭示伏笔不再被整行跳过；
  2. `engine/foreshadow-manager.ts` — 信息债统计三分类（未揭示/已揭示/已废弃）与 `getUnrevealedForeshadows`；
  3. `engine/analysis-report-engine.ts` — `moveForeshadowToRevealed` 的行匹配；
  4. `engine/settlement-engine.ts` — 结算时的伏笔统计；
  5. `ui/batch-chapters-modal.ts` — 批量建章前的伏笔统计。

### 3. 回归

- 分类器单测 5 例（否定优先/肯定/空值/unknown/空白容忍）。
- 上下文消费者回归 2 例：未揭示与待揭示都进入相关列表、已揭示跳过；旧实现下必失败。
