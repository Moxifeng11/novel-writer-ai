# v4.96.0 — 链路修复 + 设置重构

发布日期：2026-11-14 · tag：`4.96.0` · 上一版本 v4.95.0

## 这一版解决什么

审计发现「结构化表单数据大量只流向结算/检查侧，生成 prompt 侧靠名称匹配兜底」——
**用户精心填的事实库、人物卡连续性字段，根本没进写作 prompt**。这一版把 8 条断链全部接上，
并让此前静默的降级全部可见。

## 链路修复（审计 §四 8 项）

| 断链 | 修复 |
|---|---|
| 事实库三元组从不进写作 prompt | ✅ `fact_nodes` 经 context-manager → buildStoryContext 注入 |
| 人物卡连续性三字段不进主实体块 | ✅ 已知信息/伤势/持有物品进 `${allChars}` + snapshot injury 错位修正 |
| 台账稳定 ID/关联边不参与生成 | ✅ buildLedgerIndex 传 links/relations |
| story_linkage.promptText 只进旧弹窗 | ✅ 接进一键链路（≤1800 字预算） |
| entity_status dead/hidden 无过滤 | ✅ 实体注入过滤（新旧双链路） |
| body-v4 整段丢九个注入变量 | ✅ 对齐 v2 |
| 知识检索失败静默空注入 | ✅ notifier + 时间线不再吞 chars=0 |
| 跨模型回退不可追溯 | ✅ actualModel 回带 frontmatter + 缓存命中补齐 |

## 降级可见性（阶段3）

- 时间线事件的「涉及人物/地点/类型」随事件进 prompt（`shared/timeline-events-format`）
- 上下文硬截断 → 降级事件（此前 `contextTruncated` 写入后零读者）
- 模板变量 11 处 catch 收敛到 degradation-notifier（同标签去重）
- LLM 增强降级 → `source='llm'` 上报（模块级去重，避免每章弹一次）

## 设置信息架构

18 个平铺 tab → **6 个一级分组 + 二级 tab**：
🔌 连接与模型 / ✍️ 写作与协同 / 📜 规则与一致性 / 📚 知识与拆解 / 🎨 界面与工作台 / 🗂 项目与运维。
关键词配置按用途归位：兜底词表 → 写作规则；统计词表 → 写作指纹库。

## E2E 常态化

- `OBSIDIAN_PATH` 默认按平台路径探测（不再每次手工传），`.env.example` 记录变量
- 3 个关键路径 spec：一键生成冒烟 / 事实库视图 / 一致性审核弹窗
- **注入链路验证 spec**：真实项目 + mock AI 抓 prompt，断言事实库/人物卡字段真的进了 prompt
