# v4.23.3 — 写作规则版本误报修复

发布日期：2026-11-02

## 问题

启动时反复弹出：

> ⚠️ 写作规则版本异常：版本号相同但内容不同：元文件/00-系统模板/写作规则.md（期望 hash f628cb8f，实际 08bde250）

但该文件的 frontmatter 明明写着 `version: "3.6.0-引导代禁止"`，内容也是用户主动维护的变体。

## 根因

版本号解析器 `extractVersion` 在**全文**里取第一个 semver。文件顶部的 `tags` 行是：

```yaml
tags: [写作规则, 文风, v3.6.0]
version: "3.6.0-引导代禁止"
```

`v3.6.0` 排在权威的 `version:` 之前，于是解析结果是 `3.6.0`。注册表按 `3.6.0` 找到内置版本做哈希对照，内容自然不同，被判为「同版本号被旧版覆盖」。

## 修复

1. **frontmatter 优先**：先读 `version:` 字段，只有文件没有 frontmatter 声明时才回退到「正文第一个 semver」。
2. **启动提示只看主干**：新增 `compareVersionBase(a, b)`，忽略 `-suffix`；只有 `3.5.x < 3.6.0` 这类真正落后的情况才提示同步。`3.6.0-引导代禁止`、`3.7.0-anchor` 不再告警。
3. **删除重复解析器**：`RulesService` 里未使用且更宽松的 `extractVersion` 副本移除，版本解析只保留 `shared/versioned-registry` 一处。

## 验证

- 对真实文件复现：修复前解析 `3.6.0`、哈希 `08bde250`；修复后解析 `3.6.0-引导代禁止`，注册表找不到同版本内置项，漂移告警为空。
- 新增 3 条单测；`preflight` 全绿：**524 文件 / 5862 用例**。

## 影响

- 已有自定义规则变体（带 `-后缀`）的用户：不再误报，规则文件继续生效。
- 真正使用旧版规则（如 3.5.x）的用户：仍会看到同步提示，行为不变。
