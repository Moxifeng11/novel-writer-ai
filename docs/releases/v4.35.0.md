# v4.35.0 — 体积门禁进 CI、Notice 统一与会话修剪入口（P2 尾巴批）

发布日期：2026-11-05

## 为什么发这一版

P2 清单还剩四个尾巴：体积门禁只在本地 preflight、Notice 文案格式各写各的、知识库视图仍 3,627 行、会话修剪是无声的自动行为（用户无法控制/感知）。本版由四个实现子代理并行收口。

## 主要变化

### 1. check:bundle 进 CI

- ci.yml verify job 在「构建」后插入「校验构建产物体积预算」，远程门禁与本地 preflight 对齐；跨平台矩阵与 E2E job 不跑（Windows/macOS 产物体积可能有平台差异，基线需分别维护）。

### 2. Notice 统一

- `ui/components/notice-helpers.ts`：`showErrorNotice / showSuccessNotice / showWarningNotice`——加粗标题行 + 消息 + 灰色 detail（DocumentFragment 渲染；单测环境 document 垫片不足时自动降级纯文本，保证提示一定可见、绝不抛错）。
- 6 个关键文件（导出 / 批量生成 / 模式文档 / 单元写作 / 结算 / 批量建章）铺开 29 处：失败/成功/告警三类格式统一；14 处守卫类提示与复合预检文案按「不改交互」原则保留原样。
- eslint 净减 1 条（一条 sentence-case 随文案离开 Notice sink 消失）。

### 3. 知识库视图切片（第四批）

- 3,627 → 3,368（-259）：
  - `renderStatsTab` → `kb-stats-panel.ts`（3 成员宿主，纯 DOM）；
  - `renderDetailActionButtons` → `kb-detail-actions.ts`（10 成员宿主，含强制取消确认流；13 个 this 引用收敛为 10——4 项重复成员合并为 `refreshDetailIfSelected`）；
  - `renderConfigTab`（183 行）因含两个可写状态字段、破坏「纯构建 + 只读宿主」范式而按纪律放弃，留待后续。

### 4. 会话修剪用户入口

- 设置「📈 性能监控」新增「启动时清理旧会话」开关（默认开）：关闭后启动完全不发起列举/删除。
- 新增命令「🧹 清理旧会话」：手动触发不受开关限制、必有 Notice 汇总（各目标删除数，全 0 时提示无需清理）；活跃项目 Agent 存档豁免在自动/手动两条路径都保留。
- `pruneSessions` targets 支持 `enabled`（缺省 true 向后兼容）；命令注册走 RENAME_PROJECT 直连模式，不触碰命令集合一致性测试的钉死快照。
