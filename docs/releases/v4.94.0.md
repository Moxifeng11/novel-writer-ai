# v4.94.0 — 从「猜关键词」到「读结构化字段」

发布日期：2026-11-13 · tag：`4.94.0` · 上一版本 v4.93.0

## 这一版解决什么

关键词审查发现：引擎里 158 个词表，其中 A 类「用词表判断文本含义」是最难根治的一类——
换个说法就漏报（「陨落」没在词表里），词表膨胀又带来误报。

这一版把三个 A 类模块从「词表猜」改成「读结构化字段」，词表退化为兜底。

## 改动一：人物状态快照结构化

```ts
interface CharacterStateBrief {
    lifeState?: 'alive' | 'dead' | 'unknown';
    injuryLevel?: 'none' | 'light' | 'severe' | 'critical' | 'unknown';
}
```

**关键：生产方真的填值**（否则就是死代码）。

`gate-snapshot.parseCharacterStates` 从人物块解析：

| 文本 | 结果 |
|---|---|
| 死亡/身亡/陨落/丧命/气绝 | `dead` |
| 存活/活着/健在 | `alive` |
| 濒死/垂危/奄奄一息 | `critical` |
| 重伤/断臂/吐血/昏迷 | `severe` |
| 轻伤/擦伤 | `light` |
| 解析不出 | `unknown`（回退词表） |

## 改动二：检测器结构化优先

`conflict-detector` 判定顺序：

```
① 结构化覆盖（lifeState='dead' / injuryLevel∈{severe,critical}）→ 不报
② 有铺垫迹象（emotion/injury 非空）→ 不报
③ 能力变化 → 事实库等级序（adviseAbility）
④ 都不满足 → 词表兜底报出
```

`logic-consistency-checker`：

```ts
analyzeLogicConsistency(body, { injuryLevels: { 宁缺: 'severe' } })
```

**词表没提「重伤」也能报**——只要快照说这人重伤、本段又做高强度动作。

## 改动三：语义关键词可配置化

设置界面新增「🧩 语义关键词（追加）」：

| 字段 | 用途 |
|---|---|
| 伤情词 | 「气若游丝」「断魂」 |
| 行动词 | 高强度动作 |
| 现代词 | 时代错位 |
| 地点词 | 场景锚点 |
| 剧变词 | 死亡/重伤/能力变化 |

逗号分隔、保存即生效、与内置词去重合并。**用户不必改代码**。

## 设计约束（写入模块注释）

```
判定顺序必须是：结构化字段 → 词表兜底 → 不判定
词表不是主判据
```

## 测试

本轮新增 13 条：
- 结构化优先 4 条（dead 抑制 / severe 抑制 / unknown 仍兜底 / alive 仍报）
- 逻辑检查器 4 条（结构化重伤不靠词表也报 / 结构化未受伤仍按词表 / 无信息按词表 / 追加词生效）
- 词表解析 5 条（无追加等于内置 / 追加生效 / 剧变词进每组 / 去重 / 空追加不变）

## 门禁

preflight EXIT=0（30 步）；check:prod 6/6；覆盖率无下降。

## 升级说明

无破坏性变更。快照无结构化字段时（旧项目/未解析出）自动回退词表，行为与 v4.93.0 一致。
设置里的追加词默认为空，不影响既有判定。
