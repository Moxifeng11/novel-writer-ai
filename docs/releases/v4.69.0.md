# v4.69.0 — 剧本分镜表强制必填与 E2E 37/37

发布日期：2026-11-07

## 为什么发这一版

用户拍板两项：**剧本 storyboard 改为强制必填**，以及**E2E 全量重跑**。本版落地这两项——一次有意为之的行为变更，和一次暴露并修复真实测试欠账的全量回归。

## 主要变化

### 1. 剧本分镜表强制必填（行为变更）

- 旧语义：`storyboard` 与前期调研/分集大纲一样，只要项目已有正文（`written > 0`）就算「已按既有正文跳过」。存量剧本缺分镜表也显示完成。
- 新语义：`storyboard` **只以分镜表文档是否就绪为准**。新增 `CreationFlowStage.hardDependsOn`，剧本 `units` 声明 `hardDependsOn: ['storyboard']`：
  - 未完成分镜表时，**分集写作显示 blocked**（即使已有剧集正文），原因「先完成：分镜表」；
  - 阶段面板、Agent `get_project_status` 的阶段明细都会反映该阻塞（`!分集写作`）；
  - 前期调研与分集大纲仍按存量正文跳过（不把老项目拉回调研）。
- 影响范围：只影响**剧本**模式；长篇/短篇的存量跳过规则不变。
- 测试：`creation-flow`（17）、`agent-mode-alignment`（12）、`agent-stage-panel`（20）三处旧断言同步改为强制断言；新增 `hardDependsOn` 字段注释与阻塞优先级的回归覆盖。
- bundle：+180B（硬阻塞分支），已按 §7.4e 显式 note 上调基线。

### 2. E2E 全量重跑：37/37 通过

五个 project（full-journey / button-states / view-lifecycle / lifecycle / obsidian-electron）全部通过，37.4s。首轮暴露 2 个失败，均为 v4.59.0 B3 改造的测试欠账（非本版改动引起），已修复：

1. `exportTxtViaUi` 假设导出弹窗只有 2 个 `select`；B3 后为 4 个（项目/格式/交付检查/导出范围）。改为**按「格式」下拉的选项内容定位**，不再依赖数量或下标。
2. 短篇 EPUB 用例没填作者，被成品档「EPUB/DOCX 需要作者元数据」**正确阻断**。改为按真实用户路径填作者，而不是把交付档降到草稿绕过检查。
