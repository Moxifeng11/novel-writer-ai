# v4.89.0 — 知识库事实层：让正则功能有「第二意见」

发布日期：2026-11-13 · tag：`4.89.0`（无 `v` 前缀，Obsidian 社区目录规则）· 上一版本 v4.88.0

## 为什么发这一版

v4.88.0 把一致性审核做到 19/19 子类全覆盖，并用真实原著（《将夜》）验证，
暴露出一个根本问题：

> **纯正则 + 纯规则层拿不到原著里的深层矛盾**——不是规则写得少，
> 而是**没有结构化中间层**。正则只能抽到「十八岁」「持续三日」这种带固定句式的表层信息。

于是这一版做了一件更底层的事：**用 LLM 把正文拆成结构化事实，落盘成可人工修正的事实库**，
再让所有原本只靠正则的功能来查它。

实测（《将夜》30 章真实调用）：

| 指标 | 值 |
|---|---|
| 拆解成功率 | **30/30 = 100%** |
| 条目 | 456 条（15.2 条/章） |
| 校验拒绝 | 5 条（1.1%，多为编造引文，被引文校验拦住） |
| 成本 | ¥0.295 / 30 章 → 200 章约 **¥2** |

## 新增：知识库事实层

每条事实是**可读、可改、可追溯**的：

```
第1章 [world-rule]   渭城·军事规模=军官士卒全部加在一起也不超过三百人（有效 1→今）
        「渭城不大，军官士卒全部加在一起也不超过三百人」
第1章 [relationship] 马士襄·职务=渭城最高军事长官（有效 1→今）
第1章 [age]          宁缺·年龄=约摸十五六岁（有效 1→今）
```

落盘位置：`<项目>/04-项目总控/一致性审核/事实库.json`。
**你可以直接打开改错，重跑审核即生效。**

### `validFrom / validTo` 有效区间

这是「合法变化不被误判」的结构性解法：

```
修为：练气三层  validFrom=1  validTo=50
      筑基一层  validFrom=50 validTo=null
      → 区间不重叠 → 不冲突 ✅
```

## 新增：第二意见（P2）

原本只靠正则判断的三类功能，改为「**正则找候选 → 查事实库定结论**」：

| 功能 | 接入结果 |
|---|---|
| **时间线** | `adviseTimeline` 已接 `ConflictDetector` + `quality-gate` 生产链路 |
| **实体状态** | `advise(claim)` 查某主体某章的有效状态 |
| **伏笔** | `adviseForeshadow` 查台账判「未兑现」但事实库已有兑现痕迹的情况 |

**三条硬规则**：

1. **未知不误判**：查不到事实返回 `unknown`（不干预），绝不因为"没数据"判冲突；
2. **冲突必带证据**：返回权威值 + 原文引文 + 章节，用户能自己核对；
3. **降级彻底**：事实库缺失/损坏 → 回到正则原行为，**功能绝不因此报错**。

## 新增：判定层（P1）

低置信矛盾的二次筛查：

```
confidence ≥ 0.85 → 直接保留（规则已可靠，不花钱）
confidence <  0.85 → ① 归一化剔除同义表述（零成本）
                    → ② 残余交 LLM 判真伪（分批 12，成本封顶）
                    → ③ 判定失败 → 保留规则结果（不丢矛盾）
```

实测效果：165 个「同主体同谓词」候选 → 归一化压掉 12.7% → LLM 判定后**误报归零**，
而原著里三处**合法变化**（修为进阶/转投门派/新增疤痕）全程未被误报。

## 架构：单一事实源

```
正文/摘要 → 拆解（LLM）→ 事实库（可人工修正）
                            ↓
                  StoryContextGraph 节点（与人物/物品/时间线同住一张图）
                            ↓
        写作上下文装配 ｜ 一致性审核 ｜ 正则功能第二意见
```

**权威序（红线）**：正文 > 事实库 > 章节摘要。

不存在「事实库 vs 摘要谁优先」的歧义——摘要只是拆解的输入，不是事实来源。

## 修复

| 缺陷 | 影响 |
|---|---|
| 无章节摘要的项目得到 **0 产出** | 正文枚举依赖摘要 → 连视角检测都跑不了；现按正文目录枚举 |

每个 `exec(id)` 必须有 `r.register`；走 UI 端口批量注册的还必须执行器有 `case` 分支。
当前 75 个命令全覆盖。
