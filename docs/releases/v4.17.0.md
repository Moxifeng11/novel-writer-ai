# v4.17.0 — 11 步不变，把调用与点击降下来

发布日期：2026-10-26

## 为什么发这一版

v4.16.0 解决了“生成质量靠什么约束”，但整章仍要用户点 9–19 次、发 8 次 AI；协同写作在本地 Ollama 上还会把同一批上下文串行发 3 次。问题不是“步骤太多”，而是：

- 5 个规划步骤重复注入同一批上下文；
- 部分步骤产出没有下游消费者（情节蒸馏、质量控制）；
- 分析报告已经产出指令，`AnalysisReportEngine` 又用 2 次 AI 重新抽取；
- 没有“一次跑完剩余步骤、但每步仍可见”的入口；
- 协同建议/改写/幽灵在本地单槽上串行排队。

v4.17.0 不改 11 步结构，只改调用组织与信息流。

## 主要变化

### 1. 单章一键编排
- 新增 `ui/full-writer/chapter-orchestrator.ts`。
- 标题栏新增“🚀 一键完成本章（剩余 N 步）”，保留“🐢 逐步完成”和原有手动按钮。
- 运行条支持暂停 / 继续 / 取消；取消会 abort 当前请求；失败停在失败步骤，可从该步续跑。
- 每步前后仍 `setCurrentStepIndex + renderInContainer`，步骤、结果文件、单独重生成全部保留。
- 规划 5 步缺任意一步即停止，不再“infoPlan 完成就跳正文”。
- 结算只在正文未结算且分析报告含 `UPDATE_/NEW_/RELATION:/GROWTH:/EMOTION:/PROMISE_/ARC:` 时执行；`status: settled` 时需显式“重新结算”。

### 2. 推荐模式：整章 4 次 AI 调用
- 5 个规划步骤全部未完成时，走 `executePlanningCombined`：1 次调用产出 5 份步骤结果，并逐模块写 `StepRunMeta`。
- 合并规划新增 `signal` / `force`，失败时只对缺失模块回退单步，不整章重跑。
- 之后正文、质量控制、分析报告各 1 次；结算 0 次。典型整章 **8 → 4** 次调用。
- 逐步模式仍为 8 次调用，仍然 1 次点击启动。

### 3. 信息利用率补齐
- `plotDistill` → V1 正文、sceneExpand 新增 `${distilledContent}`；缺失时显式标记。
- `qualityControl` → 分析报告新增 `${qualityIssues}`，只提取 `❌/⚠️` 行，不自动触发定向修订。
- `analysisReport` → 新增 `AnalysisReportEngine.analyzeFromReport()`：已有步骤 9 报告时 0 次 AI 解析；只有缺报告才走 AI。
- `characterSoul` → V2 主角详情支持用保存的步骤结果回填，不再只读 context 旧值。
- `infoPlan` → 大纲 user prompt 新增 `${infoPlan}`。
- `emotionPlan` / `sceneExpand` 补传任务 `maxTokens` 与 abort signal；`SceneGenerationLoop` 改用 body 任务模型。

### 4. 协同写作批量化（重点本地模型）
- 本地模式一次 `suggestNext` 返回 3 个方向候选（1 次调用）；解析失败/候选不足自动回退原 3 次串行。
- `rewriteSelection` 同样批量 1 次；回退路径保留。
- 幽灵联想只取 1 个最强 hint，触发门槛改为句末/段末，间隔 8 秒。
- 输入 / 插入 / 保存共用一个“增长 300 字或冷却 5 分钟”的守卫闸门；手动检查不受限。
- 本地调用新增进程级信号量：建议、幽灵、守卫、验证串行排队，不再互相抢 Ollama 单槽。
- 本地模型首次调用前探测 `num_ctx`；批量 JSON 使用更高 maxTokens，避免 600 截断。
- UI 质量修复改走协同模型路由，禁止回退到全局 default 云端模型。
- 编辑验证 / OOC 支持 abort，取消后不返回半成品候选。

### 5. 验证与可视化
- 新增 `tests/unit/ui/chapter-orchestrator.test.ts`（8 用例）。
- 新增 `tests/unit/engine/co-writer-batched-candidates.test.ts`（5 用例：候选批量、改写批量、两次回退、本地串行）。
- 新增 `tests/unit/engine/analysis-report-from-report.test.ts`（2 用例：已有报告 0 调用、缺报告仍走 AI）。
- 新增 `scripts/eval-cowrite-local.mjs` 与 `npm run eval:cowrite-local`：
  - 无 Ollama / 无生成模型时退出 0；
  - 有模型时跑 3 候选 + 3 改写，输出耗时与 JSON 合法率。
- 新增 `docs/analysis/v4.17-pipeline-efficiency.html`：11 步信息流、调用/点击账单、协同调用审计、验证与边界；支持推荐/逐步模式切换。

## 使用建议

1. 章节规划未完成时点“🚀 一键完成本章”，默认推荐模式；想逐步看结果就切“🐢 逐步完成”。
2. 若合并规划输出结构不完整，会在缺失模块上自动回退单步；仍失败则停在规划，不会带着残缺规划写正文。
3. 协同写作本地模式默认批量候选；模型输出不稳定时可在设置关闭“本地候选批量化”，回到逐方向路径。
4. 运行 `npm run eval:cowrite-local` 可快速确认本地模型能否稳定输出 3 候选/3 改写 JSON。

## 已知边界

- 批量候选依赖模型输出合法 JSON；失败会回退 3 次串行，此时耗时回到旧水平，但候选数量不受影响。
- 质量控制与分析报告仍是两个独立 AI 步骤，不合并 prompt，避免超大 prompt 挤掉正文与问题清单。
- 设定守卫与编辑验证仍未合并：OOC 与实体状态检查目标不同，合并会降低可解释性；本轮只做节流、路由与 abort。
- 推荐模式质量仍取决于合并规划 prompt；若实测不达标，应切逐步模式，而不是继续压缩调用。
- 本版改动仍在本地工作树，尚未提交/推送远端。
