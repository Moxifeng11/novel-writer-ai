# v4.16.0 — 从“能写完”到“可打磨”：场景卡、样章、状态快照与定向修订

发布日期：2026-10-26

## 为什么发这一版

v4.15.0 解决了参数路由与截断状态机，但正文仍缺三样东西：生成期的工艺硬约束、真实 prose 样章、可逐条核对的长篇状态。v4.16.0 按“提示词工艺 → 数据表格 → 反馈闭环”补上这三层。

## 主要变化

### 1. 场景卡与工艺约束
- sceneExpand 每个场景新增：POV、时间、地点、入场状态、转折、离场状态、工艺备注。
- 场景编辑器、逐场景正文任务卡、组合规划、模板管理器、校验器同步。
- 正文 V1/V2、场景展开、逐场景正文的 system prompt 加入：
  - 具体性配额（每场景至少 2 个五感细节）；
  - 情绪行为化（禁止直接命名情绪）；
  - 对话纪律（禁止副词标签、每段对话必须有功能）；
  - 场景必须有可指认的转折，`entry_state != exit_state`；
  - POV 纪律、段落收束、节奏变化；
  - 生成期负面清单（来自现有 AI 味词库，限长）。

### 2. 真实样章 few-shot
- 新增 `StyleSampleService`：启用指纹 → 强度过滤 → 样章向量检索 → 3 条样章；无 embedding 时回退原始样章。
- 指纹新增/复制/融合/重建自动写入样章向量。
- 11 步正文通过 systemTail 注入样章，预算裁剪不会先丢样章。
- V2 补回 `sceneStyleSnippet/suggestedRhythm`。
- 知识库导入指纹只接受真实原文样章；拆解报告段落不再冒充 prose。
- 新增 `写作对照库.md`：按场景类型注入最多一对“弱写法/强写法/差异”。

### 3. 世界状态快照
- 每章结算后生成 `04-项目总控/章节状态快照/第N章_状态快照.md`：
  - 章节结束时间/视角/地点；
  - 人物状态/情绪/位置/目标/已知信息/伤势物品；
  - 关系数值；
  - 未兑现承诺、未回收伏笔。
- 工作台、批量、协同结算均写入；轻量结算写最小快照。
- 下一章 V1/V2 system prompt 注入“上一章结束状态（硬约束）”。
- 修复 `SettlementService` 传空分析报告导致结算零更新的问题。

### 4. 定向修订
- 质量报告 `❌/⚠️` 行 → 结构化 `RevisionIssue`（维度/严重度/位置/证据/建议）。
- 按严重度选择最多 3 个维度 pass：对话 / 节奏 / 描写 / 钩子 / 连续性 / 文风。
- 每个 pass 只改命中段落或场景，不整章重写；返回空、说明文本、长度异常、评分下降都会回滚。
- 正文步骤新增“🎯 定向修订”按钮；旧“自动迭代精修”的占位符泄漏已修复。

### 5. 承诺账本与角色弧线
- `02-时间线与伏笔/承诺账本.md`：角色承诺/读者问题/悬念/约定/威胁；支持 OPEN/ADVANCE/RESOLVE/DROP；信息规划注入未兑现/逾期项。
- `01-世界架构/角色弧线.md`：want/need/lie/阶段/本章推进；首次从角色 frontmatter 建骨架；分析报告用 ARC 指令更新；信息规划/质量控制注入。
- 分析报告提示词新增 PROMISE_* 与 ARC 指令；结算写账本/弧线表。

### 6. 基准样章评估
- `npm run eval:quality`：读取 `benchmarks/quality/samples.json`，对 good/bad 样章跑 WQE，输出维度分离度并断言最小均分差。
- 无 fixture 时自动跳过，不阻塞日常 `npm test`。
- 不新增第二套评分标准；WQE/QSE 仍是唯一评分内核。

## 使用建议

1. 先跑一章“规划 → Scene 展开 → 正文”，观察场景卡是否完整；旧场景缺新字段只会告警，不阻断。
2. 在 `00-系统模板/写作对照库.md` 填 1-2 对真实弱/强写法，正文会按场景类型自动选一对。
3. 结算后检查 `04-项目总控/章节状态快照/`；下一章开头应与快照一致。
4. 质量控制后点“🎯 定向修订”，先看改动维度与结果；不满意可撤销（正文走 BodyWriter/编辑器撤销栈）。
5. 要评估提示词改动，放 3-5 条 good/3-5 条 bad 到 `benchmarks/quality/samples.json`，跑 `npm run eval:quality`。

## 已知边界

- 场景卡新字段对旧项目是告警而非强制重生成；需要完全生效时重新生成 Scene 展开。
- 知识库导入指纹若没有真实原文样章，`samples` 为空，只保留特征文本；可在指纹库中重新提取或手工补充。
- 定向修订最多 3 个 pass，不追求一次改完所有问题；复杂章节建议分多次执行。
- 基准样例由用户提供，评分器只能做回归参考，不能替代人工 rubric。
