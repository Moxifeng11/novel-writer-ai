# v4.23.0 — 专项收口、dsh 可选后端与数据一致性加固

发布日期：2026-11-02

## 为什么发这一版

v4.22.0 解决了「人味怎么调、排查从哪下手」，但系统里还留着三类债：同一条数据多份实现各自为政（实体目录、结算表、文本拆分）、写入路径绕过 vault 索引（改名/偏好/正文补字段）、以及一批查不出来的静默失败。这一版把 60 个提交按「数据一致性边界」收口，并把 dsh 作为可选 Agent 后端接入。

## 主要变化

### 1. 数据一致性：同一事实只有一个入口

- **实体访问**：`entity-reader` / `entityDir` 统一实体目录解析，世界观缓存、落盘、上下文、结算引擎与 UI 扫描点全部切换，目录前缀残留清零。
- **结算产物**：结算表收敛为唯一生成器，表 / 快照 / 总览在结算后统一编排，不再由一键成文与步骤式各写一份。
- **文本处理**：`splitParagraphs` / `splitSentences` / `isChineseChar` 的 10 份副本合并，差异行为由测试锁定。

### 2. 写入正确性

- **回滚可追溯**：结算引入 `SettlementJournal` 三类条目（整文件 / 字段 / 追加）逆序回滚；正文 `status` 也进快照，部分失败不再让章节永久停在 `settled`。
- **写锁覆盖读-改-写**：时间线三处写入加锁；本轮把结算 `snapshotField` 的读取也移进同一把 `withWriteLock`，避免快照与写入之间被并发改写。
- **契约缓存自愈**：写作规则由用户直接编辑、没有保存回调，格式契约缓存改为按规则文件 `mtime+size` 指纹校验，改完即生效。
- **正文不变量不再静默丢**：`BodyWriter` 写后取不到 `TFile` 时重试，仍失败则显式告警。
- **改名不绕过索引**：项目改名的 `.project` / 世界观 / 写作配置改写改走 `writeVaultText`，`metadataCache` 不再保留旧值。

### 3. 新功能

- 内置主题画廊（7 套 × 浅/深三层配色）。
- 日/周/月字数统计、状态栏今日字数、桌面宠物浮窗。
- 版本历史 UI、首启引导、启动性能与状态面板。
- RAG 来源可见化：`rag_sources` 记录书/维度/分数/片段，步骤面板与统计页可查。
- 短篇/剧本放开通用工具与模式提示，项目迁移一键撤销。
- 静默失败清零：关键入口补提示，并新增门禁防回退。

### 4. Agent Harness 与 dsh

- Harness 回合内上下文预算、窗口化压缩阈值、事件日志纪律与工具管线加固。
- dsh 作为可选后端：stdio JSON-RPC、健康检查、启动前一次性写入确认、可 kill；`check:dsh-isolation` 门禁 + 9 条单测。

### 5. 门禁

- `preflight` 补齐 `lint` 与 `build`。
- 新增结算引擎真实行为测试、知识库标签/详情状态机、Agent 工具权限边界、embedding 请求契约、联动链锚点等回归。
- `check:release --tag` 校验 package / manifest / `versions.json` / tag 四方一致。

## 验证
