# v4.76.0 — 插件数据目录单源 + Obsidian API 门禁

发布日期：2026-11-08

## 为什么发这一版

一次按 Obsidian 官方审查口径的代码审查发现：仓库的现有门禁（any / bundle / CSS / 分层）覆盖得很好，但**没有一条管 Obsidian API 用法**。于是三类缺陷在门禁里是隐形的——其中最关键的一条会在特定用户环境里**静默丢状态**：

`shared/paths.ts` 把插件数据目录写死成 `.obsidian/plugins/novel-writer-ai/data`，而 Obsidian 允许用户改 `vault.configDir`（如 `.config/obsidian`），BRAT 安装的插件文件夹名也可能是 `obsidian-novel-writer-ai`。偏好记忆、文笔风格学习、指纹库、版本历史、`cache.json` 全部按这个常量落盘——这些用户的功能会写到不存在或错误的目录，表现为“设置好了下次打开就没了”。

同仓其实已有两份正确实现（`plugin-worker-url.ts` 用 `configDir`、`usage-ledger` 注释明写“不能硬编码”），属于「同一事实多份实现」的典型。

## 主要变化

### 1. 插件数据目录单源（行为修复）

- 新增 `setPluginRootDir()`：`onload` 用 `${vault.configDir}/${manifest.dir}` 注入一次；`pluginDataDir()` / `pluginDataFile()` / 偏好 / 风格模式 / 指纹库 / versions 全部派生。测试与纯函数环境保留兜底常量。
- 惰性求值：`humanness-scorer` 的基线路径、`human-sample-loader` 的样文目录从模块级常量改为函数——模块顶层求值会读到注入前的兜底值。
- 同时收口 10 处同类硬编码：
  | 位置 | 处理 |
  |---|---|
  | `services/usage-ledger.ts` | 账本路径 → `pluginDataFile('usage-ledger.json')` |
  | `services/backup-center-service.ts` | 配置备份路径 → `pluginDataFile('data.json.bak')` |
  | `ui/services/humanness-scorer.ts` | 人味基线 → 惰性 `pluginDataFile(...)` |
  | `ui/services/human-sample-loader.ts` | 样文目录 → `humanSampleDir()` |
  | `ui/settings/agent-section.ts` | dsh home → `pluginDataFile('dsh')` |
  | `main.ts` / `engine-registry` / `step-runner` / `agent-workbench-view` | 四份 `manifest.dir ?? 手拼路径` → `pluginRootDirPath()` |

### 2. 续写检测结果的注入面与显示缺陷

- `continue-chapters-modal` 构造了完整 Markdown（`## 续写检测结果`、`**第N章**`）却赋给 `innerHTML`：`targetVol`（大纲卷名，AI 可控）与章节文件名是注入面，`##`/`**` 又会原样显示。改为 `MarkdownRenderer.render` 渲染（Modal 不是 Component，宿主用插件实例）。

### 3. 弃用 API 与移动端 CORS

- `co-writing-view`：`MarkdownRenderer.renderMarkdown`（1.4 起弃用）→ `MarkdownRenderer.render(app, md, el, path, component)`。异步代次保护语义不变。
- `update-checker`：两处 `fetch` → `requestUrl`。移动端没有 CORS 豁免，GitHub API 会被直接拦——这条在桌面端看不出问题，属“只在移动端坏”的缺陷。流式 SSE 路径（`ai-api-stream`）必须保留 `fetch`，白名单放行。

### 4. 新增 `check:obsidian-api` 门禁（棘轮）

把上面这些**过得了全部现有门禁**的缺陷类做成静态门禁：

| 规则 | 说明 | 首版 |
|---|---|---|
| `plugin-path-hardcoded` | 禁止字面量 `.obsidian/plugins/novel-writer-ai`，只许经 `shared/paths` 派生 | **0** |
| `deprecated-api` | `renderMarkdown` / `getAllFolders`（1.5+）/ `setCssProps`（1.7+）/ `app.isMobile` | **0** |
| `direct-fetch` | 非流式 HTTP 必须 `requestUrl`；流式 SSE 白名单 | **0** |
| `global-document-listener` | document 级监听需成对移除（popout 窗口下应用 `ownerDocument`） | 9（存量登记） |
| `console-direct` | 运行时不得直接 `console.*`，统一 `shared/logger` | 24（存量登记） |

- 语义是**棘轮**：违规数只允许下降；换一个文件继续违规也会失败（对比“新增文件”而不只是总数）。
- 合法例外走白名单：`shared/paths.ts`（兜底常量）、`shared/changelog-data.ts`（历史文案）、`engine/ai-api-stream.ts` 等流式路径。
- 已接入 `preflight` 与 CI；`tests/unit/architecture/obsidian-api-policy.test.ts` 用临时夹具跑真实脚本，**6 条“故意违规必须报错”**（含棘轮用例：基线 1 处 → 再加 1 处必须失败）。
- 清理办法写在 `handbook/06` §2：改用单源 / `requestUrl` / logger / 成对移除；确需新增才 `--update-baseline` 并写 `note`。

## 影响与迁移

- 行为变更：自定义 `configDir` 或 BRAT 改名安装的用户，数据目录**从此指向真实插件目录**；旧目录里已有的偏好/指纹不会自动迁移（如需迁移可做一次性搬迁，本版不做）。
- 配置/数据迁移：无自动迁移。
- 回滚建议：revert 会恢复硬编码路径（不建议）。
