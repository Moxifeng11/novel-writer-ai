# v4.45.0 — V2 十二维特征并入蒸馏链

发布日期：2026-11-06

## 为什么发这一版

v4.44.0 的设计说明确认 `StyleDeconstructorV2` 是零调用方死端点；用户决策为**方案 A′：不直接删，能力并入 `style-distill-service`**。本版执行该决策：十二维统计能力在蒸馏链中落地，旧端点随迁退役。

## 主要变化

### 1. V2 分析器迁入蒸馏链（能力保留 + 落地）

- `style-deconstructor-v2.ts` → **`engine/style/style-features-v2.ts`**（`StyleFeaturesAnalyzerV2`）：53 个既有用例全部迁移并保持通过。
- **消费方落地**：`analyzeStyleFromSource` 样本模式（paste/project/file）在调用 AI 之后本地计算十二维特征：
  - 返回值新增 `featuresV2?: StyleAnalysisResultV2`；
  - 报告尾部追加「**## 十、十二维特征统计（本地词表计算）**」小节（新增 `formatFeaturesV2Section()` 渲染器，逐维输出 description，pending 维度带标记）；
  - 统计失败不阻断蒸馏主流程（只少该小节，log.warn 记录）。
- 书名模式（无样本）不计算、不追加。

### 2. 旧端点退役（随迁，非裸删）

- 删除 heavy-task 的 `'style:analyze:v2'` 任务注册、fallback 与 `analyzeStyleV2()` 方法及字段——全仓原本就无生产调用方；
- `StyleDeconstructorV2` 类名随文件退役；`StyleAnalysisResultV2` 类型由新模块继续导出；
- 运行时 `grep StyleDeconstructorV2|style:analyze:v2` 0 命中。

### 3. 测试

- 既有 53 个 V2 用例迁移至 `tests/unit/engine/style/style-features-v2.test.ts`，全部通过；
- 新增 `tests/unit/engine/style/style-distill-service.test.ts` 5 条：样本模式（featuresV2 + 小节顺序）、书名模式（不计算）、空白样本守卫、提示词两模式区分。
