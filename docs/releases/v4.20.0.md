# v4.20.0 — 三模式创作流程、单元工作台与多格式成稿导出

发布日期：2026-10-27

## 为什么发这一版

v4.19.0 把长篇、短篇、剧本三套创作体系建起来了，但流程还停在「提示」层：短篇/剧本创建成功只弹一个右上角 Notice，之后要自己找项目、自己找文档；「继续写作」打开的是裸 Markdown，没有 AI、没有状态回写，进度永远是 0。同时，成稿只能导出 Markdown / TXT / HTML，电子书与 Word 投稿都要另找工具。

本版把三模式从「能创建」推进到「能走完」：工作台里有一条可停留、可点击、会随磁盘变化自动刷新的创作流程；短篇/剧本有了单元写作工作台；导出补齐 EPUB 3 与 DOCX。另有一轮跨板块审计，修复了流程判定、模式越界与若干数据一致性问题。

## 主要变化

### 1. 创作流程页签

- `FullWriterView` 新增 `flow` 页签：顶部总进度与「下一步」主卡，下面是阶段列表（状态、进度条、唯一主按钮）。
- 三套阶段：
  - 长篇：初始化与全书规划 → 章节写作 → 章节结算 → 成稿导出
  - 短篇：前期调研 → 分节大纲 → 分节写作 → 导出成稿
  - 剧本：前期调研 → 分集大纲 → 分镜表 → 分集写作 → 导出成稿
- 状态由 `shared/creation-flow.ts` 的纯函数从磁盘事实推导（章节列表、单元列表、`.project`、前期调研 JSON、文档是否真正填写），不做独立缓存。
- 已有正文的老项目会把前置设定阶段标为「已按既有正文跳过」，不会被拉回第一步。
- 项目页右侧新增流程摘要（总进度、阶段圆点、下一步、查看完整流程）；Ribbon 与命令「🧭 创作流程」直接进入。
- 创建短篇/剧本后自动打开该项目的创作流程页；导航失败只降级提示，不会把「项目已创建」误报为失败。

### 2. 短篇/剧本单元写作工作台

- 新增 `TabType: 'unit'` 与 `UnitWriterController`：左单元列表、中编辑器 + AI 工具条、右大纲/故事核（场景圣经）/上一单元结尾。
- AI 能力：生成本节、续写、改写选区（改写前记录区间原文，正文改动后拒绝应用）。
- 保存：800ms 自动保存 + Ctrl+S；切换单元/关闭视图前强制落盘，避免旧定时器写错文件。
- 状态回写：保存更新 `word_count`，「完成本节」写 `status: written` 并跳下一单元；流程页、项目页、Agent 进度立即一致。
- 质量检查：本地 `prose-metrics`（风险分、平均句长、短句/对话占比、单段句数、句首重复），不额外创建质量引擎实例。
- `chapterNumber` 支持章/节/集/回/幕，`summarizeChapterProgress` 支持 `unitLabel`，短篇/剧本的「最新已写 / 建议下一节」不再恒为空。

### 3. 成稿导出：五种格式

| 格式 | 适用场景 | 说明 |
|---|---|---|
| Markdown | 二次编辑 | 保留标题层级 |
| TXT | 平台投稿 | 可选 UTF-8 BOM，兼容旧版记事本 |
| HTML | 打印 PDF | 浏览器打开后「打印 → 另存为 PDF」 |
| EPUB 3 | 阅读器/微信读书 | 完整 OCF 结构，含导航与 NCX 兼容层 |
| DOCX | 编辑/出版社 | 标题层级、首行缩进、1.5 倍行距、每章分页 |

- EPUB/DOCX 由 `engine/export/{zip-writer,epub-builder,docx-builder}.ts` 本地生成，零运行时依赖。
- EPUB 的 `mimetype` 严格首个、不压缩、无 extra field；中文文件名使用 UTF-8 标志。
- 新增 `exportBinaryFile`：桌面下载，移动端写入 vault 的「导出文件/」。
- 修复导出项目错位：外部入口传入的项目不在项目列表时，不再被替换成列表第一个。

### 4. 模式守卫与 Agent 对齐

- `shared/project-mode.ts` + `shared/command-mode-rules.ts`：命令 → 允许模式；命令面板用 `checkCallback` 隐藏，执行前再拦一次并给替代入口。
- 短篇/剧本专属命令、`ModeDocumentModal` 都会校验项目真实模式，杜绝跨模式写目录。
- Agent：新增 `open_flow`；`open_wizard` 非长篇拒绝；`open_chapter` 接受节/集；`run_command` 按模式表复核；`get_project_status` 输出章/节/集；对话 chips 按模式分叉。
- `open_co_writing` 拒绝非长篇项目。

### 5. 跨板块审计与 dsh 吸收

- 写作指纹库：持久化、作用域、向量清理。
- 知识库：索引重建、批量导入、监控与详情渲染。
- 协同写作：丢稿、并发保存、跨章状态、监控面板。
- 完整写作工作台：修正稿写错章、重复结算、向导串项目。
- Agent 工作台：项目名越界、任意命令、回合失控、协议解析。
- 吸收 dsh harness：工具结果裁剪、超时预算、按副作用的重复提醒、回合内补充（steering）、压力压缩、危险命令用户确认。

### 6. 设置与写作体验

- 三层配色（基底 / 卡片 / 强调）与 CSS 全量重构，配色方案可保存与导入导出。
- API 设置两栏化、API 格式下拉、从 URL 自动发现模型。
- 协同编辑器字体选项与自定义字体管理。
- 人味写作提示词 v2、自然段重排、人味体检。

### 7. 流程口径修复

- 结算阶段原来按「已结算 / 已写」计算，写完第 1 章顺手结算就 1/1 判「结算完成」。
- 现在按「已结算 / 全书规划章数」计算，只有全部章节结算完才完成；进度文案标出「已写 N」。
- 流程摘要圆点加描边，避免主题背景与卡片同色时未完成阶段不可见。

## 验证

- 真实 Obsidian E2E **20 条通过**：新增短篇「创建 → 流程 → 单元写作 → 状态回写 → EPUB 导出读盘校验」完整链路。

## 升级说明

- 旧项目无需迁移：模式由路径前缀与 `.project` 自动识别，缺失字段按长篇兼容。
- 导出的 EPUB 可直接导入 Apple Books、Calibre、微信读书；Kindle 用「发送到 Kindle」自动转换。
- 导出格式、作者、TXT BOM 选项会按当前选择动态显隐；短篇/剧本不显示「卷标题」。

## 已知边界

- MOBI/AZW3 需要 Kindle 官方工具链，插件内不生成；PDF 仍走 HTML 打印。
- 单元质量检查是本地语感级，六维模型评分仍走「质量仪表盘」。
- 长篇创建后仍以初始化向导为落点（向导就是第一阶段载体），流程页在其后台可用。
- 导出阶段采用「导出过一次即完成」口径；后续新增章节不会自动把该阶段退回进行中。
