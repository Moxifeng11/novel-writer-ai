# v4.72.0 — Agent 可执行命令扩容与类型收窄

发布日期：2026-11-08

## 为什么发这一版

用户拍板：把三个此前「Agent 可见不可执行」的调色板命令注册进 registry，让 Agent 能真正执行「重命名项目 / 清理会话 / 生成设定库」。同时完成 `engine/**` any 第一批与 advisor 的分工红线过滤。**无数据迁移。**

## 主要变化

### 1. Agent 可执行命令扩容（用户拍板）

- 第 90 轮发现：`list_commands` 按 id 前缀枚举、`run_command` 按 `plugin.registry.has(id)` 校验，两侧不一致——`rename-project` / `prune-sessions` / `populate-setting-lib` 可见但执行必失败，`switch-provider` 可执行但漏列。
- 第 90 轮已统一过滤口径（`registry.has`）；本版把三个命令**注册进 InternalRegistry**：
  - `rename-project`：委托 `renameProject()`（打开重命名 Modal，自带确认环）；
  - `prune-sessions`：委托 UI 执行器的会话清理（manual=true）；
  - `populate-setting-lib`：委托 `populateSettingLib()`（世界观 → 设定库，仅长篇）。
- **安全边界**：危险关键词正则补 `prune|populate`——Agent 执行清理会话 / 生成设定库前必须获用户确认；`rename-project` 打开 Modal 自带确认环，不走 dangerous。
- **模式守卫**：`populate-setting-lib` 保持 LONG_ONLY（世界观→设定库仅长篇），Agent 在短篇/剧本项目下会被模式守卫拒绝并给出替代路径。

### 2. engine any 第一批

- `engine/repository/domain/serializers/frontmatter-serializer.ts` any 4→0：`parseYaml` 返回 `Record<string, unknown>`（`Frontmatter.from` 签名天然兼容）、`serializeField` / `serializeObject` 参数改 `unknown`，递归调用处补断言。
- any 基线 148→144（81 文件）；`engine/**` 剩余约 99 处继续分批。

### 3. 自动化：advisor 按分工红线过滤

- `automation:advise` 的 backlog 判定按路径前缀过滤：`engine/**` 与 `ui/views/**` 的脏路径属 ZCode 分工红线，不计入 Trae 的在途收口，不再产生误导性 backlog 推荐（+2 例；缺省回退旧语义）。

### 4. 文档

- `handbook/04` §2.8 同步三命令注册与危险关键词；`handbook/13` §7.2 补派工新鲜度跨方编号漂移的已知边界（第 92 轮）；`PLAN` 第 92/93/97 轮台账。
