## 为什么发这一版

上一版留下的两个"待决策/待补完"由用户拍板执行：settleLight 事务语义由 ZCode 给出决策并落地；指纹编辑 UI 补上 12 维能力。协同视图切片第七批由 Trae 完成。

## 主要变化

### 1. settleLight 语义决策落地（决策 3）

- **决策**：维持「出场确认 best-effort + 写入幂等」，**不做整次事务**——每次写入都是幂等覆盖（`entity_status`/`entity_last_seen_at`/正文状态），失败重跑无副作用；引入 SettlementJournal 只省一次重跑，却把回滚复杂度带进高频轻量路径。
- **补缺口**：原先各写入点仅 `log.warn`，调用方不知道哪些失败。现在：
  - `SettlementResult` 新增 `lightFailures: { entities: string[]; foreshadow: boolean; bodyFrontmatter: boolean }` + `lightPartial: boolean`；
  - 章节结算弹窗对部分失败弹告警（列失败对象，"轻结算幂等，可直接重跑修复"）；
  - 单元结算（短篇/剧本）frontmatter 写 `settlement_partial: true`，结算报告追加失败行与重跑指引。
- 决策记录：`docs/design/g1-authority-decisions.md` §2.2 决策 3。
- 新增 `tests/unit/engine/settle-light-failures.test.ts` 3 条：单实体失败记名且不影响他者 / 重跑即修复且幂等 / 无失败不携带字段。

### 2. 指纹编辑 UI 12 维（V2 可视化闭环）

- 编辑弹窗对 `version:'v2'` 指纹显示 12 个逐维描述 textarea（pending 维度带"样本不足"说明）；V1 指纹仍只编辑元信息。
- 新增 `StyleFingerprintLibrary.updateV2FingerprintFeatures(id, scope, features)`：一次保存同步四方——V2 全量特征、V1 7 维投影、`v1Backup`、V2 逐维向量（embedding 降级不影响保存）。
- 初版缺陷被自家重载断言抓住：漏同步 `v1Backup` 导致"改完重载又变回旧值"，已修并有测试锁定。
- 新增 2 条测试（三方一致 + 重载不降级；id 不存在返回 null）。
