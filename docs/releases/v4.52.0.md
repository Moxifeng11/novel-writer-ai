# v4.52.0 — 覆盖率攻坚与热路径收口

发布日期：2026-11-06

## 为什么发这一版

Trae 的自适应循环在阻塞期（ZCode 离线约 14 轮）内持续产出：以「覆盖率实测选点」补测了四个高价值模块，同时发现并修复了两处 UI 热路径的全库扫描。本版把这批积压按「测试 → 源码/门禁 → 文档 → 台账」四批入库并发版。

## 主要变化

### 1. 覆盖率攻坚（+100 用例，584 文件 / 6,375 用例）

| 文件 | 用例 | 关键覆盖 |
|---|---|---|
| `body-writer.test.ts` | 25 → 31 | **备份链全链 6 例**（默认参数断言、false 跳过、仅 frontmatter 跳过、缺 project 跳过、saveVersion 抛错仍落盘、5 分钟节流）；parseChapterNum/dirOf/defaultBodyPath 9 例 |
| `obsidian-fs-adapter-fallback.test.ts` | 7 → 21 | 索引内外 stat、递归删除 vs rmdir、mkdir「已存在」吞掉、listFolders 递归、writeVaultText 最小 adapter 回退 |
| `template-validator.test.ts` | 19 → 38 | YAML 块标量 `>` `|`、未闭合尾部回退、同人时间线、实体缺键/空值/缺分节 |
| `template-vars-story-context.test.ts` | 12 → 43 | buildTemplateVars 信号段（灵魂层/上下文体检/自定义模板覆盖）、compact 实体口径、实体备用键 |

- **重要纠偏**：第 12 轮曾判定「备份链无注入点、不可测」。第 27 轮实测推翻——`ChapterVersionService` 是普通 ESM 类，`vi.spyOn(ChapterVersionService.prototype, 'saveVersion')` 对所有 `new` 实例生效，无需给 `BodyWriter` 加注入点、无需改 engine。

### 2. 热路径收口（perf）

- `batch-pipeline-runner#loadStepResults`（每章断点续跑一次）与 `realtime-quality-controller#loadPreviousChapterContext`（每次质量刷新一次）的 `vault.getFiles()` 改为 `listFolderFiles` 目录遍历。
- 10,080 文件实测：全库 **0.523ms/次** → 目录 **0.004ms/次**。
- 等价性审计：两处下游只认 `.md`；`listFolderFiles` 默认只返回 `.md`；深度/上限（5000 文件）不可达。

### 3. 门禁与仓库

- `check:hotpaths` HOT_FILES 8→10，并覆盖 `getMarkdownFiles` / `getAllLoadedFiles`——原门禁只匹配字面 `getFiles(`，换 API 即可静默绕过。
- `.gitignore` 纳入 `tmp/`：覆盖率中间产物不再污染 `git status`（此前每次门禁都留 `?? tmp/`）。
