# v4.65.0 — worker 协议 any 清零与协议边界测试

发布日期：2026-11-07

## 为什么发这一版

第 63 轮把 worker 跨线程协议的 `any` 全部清零，第 64 轮随即用 9 条测试把消息结构锁住——类型收紧后最容易出的问题是「编译过了、消息形状变了」。**无运行时行为变更**：`main.js` 逐字节不变。

## 主要变化

### 1. worker 协议 any 11→0（198→187）

- `worker-protocol.ts`：`WorkerMessage.payload`、`WorkerTaskDefinition.input`、`TaskCompletePayload.result` 改 `unknown`；`FallbackHandler` 改为注册侧泛型 `FallbackHandler<I = WorkerTaskInput, R = unknown>`，新增 `WorkerTaskInput` 通用入参形状。
- `worker-runtime.ts`：`TaskHandler` 入参按 `never` 建模（注册表逆变技巧，任意具体处理器可登记）、返回 `Promise<unknown>`；`postMessageToMain`/`sendComplete` 参数改 `unknown`；两处 `(self as any)` 改为本地 `WorkerScope` 窄接口 + 惰性 `getWorkerScope()`，避免主线程/Node 导入期触发 `self`。
- `worker-manager.ts`：`Map<string, FallbackHandler<never>>` 与 `handler(input as never)` 两行连带，`engine/**` 零改动。
- **为什么不用直改 `unknown` 入参**：`strictFunctionTypes` 下，`engine/deconstruction-worker-manager.ts` 等隐式 `input.text` 会被推断为 `never` 而报错；engine 是红线，故用注册侧泛型 + 协议默认形状让下游零改动。

### 2. Worker 侧协议边界测试（+9 用例）

- 新增 `tests/unit/services/worker-runtime.test.ts`：
  - `startWorkerRuntime` 安装 `onmessage` 并上报 `worker:ready`；
  - 未注册任务类型回传 `task:error` 且不产生完成消息；
  - 成功任务依次回传进度与完成结果，并向处理器暴露 `signal`；
  - 非 `Error` 拒绝归一为 `String` 文本；`AbortError` 保持静默；
  - `task:cancel` 中止在跑任务 signal 且不额外回传消息；
  - 重复注册同一类型后注册者生效；`createInlineWorkerCode` 与 `createWorkerFromHandlers` 的源码/Blob Worker 构造。

### 3. 文档

- `USER-GUIDE` 补「导出落点」（桌面走浏览器下载 / 移动端写 Vault 根 `导出文件/`）、文件名规则与封面格式（png/jpg/jpeg/webp）。
- `COMMERCIAL-GUIDE` 补成品档「TXT/MD/HTML 未填作者仅提示，EPUB/DOCX 阻断」。
