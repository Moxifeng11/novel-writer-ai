# v4.23.1 — dsh 真实环境验证与 Windows 启动修复

发布日期：2026-11-02

## 为什么发这一版

v4.23.0 把 dsh 作为可选 Agent 后端发了出去，但只在单测里验证过「参数拼得对不对」，没有在真实环境跑过。本次用发布版 `@deepseek-ai/dsh@0.2.1-rc.5` 在 Windows 11 / Node 24 上实测，发现 **dsh 后端在 Windows 上根本起不来**，同时确认了协议、密钥与沙箱的实际行为。

## 修复

1. **Windows shim 启动失败**
   - `spawn('npx', ...)` → `ENOENT`（`npx` 是 `.cmd`，不是 PE 可执行文件）。
   - `spawn('npx.cmd', ...)` → Node 18.20+/20.12+ 抛 `EINVAL`（`.cmd` 必须经 shell）。
   - 现在统一由 `ComSpec` 执行；`.exe` 保持直连；含空格的 patch 路径自动加引号。健康检查与正式启动共用同一套解析。

2. **子进程环境不全**
   体检时只传 `PATH`/`HOME` 不够：`cmd.exe` 需要 `SystemRoot`，`npx` 需要 `APPDATA`/`USERPROFILE` 才能找到缓存。现在补齐 Windows 平台必需变量（不含凭据），且空串不会覆盖已补齐的 `PATH`。

3. **空闲等待更确定**
   rc.5 新增 `session/wait`：只有根会话空闲且受管子任务推进完成才返回。插件改为与 `session.status` 竞速，旧版本无此方法时静默回落。

4. **健康检查超时**
   首次 `npx` 下载常超过 20 秒，设置页「检测 dsh 是否可用」改为 120 秒。

## 实测结论

| 项 | 结果 |
|---|---|
| provider / model | `deepseek-official` + `deepseek-flash` 被接受 |
| 密钥 | `DEEPSEEK_API_KEY` 环境变量有效；不落配置文件 |
| `--patch` sandbox | 生效：只读拒绝写入、`workspace-write` 放行 |
| 逐次审批 | 不存在（协议层无审批通道） |
| 工具集 | Windows 暴露 `pwsh`/`glob`/`read`/`write` |

## 验证

- `preflight` 全绿：**524 文件 / 5859 用例**（新增 6 条 dsh 单测）。
- `check:release --tag v4.23.1` 通过。
