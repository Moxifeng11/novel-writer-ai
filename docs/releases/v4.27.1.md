# v4.27.1 — 可信门禁、Agent 写入确认与密钥迁移

发布日期：2026-11-04

## 为什么发这一版

v4.27.0 的架构审计发现三类“看起来有、实际没有”的问题：

1. ESLint 门禁空转，长期显示“0 警告”但关键规则从未生效；
2. Agent 写工具默认放行，模型或提示注入可以整篇覆盖用户正文；
3. dsh 用 `npx -y` 拉最新包，且口令锁定时把密文当 Key 注入。

同时，短篇/剧本的字数统计扫错了顶层目录，v1 旧密文没有升级路径，设置迁移没有备份。这一版先把这些高风险项止血，并让门禁重新可信。

## 主要变化

### 1. 门禁可信化

- `eslint.config.mjs` 改用 `ruleConfigs.recommended` 并显式注册 `typescript-eslint`；`no-unused-vars`、`no-explicit-any` 等规则真实生效。
- 存量 1,894 条违规先按 `warn` 收敛，`lint` 设 `--max-warnings 1900` 上限；0 error。
- 修复 `no-problematic-settings-headings`（设置页标题不再包含插件名）。
- 移除 iOS 不安全的 lookbehind 正则（角色拆解句子切分）。

### 2. Agent 写入确认

- 新增设置 `agentWriteApproval`（默认 `ask`），设置页提供「Agent 写入确认」下拉。
- Agent 工作台显式传给 Harness：覆盖已有文件需确认，新建文件放行；`dangerous` 操作始终确认。
- Harness 库级默认保持 `allow`，避免破坏既有调用方；安全策略由宿主决定。

### 3. dsh 供应链与密钥

- 默认固定 `@deepseek-ai/dsh@0.2.1-rc.5`，不再 `npx` 拉 latest；新增设置 `dshVersion` 可显式升级。
- 工作台启动 dsh 前用 `decryptKey` 解密 `settings.apiKey`；解密失败给出可见提示，不把密文传进子进程。
- 设置页新增「dsh 固定版本」说明：固定版本、不自动升级。

### 4. 数据可靠性

- 新增 v1 密文自动升级 v2：有会话口令时启动迁移自动重加密并计数；无口令时保持旧密文，绝不降级明文。
- 设置迁移/回写前写 `data.json.bak`（仅插件目录内）；迁移失败仍保留原文件。
- `BODY_CONTENT_ROOTS` 改为从 `MODE_LIBRARY_ROOTS` 派生，修正短篇/剧本统计扫错顶层目录的问题；`isChapterBodyPath` 支持 `03-正文/第N节` 与 `03-剧本/第N集`。
- `frontmatter-schema` 路径兜底同步修正，短/剧正文能被正确识别。

### 5. 写入入口门禁

- 新增 `check:write-entry`：运行时代码中的 `adapter.write/append` 只允许在 `shared/file-system-port.ts` 网关，或索引外文件（JSON/YAML/`.project`/`.bak` 等），其余必须显式 `// write-entry-allow: 原因`。
- 拆解报告、协同审核记录、备份元文件、示例项目、项目创建模板复制全部改为 `writeVaultText`，进入 vault 索引。
- 章节版本回滚正文、知识库标签体系、预研报告在拿到 App 时走索引写入；测试/无 App 分支保留 adapter。

### 6. 文档

- 新增 `docs/audits/v4.27.0-architecture-and-roadmap.md`（完整审计与问题清单）。
- 新增 `docs/PRODUCT.md`、`docs/roadmap/ROADMAP.md`。
- 新增 ADR-008~012：可信门禁、Agent 写审批、ModeRuntime、AssetRegistry、JobService。
- 补齐 v4.25.0 / v4.26.0 / v4.26.1 发布说明。

## 影响与迁移

- 破坏性变更：Agent 覆盖已有文件默认需要确认；可在设置中改为 `allow`。
- 配置/数据迁移：旧配置无需操作；v1 密文在有会话口令时自动升级；迁移前生成 `data.json.bak`。
- 回滚建议：回滚到 v4.27.0 后，`data.json` 仍可读；如已升级 v2 密文，回滚后需重新输入口令。
