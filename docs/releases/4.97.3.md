# v4.97.3 — 构建可复现：内联 worker 的 gzip 头与压缩实现

> 标签 `4.97.3` · 2026-11-20 · 上一版 [4.97.2](4.97.2.md)

## 为什么发这一版

4.97.2 修掉了审核扫描器唯一保持 error 的 `eslint-comments/require-description`，但那只是「Source code」这一段。审核还有一段 **Build verification**：重新构建仓库，并与 GitHub Release 里的 `main.js` 比对。本仓这一条一直是坏的：

- `scripts/generate-worker-inline.mjs` 把两个 worker 的打包产物 gzip+base64 内联进 `shared/workers-inline.generated.ts`，而 gzip 头里的 **MTIME 写的是构建时刻** → 同一台机器连跑两次，生成物哈希都不同；
- 更根本的是压缩用的是 `node:zlib`，deflate 输出随内置 zlib 版本变化 → 本机（Node 24）与 CI（Node 20）构建出的 `main.js` **字节数相同但内容不同**：首个差异在 offset 1,835,905，全部落在 base64 里（本地 `CB43DB80…`，CI 发布版 `B4B4FF16…`）。

审核方用哪个 Node 重建我们无法控制，所以唯一稳的做法是让构建**与环境无关**。

## 变更

| 文件 | 变更 |
|---|---|
| `scripts/generate-worker-inline.mjs` | 压缩从 `node:zlib` 换成纯 JS 的 `fflate.gzipSync(…, { level: 9, mtime: 0 })`；注释写明为什么不能再回 zlib |
| `package.json` / lockfile | 新增 devDependency `fflate@^0.8.3`（只参与构建，不进包） |
| `shared/workers-inline.generated.ts` | 重新生成（`INLINE_WORKER_COMPRESSION` 仍是 `gzip+base64`，运行时解压路径不变） |
| `shared/changelog-data.ts` | 新增 4.97.3 条目（并删除最旧的 4.89.0，保持 ≤12 条上限） |
| `docs/releases/community-submission.md` | 新增「构建可复现」一节，记录坑与验证口径 |

## 验证

- 生成物确定性：`node scripts/generate-worker-inline.mjs` 连跑两次 + 换 `TMP`/`TEMP` 再跑一次，`shared/workers-inline.generated.ts` 三次哈希均为 `5A2AC542…63C6`（350,569 字节）。
- 构建确定性：`npm run build` 连跑两次，`main.js` 哈希均为 `11472CB43488581D10E76A665A9517DA7B6DCAFCD90EAA60323688D893EC381A`（6,241,484 字节）。
- 运行时不回归：`tests/unit/shared/worker-inline-compression.test.ts`（6 例，含 `DecompressionStream('gzip')` 解压 + 语法校验 + ≥35% 压缩率）与 `plugin-worker-url.test.ts`（10 例）通过。
- `npx tsc --noEmit` EXIT=0；`npm run check:obsidian-review` EXIT=0；`npm run preflight` EXIT=0（1013 测试文件 / 10,503 通过 + 3 跳过）。
- **跨环境验证（关键）**：4.97.3 的 Release 资产 `main.js`（CI 用 Node 20 构建）SHA256 = `11472CB43488581D10E76A665A9517DA7B6DCAFCD90EAA60323688D893EC381A`，与本机 Node 24 构建结果**完全一致**；4.97.2 时代两者分别是 `B4B4FF16…` 与 `CB43DB80…`。这意味着审核方在任意 Node 版本重建都能与发布资产对上。

## 影响与迁移

- 无功能变化、无配置迁移；`main.js` 体积 +2,571 字节（压缩率略低于 zlib），bundle 基线已同步上调。
- 破坏性变更：无。
