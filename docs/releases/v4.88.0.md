# v4.88.0 — 一致性审核闭环：19 子类全覆盖 + 结算自动兜底

发布日期：2026-11-13 · tag：`4.88.0`（无 `v` 前缀，Obsidian 社区目录规则）· 上一版本 v4.87.0

## 为什么发这一版

v4.87.0 把「跨章一致性审核」做出来了，但有两个缺口：

1. **覆盖不全**——只做了 9/19 个子类（事实与细节 + 时间线）；
2. **要靠用户想起来点**——功能藏在命令里，不点就等于没有。

这一版把两件事都补齐了：**19 子类全覆盖**、**结算后自动跑**。

## 新增：剩余 10 个子类

| 类别 | 子类 | 判定方式 |
|---|---|---|
| **人物刻画** | **记忆矛盾** | ✅ 规则层：同角色跨章「记得」vs「忘了」同一事物（公共子串配对） |
| | 知识矛盾 · 能力波动 · 遗忘能力 | ⏳ 疑似（需世界知识/等级序） |
| **世界观设定** | **核心规则违规** | ✅ 规则层：设定「不能/无法 X」，后文出现 X 且不带否定前缀 |
| | 社会规范 · 地理矛盾 | ⏳ 疑似 |
| **叙事与文风** | **视角混乱** | ✅ 规则层：同章第一/第三人称各 ≥3 处且比例 ≥0.25 |
| | 语气不一致 · 文风漂移 | ⏳ 疑似 |

### 一个重要的取舍

这 7 类**故意不做确定性判定**，全部进「疑似」交模型或人工复核：

> 它们需要**世界知识**或**等级序**。用「值不等即矛盾」这种粗暴规则，
> 会把**合法成长**（修为进阶、转投门派、疤痕新增）全判成 bug。
>
> **宁可少报，不可把合法成长判成 bug。**

## 结算流程自动兜底

```
写章 → 结算 → ① 规则层全量（零 token）
                ↓ 仅当有疑似项
              ② AI 识别（成本封顶 3 对）
                ↓
              ③ 有矛盾 → 主动弹 Notice
                ↓
        用户点「一致性审核」看证据链、跳正文
```

三个关键约束：
- **不 await**：审核失败绝不影响结算（结算是数据写入，比派生检查重要）
- **AI 只在有疑似项时才启**：真有可能有问题才花钱
- **AI 失败退化为规则层结果**，不阻断流程

## 修复：rename 覆盖类问题全仓排查

「先写临时文件再 rename」在 Obsidian 下是**错的**——`adapter.rename` 目标已存在时抛
`Destination file already exists!`，导致第一次写成功、此后每次失败。

本仓此问题共出现 **4 次**（前两次在 v4.87.0 修）：

| 位置 | 后果 |
|---|---|
| `engine/consistency/consistency-service.ts` | 审核报告第二次起写不进去 |
| `services/knowledge-base-manager.ts#writeJsonAtomic` | **知识库索引**第二次起写不进去 |

统一修法：目标存在走 `write`，不存在才 `tmp + rename`（保留崩溃安全）。

### 同时修正 3 处「测试锁住错误行为」

有测试原本断言「目标存在时仍走 tmp+rename」——它锁的正是这个 bug，
所以修完后测试变红。已改写为断言**新行为**（直接覆盖写 + 内容已更新），
并保留「不存在时仍走 tmp+rename」的崩溃安全验证。
