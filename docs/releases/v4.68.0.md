# v4.68.0 — 三文件 any 清零与 v5 模块 API 文档

发布日期：2026-11-07

## 为什么发这一版

v4.67.0 之后四批：继续 any 收窄（174→163）、把 v5 闭环的五个模块补进 `API.md` / `ARCHITECTURE.md`、并对 any 债务做了结构取证。**无运行时行为变更**：`main.js` 逐字节不变。

## 主要变化

### 1. `main.ts` any 4→0

- `catch (error: any)` → `catch (error)` + 编译期结构断言 `(error as { message?: string }).message`。
- **不用 `instanceof Error`**：`DOMException` 不是 `Error` 子类，且三元表达式会引入运行时体积（实测 +55B）。
- 两处 `let leaf: any` → `Obsidian.WorkspaceLeaf`；`updateProvider(id, updates)` → `Partial<CustomProvider>`（与 `core/provider-manager.ts` 实现一致）。

### 2. `services/knowledge-base-manager.ts` any 4→0

- 新增本地 `LruCapacityView { maxSize; ttlMs }` 窄接口：TS 的 `private readonly` 只是编译期约束，运行时是普通可写字段。只做类型收窄，不新增运行时方法。

### 3. `ui/settings/writing-sections.ts` any 3→0

- 三个 dropdown 引用改 `DropdownComponent | null`（与 `export-manuscript-modal` 的用法一致）。

### 4. 文档

- `docs/API.md` 新增 §十「v5 协同写作闭环 API」：阶段事实源 `creation-flow`、`agent-port` 的 flow 投影与 `stage-panel`、三档 `publication-profile` + `splitUnitsByBody`、`platform-export` 平台包与敏感词预检。
- `docs/ARCHITECTURE.md` 新增 4.10 模块表与 §八「v5 协同写作闭环」索引。
- `docs/PLAN.md` §v5 把 B3 旧布尔「严格模式」表述改为三档 + 范围。

### 5. any 债务结构取证

- 全仓 170→163 处 / 88 文件；`engine/**` 约 103 处（约 60%），由 ZCode 自行接手。
- 非 engine 可动池约 54 处 / 40 文件，多数文件仅 1–2 处。据此把 Trae 视角 `gate-fix` 权重调整为 1.6，且**只接单文件 ≥3 处的批次**（ZCode 视角维持 1.76）。
