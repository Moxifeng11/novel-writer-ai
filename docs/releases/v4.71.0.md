# v4.71.0 — 偏好记忆浅拷贝修复与派工新鲜度判据

发布日期：2026-11-08

## 为什么发这一版

第 91 轮补测时发现一个真实隐患：`GenrePreferenceMemory` 的默认数据浅拷贝会让多实例互相污染。修复过程中双自动化循环又暴露了第二处真实缺陷：跨方轮次编号漂移会让同号派工被误判陈旧。本版修复这两处。

## 主要变化

### 1. `GenrePreferenceMemory` 默认数据浅拷贝修复

- **根因**：`constructor` / `reset` 以 `{ ...DEFAULT_PREFERENCE_DATA }` 浅拷贝，`corrections` / `genreBias` / `subGenreBias` / `channelBias` 与模块级 DEFAULT **共享引用**——两个实例（或 reset 后）的纠正记录与偏置互相污染，`push` 会写进模块级常量。
- **修复**：`createDefaultPreferenceData()` 每次新建嵌套对象；`savedData` 合并时对四个嵌套字段逐一拷贝。零外部行为变化。
- **回归**：+1 例「两个实例互不可见 + reset 不污染」。
- 生产影响评估：当前由 `knowledge-base-manager` 单实例持有且构造后立即用保存数据替换，暂未暴露；属真实隐患而非已发生故障。

### 2. 派工新鲜度判据修复（双自动化循环）

- **根因**：`isFreshDispatch` 判 `targetRound > currentRound`；ZCode 按「上一轮 + 1」编号派工，Trae 开工时台账已前进到同号 → `90 > 90` false → 派工被误判陈旧过滤（第 91 轮实测漏掉一次派工）。
- **修复**：判据改 `>=`（同号派工新鲜）+ `lastDispatchId` 去重——canonical 台账记录最近已执行派工的消息 id（CLI 传 `message.id`），同号重复投递不再执行；无轮次主题仍按 6 小时时效。
- **约定**：派工主题须显式含「派工」二字（`「已收单」`且不含`「派工」`的主题会被采集器跳过）。
- **回归**：+1 例（同号新鲜 / 同号去重 / 旧轮次陈旧）。

### 3. 文档

- `handbook/13`：§1 Trae 可写范围补 `main.ts` 与 `.trae/automation/**`、§2 去掉写死的 `newPathBudget`、§3 `check:automation` 校验项写准、§7 派工新口径与已知边界。
- `PLAN`：第 92/93 轮台账；v5-acceptance 对齐 v4.70.0（E2E 基线 40、B5 三模式闭环、提交列表补全）。
