# v4.23.4 — 规则版本解析补强与版本显示修正

发布日期：2026-11-02

## 背景

v4.23.3 修掉了「同版本号假漂移」的主因（frontmatter 优先）。按用户要求对插件相关内容做了一次复检，又发现三类相关问题。

## 修复

### 0. 内容身份与元数据分离（本轮最深的一处）

同一份规则有两种形态：内置常量 `WRITING_RULES`（纯正文，注入 prompt）与 vault 文件（带 `tags`/`version`/`updated`）。正文逐字相同，但整文件哈希不同——只要版本号碰巧相等，就会被判成「同版本不同内容」。

- 新增 `canonicalContent()`：去 BOM、统一换行、剥离 frontmatter、去首尾空白；
- 注册表对内置常量与文件统一按规范化内容算哈希，元数据不再参与内容身份；
- `assets/template-scaffold/00-系统模板/写作规则.md` 的 `version` 从 `3.6.0-引导代禁止` 对齐为 `3.6.0`，`tags` 去掉多余的 `v3.6.0`。

### 1. 解析边界补强（`shared/versioned-registry.ts`）

- 跳过文件头 BOM（Windows 记事本/部分同步工具会写 `U+FEFF`，会让 `^---` 匹配失败）；
- 支持空 frontmatter（`---\n---`）；
- 只认**顶层** `version:`，嵌套的 `meta.version` 不再被误当文件版本；
- `compareVersionBase` 兼容前导 `v`（`v3.6.0` 与 `3.6.0` 视为同一主干）。

### 2. 设置页：版本下拉与漂移提示

- 选项从 `vault:路径` 改为 `vault:路径 · v3.6.0（vault …）`，并存多个规则文件时可区分。
- 描述里承诺的漂移提示此前**从未渲染**：现在会在下拉上方显示 `⚠️ …`（数据来自 `listRulesVersions().drift`）。

### 3. 工作台状态条：不再硬编码版本

`ui/full-writer-view.ts` 原来固定显示「内置 3.6.0」，即使项目或 vault 规则生效也会误报。现在：

- 设置了 `activeRulesVersion` → 显示所选 id；
- `auto` → 先显示 `auto`，异步解析实际生效版本后替换为实际版本（或 `…（内置）`）。

## 验证

- `preflight` 全绿：**524 文件 / 5866 用例**（新增 4 条测试）。
- 真实 Electron E2E 复检：**25 passed / 14 skipped**，插件加载、命令注册、项目创建链路均正常。

## 影响

无行为回退；仅解析更稳、显示更准。已配置自定义规则变体的用户看到的是文件真正声明的版本；正文与内置一致的旧文件会被内容重新标注为 `3.6.0`，不再误报。
