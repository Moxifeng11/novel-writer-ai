# v4.18.0 — 同人考据、人工审核与快捷工具收口

发布日期：2026-10-26

## 为什么发这一版

这一版先解决“工具能点但结果不可信/会丢数据”的问题：

- 同人设定此前可以凭模型记忆生成并直接绑定，无法区分原著与同人/改编/外传，也没有人工审核。
- 脑洞构思、黄金开篇的“导出为项目”只建空目录，没有 `.project`、模板和写作配置。
- 项目重命名只改 `.project` 标题；顶层项目还会错误生成 `旧名/新名` 子目录。
- 全书简介先删旧文件再创建，保存失败就丢稿；只保留一版。
- 文笔风格蒸馏只输入书名，无法基于真实样本分析。

## 两条硬约束

### 1. 同人设定只参考原著，不参考衍生作品

- 来源分级：官方原著、官方 Wiki、参考资料、衍生作品、未知。
- 同人、改编、外传、动画/影视/游戏/漫画等默认排除；手工误标也会被识别为衍生来源。
- 没有官方来源时只能生成骨架或写“待核实”，禁止模型凭记忆补全。
- 只缓存引用元数据与短摘录，不抓整本原文、不绕过付费墙。
- 检索方式：手动官方 URL/摘录（默认），或配置 Bing/Brave/Serper/Tavily 搜索 API。

### 2. 生成后必须人工审核

- 生成写入 `05-同人设定库/_待审核/`，状态 `pending`。
- 未审核：
  - 不能绑定 `.project`；
  - `readFanficRules` 返回 `unreviewed`；
  - 协同写作不注入任何同人约束。
- 审核页逐字段展示来源、未核实字段、衍生来源告警；四项检查全部勾选且无阻断错误才能通过。
- 通过后写入审核人、审核时间、来源哈希和 `_审核/{作品}_审核记录.md`，再绑定项目。
- 审核后修改文件或来源，哈希不匹配会自动失效，要求重新审核。
- AI 只能辅助审核/补全，不能自动通过；补全后回到 `pending`。

## 主要变化

### 同人设定库

- 新增 `shared/canon-source.ts`、`services/canon-research-service.ts`、`shared/fanfic-audit.ts`、`ui/fanfic-review-modal.ts`。
- 来源区改为独立卡片 + 表单间距，解决字段拥挤与提示遮挡；替换原生 `<select class="... dropdown">` 为自定义选择器，消除重复箭头/背景菱形。
- 文件选择器候选排除模板与自带示例，避免把模板当原作绑定。
- 模板持久化：项目内保留 `05-同人设定库/同人设定模板.md`；模板丢失时自动从 `元文件` 或内置骨架恢复；新增“从模板新建空白设定 / 恢复项目模板”。
- 管理入口增加待审核草稿列表、补全、规则审核、可选 AI 审核。
- 统一文件名规则 `fanficSettingsFileName()`，避免 `.project` 指向未净化路径。
- 旧文件无审核状态按 legacy 兼容，但提示建议重新审核。

### 项目与快捷工具

- 项目重命名：新增 `ProjectRenameService`，同步 `.project`、世界观 frontmatter、写作配置、插件偏好文件；修复顶层父路径 bug；项目卡片和右侧操作区露出入口。
- 脑洞构思：改为真实项目创建；增加 `titleCandidates` 书名候选；支持保存到当前项目；换一批保留输入；单批 10 条降低 JSON 截断。
- 黄金开篇：改为保存到当前项目或真实创建项目，输出 `04-项目总控/黄金开篇.md`。
- 新增 `shared/project-name.ts`：创建/重命名/脑洞转换共用项目名校验，拒绝空名、纯标点、系统目录、Windows 保留名与重名。

### 全书简介

- 新增 `shared/synopsis-spec.ts`、`services/synopsis-store.ts`。
- 一次生成四种风格：悬念、爽点、人物、世界观；首屏钩子、信息顺序、字数档位、负面清单、8 维 rubric。
- 多版本目录：`04-项目总控/全书简介/index.json` + `v001_*.md` + `草稿.md`；`全书简介.md` 保留为采用版本兼容副本。
- 切换项目自动保存草稿并加载该项目版本；生成永不覆盖；支持预览、编辑、删除、设为采用。
- 旧单文件首次打开会自动导入为 v001。

### 文笔风格蒸馏

- 来源：粘贴样本 / 当前项目章节 / 当前文件 / 书名。
- 样本模式必须引用原文短句证据；书名模式明确标注“模型记忆推测”。
- 使用任务级模型预算，支持 abort；保存前预览、可编辑；写入项目时自动备份。

### 数据安全与回归

- GitHub 参数统一：`shared/github-repo.ts` 集中 owner/repo/branch/API/Web 地址；package/manifest/更新检查/User-Agent/设置占位统一为 `Moxifeng11/novel-writer-ai`（master）。
- 私有仓库更新检查：新增加密保存的 GitHub Token，Release API 支持 Bearer Token；无 Token 时 Private 仓库仍返回 404。
- 自动重命名统一：世界观生成/AI 世界元素生成改走 `ProjectRenameService`，同步项目元数据并由统一规则校验项目名。
- 旧仓库名迁移：默认 GitHub 仓库统一为 `Moxifeng11/novel-writer-ai`，启动迁移旧 `trae-ai/...` 并清空旧 404 缓存。
- 覆盖写保护：世界观、跨卷快照、信息债看板、诊断报告改为 modify 优先，写盘失败不先删旧文件。
- 分卷大纲重新生成前先备份；备份失败保留旧文件。
- 同人考据 URL 只允许 http/https，拒绝 file://、本机与内网地址。
- 更新缓存版本对齐：`UpdateChecker.getLastCheckResult()` 对升级前旧缓存按当前版本重算 `currentVersion/hasUpdate`，避免更新 UI 仍显示 4.12.4。
- 指纹 embedding 显式设置优先：用户切换向量 provider/model 后，指纹提取按当前设置构造 provider，避免共享旧 provider 写入不一致的 modelId/维度。
- 设置页任务级参数改为卡片 + 网格分栏，修复 5 个控件横向溢出/换行和“多出全局思考模式”的视觉问题；任务级思考改名为“思考覆盖（跟随全局）”。
- 全书简介改为原地修改 + 备份，不再 `delete` 后 `create`。
- 分析报告：普通叙述型报告无结构化指令时回退 AI，避免 v4.17 静默空结果。
- 逐步执行：每步启动前检查 abort，取消后不再跑后续步骤。
- 本地 AI 队列：增加等待超时与 abort 清理。

## 使用建议

1. 同人项目先生成/导入官方来源，再生成草稿；草稿必须在审核页逐项核对后才能绑定。
2. 没有搜索 API 时，用“添加官方来源”手动粘贴作者/出版方/官方 Wiki 的 URL 或短摘录。
3. 项目卡片上的 ✏️ 可重命名项目；若只看到目录改名成功但元数据失败，会明确提示。
4. 全书简介先生成四版，再挑一版“设为采用”；切换项目会自动保存草稿。
5. 文笔风格蒸馏优先粘贴 1000-5000 字样本；只给书名时结果会标注不可靠。

## 已知边界

- 没有搜索 API 时无法自动联网，只能手动导入官方来源；不会退回模型记忆。
- AI 审核/补全是可选操作，仍必须人工通过。
- 旧同人文件没有审核记录，按 legacy 兼容；建议重新审核。
- 快捷工具审计中仍有“待审计”项，详见 `docs/audits/v4.18-quick-tools-health.md`。
- 本版改动仍在本地工作树，尚未提交/推送远端。
