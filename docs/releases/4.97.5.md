# 4.97.5 —— 正文质量链路：本章四项校验（软聚合 / 按需重算 / 精度提升）

> 发布日期：2026-11-24 · 非破坏性：最低 Obsidian 版本维持 **1.8.7**，无数据迁移。

## 一、为什么发这一版

正文生成在第 7 步只有「字数」一项硬门禁；格式由 `BodyWriter` 静默规整、视角判定藏在一一致性审核、钩子检测在正文保存后才跑，四个信号分散在三处，用户无法在一个地方看到「这一章到底哪里不合规」。

工作流规范（`docs/design/v4.21-workflow-ai/01-three-mode-workflow-spec.md` 第 7 步）要求「字数 / 格式 / 视角 / 钩子四项校验」。本版把这四项做成**软聚合视图**：字数仍为硬门禁，其余只提示、不阻断；并把同一套口径接到「协同写作 / 场景循环 / 续写 / 定向修订」这些不经过第 7 步的正文写入路径上。

## 二、改了什么

| 位置 | 内容 |
|---|---|
| `shared/chapter-four-checks-model.ts`（新增） | 四项校验报告模型：`buildFourCheckReport` / `renderFourCheckReport` / `fourCheckAttentionItems`；状态 pass/warn/fail/skip，格式偏离告警阈值 15% |
| `services/four-check-store.ts`（新增） | 按项目落盘 `04-项目总控/质量面板/四项校验.json`，最多保留 500 章，损坏降级 |
| `engine/quality/gate-snapshot.ts` | 从「章末钩子」声明生成非必做 hook 节拍（不进入 requiredBeats，避免新增阻断） |
| `engine/quality-gate.ts` | 钩子判定改用 `BeatVerifier` 子短语口径（`detectHookCoverage`），结尾 200 字窗口；无钩子声明时跳过 |
| `engine/step-runner.ts` | 第 7 步保存正文后聚合四项校验并归档；`emitDiagnostic` 输出可读报告 |
| `shared/body-format.ts` | `analyzeBodyFormat` 只读原文统计（不再先规整），输出偏离样例（最多 8 条，含行号） |
| `engine/consistency/extended-rules.ts` | 抽出 `detectPerspectiveMix`；先剔除对话引号再数人称，降低「他说」误报 |
| `engine/quality/four-check-refresh.ts`（新增） | `FourCheckService.refresh`：按磁盘正文 + 信息规划重算任意章节，覆盖所有正文写入路径 |
| `ui/quality-loop-modal.ts` | 质量面板新增「本章四项校验」区块与「按磁盘正文重算」按钮，切章联动 |
| `main.ts` | `refreshFourChecks(project, chapterName)` 公开入口 |

## 三、验证

- 新增测试：四项校验模型 18 例、四项校验存储 6 例、格式偏离 6 例、视角混用 4 例、按需重算 7 例；门禁/钩子相关用例同步更新。
- 全量：**1024 个测试文件 / 10621 通过 + 3 跳过**；`tsc --noEmit` 0 错；`preflight` 全绿。
- 构建产物体积基线显式上调（`main.js` 6262628 字节，较上版 +9 字节），`check:bundle` 通过。
- 无新增网络请求、无遥测；四项校验全部本地计算。

## 四、影响与遗留

- 非破坏性：不改变正文落盘格式与既有质量门禁的阻断行为；四项校验仅新增诊断与展示。
- 已知口径：视角混用基于人称代词比例（剔除对话后），对第一人称小说仍可能给出提示；格式偏离只提示占比与行号，不自动改写。
- 遗留：第 7 步的钩子校验依赖「信息规划」里声明了「章末钩子」；未声明时该一项显示「跳过」。
