# v4.54.0 — v5 B1 阶段快照契约与 any 第三批

发布日期：2026-11-06

## 为什么发这一版

v5 最小闭环（Agent 对话 + 多步骤协同写作）启动，B1 是 engine 侧契约：让 Agent 能读到与 UI 同源的阶段快照，并按 `nextStageId` 引导，而不是凭记忆套固定八阶段。同批合并 Trae 第 30 轮的 any 收口与交互边界守护，以及 B2 的类型收口。

## 主要变化

### 1. B1：Agent 阶段快照契约

- `engine/agent/agent-types.ts`：`AgentProjectStatus` 新增 `flow?: CreationFlowSnapshot`（直接取自 `shared/creation-flow`，engine 只投影不定义阶段）。
- `get_project_status`：
  - 输出「阶段进度：N%（下一步：阶段名（阻塞原因））」；
  - 单独提示非下一步的阻塞阶段；
  - 「阶段明细」用 ✓/→/!/○ 逐阶段展示；
  - `data.flow` 携带完整 stages，Agent 可自行读取。
- `prompt-sections.ts`：明确「阶段事实源」——先 `get_project_status`，按 `flow.nextStageId` 引导；硬编码生命周期顺序降级为「无 flow 时的通用回退」；阻塞阶段必须先说明原因。

### 2. B2 类型收口与阶段用例

- `agent-port` / `agent-workbench-view` 移除本地交叉类型 `AgentProjectStatus & { flow?: ... }`，改用 B1 的正式字段。
- 剧本阶段面板补 3 条用例（分镜表 → 分集写作的 active/todo/blocked 迁移）。

### 3. any 收口第三批

- `ui/full-writer/intervention-controller.ts` any **9→0**：
  - `getVars`/`setVar` → `Record<string, string>`；
  - `makeStepRunCtx` → `StepRunCtx`（type-only）；
  - `catch(e: any)` → `catch(e)` + `instanceof Error` 窄化；
  - 语音识别回调 → 本地 `SpeechResultEvent` / `SpeechErrorEvent`（只声明实际使用字段）。
- 新增 2 条交互边界用例：并发点「确认执行」只执行一次；理解后切步骤拒绝执行且不写 `userIntervention`。
- 全仓 any **260 → 251**，基线收紧。

### 4. 联动清单

- `check:linked-scenarios` 新增「Agent 阶段引导 → 商业化导出检查」链（creation-flow → stage-panel → publication-profile → 导出严格模式 → check-automation），4 条链 / 32 个锚点。
