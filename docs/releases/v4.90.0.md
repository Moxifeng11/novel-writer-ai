# v4.90.0 — 事实库自动化：自动维护 + 可视化 + 第二意见扩面

发布日期：2026-11-13 · tag：`4.90.0`（无 `v` 前缀，Obsidian 社区目录规则）· 上一版本 v4.89.0

## 为什么发这一版

v4.89.0 建立了「知识库事实层」：LLM 把正文拆成结构化事实，供审核与正则功能查询。
但它有三个明显的缺口：

| 缺口 | 后果 |
|---|---|
| 事实库要**手动跑脚本**建立 | 不跑就等于没有，功能形同虚设 |
| 事实库**看不见** | 用户无法确认它记了什么，也无法修正 |
| 第二意见只接了时间线 | 地点等其他正则判定仍是"冷冰冰的正则" |

这一版把三个缺口全部补上。

## 新增：事实库自动维护

结算流程在写完章节摘要后，**自动**对本章做增量拆解并入库：

```
写章 → 结算 → 章节摘要 → 事实库维护（本章拆解入库）→ 一致性审核
```

四条安全约束：

| 约束 | 说明 |
|---|---|
| **按章幂等** | 已拆过的章默认跳过，不重复计费；需要重拆时可传 `force` |
| **损坏拒绝写** | 事实库读失败时**拒绝写入**，绝不覆盖用户已有数据 |
| **失败不抛错** | 模型超时/返回非 JSON → 只记录失败状态，**结算流程照常完成** |
| 批量重建 | `maintainFactsBatch` 带进度回调，可用于回填历史章节 |

## 新增：事实库浏览视图

命令面板 → **「知识库事实库」**

按主体分组展示，每条包含：

```
第1章 [规则] 军事规模=军官士卒全部加在一起也不超过三百人（第1章起；置信 0.90）
    「渭城不大，军官士卒全部加在一起也不超过三百人」
```

- 类型徽章（年龄/地点/持有/能力/关系/时间/规则/认知/记忆）
- 有效区间（`第N章起` / `第N–M章`）
- 置信度
- **原文引文**（可直接核对）
- 底部标注 JSON 文件路径，方便人工修正

事实库为空时给出明确引导，而不是一个空白窗口。

## 新增：第二意见扩面（地点）

「场景地点与本章设定不符」判定前先问事实库：

| 事实库结论 | 行为 |
|---|---|
| `consistent` | **抑制**（正文合理的换场/回忆，不再误报） |
| `unknown` | 不干预（与升级前行为一致） |
| `conflict` | 照常报，并在详情中附上事实库的理由 |

至此**四类功能**具备「正则找候选、事实库定结论」能力：

| 功能 | 接入方式 |
|---|---|
| 时间线 | `adviseTimeline` |
| 实体状态 | `advise(claim)` |
| 伏笔 | `adviseForeshadow` |
| 地点 | `adviseState`（本版新增） |

## 可靠性细节

- 所有第二意见在**事实库缺失/损坏时降级为「不干预」**，功能行为回到升级前，绝不因读不到事实而报错
- 本次特意检查了「新回调是否有生产调用方」——避免再次出现"写了但没人用"的死代码（`quality-gate` 已透传）
- 命令注册三处齐备（数组 / `addCommand` / `r.register` UI 列表 + 执行器 `case`），
  `check:command-handlers` 覆盖 **76 个命令**

## 升级说明

无破坏性变更。升级后正常结算即可，事实库会逐章自动累积。
事实库为空或不可用时，所有第二意见返回「不干预」，行为与升级前完全一致。
