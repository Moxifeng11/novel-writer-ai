# v4.97.2 — 通过社区审核：补上 eslint 指令说明

> 标签 `4.97.2` · 2026-11-20 · 上一版 [4.97.1](4.97.1.md)

## 为什么发这一版

4.97.1 发布后账号页显示的是 **Failed**，而不是「等待审核」：Reviews 区里 4.83.1 / 4.85.0 / 4.95.0 / 4.96.0 / 4.97.1 **全部 failed**，也就是从 4.83 起每一版都没通过自动扫描，插件因此一直没进客户端市场清单。

按官方 Community plugin scanner configuration 复刻扫描器判据后，当前代码树里真正会阻断的只有一条规则、两处命中：

```
eslint-comments/require-description
  engine/agent/harness/mcp-stdio-transport.ts:31
  services/chapter-version-service.ts:57
Unexpected undescribed directive comment.
```

扫描器把绝大多数 `eslint-plugin-obsidianmd` 规则降级为 **warn**（warn 不阻断），真正保持 **error** 的只有安全类（`no-eval`、`no-unsanitized/*`、`regex-lookbehind`、`no-forbidden-elements`、`no-new-func`、`no-implied-eval`），外加最新提交层额外收紧的 `settings-tab/*`、`no-static-styles-assignment`、`no-unsupported-api` 等 API 规则与 `eslint-comments/*`。所以「本地 lint 全绿」不等于审核通过——本地 lint 里那 1721 条 error 绝大多数在扫描器里只是 warn，而本地从不检查的那条 `require-description` 才是真凶。

## 为什么要把这个判据固化进 preflight

之前两版（4.97.0 / 4.97.1）都以为「等审核」，实际每一版发布即失败。把扫描器判据复刻成本地门禁后，`npm run check:obsidian-review` 的退出码等价于「这一版会不会被自动扫描打回」，大约 52 秒跑完，避免再用一次发版去试错。
