# v4.29.0 — 短篇/剧本最小闭环：AI 文档、质检、结算与平台包

发布日期：2026-11-05

## 为什么发这一版

短篇/剧本此前只有「骨架 + 单元写作 + 本地语感检查」：故事核/大纲/分镜要手填，单元生成后没有六维质检、没有结算，导出也没有平台投稿所需的信息。用户从创建到导出仍要自己补关键环节。

这一版把短篇/剧本补成一条可走通的闭环：**AI 前置文档 → 单元写作 → 模式质检 → 单元结算 → 平台包导出**。

## 主要变化

### 1. ModeRuntime：上下文不再只有 4 个文档

- 新增 `engine/mode-runtime.ts`，统一读取：
  - 故事核（短篇）/ 场景圣经（剧本）
  - 分节/分集大纲 + 剧本分镜表
  - 前期调研摘要
  - 人物/地点/势力/物品状态
  - 项目文笔风格
- 单元写作提示词接入全部上下文；剧本不再漏掉分镜表，短篇/剧本不再只读故事核/大纲/调研人物。

### 2. 前置文档 AI 生成

- 故事核、分节大纲、场景圣经、分集大纲、分镜表均新增「🤖 AI 生成」按钮。
- 生成基于前期调研 + 现有文档 + 实体状态；覆盖编辑区前二次确认，保存仍由用户显式点击。
- 短篇大纲强制「开篇三屏」：第 1 屏立人物/困境，第 2 屏升级冲突，第 3 屏抛出主悬念；前 3 节单元写作文本也带同一约束。

### 3. 六维/可拍质检

- 新增 `shared/quality-profile.ts`：三模式的通过线、最低维度分、额外检查、修订闸门参数集中配置。
- 新增 `engine/mode-unit-quality.ts`：
  - 复用 `QualityScoreEngine` 六维评分；
  - 短篇追加「开篇钩子 / 结尾兑现」；
  - 剧本追加「场次可拍 / 对白占比 / 动作行」；
  - 报告写入 `04-质检`/`05-质检`，并回写单元 frontmatter。
- 单元工具条由「质量检查」升级为「🧪 六维质检 / 🎬 可拍质检」。

### 4. 单元结算

- 新增 `engine/mode-unit-settlement.ts`：复用 `settleLight` 做人物/地点/势力/物品出场确认；自动从正文匹配实体名，避免要求用户手填 `涉及人物`。
- 单元标记 `status: settled`，写 `_结算.md` 记录（实体更新数、时间、模式）。
- 明确边界：完整实体图谱/时间线仍由长篇流水线处理，短篇/剧本当前是轻量结算。

### 5. 修订闸门按模式适配

- 改写选区后先过 `evaluateRevision`：短篇 ±12%、剧本 ±15%，对话跌幅上限 6%/10%；未通过保留原稿并提示原因。
- 锁定人物名从实体摘要提取，防止改写换人。

### 6. 平台导出包

- 新增 `shared/platform-export.ts`：
  - 番茄小说短篇 / 红果短剧的平台名与文件名前缀；
  - 简介（来自前期调研）、标签、字数、单元数；
  - 内置敏感词预检（赌博/毒品/暴力/色情/宗教极端等），只提示不阻断。
- TXT/Markdown 导出自动加「平台投稿信息」头；EPUB/DOCX 写入简介与标签元数据；文件名改为 `番茄短篇_书名_日期` / `红果短剧_书名_日期`。

## 验证

- 单测：**542 文件 / 5,933 用例** 全绿。
- 真实 Obsidian + mock AI E2E：**12 passed**，其中新增短篇/剧本各 1 条完整闭环。
- 短篇 E2E 覆盖：AI 大纲 → AI 单元 → 六维质检落盘 → 结算落盘 → 番茄平台包 TXT。
- 剧本 E2E 覆盖：AI 大纲/分集 → AI 单元 → 可拍质检 → 结算 → 红果平台包 TXT。
- 长篇主旅程、按钮、视图、生命周期 E2E 无回归。

## 影响与迁移

- 破坏性变更：短篇/剧本导出文件名与内容头变化；旧导出文件不受影响。
- 配置/数据迁移：无需迁移；已有单元可直接质检/结算，缺少 `涉及*` 时按正文实体名匹配。
- 回滚建议：回滚到 v4.28.0 后，`04-质检`/`05-质检` 与 `_结算.md` 仍可读，不影响正文。

## 未完成（明确记录）

- 短篇/剧本尚未接入知识库/RAG/指纹库的完整注入（M4）。
- 单元结算是轻量结算：不生成完整时间线/关系图谱，也不跑分析报告指令。
- 平台敏感词为内置通用词表，不等同于平台官方审核；导出前仍需作者自查。
- 短/剧「开篇三屏」目前是提示词约束，不是独立的三屏可视化编辑页。
