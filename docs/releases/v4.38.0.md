# v4.38.0 — 写锁加固、协同引擎三批与 Notice 三批

发布日期：2026-11-05

## 为什么发这一版

审计 P1-3 的「写锁覆盖约 23%」一直只做了用户可见 Markdown 的写入入口，核心的「读 → 改 → 写」并发丢更新还没收口。本版由三个实现子代理并行：补齐 6 处高风险读改写锁、协同引擎最后一块大方法切片、Notice 第三批。

## 主要变化

### 1. 核心读改写路径写锁加固

- 补齐 6 处整段锁（读、计算、写都在锁内）：
  1. `analysis-report-engine.applySingleCharacterStatusChange` — 单人物状态更新；
  2. `settlement-engine.settleStep_updatePromiseLedger` — 承诺账本；
  3. `settlement-engine.settleStep_updateCharacterArcs` — 角色弧线表；
  4. `settlement-engine.settleStep_updateV2Relations` — V2 关系状态 load→apply→snapshot→save；
  5. `settlement-engine.deleteEntity` 伏笔分支；
  6. `settlement-engine.deleteEntity` 时间线分支。
- 第 2/3/5/6 处改为**锁内重读最新文件再合并**：旧实现用锁外读到的快照整表覆盖，并发新增的条目会被抹掉。
- 审计确认 `withWriteLock` **不可重入**（内层同 key 会死锁）：已在外层锁内的路径一律不重复加锁；伏笔揭示/新增、时间线追加、实体字段更新等 13 处原有锁保持不变。
- 并发回归 3 例：真实锁 + 内存 fs，`read` 中让出事件循环放大交错窗口——并发新增/删除伏笔、不同路径并行、两个结算并发写承诺账本；**去掉锁后用例必失败**。

- 大文件现状：co-writing-view 4,986 / co-writer-engine 3,479 / knowledge-base-view 3,226（累计 -2,323 行）。
