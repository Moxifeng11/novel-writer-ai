# 4.97.4 —— 按 vault 隔离存储（minAppVersion 提到 1.8.7）与删除改走回收站

> 发布日期：2026-11-21 · 破坏性变更：最低 Obsidian 版本 1.4.4 → **1.8.7**

## 一、为什么发这一版

社区审核扫描器的 `no-restricted-globals` 还剩 18 处裸 `localStorage`（第 8b 批）。官方推荐改用
`App#loadLocalStorage` / `App#saveLocalStorage`：数据存进**按 vault 隔离**的命名空间，
同一台机器上多个 vault 不再共用一个草稿/偏好桶。

这套 API 自 **Obsidian 1.8.7** 提供（`node_modules/obsidian/obsidian.d.ts` 的 `@since 1.8.7`），
而审核的 `obsidianmd/no-unsupported-api` 是 **error 级**（阻断），它按成员访问的符号判版本、
**不认运行时特性检测**；`no-restricted-globals` 也**禁止 disable**（`eslint-comments/no-restricted-disable`）。
所以只有两条路：提 `minAppVersion`，或永久保留这 18 条 warn。

用户裁定（2026-11-21）：**提版本、做迁移**。当前客户端已到 1.14.5。

## 三、迁移语义（用户草稿不能丢）

1. 读某个键时先问 App 存储；有字符串值直接返回，非字符串值 `JSON.stringify` 后返回。
2. App 存储没有而旧全局键有 → 把旧值写进 App 存储，再返回旧值。**旧键不删除**：
   - 回滚到 4.97.3 仍能读到原数据；
   - 重复迁移是幂等的（App 存储有值后不再看旧键）。
3. 没有注册宿主（单测、极早期初始化）→ 退回旧全局键，行为与 4.97.3 一致。
4. 写失败（配额/权限）不冒泡：`vaultSave` 兜住异常并退回旧全局键，最坏情况等于旧行为。

## 四、验证

- `tests/unit/shared/local-storage.test.ts` 6 例：App 读写不碰旧键、旧键迁移并回写、无宿主回退、非字符串序列化、`vaultClear` 双清、写入抛错回退。
- `tests/unit/architecture/official-review-rules.test.ts` 的 `minAppVersion` 断言改 1.8.7。
- `tests/__mocks__/obsidian.ts` 的 `App` 补内存版 `loadLocalStorage` / `saveLocalStorage`（`null` 即删除）。
- 扫描器 warn：**859 → 790**（`no-restricted-globals` 19 → 1，只剩 `shared/http-transport.ts` 的桌面端 `fetch` 有意例外；`prefer-file-manager-trash-file` 25 → 0），error 0。
- `npx tsc --noEmit` 0 错；全量 preflight 见提交说明。

## 四之二、删除语义变化（用户可见）

- 4.97.4 起，模板、封面、实体卡、章节版本快照、风格备份等**用户可见文件**的删除改走 `FileManager.trashFile`：按用户在「设置 → 文件与链接 → 删除文件」里的偏好处理，默认进回收站、可恢复；此前是直接硬删。
- 事务日志、结算日志、派生记忆历史这类**内部临时文件**仍直接删除，不进回收站，避免把用户的 `.trash` 刷满噪声。
- 这同时消化了审核扫描器的 `prefer-file-manager-trash-file` 25 条（`vault.delete` / `vault.trash` 已废弃）。

## 五、破坏性影响与补救

- Obsidian **< 1.8.7** 将无法启用 4.97.4（市场会按 `versions.json` 卡住升级）。这些用户停留在 4.97.3 仍可正常使用，数据也仍留在旧键里。
- 若要把兼容性降回 1.4.4：把 16 处 `vaultLoad` / `vaultSave` 换回旧的 `localStorage` 写法（`shared/local-storage.ts` 的旧键回退分支就是原行为），并把 `manifest.minAppVersion` 与断言改回去；这 18 条 warn 会重新出现。
