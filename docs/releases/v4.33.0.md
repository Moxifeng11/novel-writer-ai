# v4.33.0 — 卸载契约、分层门禁收口与治理批（M4 第四批）

发布日期：2026-11-05

## 为什么发这一版

审计报告（v4.27.0）里有两项 P1 一直排不上：卸载路径全部 fire-and-forget（flush 与引擎销毁互相竞争、字体与主题变量从不清理）、分层门禁对 `domains/`、`utils/` 完全失明。本版连同协同视图切片第三批一起收口，全部由三个实现子代理并行完成。

## 主要变化

### 1. 卸载清理契约

- `onunload` 顺序化：**先** `withUnloadDeadline(2s)` 等待设置写入器 `dispose()` + 知识库/批量导入/指纹库 flush，**再** `withUnloadDeadline(3s)` 等待 `engineRegistry.disposeAll()`——修复「flush 还没落盘，引擎已经被销毁」的竞争；超时只告警不阻塞卸载（Obsidian 不会等 onunload，内部顺序化仍有真实价值）。
- 自定义字体：新增 `unregisterAllCustomFonts()`，卸载时 `document.fonts.delete` 全部已注册 FontFace（`settings.customFonts` 清单保留，重启自动恢复）。
- `ThemeManager`：新增 `dispose()`（移除主题样式 + 对称清理 15 个 `--nw-*` 布局变量）；`THEME_LAYOUT_VARS` 常量数组成为 set/remove 的单一事实来源，`disposeAll()` 不再静默跳过它。

### 2. 分层门禁收口

- `domains/`、`utils/` 进入 LAYERS：
  - **新增的真实约束**：domains/utils 出向只许依赖 shared（domains→engine、shared→domains 从此被门禁拦截）；
  - `ui/engine/services → domains/utils` 作为既有合法入站依赖显式声明（如实登记，不假装不存在）。
- 修根因零违规（基线零播种）：
  - `resolveProjectRoot` / `modeFromLibraryPath` 下沉到 `shared/project-root.ts`（纯路径计算属 shared 能力），`project-locator` 保留 re-export，约 30 个 import 站点不动；
  - 删除 `domain-project-factory` 中完全未使用的 `WritingProfileManager` 运行时 import（实例本就经 engineRegistry 获取）。
- `main.ts` 在检查器中显式登记为组合根、不参与分层（此前是「静默失明」，现在是有文档的决策）。

### 3. 协同视图切片（第三批）

- `ui/co-writing-view.ts` 5,152 → 4,986（-166）：
  - `parseQualityReport`（纯函数）+ `QualityIssue` 接口 → `ui/co-writing/quality-report.ts`（保留类型 re-export 兼容）；
  - `calculateChapterMatches` + `buildMatchCard` → `ui/co-writing/chapter-match.ts`，三处重复的内联 match 形状统一为 `ChapterMatch` 类型。
