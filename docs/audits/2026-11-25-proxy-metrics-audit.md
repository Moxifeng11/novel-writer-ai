## 一、代理指标准确性实测（有数据）

用三组已知朱雀结果的样本交叉验证 `anti-ai-detector`：

| 组 | 朱雀人工率 | 样本 | anti-ai 判定「AI 味分」 |
| --- | ---: | ---: | ---: |
| 真人网文（完美世界/将夜/武动/紫川/莽荒纪/诡秘/雪中） | **100%** | 7 | **10.6** |
| 云笔 5570 | 42.3% | 4 | **9.0** |
| AI 模板（议论文/网文/抒情） | **0%** | 3 | **14.0** |

### 判定：排序完全错误

**理想排序**：真人 < 云笔5570 < AI模板（AI 味分应该单调递增）

**实际排序**：**云笔(9.0) < 真人(10.6) < AI模板(14.0)**

- ❌ **真人的 AI 味分（10.6）比云笔（9.0）还高** —— 方向反了
- ❌ AI 模板只拿到 14/100 —— 完全没有区分度（本该接近满分）
- ❌ 真人样本里有 3 部（紫川/莽荒纪/诡秘之主）因「硬伤标点」被扣满 10 分——它们只是用了破折号，真人本来就在用

### 更严重：它把真人当违规

| 真人作品 | 扣分主因 |
| --- | --- |
| 紫川 | 硬伤标点 10.0（满分扣光） |
| 莽荒纪 | 硬伤标点 10.0 |
| 诡秘之主 | 硬伤标点 10.0 |
| 雪中悍刀行 | 硬伤标点 5.0 |

「硬伤标点」的判据是**分号/省略号/破折号密度**。但 139 段真人基线实测：
- 省略号中位 **2.38/千字**（P75 5.82）—— 真人在用
- 分号中位 0 —— 这条对
- 破折号中位 0（P90 才 1.19）—— 这条对

**所以「省略号」这一项是错的**，它在惩罚正常写作。

## 二、不准的指标清单（4 个，含权重）

### 1. `engine/anti-ai-detector.ts` —— 加权评分（**核心问题**）

```
模板短语 35 分上限  ← 数「眼中闪过一丝」这类短语
句式模板 20 分上限  ← 数「不是A而是B」这类句式
高频词   15 分上限  ← 密度 × 5
句长波动  8 分      ← 句长标准差映射
开头多样性 6 分     ← 连续3句开头2字重复度
标点单调  6 分      ← 标点类型数
对话密度  4 分      ← 对话占比
硬伤标点 10 分      ← 分号/省略号/破折号密度
────────────────────
totalCap 100
```

**准确性问题**：
- 加权求和把「可解释的具体命中」（短语/句式）和「模糊统计」（句长/标点）混在一起，最后给一个 0-100 的伪精确分数
- 权重是拍的（v4.10 行为基线），没有用朱雀结果标定过
- 实测排序反了（见上）

### 2. `ui/services/humanness-scorer.ts` —— 复合分（**污染最广**）

```ts
composite = 0.55 × (100 - antiAI)/100 + 0.45 × fidelity
```

**55% 权重压在已证明不准的 antiAI 上。** 而且这个 composite 被用于：
- 迭代精修的轮次判断（选哪一版）
- 「人味提升」的量化展示

**结论**：这个复合分不可信。

### 3. `shared/human-similarity.ts` —— 分布相似度

拿真人语料的句长/段长/标点/对话占比**直方图**做分布比对。

**比 anti-ai 合理**（不数特征、比分布），但：
- 它度量的仍是**句法统计**——而我们已实测这些与朱雀人工率相关性弱（长句 r=0.150）
- 基线来自本地 `human-samples/baseline.json`，只有 7 部网文的分布

**结论**：思路可以留，但**不能当「人味判据」**，只能当「风格偏离提示」。

### 4. `engine/quality-scorer.ts` —— 维度质量分

拆解各维度的质量打分。这个**不用于判断人味**，是「拆解结果自身可信度」，可以留。

## 三、Bug 清查结果

### Bug 1（严重）：「人工率」概念在两处实现、互相矛盾

| 位置 | 口径 | 状态 |
| --- | --- | --- |
| ~~`ui/co-writing/human-rate.ts`~~ | 句长/开头/标点/词表 → 0-100 | **已删（5d50639a）** |
| `engine/anti-ai-detector.ts` | 同类加权 → 0-100（方向相反） | **仍在用** |
| `engine/zhuque-detector.ts` | 朱雀真实判定 | 默认关闭 |

**同一份正文，两个「人味」指标可能给出完全相反的结论。**

### Bug 2（严重）：真人的正常写法被判为「硬伤」

见上：紫川/莽荒纪/诡秘之主因省略号/破折号被扣满分。**这会导致提示词约束过度**——`craft-constraints.ts` 用同一个 `AI_HIGH_FREQ_WORDS` 生成禁令，可能连带禁掉真人常用词。

### Bug 3（中）：`anti-ai` 的「对话密度低」判据反了

它认为「对话密度低 = AI 味重」（4 分）。实测：
- 云笔 5570（人工率 42.3%）引号 **25.0/千**
- 云笔 6153（人工率 0%）引号 **1.6/千**
- 真人中位 **18.53/千**

**对话密度确实是弱正相关（r=0.453），这条方向是对的**——但它的权重只有 4 分，而错得离谱的「模板短语」占 35 分。

### Bug 4（中）：`humanness-scorer` 的 baseline 缺失时静默降级

无基线时 `composite = 0.55×antiAI + 0.45×fidelity`，humanSim 记 0。
用户看不出「这次评分没包含人味维度」。

### Bug 5（低）：拆解卡死的三根因已修，但 `sampleMode` 语义仍混乱

已加硬上限 15 万字兜底，但 `sampleMode=false + textSampleLimit=10000000` 这种矛盾配置仍可能出现在老用户 data.json 里（我手动改了当前配置，但没有迁移逻辑）。

## 四、处置建议（需你决定范围）

### 方案 A：只删「判定」，保留「约束生成」（推荐，改动适中）

| 模块 | 处置 |
| --- | --- |
| `anti-ai-detector.detect()` / `score()` 加权评分 | **删**（或标 `@deprecated` 不再对外） |
| `anti-ai-detector.detectAIWords()`（具体命中列表） | **留**——它是可解释的，不产生伪精确分数 |
| `AI_HIGH_FREQ_WORDS` + `craft-constraints` | **留**（用于生成提示词禁令） |
| `humanness-scorer.composite` | **删 composite**，或把 antiAI 权重降到 0 只留 fidelity |
| `human-similarity` | **留但改名**：「风格偏离度」而非「人味分」 |
| 人味判据 | **只用朱雀** |

**理由**：删掉的是「伪精确的合成分数」，保留的是「可解释的具体命中」和「提示词约束」。
后者不声称自己是「人味判断」，不会误导。

### 方案 B：全删（激进）

把 anti-ai-detector 整体删掉。代价：
- `craft-constraints.ts` 失去高频词禁令来源（会影响提示词质量）
- `quality-gate.ts` 失去一层检查
- 需要重写 5 处消费者

**不推荐**——高频词禁令本身是有效的（它对应真实的 AI 特征），错的是「加权成 100 分」这个动作。

### 方案 C：保留但标 deprecated

不改行为，只在 UI 上标注「这是启发式估算，不代表朱雀判定」。
**最小改动，但用户仍会看到错误分数。**
