# v4.19.0 对话引导式智能 Agent 验证报告

- 日期：2026-10-28
- 版本：4.19.0（本地工作树）
- 范围：业务流程对话化、多轮槽位收集、项目创建闭环、插件接入与验证

## 一、参考与分层

参考 deepseek-harness 的分层思路，但不复制其代码：

| 层 | 本项目实现 |
| --- | --- |
| Memory（会话状态） | `AgentSlots`：项目名/题材/类型/原作/结构/基调/金手指/当前项目 |
| Tools（工具调用） | `GuideAgentPort`：创建项目、打开向导、故事结构、项目与章节、前期调研 |
| Planner（流程编排） | `GuideAgentEngine` + `SLOT_SPECS` 槽位定义 + 动态分支 |
| Runner（执行与回填） | `AgentGuideModal`：渲染消息/chips，执行 intent，`reportAction` 回填 |

引擎层不依赖 Obsidian/UI；宿主能力通过 Port 注入，便于单测与替换。

## 二、对话切入与分支

### 2.1 入口

- 命令面板：`🤖 对话引导（新建/继续项目）`（`novel-writer-agent-guide`）。
- 项目与章节页：长篇小说空态新增「🤖 对话引导创建（推荐）」。
- 两个入口都直接打开同一个 Modal，不跳转页面。

### 2.2 根分支

开场先根据上下文判断：

- 无项目：创建长篇 / 短篇前期调研 / 剧本前期调研 / 退出。
- 有项目：额外提供「继续现有项目」；仅一个项目时自动选中。
- 支持自由文本「创建」「继续」「短篇」「剧本」及 chips。

### 2.3 创建分支

槽位顺序：

1. 项目名（支持随机书名；校验长度、字符、保留名、重名）
2. 题材（chips 或自由文本）
3. 项目类型（原创/同人）
4. 原作名称（仅同人）
5. 故事结构（五套 + 智能随机）
6. 叙事基调（可跳过/随机）
7. 金手指（可跳过/随机）

支持：

- `上一步` 回退并清空当前槽位；
- `取消` 退出；
- `帮助` 查看用法；
- 一句话多槽位：优先由 `createAiNlu` 解析，失败回退 chips/序号/关键词；
- `__random__` / `__skip__` 哨兵值直接生效。

### 2.4 确认与闭环

- 所有槽位完成后生成确认摘要：项目名、题材、类型、结构阶段比例、基调、金手指、随机来源。
- 用户确认 → `AgentIntent.create_long_project`。
- 宿主调用 `createLongNovelProject()`：
  - 模板复制、`.project`、创作/故事结构指南、写作配置、打开工作台；
  - 同人设定审核、覆盖确认由调用方注入；
  - 返回 `created/projectId/fileCount/reason`。
- 回填成功：显示创建完成，提供「打开项目向导 / 修改故事结构 / 打开项目与章节 / 就到这里」。
- 回填失败：显示原因，提供「修改设定重来」或退出。

### 2.5 继续现有项目

- 点选/序号选择项目；
- 菜单分支：打开向导、修改故事结构、打开项目与章节、退出；
- 对应 host 调用 `FullWriterView.openWizardForProjectById`、`StorySettingsModal`、`openFullWriterView`。

## 五、稳定性

- 会话 `busy` 锁：上一条消息处理中不接受新输入，避免重复提交/创建。
- 覆盖确认：Agent 使用 `confirmOverwrite: true`，表单弹窗使用确认弹窗；服务本身不依赖 UI。
- 循环依赖：抽取服务后曾新增 2 条，已通过移除 `main`/engine registry/动态 Modal 依赖消除；`check:deps` 基线通过。
- 引擎守卫：`GuideAgentEngine` 为每个 Modal 独立会话，已加入白名单并说明理由。
- 失败路径：创建失败/打开向导失败都回填为对话消息，不静默失败。

## 六、边界

- E2E 不复制本机 `data.json`，不会调用真实 AI；因此 AI 槽位解析只做单元测试，真实模型解析质量未评估。
- 对话引导覆盖「创建/继续项目 + 入口衔接」，不替代 11 步写作流程本身；创建完成后仍进入原有向导/工作台。
- 短篇/剧本的完整对话流程只提供前期调研入口，未把其创建表单全部对话化。
- 同人 Agent 创建暂未包含原作设定选择；表单弹窗仍保留完整同人流程。
- 版本仍为 4.19.0，未提交/推送。


## 七、类型专属流程迭代（2026-10-28）

### 7.1 最前端项目类型入口

开场不再直接进入长篇创建，而是先给：

- 📖 长篇小说
- 📄 短篇小说
- 🎬 剧本
- 📂 继续现有项目（有项目时）
- ❌ 退出

### 7.2 长篇双路径

- 原创：项目名 → 目标频道 → 题材 → 故事结构 → 叙事基调 → 金手指。
- 同人：项目名 → 原作名称 → 题材 → 同人类型 → 改动范围 → 故事结构 → 叙事基调。
- 两条路径共用 `createLongNovelProject()`，但确认摘要和后续提示词不同；同人额外把原作/同人类型/改动范围带入 intent。

### 7.3 短篇路径

节点压缩为 8 个：项目名 → 平台分类 → 一句话故事 → 核心冲突 → 情绪承诺 → 反转设计 → 结尾兑现 → 主角核心。

- 默认 8 万字 / 20 节，不再让用户填长表单。
- 确认后 `DomainProjectFactory` 创建短篇项目，写入 `00-前期调研/调研数据.json`、报告与五维分类，并打开工作台。
- 创建后可继续编辑前期调研或打开项目与章节。

### 7.4 剧本路径

节点覆盖专业剧本要素：项目名 → 红果类型 → logline → 3 秒钩子 → 核心冲突 → 核心兑现 → 主要角色 → 核心场景 → 目标集数 → 强付费卡点。

- 默认 6 万字、90 秒一集。
- 创建后写入剧本定位/前期调研并打开工作台。
- 保留现有分集、分镜与协同写作流程，不重写执行引擎。

### 7.5 与现有架构的兼容

- 长篇仍走 `创建项目 → 项目向导 → 11 步流水线`；短篇/剧本走 `DomainProjectFactory → 00-前期调研 → 模式专属写作`。
- 没有修改小模型负责前置推导与正文生成的模型路由；Agent 只负责收集参数与触发入口。
- 长篇创建后的“打开项目向导/项目与章节”继续承接整篇完善与输出；Agent 不直接改写正文。
- 新增 `create_short_project` / `create_script_project` intent 与 port 方法，保持引擎层无 Obsidian 依赖。


## 八、引导/自动双模式升级（2026-10-28）

### 8.1 每个节点的选择说明

`AgentChip` 增加 `description / bestFor / risk / preview`；UI 在存在说明时渲染为选择卡：

- 预期效果：description；
- 适用场景：bestFor；
- 风险提示：risk；
- 操作预览：preview。

已覆盖：项目类型（通过类型入口）、长篇原创/同人、频道、五套故事结构、短篇分类、剧本类型、执行模式。普通 chips 保留紧凑样式。

### 8.2 引导模式

逐项提问 → 用户选择/输入 → 每步显示进度、上一步、取消；确认摘要后创建。每个槽位额外提供「⚡ 自动完成剩余项」入口。

### 8.3 自动模式

选择自动模式后：

- 已填槽位保留，只补缺失项；
- 长篇结构/基调/金手指用 `generateRandomStorySettings()` 自洽抽样；
- 短篇/剧本用平台分类、冲突/情绪/反转/角色/场景等模板生成；
- 每项都过 `validate`；任一项无法生成合法值就自动切回引导模式；
- 自动填参在本地完成，单元测试实测 `handle('自动模式') < 500ms`（不含文件创建 IO）；
- 直接产出创建 intent，无逐步输入；宿主创建时 UI 先显示“正在创建”。

### 8.4 模式切换

- 引导中任意节点输入「自动完成」→ 补完并创建；
- 任意时刻输入「自动模式」/「引导模式」→ 切换；
- 已填值保留；自动值失败回退引导。

### 8.5 验证

- 单元测试新增：长篇/短篇/剧本自动模式、自动链路 <500ms、引导中切换自动、选择卡元数据。
- E2E 第 4 条：真实 Obsidian 打开 Agent → 长篇 → 原创 → 自动模式 → 无需输入 → 创建完成并落盘。

### 8.6 边界

- 自动模式完成的是“项目创建链路”，不自动生成整本小说正文；长篇创建后进入项目向导，正文仍由现有步骤/一键完成本章产出。
- 自动填充的故事核/剧本要素是自洽模板，不是最终创作质量；用户仍可在前期调研中修改。
