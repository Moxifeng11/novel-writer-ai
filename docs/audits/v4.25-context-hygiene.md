# v4.25 写作流程与上下文污染治理

- 日期：2026-10-31
- 背景：外部检测已证明不是提示词能解决的（见 v4.23/v4.24）。这一轮回到作品本身：梳理现有写作流程，找出「上下文污染」的具体来源并修掉，再给出方法论层面的优化项。

## 一、现有流程（10 步 + 注入面）

| # | 步骤 | 产出 | 进入正文 prompt 的形式 |
|---|---|---|---|
| 0 | 上下文加载 | 世界书/设定库/人物/时间线/伏笔/上章 | `${worldView}` `${settingLib}` `${allChars}` `${timelineEvents}` `${unrevealedForeshadow}` `${prevChapEnding}` |
| 1 | 信息规划 | 本章冲突/信息释放/章末钩子 | `${infoPlan}`（+ 结构化硬要求块） |
| 2 | 情节蒸馏 | 必须发生的事件 | `${distilledContent}` |
| 3 | 角色灵魂 | 主角 9 字段 | `${protagonistSoulDetail}`（决定 V2） |
| 4 | 大纲摘要 | 本章大纲 | `${outlineContent}` |
| 5 | 情绪规划 | 情绪弧 | `${emotionPlan}` |
| 6 | Scene 展开 | 场景/对话骨架 | `${sceneExpansion}` `${dialogueSkeleton}` |
| 7 | 正文生成 | 章节 | system + user 约 30 段 |
| 8 | 质量控制 | 报告（不改稿） | 不进正文 |
| 9 | 分析报告 | 报告 | 不进正文 |
| 10 | 章节结算 | 回写状态/时间线/伏笔/记忆 | 下一章以 `${prevChapEnding}` `${longTermMemory}` 形式回来 |

**结构性观察**：规划链很长（7 步前置），但**生成后没有闭环修订**——`fix/finalFix` 已废弃，质量控制只出报告。流程把「写得好」寄希望于一次性 prompt，而不是「写→诊断→定向改」。

## 二、已确认的上下文污染源（本轮取证）

### 2.1 规则与「文笔风格」互相打架（高）

项目的 `01-世界架构/文笔风格.md` 第 16 行仍写着：

> 每段仅一个句号，句号后必须换行。

而写作规则（3.6.0 与 3.7 锚点版）要求「自然段 2–6 句、80–220 字」。两段都进 prompt，**文笔风格在 user 侧、更具体、位置更靠后**，模型通常听它 → 段落被重新打碎。

用真实文件实测（`shared/context-hygiene` 的检测器）：

| 生效规则 | 检出冲突 | 处理 |
|---|---|---|
| vault 旧版（无自然段锚点） | 每段仅一个句号 / 句号后必须换行 | 只告警「规则缺锚点」，不改风格文本 |
| 3.6.0 / 3.7.0-anchor | 同上 | 剔除冲突行（1520 → 1420 字符），其余风格描述保留 |

### 2.2 规则去重开关对正文链路无效（高，已修）

上一轮加的 `dedupeRulesInStyle` 只清空了 `writingStyle`，而正文模板实际用的是 **`writingStyleContent`**（文笔风格.md 原文）——开关拨了也不生效。本轮改为两个变量同时判重。

### 2.3 注入面过长且互相重叠（中）

正文 user 侧约 12k 字符，其中：

- 场景展开 `${sceneExpansion}` 与场景卡 `${sceneCardDigest}` 同源、常有大段重复；
- 世界观 `${worldView}` 与设定库 `${settingLib}` 局部重合；
- 情节蒸馏 `${distilledContent}` 与信息规划 `${infoPlan}` 事件重叠；
- 上一章结尾同时出现在 `${prevChapEnding}` 与 `${prevChapterStateSnapshot}`。

同一条信息重复出现不会「让模型更懂」，只会**提高它在采样时的权重**，并让后一段的措辞覆盖前一段（污染）。

## 三、已落地的治理（本轮代码）

### 3.1 `shared/context-hygiene.ts`（纯函数）

| 能力 | 判定 | 动作 |
|---|---|---|
| 重复段 | 2-gram Dice ≥ 0.85 且两段都 ≥200 字 | 保留权威版本（规则 > 世界观 > 设定库 > 规划 > 场景 > 风格 > 上下文包），清空另一份 |
| 规则×风格冲突 | 风格含「一句一段/每段一个句号/句号后换行」，规则含「自然段 2–6 句」 | 剔除冲突行；若规则缺锚点则只告警 |
| 串章 | 步骤结果里出现的章节号**都不等于**当前章，且提及 ≥2 次 | 只告警（可能是合法引用） |

- 接入点：`template-vars-builder` 在账本生成之前执行，保证账本统计的是「真正发出去的段」。
- 设置：`contextHygieneAutoFix`（默认开；关掉则只报告不修改）。
- 账本：`InjectionLedger.hygiene`，执行时间线新增 `【上下文体检】1 处重复（已清空 settingLib） / 1 处规则冲突 / 1 处疑似串章`，冲突与串章逐条打印原因。

### 3.2 修掉「规则去重对正文无效」

`writingStyle` 与 `writingStyleContent` 同时走 `looksLikeWritingRules`；真实项目里两者都不含规则副本，所以行为不变；对「文笔风格里抄了规则」的项目才会真正去重。

## 四、方法论建议（按「写好小说」而不是「过检测」）

1. **单一事实源**：规则只管节奏与格式，文笔风格只管语感与用词，人物卡只管设定。同一件事只允许一处定义——本轮 3.1 把「越界」变成可检测项。
2. **每章一份「章节契约」**：进场状态 → 本章目标 → 阻碍 → 离场变化 → 钩子。信息规划已有字段，建议在正文生成前做一次「契约完整性」校验（缺项不阻断，但在账本里标出）。
3. **补回修订闭环**：质量控制之后加「按报告定向修订」（只改报告里的具体问题、保留情节与人设），这是目前流程最大的缺口——一次性生成再报告，等于把改稿全交给人。
4. **连续性账本**：人物「知道什么/在哪/伤到哪」应作为结构化事实按章累积（最新优先、带来源章号），而不是散落在正文与记忆碎片里；这是防 OOC 与防「上一章结尾复述错」的根本。
5. **注入预算按「边际信息」分配**：已经在前文出现过的内容不重复注入；场景卡与场景展开二选一（或只给差异部分）。本轮体检的重复检测可直接作为预算裁剪的输入。
