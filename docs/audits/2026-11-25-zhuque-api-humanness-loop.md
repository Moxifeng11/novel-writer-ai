## 一、API 接入（已打通）

### 端点与凭据

```
POST https://ai-gateway.edgeone.link/v1/providers/zhuque-text/classify
Authorization: Bearer $MAKERS_MODELS_KEY
{ "text": "...", "is_merge": true }
```

- 文档：`https://cloud.tencent.com/document/product/1552/137539`（腾讯云 · 使用朱雀模型）
- Key 来源：EdgeOne Makers 控制台 → Models → API Key（用户已开通，永久有效）
- **Key 存放**：仓库根 `.env.local` 的 `MAKERS_MODELS_KEY`（已加 `.gitignore`，不进版本库）
- 额度：Makers 每月 **500,000 tokens** 免费；响应里 `makers_models_usage.total_tokens` 是真实扣费数

### 踩坑记录（Git Bash 特有）

**中文 body 在 Git Bash 里会被 shell 破坏编码**，导致 API 返回 `Invalid request body`。
用文档原文 `"hello world"`（纯 ASCII）测试立刻 200 —— 确认是 shell 编码问题，不是 body 格式问题。
**结论：一律用 Node/脚本发请求，不要用 `curl -d '{"text":"中文"}'` 在 Git Bash 里测。**

### 工具

`scripts/zhuque-detect.mjs`（新增）：

```bash
node scripts/zhuque-detect.mjs --text "..."                 # 单条
node scripts/zhuque-detect.mjs --file ch.md                  # 单文件
node scripts/zhuque-detect.mjs --file ch.md --segments       # 分段打分（定位 AI 味集中段）
node scripts/zhuque-detect.mjs --dir chapters/ --json --out r.json   # 批量 + 机器可读
```

返回归一化字段（口径固定，供实验脚本消费）：

| 字段 | 含义 |
| --- | --- |
| `humanRate` | **人工占比（0–100）** —— 本仓「人工率」就取这个 |
| `aiRate` / `suspectedRate` | AI 占比 / 疑似 AI 占比 |
| `softmax` | 整体判定置信度（越高越像 AI） |
| `billedTokens` | 真实扣 Makers 免费额度的 token 数 |
| `segments[]` | 分段结果（`--segments` 时） |

## 二、基线标定（2026-11-25 实测）

用公版文学做「确定人工」锚点，AI 模板文本做「确定 AI」对照：

| 样本 | 人工率 | softmax | 判定 |
| --- | --- | --- | --- |
| 鲁迅《孔乙己》节选 | **100%** | 0.0107 | 人工 |
| 老舍《骆驼祥子》节选 | **100%** | 0.2895 | 人工 |
| 沈从文《边城》节选 | **100%** | 0.0101 | 人工 |
| AI 三段式议论文 | 0% | 0.9999 | AI |
| AI 网文开篇（模板化） | 0% | 0.9999 | AI |
| **本仓示例项目第2章** | **0%** | 0.9982 | **AI** |

**结论**：API 判别力极强且方向正确。本仓产物与「AI 模板文本」同档（softmax 0.9982 vs 0.9999），
离人工锚点（0.01–0.29）差距是两个数量级。

## 三、归因分析（纯本地统计，不费额度）

用 638 字连续人工文本 vs 两种 AI 文本，同口径 15 项指标对比：

| 指标 | 人工《孔乙己》 | AI-议论文 | AI-网文 | 可分性 |
| --- | --- | --- | --- | --- |
| **句长标准差** | **17.3** | 7.5 | 9.2 | ✅ 人工显著更高 |
| **长句占比%（≥40字）** | **30.0** | 0 | 0 | ✅ 人工显著更高 |
| **破折号/千字** | **6.3** | 0 | 0 | ✅ 人工显著更高 |
| **模糊限定/千字**（大抵/几乎/往往） | **4.7** | 0 | 0 | ✅ 人工显著更高 |
| **地点锚点/千字** | **28.2** | 0 | 2.8 | ✅ 人工显著更高 |
| **口语词/千字** | 54.9 | 71.9 | 81.5 | ✅ **AI 反而更高** |
| 分号/千字 | 6.3 | 0 | 0 | ✅ |
| 连词开头%（首先/其次/总之） | **0** | **72.7** | 0 | ✅ AI 议论文特征 |
| 平均句长 | 30.9 | 29.4 | 22.7 | ✗ 不可分 |

### 三条最重要的发现

**① 句长节奏是最大区分点，且方向与直觉相反。**
人工文本句长标准差 17.3（长短交错剧烈），AI 文本 7.5–9.2（平稳）。
本仓历史一直在做「短句、碎段」（历史 CHANGELOG 明确记载「短叙述占比 82–95%，碎过头」），
**这恰恰是 AI 特征，不是人味特征**。

**② 口语词多反而是 AI 特征。**
人工 54.9/千字 vs AI 71.9–81.5/千字。历史实验一直在「加口语词」，方向可能是错的——
人写小说时口语词密度并不高，AI 为了「显得自然」会堆砌「了/的/着/吧/啊」。

**③ 具体性（地点/时间锚点、模糊限定）是人工独有的。**
《孔乙己》有「柜台/坛子/壶/店面」等具体物象 28.2/千字，AI 文本几乎为零。
「大抵/几乎/往往」这类**不确定语气**也是人类叙事的标志，AI 倾向于绝对化表述。

## 四、迭代方案（按证据强度排序）

### 阶段 1：改一条，测一次（成本可控）

| # | 改动 | 依据 | 预期 | 测量 |
| --- | --- | --- | --- | --- |
| 1 | 提示词加入**句长节奏要求**：每 300 字至少 1 句 ≥40 字；句长标准差目标 ≥15 | 归因 ①② | 长句占比 0%→25%+，softmax 下降 | 朱雀 humanRate |
| 2 | **降低口语词密度**：删除「多用了/吧/啊」类指令 | 归因 ② | 口语词 48→55 区间 | 同上 |
| 3 | 强化**具体物象**：要求「每段至少 1 个可触摸的具体物（器物/食物/衣物/建筑部件）」 | 归因 ③ | 地点锚点 0→20+ | 同上 |
| 4 | 加入**不确定语气**：允许「似乎/多半/大约/恐怕」 | 归因 ③ | 模糊限定 0→4+ | 同上 |

**每条独立 A/B**：同一章大纲 + 同一模型 + 同温度，只改一条指令，朱雀 `humanRate` 作为主指标。
预算：每章约 1500 字 ≈ 1800 tokens，一条指令跑 3 个样本 ≈ 5400 tokens。
4 条 × 3 样本 = 21,600 tokens（免费额度 4.3%）。

### 阶段 2：组合验证 + 分段定位

阶段 1 找到有效指令后组合，并用 `--segments` 定位「哪些段落仍是 AI 判定」，
针对性地看是「叙述段」还是「对话段」拉低整体。

### 阶段 3（若阶段 1/2 撞天花板）：换攻法

如果提示词改动后 `humanRate` 仍稳定在 0–10%，说明瓶颈在模型 token 分布层
（与历史 6 组实验结论一致）。此时可行的方向：
- **后处理层**：`shared/prose-naturalizer.ts` 已有自然段重排，可扩展「句长节奏重塑」（合并短句、注入具体物象）
- **人工介入点**：在关键章节引入人工改写环节，而不是继续堆提示词

## 五、预期校准（重要）

历史 6 组实验的核心发现是「**局部指标全变、朱雀判定不变**」——
段数 2→96、平均句长 19.4→13.5、对话占比 9%→17.2%，判定仍是同一档。

**这意味着**：如果阶段 1 的四条改动全部让指标达标但 `humanRate` 仍是 0%，
那说明提示词层面的天花板是真实的，**应该诚实报告这个结论，而不是继续无边界地试指令**。

但本次与历史有三点不同，值得一试：
1. **模型已更新**（用户明确说旧结果不具参考性）
2. **测量成本降到几乎为零**（API vs 网页手工），可以跑大样本而非 n=1
3. **归因方向反了**（历史一直做「短句/碎段/加口语」，而数据显示应该做「长短交错/减口语/加具体物象」）
