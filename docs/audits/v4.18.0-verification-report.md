## 3. 高危问题清单与处理

### P0-1 覆盖写先删后建（数据丢失）

- **位置**：
  - `ui/generate-worldview-modal.ts`
  - `ui/ai-builder-modal.ts`
  - `ui/plan-book-modal.ts`
  - `ui/cross-volume-state-modal.ts`
  - `ui/batch-chapters-modal.ts`
  - `ui/diagnose-writer-modal.ts`
- **触发条件**：目标文件已存在，用户确认覆盖；随后 `vault.create` 因权限、磁盘、路径冲突失败。
- **影响**：旧世界观/状态快照/信息债看板/诊断报告已被删除，新文件未创建。
- **影响用户**：重复生成世界观、跨卷快照、信息债、诊断报告的写作者。
- **等级**：P0（数据丢失）。
- **处理**：全部改为 `existing instanceof TFile ? modify : create`，不再先删旧文件。
- **验证**：typecheck 通过；相关模块无新增运行时错误。

### P0-2 AI 全书规划先清空旧分卷大纲（数据丢失）

- **位置**：`engine/ai-outline-generator.ts` Phase -1。
- **触发条件**：重新生成全书规划；AI 蓝图/分卷生成失败或用户取消。
- **影响**：旧分卷大纲已被删除，生成失败后无法恢复。
- **影响用户**：重新规划已有项目的作者。
- **等级**：P0（数据丢失）。
- **处理**：删除前把旧 `_分卷大纲.md` 汇总备份到 `04-项目总控/分卷大纲备份_<时间戳>.md`；备份失败则保留旧文件不删除。新内容成功生成后仍由 `writeVolumeOutlines` 清理残留旧卷。
- **残余风险**：备份成功后生成失败，不会自动回滚；备份文件保留，可手工恢复。

### P0-3 顶层项目重命名生成 `旧名/新名`

- **位置**：`services/project-rename-service.ts`（v4.18 新增）。
- **触发条件**：对顶层项目重命名；旧实现 `replace(/\/[^/]+$/, '')` 在没有 `/` 时返回自身。
- **影响**：新目录嵌套在旧项目内，项目路径、工作台和 `.project` 全部错位。
- **影响用户**：所有顶层项目重命名用户。
- **等级**：P0（项目结构破坏）。
- **处理**：父路径改为 `includes('/') ? slice(0,lastIndexOf('/')) : ''`；单测覆盖顶层重命名。
- **验证**：`project-rename-service.test.ts` 通过。

### P0-4 更新缓存版本与仓库名不一致

- **位置**：`services/update-checker.ts`、`core/settings-service.ts`、`shared/settings-migrator.ts`。
- **证据**：`data/cache.json` 曾同时存在 `lastRunVersion=4.18.0`、`updateLastResult.currentVersion=4.12.4`、`settingsBackup.version=4.15.0`；`data.json` 仓库为旧 `trae-ai/novel-writer-ai`。
- **触发条件**：插件升级后检查间隔未到，直接返回旧缓存；旧默认仓库名未迁移。
- **影响**：更新 UI 显示旧版本号；更新检查持续 404。
- **影响用户**：所有从旧版本升级且开启自动检查的用户。
- **等级**：P1（版本信息错误/更新不可用）。
- **处理**：
  - 缓存结果按当前 `PLUGIN_VERSION` 纠正 `currentVersion` 并重算 `hasUpdate`；
  - 旧错误结果无 `latestVersion` 时纠正版本并触发新检查；
  - 旧 `trae-ai/...` 仓库迁移为 `Moxifeng11/...`；
  - 仓库变更清空旧缓存。
- **残余风险**：仓库为 Private，未带 Token 的 GitHub API 仍 404；见 §1。

### P1-1 指纹 embedding 使用旧共享 provider（向量不一致）

- **位置**：`ui/fingerprint-embedding.ts`。
- **触发条件**：用户切换向量 provider/model 后未重启插件，但共享 provider 仍是旧实例；指纹提取/重填仍用旧模型。
- **影响**：写入旧 `modelId`/维度，检索时被模型治理逻辑跳过，表现为指纹注入静默消失。
- **影响用户**：切换本地/云端向量模型、重新提取指纹的用户。
- **等级**：P1（数据不一致/功能静默失效）。
- **处理**：有显式 `settings` 时优先按当前设置构造 provider；共享 provider 只在没有设置时兜底。
- **验证**：新增 `fingerprint-embedding-settings.test.ts`。

### P1-2 同人考据 URL 可抓取本机/内网/非 HTTP 地址（SSRF/本地读取风险）

- **位置**：`services/canon-research-service.ts`。
- **触发条件**：用户在“官方资料 URL”输入 `file://`、`localhost`、`127.0.0.1`、私网地址或 `169.254.169.254`。
- **影响**：可能读取本机资源或访问内网服务；即使只保存摘录也存在安全边界问题。
- **影响用户**：使用手动来源功能的用户；恶意引导场景也需防护。
- **等级**：P1（安全）。
- **处理**：只允许 http/https；拒绝 localhost/.local/回环/私网/链路本地地址；手工来源与检索结果都经过校验。
- **验证**：新增 `canon-research-service.test.ts`。

### P1-3 全书简介覆盖写先删后建（数据丢失）

- **位置**：`ui/volume-intro-modal.ts`（v4.18 已修）。
- **触发条件**：已有 `全书简介.md`，保存新版本时创建失败。
- **影响**：旧稿丢失。
- **处理**：改为原地 `modify` + 备份；多版本目录另行保存。
- **状态**：已修复。

### P1-4 分析报告普通叙述文本被当成空结构化报告

- **位置**：`engine/analysis-report-engine.ts`（v4.17 已修）。
- **触发条件**：旧报告/叙述型报告不含 `UPDATE_` 等指令。
- **影响**：实体/时间线静默为空。
- **处理**：无结构化指令时回退 AI；仅 PROMISE/ARC 指令仍走 0 次 AI。
- **状态**：已修复，测试通过。

### P2 已知残余边界

1. GitHub 更新检查对 Private 仓库仍需要用户配置 Token；未配置时 404 是预期行为，不是版本错误。
2. AI 全书规划备份需要手工恢复；未实现自动回滚。
3. 同人审核 AI 复核/补全依赖外部模型，仍必须人工通过；这是设计约束，不是缺陷。
