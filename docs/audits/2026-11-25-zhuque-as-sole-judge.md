# 朱雀参数作为唯一判据（2026-11-25）

> 状态：**判据已切换，测量受阻于额度** · 2026-11-25 · ZCode
> 用户要求：「人工率判断不用句长这些模糊字段。直接使用朱雀模型参数识别判断。」

## 一、为什么要放弃代理指标

此前用句长、段落均字、单句成段做判据。实测证明这些**相关性很弱**：

| 指标 | Pearson r vs 朱雀人工率 | 结论 |
| --- | ---: | --- |
| 引号/千字（对话密度） | 0.453 | 中等 |
| 段落均字 | 0.450 | 中等 |
| **长句占比（≥35字）** | **0.150** | **弱到不能做判据** |

**长句就是被这些代理指标误导的例子**：
- 代理指标说「21.60% < 真人 P25 26.98%，是缺口」
- 但 A/B 实测：把长句从 39.6% 改成 11.2%，朱雀分数没变差
- 而且人工率 42.3% 的云笔 5570 长句只有 13.79%

**结论**：只有朱雀返回的 `labels_ratio` 可信。

## 二、判据口径（唯一）

朱雀返回：
```json
{
  "labels_ratio": { "0": 0.42, "1": 0.15, "2": 0.43 },
  "softmax_confidence": 0.6339,
  "ratio_confidence": 1,
  "makers_models_usage": { "total_tokens": 835 }
}
```

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `labels_ratio['0']` | **人工占比** | 主判据 |
| `labels_ratio['1']` | AI 占比 | 辅助 |
| `labels_ratio['2']` | 疑似 AI 占比 | 辅助 |
| `softmax_confidence` | 越高越像 AI | 排序/灵敏度 |

判定档位：

| 人工率 | 档位 |
| ---: | --- |
| ≥80% | HUMAN |
| ≥50% | LIKELY-HUMAN |
| ≥20% | MIXED |
| >0% | LIKELY-AI |
| =0% 且 softmax>0.99 | AI |
| =0% 且 softmax≤0.99 | AI(low-conf) |

## 三、工具：scripts/zhuque-ab.mjs

纯朱雀口径的 A/B 实验器，**不再计算任何句法指标**。

```bash
# 单文件
node scripts/zhuque-ab.mjs --file ch.md

# A/B 两组对比（直接给「B 优于 A N 个百分点」）
node scripts/zhuque-ab.mjs --dir-a dirA --dir-b dirB

# 机器可读
node scripts/zhuque-ab.mjs --dir-a dirA --json
```

这是目前最大的信息空白——三因子全达标但朱雀分数完全未知。
如果这 3 章能到 50%+，说明本仓已接近达标；如果 0%，说明三因子模型不完整。

**第二优先：验证小片段判据**

- 真人 500 字 → 100%（已验证 n=1）
- 本仓 500 字 → ？

**第三优先：按朱雀分数做提示词 A/B**

不再看句长，只比较「A 组人工率 vs B 组人工率」。

## 七、方法论更正记录

| 之前做法 | 问题 | 现在 |
| --- | --- | --- |
| 用句长/段落/单句成段做判据 | r=0.150 长句、0.45 对话，都不够强 | **只用朱雀 labels_ratio** |
| 用「与 139 段真人基线比」判断缺口 | 和朱雀结果无因果关系 | **只比朱雀分数** |
| 单次测量下结论 | 单章方差极大（22.94%↔39.58%） | 每组至少 3 样本取均值 |

**用户这次的要求本质上是**：不要用「可能相关的代理指标」替代「真实目标」。
这是对的——代理指标会让人优化错方向（长句就是这么白忙一场）。
