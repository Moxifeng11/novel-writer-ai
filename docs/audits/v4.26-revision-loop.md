# v4.26 修订闭环（质量控制 → 定向修订 → 闸门 → 可回滚）

- 日期：2026-10-31
- 背景：流程 10 步里 7 步是前置规划，正文生成后只有「质量控制」报告，`fix/finalFix` 已废弃——改稿全靠人。本轮把「按报告定向修订」接回主流程，并加接受闸门与版本备份。

## 一、闭环结构

```
正文生成 → 质量控制（14 项报告）
        → 解析问题（高/中优先，最多 8 条）
        → 定向修订（单次调用，锁定人物/情节）
        → 接受闸门（长度 ±10% / 人物不丢 / 对话占比不塌 / 非 JSON）
        → 采纳：先存章节版本，再写回正文，失效下游 QC/分析/结算
           拒绝：保留原稿，Notice 说明原因
```

- **手动入口**：写章面板「🎯 定向修订」按钮（原有入口，现在走闸门）。
- **自动入口**：设置「质量控制后自动定向修订」（`autoRevisionAfterQC`，默认关；每次 1 次正文调用）。只在 QC 结构完整（`verdict=complete`）时触发。

## 二、闸门口径（`engine/revision/revision-guard.ts`）

| 条件 | 阈值 | 拒绝原因示例 |
|---|---|---|
| 字数比例 | 0.9–1.1 | `字数减少 23%（超过 10% 上限）` |
| 锁定人物 | 原稿出现过的名字全部保留 | `丢失锁定人物：沈铁山` |
| 对话占比 | 跌幅 ≤ 5 个百分点 | `对话占比下降 7 个百分点（上限 5）` |
| 形态 | 非空、非原样、非 JSON/代码块 | `修订稿看起来是 JSON/代码块，不是正文` |

锁定人物来源：`allChars` 解析出的名字，且只锁定原稿里真的出现过的（不要求模型凭空补人）。

## 三、可回滚

采纳前用 `ChapterVersionService.saveVersion(project, 'chapter', chapterName, chapDir, 原稿, { type: 'manual', note: '定向修订前自动备份' })` 存一份；失败只告警不阻塞（修订仍会走闸门）。

## 四、同时修掉的提示词矛盾

质量控制提示词第 2 项原来要求「每段仅 1 个句号 + 换行」，与写作规则的「自然段 2–6 句」正面对冲，已改为「以自然段为主（2–6 句、80–220 字），一句成段全章不超过 5 处」。

## 五、验证

- 全量 `vitest` 471 文件 / 5443 用例；`tsc` / `lint` / `check:deps`（无新增）/ `build` / `check:release` / 真实 Electron E2E 23 passed。
