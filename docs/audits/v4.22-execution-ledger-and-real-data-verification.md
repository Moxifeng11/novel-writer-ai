- 日期：2026-10-31

## 一、起因

前几轮把机制建齐了，但三处「建好没跑过真数据 / 跑完读不到结果」：

| 缺口 | 取证 |
|---|---|
| `run_command` 只有 boolean 出口 | `main.ts` 的 `executeCommand` 对 registry 命令 fire-and-forget；`host-tools.run_command` 返回「请提示用户在界面继续操作」 |
| `SettlementResult` 无用后可达处 | 写章弹窗仅用于拼 Markdown（`ui/write-chapter-modal.ts:570`）；结算弹窗写文件即弃（`ui/chapter-settlement-modal.ts:148`）；`step-runner.executeSettlement` 返回 `Promise<void>`，调用方丢弃 |
| RAG 参数没有基准 | 阈值 0.35 / λ=0.7 / 各维度 topN 全为拍定值，无回归指标 |
| 数据级反 AI 在存量项目是否生效未知 | 只在单测与新建模板上验证过 |

## 二、执行登记表（`services/execution-ledger.ts`）

- 纯内存、无 Obsidian 依赖、上限 20 条；`begin/finish/recordCompleted/recordFailed/attachSettlement/getRecent/getRunning`。
- `summarizeSettlement()` 把 `SettlementResult` 投影成 8 个计数 + 伏笔闭环结论（定义见 `engine/settlement-engine.ts:61-93`）。
- 与 FullWriterView 私有的 `ExecutionRunStore`（`ui/full-writer-view.ts:134`）**刻意解耦**：后者是单视图 UI 状态，Agent/端口无法触达；登记表放在 services 层供 UI 与 Agent 共用。

埋点（完成/失败双向留痕）：

| 位置 | commandId | 记录内容 |
|---|---|---|
| `ui/write-chapter-modal.ts` 结算成功处 | `novel-writer-write-chapter` | 章节 + 结算摘要 |
| `ui/chapter-settlement-modal.ts` 完整结算 | `novel-writer-chapter-settlement` | 结算摘要；异常时 failed + 原因 |
| 同上 轻量结算 | `novel-writer-chapter-settlement-light` | 结算摘要 |
| `engine/step-runner.ts` 步骤式结算 | `novel-writer-chapter-settlement` | 成功摘要 / 无结果 / 抛错；已 settled 的幂等跳过也留痕 |
| `ui/export-manuscript-modal.ts` 导出成功 | `novel-writer-export-manuscript` | 章数/字数 |
| `ui/command-ui-executor.ts` 看板生成 | `novel-writer-generate-bases` | 生成数量；异常 failed |

读取链路：`agent-port.getExecutionLedger()` → 工具 `get_execution_status`（可过滤项目、limit 夹到 1–20、结算摘要逐项渲染、进行中不显示耗时）。`run_command` 同时改为 `await plugin.executeCommandAsync()`，派发即抛错不再被吞。

## 三、RAG 评估基准

- `shared/rag/eval-score.ts`：`scoreRetrieval()` 输出 hit@k / MRR / 近重复占比；CLI `scripts/eval-rag-retrieval.mjs`（`npm run eval:rag -- --input <fixture>`）零依赖、无输入时退出 0（不阻塞 CI）。
- **近重复用重叠系数**（`|A∩B| / min(|A|,|B|)`）：400/40 重叠分块产生的重复是「一段包住另一段」，Jaccard 会因长度差把 0.95 的重叠压到 0.7，于是「前三条在说同一件事」测不出来。首个样本 fixture 上实测：Jaccard 判 0%，重叠系数判 33%（与构造的 1/3 重复一致）。
- 冒烟 fixture：`tests/fixtures/rag-eval-sample.json`（6 条查询，覆盖命中/未命中/k 之外命中/近重复），输出 `hit@5=66.7% MRR=0.500 近重复=5.6%`——这是**评分器冒烟**，不是质量基线。真实基线需要「≥3 章真实正文 + 已拆解参考书向量索引」，当前唯一真实项目只有 1 章有正文，无法采集（见第五节）。

### 4.1 缺陷 1：存量信息规划解析为空（约束静默失效）

- 现象：`parseInfoPlanFields(第1章_信息规划.md)` → 6 个字段全空、`foreshadowPlant=[]`，`formatInfoPlanPromptBlock` 返回空串。
- 根因：旧模板写成 `**伏笔操作（本章埋设）**：` + markdown 表格；`extractSection` 只认 `^## 标题`，`readListItem` 只认 `- 需埋下的新伏笔：`。
- 修复：`extractSection` 兼容 `#{2,4}` 与 `**…**` 标题、以及下一个小节边界；新增 `readTableFirstColumn()` 兜底取表格首列（跳过表头/分隔行）。
- 修复后：同一文件解析出 5 条埋设伏笔，`formatInfoPlanPromptBlock` 输出 75 字符硬要求块。

### 4.2 缺陷 2：伏笔闭环误报（中文引号 + 简写名）

- 现象：修复 4.1 后 5 条计划里 4 条被判「未埋设」，实际报告里都存在。
- 根因：`normalizeName` 只剥 ASCII 引号，`裴无极“记下名字”` 的弯引号保留 → 与 `裴无极让姜晚"记下名字"并远喊"三个月"` 对不上；`姜晚的断口` vs `姜晚剑柄缠绳断口` 因虚词与修饰语不匹配。
- 修复：归一 `\u201c\u201d\u2018\u2019\u300c\u300d\u300e\u300f`；比较前去掉 `的/之/了/个/着`；短名（≤2 字）不做覆盖率放宽；其余以 2-gram 覆盖率 ≥0.6 视为覆盖。
- 修复后：`missingPlant` 只剩 `陆昭案关联` —— 与该项目自己的质检结论 `CRITICAL_FAIL: 伏笔操作-陆昭案关联 | 未实现` 完全一致，属**真阳性**。

### 4.3 缺陷 3：看板生成不幂等

- 现象：同一项目第二次执行「📊 生成/刷新项目看板」报 `File already exists`（E2E 串行跑第二遍时暴露）。
- 根因：`.看板/` 是点开头隐藏目录，Obsidian vault 索引不收录 → `app.vault.getAbstractFileByPath()` 恒为 null → 走 `vault.create()`。
- 修复：`writeProjectBases()` 改用 `adapter.write()`（不受 vault 索引限制、自带覆盖语义）。
- 回归：E2E 内同一项目连跑两次，两次记录均 `done`。

### 4.4 上游协议补字段

- 8 个人物 0 个有 `修为等级`/`当前位置`，实体图谱的「谁在哪/什么境界」长期为空。
- 根因不在白名单（v4.20 已补），而在**分析报告协议只给了 `UPDATE_CHARACTER: [[角色]] | 当前状态 | 新值` 一个示例**，模型照抄。
- 修复：`engine/prompts/chapter-pipeline-prompts.ts` 与 `engine/ai-chapter-helpers.ts` 增加 `修为等级`/`当前位置`/`所属势力`（人物）与 `当前状态`（物品）的显式示例，并在强制规则里写明「不输出会导致图谱为空」。

## 五、成本观测

`step-runner` 的 `prompt-ledger` 追加：

```
【本步成本】模型调用 1 次（本步） · 检索 N 次 · 嵌入 M 次（缓存命中 H/T） · 输入 ~K token
```

`M` 取 `retrieval.cacheMisses`（= 真正发生的嵌入请求）。事件 `debug` 同步带 `embeddingCalls`/`retrievalQueries`/`cacheHits`/`cacheMisses`，执行时间线与调试日志一致。

### 7.1 实测暴露并修复的 6 个缺陷

1. **正文对话校验误判（每章必中）**：`validateBodyGeneration` 的对话正则只有 ASCII `"` 与「」，中文弯引号不匹配 → 2682 字含 18 对对话的正文被判「缺少 对话描写」→ 一键成文中断在正文步。改为统一 `DIALOGUE_PATTERN`。
2. **质量控制校验误判**：真实输出 `## 一、写作技法检查` / `## 【修改建议汇总】` 不被 `## 关键词` 匹配；且三项必填齐全（found=3）但缺加分项时 score=80 < 85，`missing` 仍为空 → 用户看到「内容不完整」却没有原因。规范化中文序号/包裹符 + 三项齐全即判 complete。
3. **模型空返回导致整章中断**：思考型模型把预算全花在 reasoning、`content` 为空且 `finish_reason=stop` → 旧实现直接返回「AI返回为空」→ 步骤报错。现同模型**关闭思考重试一次**（流式 + 非流式）。
4. **后台整章异常被吞**：`runBackground` 由命令层 fire-and-forget，实测跑了 15 分钟毫无反馈（异常没人接）。现 try/catch → 执行登记表记 failed + 界面提示。
5. **同一章重复结算**：一键成文与后台整章先后跑到同一章，各自无条件 `settle` → 实体重复更新、`status` 在 settled/written 之间翻。后台整章加「磁盘已 settled 则跳过」守卫。
6. **按标题重命名后章节反解失败**：正文重命名为 `第2章_锁痕_正文.md` 后，`openChapterByPath` 与 `parseChapterFromPath` 的正则要求「第N章_正文.md」紧贴 → 「请先打开一个章节」。改为按 `第N章` 前缀反解。

### 7.2 实测中发现但未修（记录在案）

- **RAG 未在真实链路触发**（`embeddingCalls=0`）：`写作知识库/` 只有索引与标签体系，没有拆解参考书。要验证 RAG 需先导入并拆解 ≥1 本书。
- **信息债看板 ENOENT**：结算读取尚不存在的 `04-项目总控/信息债看板.md` 会打一条 console error，随后由结算写出，不影响结果。
- **自动化入口竞态**：工作台从 `workspace.json` 恢复时 `openChapterByPath` 复用旧 tab 可能未回填视图状态，`real-ai.spec.ts` 遇此显式 skip 并留日志（真实用户手点章节不受影响）。

## 八、遗留（仍需样本或单开一轮）

1. **RAG 质量基线未采集**：需「已拆解参考书的向量索引 + ≥3 章真实正文」；当前真实项目只有 1 章已写。
2. **结算表与出场记录在真实项目缺位**（步骤式结算路径）：一键成文不写结算表；`结算表.md` 只在后台整章/结算弹窗写。若要 Bases 看板完整，建议单独一轮统一。
3. **`get_execution_status` 只覆盖有完成点埋点的命令**：纯界面跳转/弹窗类命令不登记，工具会明确说明「该命令不需要登记」。
