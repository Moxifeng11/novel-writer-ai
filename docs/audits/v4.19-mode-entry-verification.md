# v4.19.0 短篇小说 / 剧本模式入口验证报告

- 验证日期：2026-10-26
- 插件版本：4.19.0
- 验证方式：源码盘点 + Obsidian 运行时 DOM / 命令注册 / 设置页检查
- 验证范围：Ribbon、命令面板、插件主界面、工作台 Tab、右侧快捷工具、项目卡片/详情、设置页、侧边栏组件、批量建章与导出入口

## 一、结论摘要

1. **短篇小说与剧本模式本身存在且可用**：新建项目弹窗内的「创作模式」有三个按钮，短篇/剧本字段可正常切换。
2. **独立入口确认缺失**：Ribbon、命令面板、插件主界面 Tab、侧边栏、文件/编辑器菜单中均没有名为「短篇小说」「短剧剧本」的入口或命令。
3. **唯一可达路径是间接的**：`项目与章节（工作台） → 右侧快捷工具 → 项目规划 → 新建项目 → 创作模式`。
4. **没有启用开关**：设置数据 90 个键中没有短篇/剧本/创作模式开关；设置页 16 个分区中也没有「创作模式」分区。模式是常开状态。
5. **没有权限限制或加载异常**：插件 4.19.0 已加载，注册 46 个命令，4 个插件 Ribbon 图标，运行时 `dev:errors` 为空；模式按钮可见、可点击、未禁用。
6. **发现一个高影响入口行为异常**：从短篇/剧本项目详情点击「批量建章」时，弹窗默认选中的是项目列表第一个项目（当前为长篇《九霄逆脉行》），没有跟随当前选中项目；用户不手动切换就会看到长篇 3 卷/400 章并可能误建到错误项目。

因此，当前问题应准确描述为：**“短篇/剧本的独立入口与按名称发现能力缺失，且批量建章入口未绑定当前项目”**，不是“模式功能未实现”。

## 三、模式显示状态

### 3.1 新建项目弹窗

运行时 DOM 状态：

- 默认：`📖 长篇小说` 为 active，`📄 短篇小说`、`🎬 短剧剧本` 均可见且未禁用。
- 点击短篇后：
  - active 变为 `📄 短篇小说`；
  - 「番茄短篇分类（必选）」显示，25 个选项；
  - 「目标字数」显示，默认 80000；
  - 红果短剧字段隐藏。
- 点击剧本后：
  - active 变为 `🎬 短剧剧本`；
  - 「红果短剧类型（必选）」显示，13 个选项；
  - 「目标集数」默认 80、「目标字数」默认 80000；
  - 番茄短篇字段隐藏。

结论：模式选项本身显示和切换正常，不存在 CSS 隐藏、禁用、权限拦截或加载失败。

### 3.2 项目卡片与详情

用两个临时项目验证（验证后已删除）：

- 短篇项目卡片：`短篇小说 · 婚姻家庭`，计数 `0节`；详情显示 `总节：0`、`已完稿：0 节`。
- 剧本项目卡片：`短剧剧本 · 都市逆袭`，计数 `0集`；详情显示 `总集：0`、`已完稿：0 集`。

结论：一旦项目以短篇/剧本模式创建，项目层的模式显示是正确的；但这是“创建后的显示”，不能替代创建入口。

### 3.3 批量建章入口

- 从短篇项目详情点击「📦 批量建章」：
  - 实际弹窗默认项目为《九霄逆脉行》；
  - 标题 `📦 批量建章（按全书规划）`；
  - 显示 `3 卷 / 400 章`；
  - 按钮 `批量创建全部卷章节`。
- 手动把下拉框切到短篇项目后：
  - 标题变为 `📦 批量建节（短篇模式）`；
  - 说明变为短篇不依赖分卷大纲；
  - 按钮变为 `创建 20 节骨架`。
- 手动切到剧本项目后：
  - 标题变为 `📦 批量建集（剧本模式）`；
  - 按钮变为 `创建 60 集骨架`。

结论：批量建章的模式分支逻辑是正确的，但入口没有携带当前项目上下文，导致用户从短篇/剧本项目进入时先看到长篇状态。

### 3.4 导出入口

从剧本项目详情点击「📦 成稿导出」：

- 项目下拉框正确选中当前剧本项目；
- 摘要显示「共 N 集」；
- 「包含卷标题」隐藏；
- 「包含章标题」改名为「包含集标题」。

结论：导出入口的项目上下文与模式显示均正常。

## 四、异常清单

### P1 — 无独立模式入口，按名称不可发现

**表现**

- Ribbon、命令面板、主界面 Tab、侧边栏、菜单均没有「短篇小说」「短剧剧本」入口。
- 命令面板搜索「短篇」「短剧」「剧本」得到 0 个插件命令。
- 唯一路径是通用的「新建项目」，且工具描述为「创建原创或同人项目（支持 AI 随机构思）」，没有提到三种模式。

**影响**

- 新用户或从旧版本升级的用户无法通过常规导航发现短篇/剧本模式。
- 用户会认为“插件没有这两个模式”，而不是“藏在新建项目弹窗里”。
- 这是本次验证确认的“入口缺失”问题的主要表现。

**位置**

- `core/command-registry.ts:82`：只有通用「新建项目」。
- `ui/full-writer/tool-catalog.ts:33`：工具名称/描述未体现模式。
- `ui/create-project-modal.ts:167-258`：模式按钮仅存在于弹窗内部。

### P1 — 批量建章不跟随当前选中项目

**表现**

从短篇/剧本项目详情点击「批量建章」，弹窗默认选中项目列表第一个项目，而不是当前项目。

**影响**

- 短篇/剧本用户看到长篇分卷大纲，误以为模式入口失效。
- 若未注意项目下拉框，可能把章节骨架创建到错误项目，属于数据落点风险。
- 该问题让“入口存在但看起来不存在”的现象进一步放大。

**位置**

- `ui/command-ui-executor.ts:147-149`：`new BatchCreateModal(app, plugin)` 未传当前项目。
- `ui/batch-create-modal.ts:43-47`：构造函数不接收项目参数。
- `ui/batch-create-modal.ts:83-105`：`loadPlan()` 直接使用下拉框第一个值。

### P2 — 入口命名仍是长篇术语

**表现**

- 右侧工具仍叫「批量建章」，项目详情仍叫「全部章节」。
- 命令仍叫「批量建章」「成稿导出」，描述偏向长篇。
- 短篇/剧本项目内部虽然会把「章」映射为「节/集」，但入口层没有提前体现。

**影响**

- 降低短篇/剧本用户对入口的识别度。
- 与模式实际能力不一致，增加学习成本。

### P2 — 没有模式启用开关

**表现**

- 设置对象 90 个键中无 `short/script/creation` 相关开关。
- 设置页没有「创作模式」分区。
- 源码中没有 `enableShortStory` / `enableScriptMode` / 类似 feature flag。

**影响**

- 模式始终开启，无法在设置中关闭、灰度或限制。
- 如果产品要求“功能配置中可启用/停用”，该项确实缺失；如果设计为常开，则属于配置层缺失而非故障。

### P3 — `SidebarComponent` 为未挂载死代码

**表现**

- `ui/sidebar-component.ts` 定义了「⚙️ 核心操作 / 📂 新建项目」侧边栏，但全仓没有实例化。
- 运行时「核心操作」元素数为 0。

**影响**

- 目前不影响用户，因为右侧快捷工具提供了「新建项目」。
- 但代码层面存在“看起来有侧边栏入口、实际永远不显示”的误导，后续维护容易误判。

## 五、未发现的问题

以下方向已排查，未发现导致入口不可见的证据：

- **加载异常**：插件 4.19.0 正常加载，注册 46 个命令，4 个 Ribbon 图标；`dev:errors` 无错误。
- **权限限制**：没有按模式限制命令或按钮的权限逻辑；模式按钮未禁用。
- **CSS 隐藏**：模式按钮与字段的 `offsetParent` 正常；短篇/剧本字段按选择显隐。
- **设置开关误关**：不存在模式开关，因此不存在“被开关关闭”的情况。
- **项目卡显示**：短篇/剧本项目创建后，卡片和详情均能正确显示模式与节/集单位。

## 六、影响范围

- **新用户**：无法从主界面/Ribbon/命令面板直接发现短篇或剧本模式，必须知道「新建项目」内部还有模式选择。
- **老用户升级**：原有长篇入口不变，但不会自然发现新增模式。
- **短篇/剧本作者**：创建项目后能正常看到模式徽章、节/集计数、批量建节/建集和模式化导出；主要障碍在创建入口与批量入口的项目上下文。
- **批量操作**：存在误建到其他项目的风险，是当前最需要优先修复的入口行为问题。
- **配置管理**：无法关闭或灰度模式；若企业/团队需要统一配置，缺少开关。

## 七、建议修复方向（本次仅验证，未改代码）

1. 在工作台「项目规划」组增加「新建短篇」「新建剧本」两个直达项，或让「新建项目」工具名称/描述明确写出「长篇/短篇/剧本」。
2. 增加模式命令（例如 `新建短篇项目`、`新建剧本项目`），或在命令面板注册带模式参数的入口。
3. 让 `BatchCreateModal` 接收当前项目参数，初始化下拉框时优先选中当前项目；命令入口从 `getActiveProject()` 或工作台上下文取值。
4. 入口文案按当前项目模式动态显示「批量建节/批量建集」「全部节/全部集」。
5. 如产品需要，增加「创作模式」设置分区与启用开关；如不需要，建议在设置页明确说明模式为常开。
6. 删除或正式挂载 `SidebarComponent`，避免“代码有入口、界面无入口”的维护误导。
