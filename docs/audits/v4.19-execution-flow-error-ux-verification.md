# v4.19.0 执行流程与错误交互重构验证报告

- 日期：2026-10-25
- 版本：4.19.0（本地工作树，未提交远端）
- 范围：一键完成本章 / 逐步完成本章的错误处理、主区域执行流程、固定日志窗口、提示词与结果展示

## 一、问题定位

本轮修复的现场问题来自完整写作工作台截图与代码路径：

1. **错误提示重复且飘散**：一次失败会连续产生多条 `章节生成中断: infoPlan 未达到完成标准` 与 `已保存但内容不完整` 浮动提示，遮挡右侧内容，且没有节点、原因与处理建议的完整上下文。
2. **两种模式报错路径不一致**：逐步模式由 `executeCurrentStep` 内部吞掉错误后由 `executeStepsSequential` 二次判断；一键模式再由 `ChapterOrchestrator` 捕获并提示，导致同一失败可能零次、一次或多次展示。
3. **错误卡会被重渲染清掉**：旧 `renderErrorResult` 直接挂到 `.novel-writer-fw-prompt-area`，下一次整步渲染就消失。
4. **主区域没有流程链路**：执行进度、状态变更和警告只在浮动提示里，无法按时间回看。
5. **提示词占据首屏**：系统/用户提示词是两个大 textarea，结果区在按钮之后；模板骨架也会被当成“上次结果”。
6. **信息规划误判**：校验器只接受“冲突强度：长文本”，AI 输出“冲突强度 4/5”或独立小节时被误判缺失，一键模式因此反复中断。

## 二、实现内容

### 2.1 统一错误模型

新增 `shared/execution-events.ts`：

- `StepFailure` 固定包含：步骤 key、步骤名、错误类型、原始消息、补充详情、缺失项、处理建议、是否可重试、时间、堆栈。
- `classifyStepFailure()` 按消息归为 `validation/api/parse/save/incomplete/truncated/exception/cancelled`。
- `suggestionForFailure()` 输出可操作建议；有缺失项时直接列出缺失字段。
- `createStepFailure()` 为两种执行模式提供唯一构造入口。

`engine/step-runner.ts` 在以下分支统一走 `reportFailure()`：

- 用户提示词为空；
- fix/finalFix 前置校验失败；
- 通用步骤 preValidation 失败；
- AI 返回 error；
- postValidation 失败；
- 保存成功但结构校验未通过（含输出截断）；
- 文件写入失败；
- 执行异常（带堆栈）。

同时新增可选回调：

- `onStepFailure(failure)`：结构化失败；
- `onExecutionEvent(event)`：步骤开始/完成/取消、上下文、运行进度；
- `onDiagnostic(entry)`：模型、prompt 长度、耗时、usage、堆栈等调试信息。

旧 `showError/showNotice/showSuccess` 保留，兼容既有测试与调用方；UI 层会把重复文本合并为一条。

### 2.2 主区域执行流程

新增 `ui/full-writer/execution-run-store.ts` 与 `ui/full-writer/execution-panels.ts`：

- `ExecutionRunStore`：事件上限 300 条、日志上限 800 条；相同步步骤 + 相同文本在 2 秒内去重并升级级别；状态更新 120ms 节流。
- `ExecutionTimelinePanel`：显示“执行流程”标题、实时状态、按时间排序的事件（含时间、级别、步骤、消息）；错误事件带“重试”按钮。
- 自动步骤（上下文加载 / 章节结算）同样挂载时间线与错误卡。
- 步骤完成或重新开始时自动清除该步骤的旧错误。

### 2.3 内联错误卡

`renderStepFailureCard()` 直接渲染在失败步骤位置，包含：

- 发生节点：步骤名（stepKey）；
- 原因：原始错误信息；
- 缺失项：结构校验缺少的字段；
- 处理建议：按错误类型给出可操作步骤；
- 可展开的错误详情；
- “重试本步”“查看完整日志”两个动作。

一键模式失败时 `onStepFailure` 会自动把当前步骤切到失败节点，保证错误卡可见；逐步模式使用同一个回调与同一个重试入口。

### 2.4 固定日志窗口

`ExecutionLogPanel`：

- 固定在视口右下角，支持展开/收起；
- 错误计数徽章；
- 按全部/错误/警告/调试筛选；
- 滚动查看，错误详情与堆栈可展开；
- 复制完整日志文本；
- 重渲染、切换步骤不会丢历史；切换章节时清空。

### 2.5 移除浮动过程提示

- `StepRunner` 的进度、成功、通知、错误全部改为 `ExecutionRunStore` 事件或状态，不再创建 `Notice`。
- `ChapterOrchestrator` 的进度、暂停、失败、完成改为时间线事件，不再弹 Notice。
- `ContextLoaderController` 增加 `reportProgress/reportNotice` 回调；加载进度、上下文缺项、模块加载失败、角色灵魂提取、跨卷快照全部进入主区域。
- 上下文失败后不再在每次重渲染时自动重试，避免“失败 → 渲染 → 再加载”的死循环；由错误卡“重试本步”触发。

### 2.6 提示词与结果展示

- 系统/用户提示词改为 `<details>` 默认折叠，摘要显示字数与“点击展开编辑”。
- 执行结果移动到提示词之前，先展示结果预览（最多 2400 字），原文编辑放入折叠区。
- 用 `isTemplateSkeleton()` 识别模板骨架：骨架不再作为“上次结果”展示，改为提示“只有模板骨架，未产出有效内容”。
- 修正提示词编辑区背景，去掉误用的危险色底色。

### 2.7 一键模式报错修复

- `validateInfoPlan` 的冲突强度校验新增：
  - `冲突强度 4/5`、`冲突强度：4 级`、`冲突强度为 4`；
  - 独立的 `## 冲突强度` 小节。
- `COMBINED_PLANNING_SYSTEM_PROMPT` 的 `INFO_PLAN` 改为与校验器一致的显式结构标签：
  - `## 章名与核心冲突`、`## 情感与冲突量化`、`## 信息释放计划`、`## 伏笔操作`、`## 关系推进`；
  - 情感温度、冲突强度明确要求带量纲。
- `INFO_PLAN_PROMPTS` 单步系统提示词同步改为逐项 Markdown 标签格式，强制输出独立的 `冲突强度：N/5` 行；用户提示词也固定了三个量化指标格式。
- 修复后，合法但格式不同的模型输出不再被判缺失，重新生成也更难遗漏冲突强度。

### 2.8 步骤页排版重构

- 新增置顶操作栏 `nw-step-actionbar`：
  - 左侧显示步骤名与状态（未完成 / 已完成 / 执行失败）；
  - 右侧是紧凑胶囊按钮：`重新生成本步` / `生成此步` / `继续生成`、`跳过`；
  - 正文步骤显示 `进入句级协同写作` 与 `整章草稿` 两个紧凑入口，删除原大块营销卡；
  - 温度滑杆收进操作栏第二行。
- 操作栏使用 sticky 定位，滚动提示词时仍可点击，不需要再滚到底部找按钮。
- 系统/用户提示词默认折叠为两行摘要；结果区移动到提示词之前。
- 旧 `.novel-writer-fw-btn-primary` 的 `flex:1` 长条样式改为 `flex:0 0 auto`，全工作台按钮统一缩小圆角与内边距。
- 修正提示词编辑区背景，并统一折叠面板的 hover、箭头与分隔线。

### 2.9 生效说明

本次修改了 `main.js` 与 `styles.css`。Obsidian 正在运行的旧插件实例不会自动重新执行新代码；需要在“设置 → 第三方插件”中关闭再启用「小说工坊 AI」，或重启 Obsidian，新的操作栏、错误卡、日志窗口与提示词排版才会出现。

## 四、兼容性与边界

- 旧 `StepRunnerCallbacks` 调用方无需改动；新增三个回调均为可选。
- `showError/showNotice/showSuccess/showProgress` 行为在无新回调时保持原样。
- 步骤完成判定、失效传播、文件落盘、导出逻辑未改。
- 模板骨架识别复用现有 `isTemplateSkeleton`，不新增判定标准。
- 日志/时间线为内存态，不写项目文件；切换章节时清空。
