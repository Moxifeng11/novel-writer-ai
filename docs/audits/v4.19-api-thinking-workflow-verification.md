## 一、API 连通性测试

### 实现

- `services/api-connectivity-service.ts`
  - 端点规范化：补 `/v1/chat/completions`、保留 `/api/chat`。
  - 最小 POST 请求：8 token、temperature=0、stream=false。
  - 15s 超时；5s 以上标记 degraded。
  - 状态分类：ok / empty_response / degraded / auth_failed / not_found / rate_limited / server_error / timeout / network_error / invalid_config。
  - 本地端点允许无密钥；云端缺密钥直接失败。
  - 不记录/展示密钥。
- `ui/settings-tab.ts`
  - API 区域新增「🔌 测试连通性」按钮与状态文本。
  - 测试中禁用按钮，防止并发。
  - 绿色/黄色/红色状态 + Notice 告警。

### 运行时验证

- 设置页 API 区域显示按钮。
- 当前 DeepSeek 配置点击测试：
  - 15s 内返回；
  - 状态：`❌ 鉴权失败（HTTP 401）：Authentication Fails, Your api key: ****7Kho is invalid`；
  - 按钮恢复为「🔌 测试连通性」；
  - 未显示完整密钥。
- 该结果为当前本地密钥失效，不是探测逻辑异常；成功/限流/空响应/HTTP 200 + error 等路径由单测覆盖。

### 单测

`tests/unit/services/api-connectivity-service.test.ts` 8 项：

- 端点规范化；
- 200 成功；
- 401 鉴权失败；
- 429 限流；
- 200 + error body；
- 空响应；
- 缺密钥/模型/非法端点不发请求；
- 本地端点无密钥。

## 二、四级思考强度

### 实现

- `shared/task-model.ts`
  - 新增 `ThinkingLevel = fast|standard|deep|max`。
  - 预设：0%/35%/70%/100%，对应 off/auto/on/on。
  - `thinkingIntensity` 0–100；滑杆取最近等级。
  - 自动预算 = `maxOutput × 0.3 × intensity%`；显式预算按强度缩放。
  - 未设置新字段时完全保持旧 `thinkingMode/thinkingBudget` 行为。
- `ui/settings-tab.ts`
  - 全局：四个等级按钮 + range 滑杆 + 百分比 + 说明 + 预算上限。
  - 任务级：四等级覆盖下拉，显示 `思考 深度 70%`。
- `main.ts` 设置字段：`thinkingLevel/thinkingIntensity`。

### 运行时验证

- 设置页显示：极速 0%、标准 35%、深度 70%、极限 100%，滑杆 1 个。
- 旧配置 `thinkingMode='on'` 初始显示「深度 70%」。
- 拖到 100% 后：
  - `thinkingLevel=max`、`thinkingIntensity=100`、`thinkingMode=on`；
  - 「极限 100%」按钮高亮；
  - 说明文字更新为极限描述。
- 恢复原配置后：新字段删除、`thinkingMode='on'`、滑杆回到 70%。
- 任务级下拉包含「跟随全局 + 四等级」。

### 单测

`tests/unit/shared/thinking-levels.test.ts` 9 项：

- 四等级映射；
- 滑杆最近等级；
- 0/50/100 强度预算；
- 显式等级；
- 任务级强度覆盖；
- 旧配置兼容；
- 任务级显式关闭优先。
