- 版本：4.21.1 工作树（改动未打版，建议 v4.22.0）

## 一、为什么改：三条实测取证

### 1.1 「消痕后更像 AI」的机制

| 证据 | 位置 |
|---|---|
| 真正发出的消痕提示词是 `HUMAN_VOICE_BLOCK`（23 条数值配额 + 20 个禁用词） | `engine/harness/long-novel-tasks.ts:114-124`（改造前） |
| 面板展示的检测/改写两套提示词并未生效，`deaiCheckUserPrompt` 构造了却未传参，`rewriteBtn` 是死代码 | `engine/step-modal-controller.ts:212-278`（改造前） |
| 全链路 0 段正例样文 | `deai-prompts.ts` / `human-voice.ts` / `long-novel-tasks.ts` |
| 10 套文风预设的「零、参考样本」30 个槽位全是 `（在此粘贴样本）` | `assets/template-scaffold/00-系统模板/文笔风格预设/*.md` |
| 文笔模板自己写着「不填参考样本，效果可能偏 AI 味」 | `文笔风格模板.md` 第 28 行 |
| 「自动迭代精修」只调一次 refine，`refineRounds=3` 从未被读取 | `step-modal-controller.ts:431-456`（改造前） |
| 旧 3 轮循环用 `content.includes('❌')` 判好坏，无分数/无回滚 | `ai-chapter-helpers.ts:244` |
| 评分体系互相打架：WQE 给排比加分，human-voice 禁止排比 | `writing-quality-engine.ts:285-289` vs `human-voice.ts:36-38` |

**结论**：配额式提示词会把文本推向「每项指标都刚好合格」的均匀状态，而均匀本身就是 AI 观感；缺的不是禁令，是正例。

### 1.2 上下文丢截的机制

| 证据 | 位置 |
|---|---|
| `resolveStepBudgetLimits(model)` 不传 endpoint；供应商 endpoint `https://api.deepseek.com` 与设置 `.../v1` 严格比较失败 → 回退 32768/8192 | `engine/step-runner.ts:655-667`（改造前）+ `core/provider-manager.ts:110-120` |
| 闸门 `32768-8192-500 = 24076` token，与实测日志 `~24174t` 吻合；而模型能力 1,048,576 | `shared/prompt-budget.ts:341` |
| 段内截断只留前缀，正文模板把写指令放在段尾 → 最先被吃掉 | `shared/prompt-budget.ts:180-192` |
| 固定切片：上一章结尾 500 字、长篇记忆 1500 字、场景卡 12 场/3000 字、实体速览 8 人、人物字段 clip 240 | 见 §3 对照表 |
| 丢弃不可见：`fitPromptToContext` 只回布尔；提示统一写「增加 maxContext」（闸门根本不读它） | `step-runner.ts:927-928`（改造前） |

### 1.3 校准发现（最重要的一条）

用第2章真实 AI 正文（2748 字）与本地真人样文对比：

| 指标 | 真人样文均值（21 段） | 第2章 AI 正文 |
|---|---|---|
| antiAI（0–100，越低越好） | **6.3** | 11 |
| humanSim（分布相似度） | 0.578 | **0.636** |
| 对话占比 | 0.26 | **0.09** |
| 平均句长 | — | 16.6 |

**surface 分布相似度无法区分这段 AI 正文与真人文本**——因为句长/段长早就被我们的提示词优化过了。真正有判别力的是**对话密度**（0.26 vs 0.09）。因此：

- `humanSim` 只作参考指标，不再宣称是「AI 检测器」；
- 判据改为 `antiAI + 章级对话下限 + 保真`；
- 章级（≥1200 字）对话占比 <12% 直接判不保真（`shared/human-similarity.ts`）。

## 二、改动清单

### 2.1 上下文放开

| 项 | 改造前 | 改造后 |
|---|---|---|
| 闸门输入预算 | `maxContext - maxOutput - 500`（实测 24076） | 任务预算 `maxInput`（按真实窗口，硬上限 200K / 可设 `contextTokenCap`） |
| 端点匹配 | 严格相等 | `normalizeEndpointKey` 归一（忽略 `/v1`、`/chat/completions`、尾斜杠） |

| 最终写作指令 | 在文笔风格段尾，先被吃 | 独立 `【最终写作指令】` 段 + mustKeep |
| 丢弃可见度 | 布尔 | `droppedSections/trimmedSections/maxInputTokens` → prompt-ledger `【本步预算】` |

| 场景卡 | 12 场 / 3000 字 | 12–40 场（按预算）/ 单场 400–900 字 |
| 实体速览 | 8 人 | 20–60 人 |

| 世界观/设定库压缩 | 用 `settings.maxContext`(32768)，keyword 压缩不计截断 | 用真实窗口（25%/15%），keyword 压缩也置 `truncationApplied` |

### 2.2 提示词与人味地基

- `scripts/sample-human-corpus.mjs`（`npm run sample:human`）：7 本 / 3165 万字 → 21 段样文（250–400 字/段），GBK 用 `gb18030` 解码；基线 `baseline.json` 记录句长/段长/标点/对话占比分布。**只落本机 `data/`，不入仓库不入包**。
- `shared/human-similarity.ts`：分布相似度（句长 0.30 / 段长 0.20 / 标点 0.15 / 对话 0.35）+ 保真（长度 ±15%、2-gram 覆盖 ≥0.55、数字保留）+ 章级对话下限 + 综合分。
- `npm run eval:humanness`：样文自查 / 单文件评估 / 改写前后对比。
- `engine/prompts/style-exemplars.ts`：按场景挑 3 段样文，`formatExemplarBlock` 注入。
- `human-voice.ts` v4：`HUMAN_VOICE_WEAK_RULES`（6 条弱约束）+ `buildHumanVoiceBlock({mode})`；旧配额保留可回退。
- `long-novel-tasks.ts` deai/refine：改为「最多 3 处具体问题 → 照样文重写 → 情节/人设不变、字数 ±10%」。
- 冲突统一：删除「每段只有一个句号」检查；精准模式标点改为「服从语气，省略号/破折号各≤2」。
- `ai-lexicon`：「点了点头/摇了摇头/沉默良久/深吸一口气/过了许久」降级为弱提示。
- 双文件陷阱：`文笔风格.md` 无样文而 `文笔风格模板.md` 有时自动补入「零、参考样本」（实测项目里已有《雪中悍刀行》3 段，此前从未被读取）。

### 2.3 真迭代精修

- `shared/iterative-refine.ts`：多轮（`refineRounds`，夹到 0–5）+ 每轮打分 + 只接受严格更优（增益 >0.005）+ 保真不过拒收 + 连续 2 轮无提升提前停 + 支持取消。
- `ui/services/humanness-scorer.ts`：AntiAIDetector + 真人基线 + 保真；无基线退化为「AI 味 + 保真」。
- 面板逐轮显示：`R1: 62.0（综合分未提升）⛔` / `R2: 68.0 ✅接受`，末尾给停止原因与总调用数。

## 三·B 朱雀真实 A/B（2026-10-31，外部检测器）

同一章正文（第2章 2468 字）→ 6 套提示词各生成一版 → 逐份上传 `matrix.tencent.com/ai-detect/ai_gen`（模型更新 2026-07-21）。

| 变体 | 提示词结构 | 字数 | 段数 | 平均句长 | 对话占比 | 朱雀结论 |
|---|---|---|---|---|---|---|
| original | 原稿（无处理） | 2468 | 2 | 19.4 | 9.0% | 未发现明显的人工创作特征 |
| v1-quota | 旧版 23 条数值配额 + 禁用词 | 1570 | 15 | 22.5 | 9.2% | 同上 |
| v2-exemplar | 只给 3 段真人样文，无规则 | 2435 | 40 | 16.9 | 9.2% | 同上 |
| v3-weak | 3 段样文 + 6 条弱约束（当前默认） | 2411 | 51 | 16.1 | 9.3% | 同上 |
| v4-dialogue | v3 + 「对话占比约 25%」 | 2531 | 96 | 13.8 | 16.1% | 同上 |
| v5-scene | 「场景稿：对话≥40%，叙述≤25 字」 | 1968 | 35 | 16.9 | 11.1% | 同上 |
| v6-skeleton | 先出台词清单（12 条）→ 按清单写 | 1354 | 43 | 13.5 | 17.2% | 同上 |

**结论（数据驱动）**：
1. **六组全部落在同一档**，朱雀的判定没有被任何提示词结构改变——与 2026-10-27 那轮「换模型/换提示词都无法改判」一致。
2. **提示词确实能改变局部指标**：段数 2→96、平均句长 19.4→13.5、对话占比 9%→17.2%，但**这些都不足以改变判定**。
3. **模型不执行比例指令**：v5 明确要求对话≥40%，实测只有 11.1%；v6 给了 12 条台词清单也只到 17.2%。
4. 因此**提示词层面已到天花板**。继续在提示词里加禁令/配额/样文，收益趋零。

**据此做的两件事**：
- 把「章级对话 <12% 判不保真」写进评分（对话是唯一有判别力的局部指标，真人 26% vs 生成 9–17%）；
- 精修面板新增**定向对话补修**：测出对话占比 <15% 时，只跑一轮「把最重要的 3 处叙述改成对话」，接受条件是新版占比更高且保真通过（最多 1 次额外调用）。不再写「对话占比 25%」这种模型数不出来的指令。

**未采用的方案**：把真人样文句子直接拼进正文（能拉高「人类文本占比」，但破坏作品一致性，也属于对抗检测而非提升质量）。

## 三·C 人工样本特征分析（朱雀判「人工创作特征显著」）

拿一份 100% 人工样本（2306 字，朱雀判定「人工创作特征显著」）与六份生成稿做同一套统计：

| 特征 | 人工样本 | v3-weak | v4-dialogue | v6-skeleton | 判读 |
|---|---|---|---|---|---|
| 对话占比 | **0.384** | 0.093 | 0.161 | 0.172 | 差 2–4 倍，首要差距 |
| 对话块数/千字 | **27.7** | 11.2 | 23.3 | 16.3 | 人工靠短对话推进 |
| 平均对话块长 | 13.8 字 | ~7 | ~7 | ~13 | 我们的对话更碎 |
| 短叙述占比（≤25 字） | **0.63** | 0.82 | 0.86 | 0.95 | 我们「碎」过头 |
| 对话/叙述交替率 | 0.41 | 0.44 | 0.39 | 0.60 | 接近 |
| 口语标记/千字 | **2.2** | 0 | 2 | 0 | 我们几乎没有人话 |
| 时间/序数锚点 | **12** | 0–2 | 0–2 | 0–2 | 人工用「第一波/第八分钟」定节拍 |
| 本地评分卡 | **100/100** | 20 | 40 | 20 | 与朱雀判定同向 |
| 朱雀判定 | 人工创作特征显著 | 未发现明显人工特征 | 同左 | 同左 | — |

**新增 `shared/human-feature-rubric.ts`**：把上表做成可计算评分卡（对话占比、对话块密度、短叙述上下界、口语密度、时间锚点），章级文本才评，输出 0–100 与逐项原因。它与朱雀判定同向（100 vs 20–40），可作为离线回归指标；`npm run eval:humanness` 已输出 `humanFeatureScore`。

**据此的提示词/阈值迭代（v5）**：
- 弱约束从「句子长短不要一致」改为**特征驱动**六条：信息由人物说出（每场 6–10 次来回、对话占三分之一）、叙述长短混用（短句跑节奏但要有长句）、让人物说人话（口语/打断/答非所问）、用具体时间与序数定节拍、不写总结升华、承接上一章结尾。
- 章级对话下限 **12% → 20%**；定向补修触发线 **15% → 25%**，指令从「挑 3 处」改为「把叙述者解释的段落改成对话，目标对话占三成以上」。
- 依据：**「不要碎」比「要短」更接近人工样本**——人工样本短叙述只占 63%，我们的稿子 82–95%，碎句本身就是 AI 腔的一部分。

## 三·D 场景卡对话骨架 + 重写第1/2章（验证）

**实现**（全部落在插件里）：
- `shared/scene-card.ts`：`SceneCardFields.dialogueBeats` + `parseDialogueBeats()`（多行字段解析）+ `formatDialogueSkeleton()`；摘要 `dialogue_beats: 6–10 条「谁→谁｜台词｜完成什么」`。
- `engine/scene-expander.ts`：Scene 展开新增第 19 项 `dialogue_beats`（6–10 条，要求可直接用于正文、禁止写「两人讨论战术」这类概述）。
- `engine/prompts/body-v2-prompts.ts`：新增 `${dialogueSkeleton}` 段；`template-vars-builder` 从场景卡填充；`shared/prompt-budget.ts` 把「对话骨架」列入 mustKeep；`shared/injection-ledger.ts` 登记该段（正文模板段 31→32）。
- `engine/settlement-engine.ts`：结算回写正文 frontmatter 新增 `对话占比 / 口语密度 / 时间锚点 / 人味分`（来自 `evaluateHumanFeatures`）。
- `shared/human-feature-rubric.ts` + 单测 6 条；`npm run eval:humanness` 输出 `humanFeatureScore`。
- `tests/e2e/rewrite-chapters.spec.ts`：真实重写驱动（重置正文与 Scene 展开 → 一键成文 → 读盘核对人味字段），默认 skip。

**重写验证**（第1/2章，台词骨架 32–45 条 → 按骨架写正文，人味约束 v5 + 3 段真人样文）：

| 对象 | 字数 | 对话占比 | 人味分 | 朱雀判定 |
|---|---|---|---|---|
| 真人人样文（参照） | 2306 | 0.384 | 100 | 人工创作特征显著 |
| 第2章（旧） | 2468 | 0.09 | 20 | 未发现明显的人工创作特征 |
| 第1章（重写） | 2792 | 0.264 | **60** | 未发现明显的人工创作特征 |
| 第2章（重写） | 2009 | 0.181 | **40** | 未发现明显的人工创作特征 |

**结论**：对话骨架确实把**可测结构**拉到了接近真人的区间（对话 9%→26%，人味分 20→60），但朱雀判定一格没动；而同一轮里真人样文拿到「显著」。说明差距不在段落/句长/对话密度，而在模型 token 分布（困惑度/突发度）层面——提示词与数据骨架都触不到。

**因此**：插件侧把这套骨架机制保留（它让正文**读起来**更像人：对话推动、句长混用、口语与时间锚点），但**不再把外部检测分数当验收标准**；需要过检测的场景只剩人工改写关键段落。

## 四、本轮未做 / 下一轮

1. **真实付费 A/B 未跑**：用户已同意「离线 + 一次真实对比」，本轮只完成离线部分；真实对比需要再启一次 Obsidian 跑「正文 → 消痕」，约 2–4 次调用，可随时执行。
2. **10 套预设的批量填样文命令未做**：本轮只修了双文件陷阱（让已有样文生效）。按风格词从本地样文库批量填充 30 个槽位的命令留待下一轮。
3. **WQE 修辞加分未改**：`writing-quality-engine.ts` 仍给排比/「不仅…而且」加分，与 human-voice 冲突；只在 benchmark 注释里标注了，未动评分权重（恐影响既有质量分基线）。
4. **故事总线覆盖 `allChars` 的问题只做了缓解**（字段上限 240→600），未改成「总线文本作为补充段」。
