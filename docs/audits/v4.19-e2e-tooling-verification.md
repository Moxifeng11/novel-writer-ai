## 一、真实 Obsidian E2E

### 1.1 原失败原因

原 `tests/e2e/utils/obsidian-app.ts` 使用 Playwright `_electron.launch`：

- Obsidian 启动器不会完成 Playwright 的 Electron 握手，`electron.launch` 120s 超时；
- 直接启动第二个实例会触发单实例锁，测试进程被现有 Obsidian 接管后退出；
- 即使启动成功，Obsidian 1.14 会把 Modal 渲染到独立的 `about:blank` 窗口，原来只在主工作区页面查找 `.modal-container`，因此误判“命令没有打开弹窗”。

### 1.2 解决方式

改造为独立配置 + CDP：

- 每次测试创建独立 `--user-data-dir`，写入只包含测试 vault 的 `obsidian.json`；
- 使用 `--remote-debugging-port` 启动 Obsidian，再通过 `chromium.connectOverCDP` 连接；
- 等待 `.workspace` 就绪，点击“信任仓库”弹窗；
- `waitForPluginLoaded` 以命令注册/`_loaded` 为准，不再只看插件对象是否存在；
- 新增 `waitForModalPage()`，在所有窗口中定位承载 `.modal-container` 的 Modal 页面；
- 关闭时先断开 CDP、结束测试进程，再清理临时 userData；Windows 文件锁使用重试删除。

这样即使用户的 Obsidian 正在运行，也不会共享配置或触发单实例锁。

### 1.3 覆盖旅程

`tests/e2e/obsidian-plugin.spec.ts`：

1. 插件被 Obsidian 加载并注册 `novel-writer-ai:novel-writer-create-project`；
2. 通过真实命令打开新建项目弹窗，创建 `长篇小说/{项目名}`；
3. 验证 `03-大纲与章节` 与 `元文件/00-系统模板` 落盘；
4. 写入最小正文，调用 `openChapterInFullWriter` 进入章节步骤页；
5. 验证新交互：
   - `.nw-step-actionbar` 可见；
   - `.nw-exec-timeline` 可见；
   - 两个 `details.nw-prompt-collapsible` 默认折叠。

E2E 未复制本机 `data.json`，因此不会调用真实 AI，也不会触发“信息规划失败 → 错误卡 → 重试本步”的完整链路。该链路已由单元测试覆盖（`execution-events`、`execution-run-store`、`step-runner-common-branches`、`step-validator`），但仍建议在真实 Obsidian 中用实际 API 做一次人工点击验收。
