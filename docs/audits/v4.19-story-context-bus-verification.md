# v4.19.0 长篇故事上下文总线验证

- 日期：2026-10-28
- 版本：4.19.0（本地工作树）
- 范围：世界观、设定库、人物/势力/地点/物品、时间线、伏笔、场景卡、情绪弧的统一索引、自动关联、检索与本地/云端预算装配

## 一、要解决的问题

改造前，长篇创作的信息是分散的：

- 一键生成走 `GatheredContext → template-vars-builder → 模板变量`，各自有字符上限，实体、设定、时间线、伏笔之间没有交叉引用。
- 协同写作走 `ContextSnapshot → PromptBuilder`，是另一套字符串拼接；`story-linkage` 已经算出了伏笔/时间线/设定的关联，但 `promptText` 只用于面板展示，没有进入正文 prompt。
- 时间线/伏笔库里的重复行没有去重。真实项目 `九霄逆脉行` 的伏笔库有 42 行，同名去重后只有 6 条；时间线 24 行，去重后只有 6 条。
- 本地 Ollama 与云端 API 共用一套上下文拼接，本地 8K 窗口容易被低优先级信息挤爆，云端大窗口又大量空置。

结果就是：信息在面板里能看到，但生成时不一定用得上；同一份设定，一键生成和协同写作拿到的版本还可能不一致。

## 二、统一信息模型

新增 `engine/context/story-context-types.ts`：

- `StoryContextNode`：标准化信息节点，字段包括 `id / kind / title / text / compactText / priority / required / tokens / links / metadata`。
- `StoryContextKind`：`worldview / setting / character / faction / location / item / timeline / foreshadow / scene / emotion`。
- `StoryContextGraph`：节点表 + 按类型索引 + 名称/别名索引 + 自动关联边。
- `StoryContextBundle`：一次检索与预算裁剪后的节点集合 + 覆盖度遥测。

新增 `engine/context/story-context-graph.ts`：

1. **标准化**：把 `GatheredContext` 里的 Markdown、frontmatter、表格统一转成节点。
2. **自动关联**：
   - 场景卡 → 出场人物 / 地点 / POV / 文本中提到的实体 / 伏笔；
   - 伏笔 → 关联人物 / 关联主线 / 设定条目；
   - 时间线 → `involvedEntities` / 文本中提到的实体；
   - 设定条目 → 文本中提到的实体；
   - 情绪弧 → 场景号 / 关系变化中提到的人物。
3. **去重**：
   - 时间线按 `时间|章节|事件|影响` 去重；
   - 伏笔按规范化名称去重；
   - 去重结果写入 `graph.warnings`，并进入信息包遥测与上下文步骤的「故事上下文包」面板；不改写原文件。
4. **检索与预算装配**：
   - 场景级：当前场景、显式关联人物/地点、当前情绪弧、本章时间线、到期伏笔为必含；
   - 章节级（一键生成）：全部场景卡、全部显式关联实体、全部情绪弧为必含；
   - 可选信息按 `priority + 场景链接 + 关键词重叠 + 必含项关联` 排序；
   - 必含项永不静默丢弃；预算不足时先压缩到 `compactText`，再截断，并在遥测里标记 `truncated`。

新增 `engine/context/story-context-service.ts`：

- `buildStoryContext`：一次请求同时返回图与信息包；
- `applyStoryContextToVars`：一键生成适配，覆盖既有模板变量；
- `attachStoryContextToSnapshot`：协同写作适配，把选中的实体/设定/时间线/情绪写回 `PromptSnapshot`，并挂上完整/压缩信息包；
- `resolveStoryContextTier`：自动判断本地/云端；
- `logStoryContextSummary`：记录 tokens、必含覆盖、丢弃、截断。

## 三、本地 / 云端两套策略

| 维度 | 本地 Ollama / 小窗口 | 云端 API / 大窗口 |
| --- | --- | --- |
| 信息包上限 | 4200 tokens（再按输入窗口 55% 收窄） | 24000 tokens（再按输入窗口 55% 收窄） |
| 文本选择 | 优先 `compactText`：人物保留定位/身份/状态/动机/势力/情绪；场景保留 POV/时间/地点/目标/冲突/转折/离场 | 优先完整 `text`：保留背景、外貌、软肋、习惯、功法、关系变化等 |
| 人物名额 | 8 | 24 |
| 设定名额 | 6 | 20 |
| 时间线名额 | 8 | 40 |
| 伏笔名额 | 6 | 24 |
| 场景 / 情绪 | 各 8 | 各 12 |
| 必含策略 | 必含项优先，超出预算时压缩/截断并告警 | 必含项优先，通常可全部保留 |
| 适配入口 | 协同写作 `coWriteModelMode=local`；一键生成端点/模型命中本地 | 协同 `coWriteModelMode=cloud`；一键生成默认云端模型 |

设置页新增「故事上下文档位」：`自动 / 本地 Ollama / 云端 API`。自动模式下：

- 协同写作按 `coWriteModelMode`；
- 一键生成按 `apiEndpoint` 是否 localhost/ollama、`defaultModel` 是否本地模型判断，无法判断时按云端处理（宁可多给上下文，不静默丢信息）。

## 四、接入点

### 一键生成

`ui/full-writer/template-vars-builder.ts` 在 `buildTemplateVars` 末尾调用 `applyStoryContextToVars`：

- 覆盖 `worldView / settingLib / allChars / allFactions / allLocs / allItems / timelineEvents / unrevealedForeshadow / emotionPlan / sceneCardDigest`；
- 新增 `storyContextPack`（场景/情绪/时间线/伏笔的关联摘要）；
- 新增 `_storyContextTelemetry`（JSON 遥测）。

`engine/prompts/body-v2-prompts.ts` 与 `chapter-pipeline-prompts.ts` 的正文用户模板新增 `${storyContextPack}`，把「场景→实体、伏笔→人物/主线、时间线→实体」的关联摘要注入正文 prompt。既有模板变量名不变，用户自定义模板仍可继续用旧变量。

### 协同写作

`engine/co-writer-engine.ts`：

- `init` 后按整章建包；
- `setChapterBrief / setCurrentSceneIndex / refreshBriefProgress` 在场景变化时重建信息包；
- `refreshStaticContext` 在设定/伏笔/时间线文件变化后强制重建；
- 通过 `attachStoryContextToSnapshot` 写回 `allChars / allFactions / allLocs / allItems / timeline / settingLib / emotionPlan`，并挂 `storyContextPack / storyContextPackCompact / storyContextTelemetry`。

`engine/prompt-builder.ts`：

- `PromptSnapshot` 新增 `storyContextPack / storyContextPackCompact / storyContextTelemetry`；
- `buildSuggestionPrompt` / `buildRewritePrompt` 注入完整信息包；
- `buildAssociationPrompt` / `buildIteratePrompt` 注入压缩信息包；
- 检测到信息包后，停用旧的实体/设定/时间线/伏笔分段，只保留关系状态、跨卷快照、人物灵魂、章节简报、剧情节点、知识注入等**信息包不包含**的动态内容，避免重复注入。

### 覆盖度面板

`ui/full-writer/step-render-controller.ts` 的上下文步骤新增一行「故事上下文包」：

## 五、真实项目数据验证

用 `九霄逆脉行` 的真实文件（8 个角色、2 个势力、1 个地点、1 个物品、设定库 11 节、4 个场景、4 个情绪场景）在 Node 里模拟 `GatheredContext`，执行图构建与四种组合装配。结果：

| 组合 | 信息包 | 必含覆盖 | 缺失 | 人物 | 设定 | 时间线 | 伏笔 | 场景 | 情绪 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 协同 / 本地 | 33 项 / 4199 tokens | 10/10 | 0 | 4/8 | 6/11 | 5/6 | 5/6 | 4/4 | 4/4 |
| 协同 / 云端 | 44 项 / 14096 tokens | 10/10 | 0 | 8/8 | 11/11 | 6/6 | 6/6 | 4/4 | 4/4 |
| 一键 / 本地 | 34 项 / 4189 tokens | 17/17 | 0 | 5/8 | 6/11 | 4/6 | 6/6 | 4/4 | 4/4 |
| 一键 / 云端 | 44 项 / 14096 tokens | 17/17 | 0 | 8/8 | 11/11 | 6/6 | 6/6 | 4/4 | 4/4 |

去重结果：

- 时间线：24 行 → 6 条唯一事件（18 条重复）；
- 伏笔库：42 行 → 6 条同名唯一伏笔（36 条重复）；
- 去重只影响 prompt 装配，不改写用户原文件；`graph.warnings` 会记录。

结论：

1. **必含项无遗漏**：四种组合的 `missingRequired` 都是 0。
2. **本地不是简单砍半**：本地优先保留当前场景显式关联的人物/地点、场景卡、情绪弧、到期伏笔与本章时间线；被丢弃的是未在本章场景中出现的可选项。
3. **云端信息完整**：云端四种组合都拿到了全部 8 个人物、11 节设定、6 条时间线、6 条伏笔、4 个场景和 4 条情绪弧。
4. **本地/云端必含核心一致**：同一场景下，本地与云端都包含当前场景、当前情绪弧、场景中点名的沈砚/裴无极/霍清澜、地点碎砂渡、本章时间线与到期伏笔；差异只在可选项的详略。

## 七、边界与后续

- 本轮验证的是**信息装配与覆盖度**，不是模型生成质量。两种模式的 prompt 里都拿到了必含信息，但最终文风/情节质量仍取决于模型。
- 本地档位会丢弃部分可选人物/设定；这是小窗口下的主动取舍，不是数据丢失。面板会显示丢弃数量，遥测里保留具体 ID 与原因。
- 真实项目中时间线/伏笔库存在大量重复行。本轮只做**装配去重**，没有改用户文件；如果希望从源头清理，需要另做一次带 dry-run/备份的迁移。
- 云端信息包目前 14096/24000 tokens，仍有约 1/3 余量；后续可以把知识库/指纹检索也纳入同一优先级体系，而不再各自按字符上限截断。
- 未提交远端；按当前迭代约定停留在可发布工作树。
