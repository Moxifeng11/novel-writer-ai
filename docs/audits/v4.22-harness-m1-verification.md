## 二、M1 实现

| 模块 | 文件 | 能力 |
|---|---|---|
| PromptArtifact | `engine/harness/prompt-artifact.ts` | 模板版本、变量、context/rule/contract id、预算、稳定 hash |
| ContextPack | `engine/harness/context-pack.ts` | typed fragments、required 防裁剪、去重、预算 dropped |
| RetrievalPlan | `engine/harness/retrieval-plan.ts` | 四类查询、RagCitation 可信度、无证据提示 |
| MemoryStore | `engine/harness/memory-store.ts` | 项目内 pending/confirmed/rejected、AI 记忆默认 pending |
| ToolRegistry | `engine/harness/tool-registry.ts` | 模式过滤、权限校验、危险确认、结构化错误 |
| Builtin tools | `engine/harness/builtin-tools.ts` | 长篇正文格式、短篇分类/字数/反转/结尾、剧本类型/时长/钩子/ID/对白 |
| DomainProfile | `engine/harness/domain-profile.ts` + `domains/*/harness-profile.ts` | 三域 schema、必备上下文、规则集、工具、质量门 |
| Profile registry | `domains/harness-profile-registry.ts` | 按模式取 profile，不反向依赖 Kernel |
| Runner 接入 | `engine/harness/single-call-runner.ts` | 可选 PromptArtifact；未提供时保持原路径 |
| Context 接入 | `engine/harness/context-aggregator.ts` | `aggregateContextPack()` 输出 ContextPack |

## 三、隔离

- 三域 profile 分别位于 `domains/long|short|script`，互不 import。
- `engine/harness/domain-profile.ts` 只定义接口，不导入领域。
- 静态测试验证 profile 互不依赖与 Kernel 无反向依赖。
- 各 profile 的 tool/template/quality id 无重复。

## 七、边界

- M1 是契约与本地工具层，不重写长篇 11 步、短篇三步流程或剧本分镜链。
- RAG 目前是计划与引用契约；语义检索仍复用现有 KnowledgeVectorStore，尚未在 UI 全量接入。
- MemoryStore 已提供 pending→confirmed 状态机，但尚未在结算/质检流程中自动创建 pending 记录。
- ToolRegistry 已注册本地核心校验工具；profile 中列出的其余工具属于 M2+ 实施范围。
