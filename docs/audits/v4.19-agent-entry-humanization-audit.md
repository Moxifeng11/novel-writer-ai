## 一、Agent 入口指引

当前有三个入口，任选其一：

### 1. 项目与章节页顶部工具栏（新增，推荐）

打开「完整写作工作台 → 项目与章节」，页面顶部（项目网格上方）现在固定显示：

```text
长篇小说   1 个项目                    [🤖 对话引导] [＋ 新建长篇小说]
```

- `🤖 对话引导`：进入多轮对话，先选长篇/短篇/剧本。
- `＋ 新建…`：走原有表单/前期调研。
- 切换左侧「长篇小说 / 短篇小说 / 剧本」时，工具栏标题和新建按钮同步变化。

### 2. 命令面板

`Ctrl/Cmd + P` → 输入「对话引导」→ 选择：

```text
🤖 对话引导（新建/继续项目）
```

命令 ID：`novel-writer-agent-guide`。

### 3. 空态卡片

当前分类没有项目时，空态卡片新增「🤖 对话引导创建（推荐）」。

### 4. 为什么之前找不到

旧版入口只存在于「空态卡片」和命令面板；已有项目时项目页不显示，且没有固定按钮。现在项目页工具栏对所有状态可见。

## 二、项目入口排版

- 项目区新增固定工具栏：模式标题、项目数量、Agent 入口、当前模式新建入口。
- 工具栏与项目网格之间用分隔线区分，按钮改为紧凑胶囊样式。
- 窄屏时工具栏换行，按钮等宽铺满，不挤压项目卡片。
- 新建按钮按当前模式路由：长篇 → 表单；短篇/剧本 → 前期调研。
- 原有项目卡片、右侧快捷工具、模式切换保持不变。

## 三、插件现状梳理与优化优先级

结合当前代码与已验证范围：

### 已完成且通过门禁

- 长篇 11 步流水线、单章一键编排、协同写作、知识库、指纹库、导出、设置。
- 三模式（长篇/短篇/剧本）领域隔离、项目库、迁移、前期调研、Agent 创建。
- Harness M1 契约、单次调用 Runner、调用账本、记忆契约。
- 399 个测试文件 / 4623 用例、preflight、build、check:release、E2E 4 条。

### 最应该优先优化的五件事

1. **正文人类化与外部检测通过率（最高优先级）**
   - 现状：第一章在朱雀检测中疑似 AI 100%；已完成 5 组对照实测（见第六节）。
   - 已做：重写 human-voice（自然段、句长、对话、标点）；新增正文统计与自然段重排；一键/续写/批量/场景写入默认自然化；新增「人味体检」面板。
   - 结论：朱雀对 LLM 生成文本非常敏感，只靠提示词/分段/换模型无法稳定达到 70% 人工率。
   - 建议下一步：把“人味体检”作为质量门禁，正文生成后先看指标；需要更高人工率时，必须引入人工改写或非 LLM 生成环节，而不是继续堆提示词。

2. **多章节端到端验证**
   - 现状：只写过第一章；第二章之后的上下文承接、伏笔、结算、跨章一致性没有真实样本。
   - 建议：用同一项目连续生成 3 章，检查上一章结尾承接、角色状态、伏笔回收、重复信息、章节字数与质量报告。

3. **Agent 全流程与写作流水线的衔接**
   - 现状：Agent 能完成创建与参数收集，但正式正文仍由项目向导/一键完成/协同写作执行。
   - 建议：把“创建后自动进入向导第一步”做成明确选项，并在每一步提供“继续/暂停/切换自动”的对话控制。

4. **项目页信息密度与卡片操作**
   - 现状：工具栏已补齐；项目卡片在项目少时仍偏大，右侧快捷工具分组较多。
   - 建议：项目少时卡片最大宽度收窄，右侧工具按使用频率折叠；把“对话引导/新建/导入”固定为一级动作。

5. **成本、失败与重试可观测性**
   - 现状：调用账本与执行日志已有，但缺少按章节/步骤的成本面板。
   - 建议：把逻辑调用数、网络调用数、token、失败步骤、重试次数汇总到章节页，支持导出。

## 四、人类化写作改造（2026-10-27 复盘）

### 4.1 旧版为什么反而制造了 AI 腔

旧版 `human-voice` 用配额鼓励“短句、单句成段”，模型会把它执行成通篇碎片。第一章的量化结果：

- 4782 字，133 段，平均每段 33 字。
- 269 句里 37% 不超过 10 字；35 字以上长句只占 5.2%。
- 对话引号内字符只占 2.9%，标点几乎只有逗号和句号。
- 133 段里 48% 的叙述段只有一句话。

这不是“像人”，而是另一种稳定可识别的 AI 腔。提示词里的“允许单句成段”“每 10 句至少 3 句 ≤10 字”会被模型当成硬配额，最后把整章切成 133 个短段。

### 4.2 新版约束

`engine/prompts/human-voice.ts` 重写为：

- 自然段 2–6 句、80–220 字，一行一段；单句成段只用于强调，每千字不超过 3 处。
- 平均句长 20–30 字；35 字以上长句占 10%–20%；10 字以下短句不超过 25%。
- 对话占 25%–45%；允许停顿、打断、答非所问、口头禅和一点废话。
- 对话和说话人的动作、神态放同一段；连续对话按说话人分段。
- 每个场景 2–3 处关键身体感觉即可，不逐段打卡；允许解释、交代、过渡、重复。
- 标点正常使用问号、冒号、分号、省略号；破折号每千字不超过 2 处。
- 段落可以平淡结束；不写升华、金句、作者点评。
- 明确声明：以上要求优先于写作规则里的“一句一段 / 一段一个句号”。

### 4.3 提示词注入点

- `engine/prompt-builder.ts`、`engine/co-writer-engine.ts`：删除“段落极短，大多只有一句话”“每句只讲一件事，一句话就是一个画面”；协同续写从“1–3 句（50–150 字）”改为“1 个自然段（80–220 字，2–6 句）”。
- `engine/prompts/body-v2-prompts.ts`、`chapter-pipeline-prompts.ts`：把“每一段都必须有身体感觉 + 情绪变化”改为“每个场景 2–3 处关键身体感觉”；允许过渡段和必要交代。
- `engine/prompts/deai-prompts.ts`：检测项从“一段多句号违规”改为“段落碎片化 / 长句缺失 / 对话干燥 / 标点单一”；改写提示从“从身体第一刻开始”改为“恢复自然段、补足对话和过渡”。
- `engine/prompts/writing-rules.ts` 与 `assets/template-scaffold/00-系统模板/写作规则.md`：去掉“一句一段”“一段一个句号”，改成自然段。
- `shared/body-format.ts`：`describeBodyFormat` 从“一句话就是一段”改为“一个自然段写成一行；每段 2–6 句、80–220 字”。

### 4.4 确定性自然化

新增两个纯函数模块：

- `shared/prose-metrics.ts`：统计字数、句数、段数、平均句长/段长、单句段占比、短句/长句占比、对话占比、标点熵、句首多样性；输出 0–100 的“碎片化风险”和可解释问题列表。
- `shared/prose-naturalizer.ts`：合并相邻叙述短段；把对话和紧跟其后的说话人动作/神态并段；保留空行、场景转换句、连续对话的硬边界。只改段落边界，不改句子。

接入：

- `engine/body-writer.ts`：pipeline / batch / auto / continue / scene 写入默认执行自然段重排；manual 和 co-writer 不自动合并（协同写作是逐段插入，整篇自动合并会打断用户排版）。
- 设置页新增「自然段模式」（默认开）。
- 正文步骤新增「📊 人味体检」：指标卡、问题列表、自然段重排预览、写回正文。需要改句子时仍走「🧹 AI 消痕改写」。

### 4.5 测试

新增 `prose-metrics.test.ts`（7 条）、`prose-naturalizer.test.ts`（9 条）、`body-writer.test.ts` 自然化 2 条；更新 `human-voice.test.ts`、`body-format.test.ts`、`prompt-builder-budget.test.ts`。

## 六、朱雀实测（2026-10-27，腾讯朱雀 AI 检测助手）

测试地址：`https://matrix.tencent.com/ai-detect/ai_gen`。检测器模型更新时间：2026-07-21。当天免费额度有限，共做了 6 组对照。

| 样本 | 处理方式 | `labels_ratio` | 结论 |
| --- | --- | --- | --- |
| 鲁迅《孔乙己》2625 字 | 人类基线，原文 | `0:1.0 / 1:0 / 2:0`，confidence 0 | 100% 人工；检测器可用 |
| 第一章原文 4782 字 | 未处理 | `0:0 / 1:0 / 2:1`，confidence 1 | 100% AI |
| 第一章自然段重排版 | 只合并段落边界，不改句子 | `0:0 / 1:0.0605 / 2:0.9395` | 93.95% AI，6.05% 疑似，0% 人工 |
| 第一章网文口吻重写（DeepSeek） | 自然段 + 更多对话 + 解释 + 口语 | `0:0 / 1:0 / 2:1`，confidence 1 | 100% AI |
| 第一章网文口吻重写（Gemini） | 同上，换模型 | `0:0 / 1:0 / 2:1`，confidence 1 | 100% AI |
| 新版提示词小样 1184 字 | 自然段 + 对话，本地风险 8/100 | `0:0 / 1:0 / 2:1`，confidence 0.9866 | 100% AI |

自然段重排前后的本地指标：

| 指标 | 重排前 | 重排后 |
| --- | --- | --- |
| 段数 | 133 | 84 |
| 平均叙述段长 | 32 字 | 60 字 |
| 单句叙述段占比 | 48% | 13% |
| 平均句长 | 13.7 字 | 13.7 字（只重排段落，未改句子） |
| 风险分 | 81（高） | 58（中） |

新版提示词小样（同一模型，1184 字，已送朱雀复测）：

| 指标 | 结果 |
| --- | --- |
| 段数 | 10 |
| 平均叙述段长 | 118 字 |
| 平均句长 | 23.6 字（标准差 12.3） |
| 长句占比 | 21% |
| 短句占比 | 14% |
| 对话占比 | 24% |
| 本地风险分 | 8（低） |
| 朱雀判定 | `0:0 / 1:0 / 2:1`，confidence 0.9866，100% AI |

这说明提示词确实能把模型拉回自然段和正常句长，但“本地读起来自然”与“朱雀判为人工”是两套标准。新版提示词也没有让朱雀改判。

结论：

1. 朱雀不是只看段落长度。把 133 段合并成 84 段，AI 率只从 100% 降到 93.95%，人工率仍是 0%。
2. 换模型、换提示词也不能解决。DeepSeek 和 Gemini 用“自然段 + 口语 + 解释 + 多对话”的提示词重写，仍然是 100% AI；新版提示词小样本地风险只有 8/100，朱雀仍然判 100% AI。
3. 只靠提示词、分段、换模型，无法稳定达到 70% 人工率。朱雀看的是更深层的模型级统计特征，不是表面格式，也不是本地可读性指标。
4. 要达到 70% 人工率，可靠路径只有：人工改写/人工润色关键段落，或引入非 LLM 的生成环节。继续堆“去 AI 味”提示词，收益很低，而且会牺牲可读性。
5. 本轮没有继续做“绕过检测”的对抗性改造。那类改法（故意错别字、随机标点、拼接人类文本）会破坏可读性，也不稳定，不适合作为产品能力。
6. 外部检测器会更新，今天的结果不代表以后。建议把「人味体检」作为质量门禁，把朱雀结果作为参考，不要作为唯一验收标准。

插件现在能做的是：把“碎片化、短句、缺对话、标点单一”这些可解释的问题摊开，给出确定性的自然段重排，并让生成提示词默认按自然段写。它不能保证任何外部检测器的具体分数。
