## 一、严重（本轮已修）

### S-6 保存设置把豆包向量 Key 写成 OpenAI 的 Key

| | |
|---|---|
| 位置 | `core/settings-service.ts:234` |
| 原因 | `vectorDoubaoApiKey: encryptedVectorApiKey` — 224/225 行分别算出了两个加密值，回写时复制粘贴错字段，`encryptedDoubaoApiKey` 成了未使用变量 |
| 触发 | 任意一次 `saveSettings()`（启动自动回写即可触发）；豆包向量用户必现 |
| 影响 | 豆包向量 Key 被 OpenAI Key 覆盖；OpenAI 留空时豆包 Key 直接被清空 → 向量检索 401 / 永久丢凭据 |
| 修复 | 改为 `vectorDoubaoApiKey: encryptedDoubaoApiKey` |
| 验证 | `tests/unit/core/settings-service-d5.test.ts` 新增用例：三个向量 Key 各写各的字段（`enc:sk-openai` / `enc:sk-doubao` / `enc:sk-qwen`），互不覆盖 |

### S-7 加密锁定态下保存 mini 设置会把 API Key 写成空串

| | |
|---|---|
| 位置 | `ui/mini-settings-modal.ts:2623-2631` |
| 原因 | 密钥输入框在未解锁时被 `describeSecretForInput` 刻意留空（避免展示密文），保存却无条件 `settings.apiKey = input.value` |
| 触发 | 启用口令加密 → 重开设置停在 API 页签 → 改任意项（如默认字数）→ 点「💾 保存设置」 |
| 影响 | 已加密的 API Key 被空串覆盖，模型全部失效，且不可恢复（原始密文已丢） |
| 修复 | 新增 `pendingApiKey`（input 事件记录真实输入）；保存时**仅在非空**时覆盖，空值视为「未修改」 |
| 验证 | 手动：加密态下改默认字数并保存 → 密钥行仍显示「已加密」，模型可正常调用；typecheck + 全量单测 |
